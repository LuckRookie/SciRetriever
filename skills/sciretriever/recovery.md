# 失败与恢复

## 原则

- 出错或中断后，先重新读当前状态：会话用 `status`，文件用 `files`（`pending: true` 是还缺的），报告用 `report`。按读到的状态继续，不凭之前的输出行动。
- 写操作不要盲目重发。重发同一序号的数据只是替换那一段；确认、结束、取消之前先读状态，状态已经变了就不要再发。
- 同一个错误连续出现两次，停下来告诉用户你在做什么、错误码是什么。

## 常见情况

| 现象 / 原因码                                      | 怎么办                                                               |
| -------------------------------------------------- | -------------------------------------------------------------------- |
| 连不上地址                                         | 告诉用户所连的地址；文献库在服务器上时，请用户检查端口映射           |
| `device-token-invalid`、`device-revoked`           | 令牌失效或被撤销，请用户重新生成连接码，按 connect.md 重新连接       |
| `device-purpose-forbidden`                         | 这个连接没有对应用途（导入、读取、操作），请用户重新生成连接码并勾选 |
| `import-library-busy`                              | 同一来源库已有进行中的会话：读它的状态接着用，或请用户决定取消       |
| `import-session-state`                             | 会话状态已变化（可能用户在网页上确认或取消了）：读状态后再决定       |
| `import-data-changed`                              | 确认前数据变了：重新预览，再确认                                     |
| `import-request-too-large`、`import-session-limit` | 数据太大：分成更多段，或分成几次导入                                 |
| `import-metadata-pending`                          | 书目还在入库，稍后再结束                                             |
| `import-file-hash-required`                        | 这篇已有 PDF，只报 SHA-256，不传文件（脚本会自动处理）               |
| 文件上传中断                                       | 重新运行 `scripts/upload_files.py`，已交的不会重复                   |
| 文件 `conflict`                                    | 库里已有另一份 PDF，不替换；报告给用户                               |
| 磁盘空间不足（HTTP 507）                           | 停下，告诉用户文献库所在磁盘空间不足                                 |

其他原因码查 `GET <地址>/api/v1/import/instructions` 里的错误表。
