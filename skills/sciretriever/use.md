# 使用文献库：HTTP 版 MCP

同一文献库地址的 `/mcp` 提供 Streamable HTTP。连接需要“读取”用途；提交任务还需要“操作”。只有“入库”用途时使用 [import.md](import.md) 的 HTTP 接口。

在支持 Streamable HTTP 的客户端中配置 `<文献库地址>/mcp`，从私有文件加载连接令牌作为请求头。具体配置方式以客户端为准；不把令牌粘贴进对话或示例配置。列出工具确认连通，实际工具和字段以服务端返回的定义为准，列表随连接用途变化。下面提到的工具名在列表里找不到时，说明这个连接没有相应的用途，请使用者核对授权，不换别的办法绕过。

入库数据与文件使用 HTTP 入库接口，不通过 MCP 传输。完整接口说明仍在 `GET <地址>/api/v1/intake/instructions`。

## 文献库与候选

库里的文献分两边，先弄清使用者说的是哪一边：

- **文献库**：使用者要的文献。他点名导入的（书目文件、PDF、指定文献、网页收藏）直接在这里。
- **候选**：程序找来、他还没有表态的文献。主题搜索和引用扩展带回来的都是候选，数量可能是几十万篇。

两边是同一个库里的同一种记录，只差一个标记。`search_library` 默认只查文献库；`collection_scope` 取 `candidates` 只列候选，取 `all` 两边都查。向使用者报数时说明是哪一边的数。

## 查找与阅读

- 先检索，再读文献详情与全文；按服务端分页读取，不一次请求整库内容。
- 打开阅读一篇候选不会让它进入文献库。
- 解析过全文的文献可能带有译文（机器翻译，默认简体中文）。读全文时先看文档说明里的译文状态；使用者要中文或对照时，按接口定义用译文或对照的读法。**引用、摘录原话和给出处时一律用原文**，译文只用来帮助阅读，并向使用者说明它是机器翻译。没有译文时照实说，不要自己翻译后冒充库里的译文。
- 解析过全文的文献通常还有**概览与脉络**：概览是提要（这是一份什么资料、局限与未决事项、精读建议）加按章节排列的要点；脉络是每个要点和它在全文里的依据。要判断一篇文献值不值得读、或要快速掌握它的内容时，先读文档说明里的阅读层状态，有就先取概览，需要时取脉络，再读全文。要点与提要是机器写的，向使用者转述时说明这一点；**引用和摘录用依据的原句**。没有阅读层时照实说（长文档与很短的文献没有），不要自己总结后冒充库里的概览。
- 入库后核对：读取批次状态、进度与报告（`intake_batch_status`、`intake_batch_report`），再按使用者要求检索新入库的文献。只持“入库”用途时继续用入库 HTTP 接口。

## 搜索与扩展

使用者要“找某个主题的文献”或“把这几篇的参考文献、被引文献找出来”时：

1. 问清范围：主题词或起点文献、要多少、引用扩展往外几层。范围越大带回的越多，一层引用扩展就可能是几千篇。
2. 主题搜索用 `discover_metadata`，引用扩展用 `discover_citations`。两者只存书目和引用关系，不下载 PDF。它们会访问外部的书目来源，使用者没有同意联网时先问。
3. 结果是一份操作报告，不保证相关。带回来的文献是**候选**，不在文献库里：告诉使用者带回了多少篇、怎样看（网页“文献库”页顶部的候选篇数，或用 `collection_scope: candidates` 检索）。
4. 不要替使用者把候选整批加入文献库。他挑出要的，再按下一节加入。

## 整理文献库

每项操作都要“操作”用途，并且只对使用者指定的文献做。

- **加入文献库**：`collect_literatures`。此外，对一篇候选做下列事情也会让它进入文献库：手动加标签、放进文件夹、提供或获取 PDF、解析全文、发起加工。只是检索到或打开阅读不算。
- **移出文献库**：`uncollect_literatures`。文献回到候选，同时离开所有文件夹；书目、PDF、全文、批注、标签和阅读记录都保留。以后再加入时，原来的文件夹归属不恢复。使用者说“这篇不算我的”“从库里拿掉”而不是“删掉”时，用移出。
- **删除与恢复**：`library_trash_manage`，查看用 `library_trash_query`。删除的文献进入“最近删除”，不再出现在检索、列表和引用关系里；恢复后回到删除前所在的一边。搜索与扩展再次找到已删除的文献时不会恢复它，使用者再次点名导入时才恢复。
- **识别书目**：只导入 PDF 而没认出是哪一篇的文献标为“书目待补”。`recognize_literatures` 用保存的 PDF 重新认一遍，不用模型、不下载 PDF。它返回一个任务，按任务编号查结果。

整批操作前先用检索数一遍会影响多少篇，把数字告诉使用者；数字与他预期的不符时停下来问。

## 获取 PDF 与解析全文

这两件事要联网、可能用到使用者的机构订阅，解析全文还要调用解析服务和模型并产生费用。每一件都要使用者明确同意，同意只对他说的那批文献有效。

**获取 PDF。**

1. 用 `acquire_pdf_preview` 看这一批的范围：多少篇、哪些已经有 PDF。
2. 把范围告诉使用者，得到同意后用 `acquire_pdf` 提交。
3. 返回的是一个任务，不代表拿到了 PDF。按任务编号用 `read_task` 查进度；结束后报告拿到几篇、没拿到的原因分别是什么。没拿到的不要反复重试，交给使用者决定。

**解析全文。** 解析全文把 PDF 变成可检索、可引用的全文，依次做解析、整理、逐页校订、翻译和书目、标签等步骤。翻译失败不影响全文可用，会留一条“需处理”。

1. 先用 `usage_estimate`（`kind: archive`）估算这一批的用量。没有历史数据时会返回未知，照实告诉使用者。
2. 把篇数和估算交给使用者，得到同意后用 `archive_manage` 的 `build` 发起。只对有 PDF 的文献有效。
3. 用 `archive_query` 或任务编号查进度，不因等待而重复提交。一篇文献可能停在“需处理”：读出问题，告诉使用者，由他决定继续、跳过还是取消，再用 `archive_manage` 的 `resolve`。
4. 中断的用 `resume` 接着做，不重新 `build`。

## 提交其他任务

遵守使用者对范围、联网与费用的授权；缺少必要授权时先问。提交后按任务编号查询，不因等待而重复提交。
