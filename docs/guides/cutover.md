# 数据库切换

本页说明从已核对的转换副本切换到唯一当前数据库结构的方法。生产代码不提供历史迁移阶梯；普通启动不会转换旧库。

1. 确认实际 Catalog 与 ArtifactStore 的精确位置，记录源库结构、数量、稳定 ID 和资产引用。配置、凭据及 Browser Profile 不混入数据转换报告。
2. 通过 SQLite 的一致性备份保存源库，保留已提交 WAL 事实。资产字节保持原样；需要移动资产时另存完整副本并核对相对路径与 hash。
3. 在独立副本完成转换，检查当前 schema 指纹、完整性、外键，以及文献、观测、资产和关系的保留情况。对派生结果的任何排除或失效单独记录，不能冒充新流程结果。
4. 停止新操作准入，等待或取消在途任务并保存已经提交的事实，关闭使用旧库的服务。确认副本创建后源库没有新提交；存在新增数据时先保全并处理这些增量。
5. 保留原库，切换到转换副本。先验证只读文献、材料和证据读取，再恢复写操作。索引重建是单独的显式动作，不由读取触发。
6. 发生问题时保留新旧副本、资产和日志。恢复前先保存切换后的增量，不覆盖唯一副本，也不让旧程序写入当前结构。

当前结构的创建与检查命令见[数据库初始化与恢复](upgrade.md)。真实 Provider、MinerU 和模型验证是独立操作，不属于本地结构转换。
