# 03 · 获取结果看得清

类型：计划（结果块）
负责：P17、P18、P19，以及 P20 在任务详情、来源统计和浏览器页的部分
状态：Ready

## Outcome

- “获取 PDF”任务显示：按渠道统计的篇数条形图、各渠道的尝试与命中、逐篇经过。
- 主题发现、引用扩展、补全书目任务显示：每个来源本次找到的条数，以及占本次合并结果的比例。
- 任务页新增“来源统计”，用比例显示每个来源好不好用。
- 以上数字都取自各任务的逐来源记录，与逐篇或逐条记录一致。
- 请求失败统一显示为“错误”。

验收口径以问题清单 P17–P20 的“怎样检验”为准。界面以[页面规格草案·获取任务详情、来源统计](../../architecture/web/page-specs.md#草案文献来源设置与获取任务详情计划-17待确认)为准。统计只给人看，不据此自动调整获取顺序。

## 进入条件

- 依赖 02 的 2.1（来源合同）和 2.7 中的错误呈现组件；其余与 02 无关，可以并行。
- PDF 的逐来源记录已由 `8b82be8` 写入任务事件。
- 元数据的逐来源计数还没有，由本块补上。

## 责任边界

- worker 负责：
  - 元数据任务的逐来源计数；
  - 来源统计的聚合接口；
  - 浏览器页把平台原因码改为“错误”的数据口径。
- Claude 负责：
  - 任务详情的条形图与表格切换；
  - 来源统计页；
  - 浏览器页的错误显示。

## Tasks

- [ ] **3.1 元数据逐来源计数**（worker）
  - 主题发现、引用扩展、补全书目三类任务，每个来源记录：返回条数、进入本次合并结果的条数、出错与未配置。
  - 本次新入库与合并到已有的总数只记在任务层面。
  - 进行中的任务经任务事件实时更新。
- [ ] **3.2 来源统计接口**（worker）
  - 时间范围分“近 30 天”和“全部”。
  - PDF 每个来源：尝试、拿到、请求出错的比例，以及三种可处理情况的标签。
  - 元数据每个来源：检索覆盖、补全命中、引用命中、错误四个比例，各带分母。
  - 只从逐来源记录聚合，不另算一套。历史任务没有记录的不计入，并返回统计起点。
- [ ] **3.3 界面**（Claude）
  - 两类任务详情、“来源统计”标签页、浏览器页的错误显示。
  - Agent 自己写的停止说明保留原样。
  - 设计样例库补齐：进行中、无结果、出错、历史无记录等状态，截图后交 R-03。
- [ ] **3.4 一致性测试**（worker 写服务端，Claude 写 Web）
  - 在合成任务上断言：条形图与统计的数字等于逐篇或逐条记录求和；
  - 未启用和冷却中的不计入尝试；
  - 每篇只计入最终拿到 PDF 的渠道。
