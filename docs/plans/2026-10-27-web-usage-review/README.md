# 计划 17：Web 实际使用问题审查与修复

类型：计划
负责：收集 Owner 实际使用中发现的问题、逐项定性，并汇总成可执行的结果块
状态：In progress（2026-10-28 Owner 确认分块后开工）

## 目标

Owner 在 4174 上实际使用 Web 工作台，一项一项提出问题。Claude 先定性（bug 还是设计问题、属于哪个模块、需要什么证据），收集齐全后统一划分结果块，再由 Claude 指挥 worker 按块实施。

收集阶段不改代码；已经修掉的问题只登记结论和提交号，不再列为待办。Owner 2026-10-28 宣布收集结束（“我们就开始把17进行分块准备执行吧”），之后的新问题另行登记，不并入本计划的结果块。

## 分工

沿用计划 14、16：Owner 提需求、审阅、授权；Claude 定性、设计、写 Web 前端、派活与验收；worker（codex 会话 `sciretriever-web`）做后端、合同、测试基础设施与部署。与 worker 的交互方式见全局 skill `codex-usage`。 本计划 worker 用 `gpt-6.1-sol`、思考强度 max（Owner 2026-10-28）。

## 审查方式

1. Owner 每提一个问题，Claude 在下方“问题清单”登记一行：现象、定性、证据位置、建议去向。
2. bug 可以当场修（Owner 规则：bug 直接修），修完在清单写提交号；设计问题只登记，与 Owner 讨论后再定。
3. Owner 宣布收集结束后，Claude 按“可独立验收的结果”把未完成项分成结果块（`01-…md` 起），写依赖与验收，交 Owner 确认，然后开工。
