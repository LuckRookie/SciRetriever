# 02 只导入 PDF 时的书目

类型：计划（结果块）
负责：只导入 PDF 时书目的认出率实测，以及没认出时采用 PDF 自带的哪些字段
状态：In progress（离线实测与 2.3、2.4 完成；2.5、2.6 取消；2.7、2.8 调查中；2.1、2.2 的在线部分等 G-provider、G-sample）

## Outcome

知道只导入 PDF 时能认出多少、认不出的原因各占多少；在不调用模型的前提下，把 PDF 自己带着的信息用足，使没认出的文献在列表里也看得出是哪一篇。

## 进入条件

- 现状：`apps/server/src/literature/file-clues.ts` 从 PDF 的 XMP、文档信息与首页文字里取 DOI 与标题；认出后取来源的书目；没认出时用读到的标题并标“书目不全”；解析全文后自动再认一次并补全（[文献与材料 8.4](../../architecture/technical/03-literature-materials.md#84-书目待补)）。
- G-provider（调用真实来源）；G-sample（样本）。

## 责任边界

本块可以改的只有两处：没认出时采用 PDF 自带的哪些字段；预览与报告里怎样说明。认篇的前三步规则不变。

## Tasks

- [ ] 2.1 样本（总设计师、Owner）：定一批 PDF，至少包括英文期刊文章、中文期刊文章、预印本、扫描件、书的章节；数量与来源由 Owner 定。正式库里已有的 PDF 只读使用。
- [ ] 2.2 实测（后端，只读）：对样本逐篇记录：PDF 里有没有 DOI；有没有可读的标题；XMP 与文档信息里有没有作者、期刊、年份；按 DOI 认出、按标题认出、没认出；没认出的原因。结果写成一张表放在本块，原始记录放 `sandbox/reports/`。
- [x] 2.3 核对 PDF 自带字段的可靠程度（后端，只读）：在按 DOI 认出的那部分上，把 PDF 自带的作者、期刊、年份与来源的书目逐项比对，给出各字段一致的比例。
- [x] 2.4 决定（总设计师，必要时问 Owner）：按 2.3 的数字，定没认出时采用哪些自带字段、达到什么条件才采用；规格写进文献与材料 8.4。
- 2.5（取消，见 2.4 的决定）后端：按 2.4 实现；这些字段作为一条来源记录保存，不覆盖人工锁定的字段，文献仍标“书目不全”。
- 2.6（取消，见 2.4 的决定）前端：批次预览与文献行上，说明这篇的书目来自 PDF 自身、还没有经来源核对。
- [ ] 2.7 首页乱码：先查清只用 MuPDF 能否读对（换取字方式或自己还原字符），再实现；做不到时把保留 `pdftotext` 作为后备的利弊交 Owner。调查已派出（只读）。
- [ ] 2.8 读线索的内存上限：量出实际占用的分布，定一个上限并实现。调查已派出（只读）。

## 离线实测的结果（2026-11-25，正式库 954 篇主 PDF，只读，不调用来源）

这是 2.2 的离线部分与 2.3。认篇是模拟的：假定来源返回的就是库里现有的书目，所以下面的“认出”是上限，不是实测的认出率。库里没有中文题名的文献，中文没有量到。

**现在能读到什么**

| 指标          |                                   篇数 |
| ------------- | -------------------------------------: |
| 读到 DOI      |      564（59.1%），其中 547 与库中相同 |
| 读到 arXiv 号 |                                    132 |
| 有候选标题    | 947，其中与库中题名一致的 723（75.8%） |
| 读不出线索    |              7：内存不足 5，只有图像 2 |

**离线模拟的认篇**

| 结果                   | 篇数 |  比例 |
| ---------------------- | ---: | ----: |
| 按标识认出             |  649 | 68.0% |
| 按标题认出             |  113 | 11.8% |
| 只够成为“可能是这一篇” |   31 |  3.2% |
| 认不出                 |  161 | 16.9% |

认不出的 161 篇里，候选标题与库中题名不够像的 149 篇，其中 58 篇是 MuPDF 把首页读成了乱码；读线索时内存不足 5 篇。

**PDF 自带字段的带有率与可靠程度**（与库中现有书目比对，952 篇）

| 字段与来源                        | 带有率 |            一致率 |      明确错误 |
| --------------------------------- | -----: | ----------------: | ------------: |
| 期刊，XMP `prism:publicationName` |  29.2% |             94.1% |          1.8% |
| 年份，XMP 的 `prism` 三项日期     |  21.6% |             90.3% |            0% |
| 年份，文档信息 `CreationDate`     |  95.4% |             83.5% |          7.8% |
| 作者，XMP `dc:creator`            |  46.8% |    第一作者 92.5% | 第一作者 7.5% |
| 作者，文档信息 `Author`           |  47.2% | 人数只有 31.5% 对 |             — |
| 标题，XMP `dc:title`              |  56.0% |             83.7% |             — |
| 标题，文档信息 `Title`            |  77.8% |             62.9% |  垃圾值 31.8% |

加条件后可以很准：XMP 的作者在“不是垃圾值、至少 2 人、XMP 带出版方字段”时 218 篇只错 1 篇；`prism` 的年份 206 篇 0 错。

**但这些字段在用得上的地方很少。** 认不出的那部分文献里，带出版方 XMP 的只有 9 篇；按上面的条件只能采用 6 篇的作者，其中 1 篇是错的。不加条件时，作者的错误率是 59%，文档信息的标题错 92%。

## 2.4 的决定（总设计师，2026-11-25）

- **不做“没认出时采用 PDF 自带的作者、期刊、年份”。** 认得出的文献用不着它，认不出的文献大多没有这些字段，有的又多半是错的；为几篇文献加一套规则不值得。2.5、2.6 因此取消。
- **改做两处收益更大的修正**（新任务 2.7、2.8）：首页被读成乱码的 PDF，和读线索时内存不足的 PDF。两者合计约占认不出文献的四成。
- 真实来源上的认出率（2.2 的在线部分）仍然要量，等 G-provider；中文文献要 Owner 提供样本（G-sample）。

## 集成与影响

2.5 改变没认出的文献入库时的书目内容；已入库的文献经“识别书目”得到同样的结果。不改库结构。

## 验证

- 2.2、2.3 的表。
- 2.5：自带字段齐全、只有部分、与读到的标题矛盾、有人工锁定字段，各一条服务端测试。
- 2.5 之后在同一批样本上重跑 2.2，比较前后。

## 退出条件

认出率与原因分布有数字；没认出的文献在可靠的前提下带上作者、期刊、年份；规格同步；已部署。
