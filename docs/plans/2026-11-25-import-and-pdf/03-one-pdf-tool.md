# 03 PDF 工具合一

类型：计划（结果块）
负责：下载验收改用 MuPDF，去掉对 pdfinfo 与 pdftotext 的依赖
状态：In progress（3.1、3.2 完成；3.3、3.4 待派工）

## Outcome

程序只依赖 MuPDF 一套 PDF 工具。安装时少一样要带的部件，`doctor` 与启动把关的清单随之缩短。

## 进入条件

- 现状：MuPDF 用于读导入的 PDF、识别书目、校订时渲染页面；`pdfinfo`、`pdftotext` 只用在 `apps/server/src/acquisition/pdf-acceptance.ts`（下载回来的 PDF 的验收）与 `doctor` 的检查项。
- [ADR 0066](../../architecture/decisions/0066-complete-program-or-failed-build.md)“还没有验证的前提”第二条：两者的结果是否一致没有比较过。

## 责任边界

只换验收里取信息的工具；验收的判断规则（是不是合法 PDF、页数、加密、是不是这篇文章）不变。

## Tasks

- [x] 3.1 比对（后端，只读）：对正式库已有的全部 PDF，分别用两套工具取：能否打开、页数、是否加密、取出的文字。逐项记录不一致的篇数与样例；另加几份构造的坏文件（截断、加密、不是 PDF）。结果写成表放在本块。
- [x] 3.2 决定（总设计师）：不一致之处逐类判断哪一个对、换了之后验收结论会不会变；会变的列出来，有影响使用者已有文献的问 Owner。
- [ ] 3.3 后端：`pdf-acceptance.ts` 改用 MuPDF；超时、输出上限、隔离照现有做法。`doctor`、启动把关、运行清单（`release/manifests/runtime-support.json`）去掉 `pdfinfo`、`pdftotext`。
- [ ] 3.4 文档：[安装指南](../../guides/installation.md)与 README 的前提条件同步。

## 3.1 的结果（2026-11-25，正式库 954 篇主 PDF，只读）

验收只用 `pdfinfo`。`pdftotext` 在生产代码里没有调用方，只有测试用它。

| 项       | 两套工具一致 | 不一致 |
| -------- | -----------: | -----: |
| 能否打开 |          954 |      0 |
| 页数     |          954 |      0 |
| 是否加密 |          954 |      0 |
| 验收结论 |          954 |      0 |

耗时相当：`pdfinfo` 中位数 20 毫秒，MuPDF 取页数、加密与元数据中位数 19 毫秒（P90 80，最大 741），没有一篇接近 10 秒的期限。

正式库里没有加密、截断或打不开的 PDF，所以这只说明合法文件不会被误拒。坏文件的结论来自 17 份构造的文件：

- **截断的 PDF 会由拒变收。** 截到一半的、只剩前 1 KiB 的两份，`pdfinfo` 失败，现在判 `pdf-invalid`；MuPDF 会自行修复并报告有 3 页。
- 去掉 xref 的、startxref 写错的两份，两套工具都修复后接受。
- MuPDF 会把 HTML 当成 HTML5、把 PNG 当成图像打开；需要用户密码的 PDF，`pdfinfo` 直接失败，MuPDF 能报告需要密码。现在都靠开头的字节检查先拦下。
- 空文件、纯文字、ZIP、0 页、三种加密，结论都不变。

另一个发现与验收无关，但与只留一套工具有关：**第 1 页的文字，MuPDF 有 57 篇读成乱码而 `pdftotext` 能读**（几乎都是 2000 年代某一种排版软件出的 PDF）。导入时读线索用的是 MuPDF，这些文献因此认不出。见 [02](02-pdf-only-metadata.md)。

逐篇记录在 `sandbox/reports/2026-11-25-plan28/measure/`。

## 3.2 的决定（总设计师，2026-11-25）

- 验收改用 MuPDF，去掉 `pdfinfo`；`pdftotext` 本来就没有被用到，一并去掉。
- 保留开头的 `%PDF-` 与 `/Encrypt` 字节检查；另外要求 MuPDF 报告的格式是 PDF、不需要密码、没有加密、页数不少于 1。
- **MuPDF 报告“做过修复”的文件判 `pdf-invalid`。** 理由：下载到一半的文件正是这种情形，现在会被拒，换工具后不能变成接受；954 篇真实 PDF 里没有一篇需要修复，所以这条不会误拒现有的文件。代价是 xref 损坏但内容完整的文件由收变拒，比现在严。
- 乱码的 57 篇不挡本块：验收不用文字。它在 02 里处理，先查 MuPDF 一侧能不能读对；查清之前不为它保留 poppler。

## 集成与影响

获取 PDF 的验收路径；安装与环境检查。不改库结构，不重新验收已有的 PDF。

## 验证

- 3.1 的表。
- 现有的验收测试全部通过；坏文件各一条。
- 在一台没有 `pdfinfo`、`pdftotext` 的环境里（或把它们从 `PATH` 里拿掉）构建、启动、`doctor` 通过。

## 退出条件

仓库里不再调用 `pdfinfo`、`pdftotext`；3.1 的结论写在本块；文档同步；已部署。
