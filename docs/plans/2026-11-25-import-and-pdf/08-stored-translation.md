# 08 全文的译文：解析时翻好，存进文献库

类型：计划（结果块）
负责：把全文翻译做成解析全文的一步并存进文献库；阅读页“全文”的原文、译文、对照三种读法；译文的导出、检索与 Agent 读取
状态：In progress（8.1–8.7 完成并已部署；索引重建、8.8 实测与在真实文献上补译文未做，等 Owner）

## Outcome

解析全文之后，一篇文献同时有原文和译文，块与块一一对应。阅读页的“全文”可以读原文、译文或上下对照；Markdown 可以导出三种；用译文的语言能搜到它；Agent 能读到译文。

## 进入条件

- [ADR 0068](../../architecture/decisions/0068-stored-full-text-translation.md)：Accepted，8.2 起以它为准。
- 现状：`apps/server/src/translation/` 已有逐页分块翻译（`fulltext.ts`）与译文缓存；块的编号、类型与章节角色由 document 模块给出。阅读页视图切换现在写“原文 · PDF”。
- 库结构要加表：部署时在正式库上执行须经 Owner 同意（他 2026-11-25 说“库结构改就改呗”，执行前仍确认一次）。
- 真实的质量与花费实测等 G-parse。
- 块与句子：做分层阅读的样稿时发现，有的块在页边界处断在句子中间，逐块翻译会把一句话拆成两半。8.2 要定：这种跨页接续的段落合在一起翻，译文怎样对回各块。
- 模型并发：整个进程同时发出的模型请求默认只有 3 个，校订、元数据、标签都在用（[05](05-parse-throughput.md) 的 5.1）。翻译加进来会抢同一组名额，8.3 要定翻译用多少并发、名额是否随之调整，8.8 要量解析全文因此慢了多少。

## 写规格时定下的事（2026-11-26）

先让一个只读代理清点了现有的翻译、建档编排、检索与读取的代码，下面各条据此而定：

- **跨页断句已经有解**：整理一步本来就把跨页、跨栏续接的叶块并成一段（合并段）。翻译以渲染出的段为单元，不以叶块为单元，半句话的问题随之消失；做样稿时看到的断句是按叶块取数造成的。
- **译文靠文字对上原文，不靠叶块编号**：叶块编号在重新解析后全部变化，按编号无法沿用。
- **存放**：照校订稿的做法，文件进 ArtifactStore、库里只登记，不把译文正文存进库表。
- **译文语言放在配置里**（`[translation].target_language`）：库里现在没有库级设置的存放处，为一项设置新建一套不值得。
- **不做独立的 Markdown 导出入口**：“下载全文”现在是分片读出来拼的，给分片读取加“原文、译文、对照”一个选项，网页、CLI、MCP 三处就都有了。
- **已知的代价**：
  - `archive_steps` 的步骤名有取值约束，加 `translate` 要改这张表，再加一张登记表，一共两处库结构改动。
  - 翻译现在不记录 token 用量，要补上，否则用量估算里这一步永远是未知。
  - 现有全文索引把一串汉字当成一个词，用中文搜不到任何东西。8.6 把切分改为按字；原文索引同样受影响，改了规则之后要重建索引才对已有的中文资料生效，重建在正式库上执行前问 Owner。
  - 已经解析过全文的文献没有译文，要各自再解析一次才补上（只跑翻译这一步），这要调用模型，等 G-parse。
- **首版不做**：补充材料的译文、表格内容的译文、一篇文献多种语言并存时的选择、术语表。

## 8.3、8.4 的结果（2026-11-26）

- 合入 `d8162263`、`93a6f2ce`、`058a4aaf`，以及截断时对半重试的 `da57bf0d`。规则写在[文档与证据第 9 节](../../architecture/technical/04-document-evidence.md#9-全文的译文)，接口字段以那里为准。
- 实测（样例校订稿，只读）：普通文献 4–11 页，每篇 31–65 个可译单元、3–11 个合并段、0.95 万到 4.8 万码点，按一批 6,000 码点要 2–8 次请求；一篇 294 页的长文档 1,524 个单元、85 次请求。分批上限不用改。
- 机构不在作者行里而在文末信息里：规格改为“首页的文章信息不翻译，文末信息照常翻译”。
- 库结构：增补集 `document-translations` 新建登记表并重建 `archive_steps`（步骤名改为格式检查，以后加步骤不用再改表）。这是存储 4.4 的第二个例外：停服执行，合成库上每 1 万篇已建档文献约 2.5 秒；执行之后旧版本打开时以 `catalog-integrity-refused` 拒绝，换回旧版本要先恢复备份。命令 `sciretriever storage schema-apply --catalog <绝对路径> --addition document-translations`。
- 验证：实施者跑了 15 个测试文件 92 条，都用假模型；我在主工作区重跑了译文相关的三个文件。真实模型上没有跑过；“模型不可用”这条路径只读过代码，没有测试。
- 交给前端的事（8.5）：步骤名表没有“翻译”；需处理多两个原因；用量估算多一项；阅读页取状态看 `describe.translation.state`；PDF 视图不再现场翻译。
- 还没有做的：
  - 设置页拿不到译文语言的值（没有加进网页的配置分区）。
  - 被替换的旧译文文件不回收，与其他被替换的不可变文件一致。

## 8.5 的结果（2026-11-26）

- 阅读页：视图“原文”改称“全文”；全文有原文、译文、对照三种读法并记住选择；没有译文时按四种情形说明；下载全文三种；PDF 对照翻译读库里的译文；“翻译”标签页在有库里译文时也出现；建档进度、需处理与用量估算认得“翻译”；设置页写出译文语言；“找文献 → Zotero”改为照实说明。规则写在[阅读体验 3.4.1](../../architecture/web/reading-experience.md#341-三种读法)。
- 验证：实施者跑了 11 个测试文件，除一条外全过；我看过译文、对照、没有译文、PDF 对照四张截图。都是测试夹具上的假译文，没有在真实译文上看过排版。
- 已知问题：
  - `next-reader-boundaries` 里“bounds PDF canvases while zooming…”一条原来偶发失败，查明是测试在位图到达前就读了结果，已改为先等位图出现，页面行为没有问题。
  - PDF 对照的截图里译文盖住半行原文，是夹具给的区域不准；真实文献上要在 8.9 部署后看。
  - 设置页只显示译文语言，不能在页面上改。

## 8.6 的结果（2026-11-26）

- 全文索引收入译文，命中回到原文单元并标明命中的是译文；中日韩文字改为按字切分，书目检索用同一规则。规则写在[文档与证据 9.7](../../architecture/technical/04-document-evidence.md#97-检索)。
- 增补集 `document-translations` 随之多了四列与六个触发器（它还没有在任何正式库上执行过）。
- 实测（三篇中文规格文档作替身，2 万汉字、133 段）：按字切分后 FTS 体积增加约 22%，词数约 5.5 倍，条目数不变；一篇 2 万字的译文在索引里约占 0.22 MiB，多出 30–65 条。
- 部署之后要做的两件事（都要在正式库上执行，先问 Owner）：
  - `maintenance rebuild-index`：全文索引重建。没有实测；按计划 26 的 07 块，书目来源约每秒 100 个，35 万篇约 1 小时。重建之前检索照常可用，结果标“索引不是最新”。
  - `maintenance rebuild-library-search`：书目检索的行按新规则重写，估计 5–20 分钟，没有实测。
- 实施者跑了 10 个测试文件 80 条；我重跑了其中两个。
- 没有做的与已知的问题：
  - 索引状态能读出“规则过时”与“书目检索按旧规则”，检索页据此如实显示并提供“重建索引”“重写书目检索”两个按钮。
  - 重建之前，增量刷新写进旧代的新条目已按新规则切分，同一代里两种规则并存。
  - 中文按字计词频，排序会变，没有评估；单字查询更容易触到 4,097 条候选上限。
  - 检索页已做：译文命中的标记与摘录、复制为 Markdown 时标明机器翻译、模式名改为“全文与知识 / 仅全文 / 仅知识”。看过两张夹具截图，没有在真实索引上看过。

## 责任边界

复用现有的分块翻译逻辑与提示词；不改校订稿、块的编号与证据定位。划词翻译与它的缓存不动。分层阅读（概览与脉络）不在本块。

## 验证

- 离线：假模型下，翻译步骤的成功、部分缺译、失败不挡全文、只补缺的一步、全文改动后只重翻变了的块，各一条服务端测试；读取与导出三种各一条；检索用译文语言命中并回到原文块一条。
- 页面：三种读法切换、对照排版、没有译文的说明；在样例库上截图看一遍。
- 真实：8.8。

## 退出条件

新解析的文献自带译文；三种读法、三种导出、译文检索、Agent 读取都可用；规格、指南与 Skill 同步；已部署。

## 恢复与交接

翻译步骤按块记录进度，中断后从没翻的块继续。8.3 完成而 8.5 未完成时，译文已在库里，阅读页仍按旧的对照翻译显示，不影响使用。
