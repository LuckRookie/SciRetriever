## Outcome

- 适配器把 Zotero 接口返回的 JSON 转成条目。本地接口与网络 API 的数据走同一段代码。
- 书目、标识、分组、标签与首选附件都能转换；不导入的内容（笔记、非 PDF 附件、链接附件等）按种类计数。
- 没有父条目的独立 PDF 转成只有文件的条目（ADR 0063 第 2 节取代 ADR 0057 第 3 节的“不导入”），交给认篇（原计划 20 的 15，已完成）。
- 批注在本块只计数，17 再导入。

## 结果（2026-11-26）

- 适配器完成：格式 `zotero-api`，`apps/server/src/literature/zotero-adapter.ts`；合成的 Zotero 数据经入库接口完整入库（书目、带层级的文件夹、两种标签、首选 PDF、独立 PDF、按种类计数）。规则写在文献与材料 6.4.9。
- 核对规格时改掉的三处：现有 CSL JSON 规则不接受 Zotero 的部分真实输出，这类条目改走字段映射；链接附件不当首选；分段的规定（父子同段、分类都要交）。
- 没有做到的：
  - “本地接口样本与网络 API 样本转换结果一致”没有测，本地接口的样本要等 [07](07-zotero-import-program.md) 的探测模式。等它确认的假设：条目结构与网络 API 相同、`include=data,csljson` 给出 `csljson`、`links.attachment.href` 以 `/items/<编号>` 结尾、大小字段、回收站用 `data.deleted` 标记、`dateAdded` 可按字符串排序。
  - 独立 PDF 现在按文件名加大小配对，几个同名时配不上。按 `编号/文件名` 配对的规则已写进 6.4.3，随 07 实现。
  - 批注只计数，落库在 [17](17-zotero-annotations.md)。
  - 新的计数种类在网页上的显示用词，随 16 做。
- 测试：`zotero-adapter`、`import-sessions`、`intake-file-items-http` 三个文件 48 条通过；类型检查通过。没有跑 `pnpm quick`。

## 验证

- 直接测试（14 的合成样本），覆盖以下情形：
  - 没有 DOI 的条目；
  - Extra 字段里的 arXiv 号；
  - 多个 PDF、链接附件；
  - 独立 PDF；
  - 群组库；
  - 多级分类与多处归属；
  - 两种标签。
- 本地接口样本与网络 API 样本转换结果一致。
- 定向测试与 `pnpm quick`。

## 退出条件

合成的 Zotero 数据能经入库接口完整入库；16.4 可以把扩展读到的数据原样交上来。
