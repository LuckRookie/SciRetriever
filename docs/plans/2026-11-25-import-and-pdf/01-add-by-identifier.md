# 01 按 DOI 或标题添加文献

类型：计划（结果块）
负责：使用者给出 DOI、网址或标题，程序认出并把这些文献放进文献库；页面、MCP 与 CLI、Skill 三处的入口
状态：In progress（1.1 完成；1.2、1.3 已派后端）

## Outcome

使用者贴入若干行 DOI、网址或标题，程序认出各是哪一篇，预览后确认，这些文献进入文献库；可以随即为它们获取 PDF。页面、MCP 与 CLI、Skill 三处都能做同一件事。

## 进入条件

- [ADR 0063](../../architecture/decisions/0063-unified-intake.md) 的批次与认篇、[ADR 0067](../../architecture/decisions/0067-library-and-candidates.md) 第 3 节（点名的进文献库）。
- 认篇的规则见[文献与材料 6.4.6](../../architecture/technical/03-literature-materials.md)；实现在 `apps/server/src/literature/intake-recognition.ts`。
- 真实来源上的核对等 G-provider。

## 责任边界

本块增加一种交数据的方式，不改认篇规则、查重规则与批次的状态。生产者是页面、CLI 与 MCP；消费者是现有的批次预览、确认与报告。

## Tasks

- [x] 1.1 规格（2026-11-25 写入[文献与材料 6.4.12](../../architecture/technical/03-literature-materials.md#6412-指定文献逐行给出标识或标题)与页面规格“找文献”的“指定文献”标签页；格式名 `lookup`，一次最多 200 行，没认出的默认不入库）。原任务：规格（总设计师）：在文献与材料 6.4 写明“逐行给出标识或标题”这种载体：每行接受什么（DOI、DOI 网址、arXiv 编号、PMID、标题）、一次最多多少行、无法识别的行怎样报告；在[页面规格](../../architecture/web/page-specs.md)“找文献”写明入口放在哪个标签页、预览怎样显示。只给标题而对上多篇时，用现有的“可能是这一篇”让使用者挑。
- [ ] 1.2 后端：把每一行解析成批次条目，进入现有的认篇与预览；没认出的行留在预览里说明原因，不入库。批次类型是导入，确认后进文献库。
- [ ] 1.3 后端：CLI 与 MCP 的同一操作，请求与结果的形状写进[代理接口指南](../../guides/agent-interface.md)。
- [ ] 1.4 前端：“找文献”页的入口、预览与确认；确认后的提示里给出“获取 PDF”。
- [ ] 1.5 Skill：`skills/sciretriever/import.md` 写明 Agent 怎样代使用者按 DOI 或标题添加。
- [ ] 1.6 真实核对（G-provider）：10 个 DOI、10 个标题（含中文标题与有歧义的标题）走一遍，记录认出、需要挑选、没认出的篇数。

## 集成与影响

新增一个写入口与一个页面入口；不改库结构。已有的导入、收藏、发现不受影响。

## 验证

- 离线：假来源下，DOI 认出、标题唯一认出、标题对上多篇、无法识别的行、重复的行、库里已有同一篇，各一条服务端测试；页面测试一条走完贴入、预览、确认。
- 真实：1.6。
- 界面在样例库上截图看一遍。

## 退出条件

三处入口都能完成添加；1.6 的数字写在本块；规格、指南、Skill 同步；已部署。

## 恢复与交接

失败时批次停在预览，不入库；重新提交即可。交给块 04 的是最终的接口名与请求形状。
