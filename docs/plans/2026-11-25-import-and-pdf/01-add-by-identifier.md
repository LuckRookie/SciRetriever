# 01 按 DOI 或标题添加文献

类型：计划（结果块）
负责：使用者给出 DOI、网址或标题，程序认出并把这些文献放进文献库；页面、MCP 与 CLI、Skill 三处的入口
状态：In progress（1.1–1.5 完成，2026-11-26 部署到 4174；1.6 真实核对等 G-provider）

## Outcome

使用者贴入若干行 DOI、网址或标题，程序认出各是哪一篇，预览后确认，这些文献进入文献库；可以随即为它们获取 PDF。页面、MCP 与 CLI、Skill 三处都能做同一件事。

## 进入条件

- [ADR 0063](../../architecture/decisions/0063-unified-intake.md) 的批次与认篇、[ADR 0067](../../architecture/decisions/0067-library-and-candidates.md) 第 3 节（点名的进文献库）。
- 认篇的规则见[文献与材料 6.4.6](../../architecture/technical/03-literature-materials.md)；实现在 `apps/server/src/literature/intake-recognition.ts`。
- 真实来源上的核对等 G-provider。

## 责任边界

本块增加一种交数据的方式，不改认篇规则、查重规则与批次的状态。生产者是页面、CLI 与 MCP；消费者是现有的批次预览、确认与报告。

## Tasks

- [x] 1.1 规格（2026-11-25 写入[文献与材料 6.4.12](../../architecture/technical/03-literature-materials.md#6412-指定文献逐行给出标识或标题)与页面规格“找文献”的“指定文献”标签页；格式名 `lookup`，一次最多 200 行，没认出的默认不入库）。原任务：规格（总设计师）：在文献与材料 6.4 写明“逐行给出标识或标题”这种载体：每行接受什么（DOI、DOI 网址、arXiv 编号、PMID、标题）、一次最多多少行、无法识别的行怎样报告；在[页面规格](../../architecture/web/page-specs.md)“找文献”写明入口放在哪个标签页、预览怎样显示。只给标题而对上多篇时，用现有的“可能是这一篇”让使用者挑。
- [x] 1.2 后端（2026-11-25，`4be8f93d`；没有改库结构；标识先在库里对，库里已有的不问来源）：把每一行解析成批次条目，进入现有的认篇与预览；没认出的行留在预览里说明原因，不入库。批次类型是导入，确认后进文献库。
- [x] 1.3 后端（`import lookup` 与 stdio 版 MCP 的 `add_literatures`，同步执行；HTTP 版 MCP 不提供，Agent 经入库接口交 `lookup` 格式）：CLI 与 MCP 的同一操作，请求与结果的形状写进[代理接口指南](../../guides/agent-interface.md)。
- [x] 1.4 前端（`ba071239`；“指定文献”标签页与批次页；Zotero 标签页的说明改为现状）：“找文献”页的入口、预览与确认；确认后的提示里给出“获取 PDF”。
- [x] 1.5 Skill（`import.md` 加“使用者点名要某几篇”一节）：`skills/sciretriever/import.md` 写明 Agent 怎样代使用者按 DOI 或标题添加。
- [ ] 1.6 真实核对（G-provider）：10 个 DOI、10 个标题（含中文标题与有歧义的标题）走一遍，记录认出、需要挑选、没认出的篇数。

## 实现记录（2026-11-25）

- 验证：`intake-lookup`、`intake-recognition`、`intake-file-items-http`、`import-http`、`mcp-stdio` 通过；整体的格式、lint、类型检查通过。
- 复核时发现一条断言依赖认篇的先后顺序而偶发失败，已改为不依赖顺序，连跑 8 次通过。
- **一次可能的真实查询**：新的 CLI 测试第一次运行时把合成配置放错了位置，很可能用默认来源向 Crossref、OpenAlex 查了一个编造的 DOI（`10.5555/offline`），没有凭据，没有使用者的数据。测试已改为先断言来源为空再运行。已告知 Owner。
- 规格里后来补上的三处（标识先在库里对、200 行按整个批次算、标题不超过 500 个码点）已实现。
- 留意：有候选而没有挑的行不进入待决定状态，批次结束后不能再补决定。

## 前端的实现记录（2026-11-26）

## 集成与影响
