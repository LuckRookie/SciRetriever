# 07 Zotero 导入程序与 Skill（Agent 这条路）

类型：计划（结果块）
负责：在装了 Zotero 的电脑上运行的一个固定的导入程序，以及 Agent 怎样代使用者用它把 Zotero 的库导进文献库
状态：In progress（7.1–7.6 完成，只在合成的 Zotero 接口上验证过；7.7 真实试用等 G-zotero）

## Outcome

使用者对 Agent 说“把我的 Zotero 导进来”，Agent 运行一个固定的程序：它读 Zotero 的本地接口，把条目、分组、标签、附件与批注原样交给文献库的入库接口，文件在后台续传；使用者在网页的批次页上预览、确认。没有 Agent 的人可以自己运行同一个程序。

## 进入条件

- Owner 2026-11-25：Zotero 两条路都做，“浏览器扩展可以，Agents 也可以”；Zotero 的端口默认用它自己的默认端口，文献库的端口默认 4174，都可以改。
- [ADR 0063](../../architecture/decisions/0063-unified-intake.md) 第 6 节：接口这一载体接受 Agent 和脚本交来的任何条目；第 5 节：来源只决定怎样读懂数据。本块不改这份决定。
- 当时否决“由 Agent 作为导入方式”的理由要守住：搬运是确定的活，不由模型临场完成；之前的问题多出在“Agent 加上传脚本搬文件”上。所以搬运全部在程序里，Agent 只负责启动、回答程序的提问和处理意外。
- 已有：入库接口与批次、文件上传脚本 `skills/sciretriever/scripts/upload_files.py`、设备连接。
- 读 Owner 的 Zotero 要他明确授权（G-zotero）；程序在哪台电脑上运行、由谁运行，届时由他定。

## 责任边界

程序只读 Zotero，不写 Zotero；不解读书目，原样交给服务端，由 [15](15-zotero-adapter.md) 的适配器转换。批注的落库在 [17](17-zotero-annotations.md)。扩展那条路在 [16](16-extension.md)。

## Tasks

- [x] 7.1 规格（总设计师）：文献与材料 6.4.9 里写明导入程序这一载体：读哪些接口、分段怎样交、文件怎样对应、进度存在哪里；Zotero 地址的默认值与修改办法。与 16.4 用同一套交数据的规定。
- [x] 7.2 探测模式：程序带一个只读的探测模式，只输出字段名、类型与计数，不输出标题、作者、笔记、批注文字、文件名或路径；它的结果就是 [14](14-zotero-probe.md) 的 14.2 与 14.4 要的输入。
- [x] 7.3 读取：列出库与分组供选择；读条目、附件、批注；本地接口没有打开或不可达时，说明怎样在 Zotero 里打开，不猜测、不改 Zotero 的设置。
- [x] 7.4 交数据与续传：按批次分段交清单；文件用现有的上传办法，中断后从没交完的继续，不重复；只上传服务端要的文件，其余只报摘要。
- [x] 7.5 地址：Zotero 默认 `http://localhost:23119`，文献库默认 `http://localhost:4174`，都能用参数改；文献库的令牌经设备连接取得，不写进命令行与输出。
- [x] 7.6 Skill：`skills/sciretriever/source-zotero.md` 写明 Agent 的步骤：确认范围、运行程序、把批次页的地址交给使用者、何时停下来问；CLI 与 MCP 里需要的入口随之补上。
- [ ] 7.7 真实试用（G-zotero）：在 Owner 的 Zotero 上先跑探测模式，再导入一个小分组；记录条目数、文件数、失败原因与耗时，脱敏结论写进本块。

## 结果（2026-11-26）

- 程序：`skills/sciretriever/scripts/zotero_import.py`，四个子命令 `probe`、`libraries`、`import`、`files`；只用 Python 标准库，对 Zotero 只发 GET。用法写在 `skills/sciretriever/source-zotero.md`。
- 服务端：文件引用是来源里的编号时按“编号/文件名”配对（文献与材料 6.4.3），同名的独立 PDF 各自配上。
- 验证：Python 测试 7 条（列库、分段与选分类、接口给文件的两种形态、数据文件夹、200 个合成 PDF 在第 77 个中断后续传、probe 的输出不含标题作者文件名、令牌与本地路径不出现在输出和本地记录里）；服务端最近的三个测试文件通过；实施者另用真实服务端加假的 Zotero 走通过一次。计划写的 2,000 个文件改为 200 个。
- 没有做的与已知的限制：
  - CLI 与 MCP 没有加入口：它们在服务器上运行，读不到使用者电脑上的 Zotero。Agent 不能在使用者电脑上运行程序时，走扩展那条路（[16](16-extension.md)）。
  - 本地接口的路径、`csljson`、`links.attachment`、大小字段与 `/file` 的形态都按 Zotero 公开文档写，等 7.7 的 `probe` 确认。
  - 个人库的来源编号暂用 `users/local`，按设备连接区分（6.4.9）。
  - 批次页没有单独的地址，程序打印“找文献”页的地址和批次编号。
  - 重跑 `import` 时按文件名判断独立 PDF 是否交过；使用者在同一批次里手动拖进同名文件时会少交一个。
  - 选了分类时，条目在没选的分类里的归属现在也会带过来（多出文件夹）；改为略去的规则已写进 6.4.9，待实现。

## 集成与影响

新增一个随 Skill 分发的程序；服务端只用到已有的入库接口与 15 的适配器。不改库结构。

## 验证

- 离线：在假的 Zotero 本地接口（用 14 的合成样本）上走通选库、交清单、上传 2,000 个合成文件并中途打断一次；令牌与文件路径不出现在输出里。
- 真实：7.7。
- 起一个全新的 Agent，只给 Skill，在合成库上完成一次导入（同 23.5 的做法）。

## 退出条件

Agent 能按 Skill 完成一次 Zotero 导入；探测结论交给 14、15；规格、Skill 与[代理接口指南](../../guides/agent-interface.md)同步。

## 恢复与交接

程序中断后重新运行即从断点继续；批次停在预览时不入库。交给 16 的是 7.2 的探测结论与 7.1 定下的交数据规定。
