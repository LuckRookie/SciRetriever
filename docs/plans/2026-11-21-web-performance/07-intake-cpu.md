# 07 · 入库每条的 CPU

类型：计划（结果块）
负责：查清入库每条约 0.4 s CPU 花在哪里，给出是否要改、改哪里的结论
状态：Pending

## 原因（待查）

CLI 引用扩展稳定在每秒 2 到 3 条、CPU 满载，约每条 0.4 s CPU。可能是入库时的身份匹配、合并或每次写入后的状态与索引维护。它不直接让 Web 卡，但写入越慢、越重，03、04 的负担越大，长任务也跑得越久。

## Outcome

- 一份剖析报告：在合成库（二十万篇）上入库一批，CPU 按函数分布；结论是缺陷（直接修，写成本块的任务）还是设计问题（交 Owner）。

## 进入条件

G-dispatch。只读调查，不改代码；可与 02 同时进行。

## 责任边界

- 后端。只在合成数据上剖析，不碰正式库与执行会话的进程。

## Tasks

- [ ] **07.1 剖析**：用 `--cpu-prof` 或等价办法，在二十万篇合成库上入库 1,000 条引用扩展结果，输出火焰图与前十个热点。
- [ ] **07.2 结论**：每个热点写明原因、性质与建议去处。

## 退出条件

07.2 的结论经总设计师审查；缺陷有了修复任务，设计问题交给 Owner。
