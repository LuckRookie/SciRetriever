# 06 · 打开 PDF

类型：计划（结果块）
负责：阅读页打开 PDF 时第一页尽快出来
状态：Pending（等 01.1 与 D4）

## 原因

- 前端先整份下载 PDF，再在浏览器里核对大小与 SHA-256，然后才把完整字节交给 pdf.js（`apps/web/src/reading/transport.ts` 的 `readPdfBytes`；`apps/web/src/reading/pdf.ts` 的 `getDocument`）。没有分段或流式加载。
- 打开前的材料查询和读字节请求，与其他 Web 读请求排在同一个工作线程上（见 05）。
- 时间到底花在哪一段还没测（01.1）。对几 MB 的 PDF，下载与校验本身未必是大头，排队可能更重。

性质：排队部分随 02–05 解决；“先校验完整再显示”还是“边下载边显示”是设计问题（D4）。

## Outcome

- 打开 PDF 到第一页出现的耗时达到 01.3 的目标，大 PDF 与小 PDF 分别给出。
- 显示的文件与记录一致；校验失败时的页面行为按 D4 的决定写进[阅读体验](../../architecture/web/reading-experience.md)。

## 进入条件

01.1 的分段测量；D4 的决定。

## 责任边界

- 前端：阅读页的加载方式。后端：若决定由服务端校验或支持分段请求（HTTP Range），读字节接口的改动。

## Tasks

01.1 与 D4 之后补齐。

## 退出条件

10.1 复测中打开 PDF 达到目标。
