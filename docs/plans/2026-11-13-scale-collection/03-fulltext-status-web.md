# 03 · Web 上的全文取得情况

类型：计划（结果块）
负责：文献库页面显示当前范围的全文取得情况
状态：Pending

## Outcome

- 文献库（含文件夹、入库批次视图与应用了筛选的结果）按 01 的 1.3 显示三个数：已取得全文、还没有、其中已试完。
- 三个数与 CLI、MCP 读到的相同（02）。
- 显示不发起获取；点击的行为按 1.3。

规格：经 01 的 1.3 补齐的[页面规格“文献库”](../../architecture/web/page-specs.md#文献库)；视觉规则见[设计内核](../../architecture/web/design-core.md)。

## 进入条件

02 完成；01 的 1.3 已写进页面规格。3.2 起与计划 21 的 10.6、计划 22 的 04 确认 `Library.tsx` 的先后（它们都改文献库的筛选区域）。

## 责任边界

- 负责：页面规格由总设计师修改（01 的 1.3）；实现由前端实施者完成。
- 触达：`apps/web/src/app/features/library/Library.tsx`（快速筛选与计数一段，`countFor` 与快速筛选列表）；`apps/web/src/app/data/library.ts`。
- 不改：文献库的虚拟列表与行渲染；快速筛选现有项的含义（除非 1.3 明确改动）；服务端。

## Tasks

- [ ] **3.1 数据**：读取 02 的三个数；类型来自 `packages/contracts`。
- [ ] **3.2 显示**：按 1.3 的位置与写法显示；进行中的获取任务结束后，计数随现有刷新更新。
- [ ] **3.3 与快速筛选的关系**：按 1.3 处理“有 PDF”“无法获取”“仅元数据”与三个数之间的关系，不让同一页面出现两个含义不同的“有 PDF”数。
- [ ] **3.4 指南**：同步 [Web 指南](../../guides/web-workbench.md)中文献库的描述（实现合入后写）。

## 集成与影响

用户可见：打开任一范围就能看到全文取得情况，不用逐个点快速筛选相加。

## 验证

- 扩展 `apps/web/test/next-library.test.ts`：三个数与合成数据一致；切换文件夹、入库批次、筛选时随之变化；页面上不出现与之矛盾的“有 PDF”计数；打开与切换范围不发起获取请求。
- `design-rules.test.ts`、`design-consistency.test.ts` 照常通过。
- 截图：全库、一个入库批次、一个文件夹三种范围，放 `sandbox/reports/`。

## 证据

提交号（G-commit 之后）；Web 定向测试结果；截图位置。

## 退出条件

Web 显示与机器入口一致；05 的真实运行结果 Owner 可以在 Web 上看（部署后）。

## 恢复与交接

与计划 21、22 同时改 `Library.tsx` 时停下商定顺序，不覆盖对方的改动。
