# 04 · 万篇机制验收

类型：计划（结果块）
负责：用合成数据与本机假来源，验证至少一万篇文献的收集机制并记录时长、吞吐、内存与磁盘
状态：Pending

## Outcome

- 一个可重复运行的机制检查：至少一万篇合成文献走过入库、重复收敛、按范围获取全文（本机假来源）、中断后继续、局部失败与库内查询。
- 计划 README 的不变量逐条有断言：已接纳的数据不丢失、中断后能继续、查询不触发扩充、临时错误不算试完、范围在提交时固定。
- 一份 JSON 报告记录收4 要求的数字：所用数据、各阶段时长、吞吐、内存、磁盘；外部调用花费为零（全部是假来源），报告写明这一点。
- 不联网，不读正式库，不需要授权；不进入普通的 `pnpm test` 与全量。

规格：经 01 的 1.4 补齐的验收口径；获取流程见[文献与材料第 4 节](../../architecture/technical/03-literature-materials.md#45-获取流程)；批量运行、中断与恢复见[任务协调 5.1、5.2](../../architecture/technical/02-task-coordination.md#52-并发中断与恢复)；测量要求见 [tests/README](../../../tests/README.md)“测试时间限制”。

## 进入条件

01 的 1.4 已写进规格；G1。4.6 中关于三个数的断言需要 02。

## 存放位置

- 测试放在 `apps/server/test/scale-collection.test.ts`，按仓库已有的做法用环境变量开启：`describe.runIf(!!process.env.SCIRETRIEVER_SCALE_RECORDS)`。同样的做法见 `browser-large-production-sample.test.ts` 的 `SCIRETRIEVER_BROWSER_513_MIB` 与各个 `SCIRETRIEVER_CLOAK_BUNDLE` 测试。没有设这个变量时，`pnpm test` 与全量把它报告为跳过，不运行。
- 篇数由环境变量给出（默认用 1.4 规定的数，不少于 10,000）；报告目录由 `SCIRETRIEVER_SCALE_REPORT` 给出，默认在系统临时目录 `sciretriever-scale-*` 下。执行者运行时指到 `sandbox/reports/<日期>-scale-collection/`（Git 忽略）。
- 按 tests/README，这是“完整流程的正确性”加“明确的性能验收”：整体用 `timeout: 0`，只测 1.4 规定的操作，不把生成数据和启动服务计入；操作级的期限与取消照常验证。
- 合成数据在运行时生成，不把一万篇的数据提交进 `tests/fixtures/`；只有生成器（带固定随机种子）进 Git。
- 本机是多人共用的 8 核机器（HARNESS 第 6 节）：运行这一测试时不并行跑别的 Vitest，执行者在报告里写明当时的机器负载。

## 责任边界

- 负责：后端实施者写测试与生成器（4.1–4.7）；执行者运行并记录（4.8）。
- 拥有：`apps/server/test/scale-collection.test.ts`；生成器与假来源（建议 `apps/server/test/scale-fixture.ts`）。
- 复用：`apps/server/src/workbench/synthetic-fixture.ts` 的合成 PDF、`network-egress-fixture.ts` 与现有获取测试的本机假来源写法（`acquisition-public-sources.test.ts`、`acquisition-source-failures.test.ts`）、导入会话（计划 20，`import-http.test.ts` 的用法）、`database-completion-chunks.test.ts` 的批量补全写法。
- 不改：生产代码。测试发现缺陷时记录，交 06 与对应的负责人；若必须为测试增加只在测试构建中可用的计数器，停下交总设计师。

## Tasks

- [ ] **4.1 生成器**：按 1.4 生成合成书目（固定随机种子）：完全重复、同一文献的不同来源、同一 MetaLiterature 的不同版本、有与没有 DOI 的比例；输出导入会话能接受的格式与假元数据来源的响应。
- [ ] **4.2 假 PDF 来源**：一个本机回环服务，按 1.4 的比例返回合格 PDF、正常未命中、临时错误、限流（带 `Retry-After`）与永久错误；PDF 大小按 1.4 的分布；记录每个请求，供“查询不触发扩充”的断言使用。
- [ ] **4.3 运行环境**：系统临时目录里的隔离 home 与 catalog；来源配置只指向假来源；网络政策只允许回环。
- [ ] **4.4 入库与去重**：按 1.4 的途径入库全部合成书目；断言库里的 Literature 与 MetaLiterature 数等于生成器给出的期望值；重复导入一次，不新增文献。
- [ ] **4.5 获取、中断与继续**：
  - 按范围提交获取（单个任务最多 10,000 篇，超过时分批，每批是一个写明范围的任务）；
  - 在 1.4 规定的中断点取消一次、关闭并重新打开应用一次；
  - 再次发起：只处理缺失的部分；已接纳的 PDF 与关系一个不少；
  - 局部失败：一部分篇目的假来源返回永久错误，其余照常完成；
  - 临时错误与限流结束的篇目没有耗尽事实；全部途径正常未命中的有；
  - 第二次全库补全默认跳过已试完的篇目。
- [ ] **4.6 库内查询**：在完成后的库上运行计数（02 的三个数）、筛选、分页与详情读取；断言三个数与生成器的期望一致；断言查询期间假来源没有收到任何请求、没有新任务被创建。
- [ ] **4.7 测量与报告**：按 1.4 记录：数据规模与组成、入库、去重、每批获取、继续、查询各自的时长与吞吐（篇／秒），进程 RSS 的峰值，catalog 文件与资产目录的大小，外部调用花费为零。报告是一份 JSON 加一页摘要。
- [ ] **4.8 运行并记录**（执行者）：在本机运行一次完整规模；把报告放 `sandbox/reports/`，把摘要数字与运行环境（机器、负载、Node 版本、提交号）记入本块“证据”。

## 集成与影响

只增加测试与测试夹具，不改生产行为。普通测试运行时间不变。

## 验证

- 小规模（例如 `SCIRETRIEVER_SCALE_RECORDS=500`）先跑通，确认断言与报告；然后跑完整规模。
- 不设该变量时 `pnpm exec vitest run apps/server/test/scale-collection.test.ts` 报告跳过。
- 断言覆盖计划 README 的每一条不变量；报告字段覆盖收4 验收行要求记录的每一项。
- `pnpm quick`（测试的类型检查与格式）。

## 证据

提交号（G-commit 之后）；小规模与完整规模各一次的命令、环境与摘要数字；报告位置（`sandbox/reports/`，不随仓库分发）；发现的缺陷清单（交 06）。

## 退出条件

完整规模运行一次，全部不变量的断言通过，数字已记录。05 可以开始。若有不变量失败，本块停在 Blocked，缺陷交对应负责人修复后重跑；05 不开始。

## 恢复与交接

- 运行中断时，隔离 home 在系统临时目录里，可以删除后重跑；报告未写完的轮次记为未完成，不计通过。
- 先跑小规模；完整规模运行中途发现问题就停下诊断、修复后重跑，不等它跑完。
