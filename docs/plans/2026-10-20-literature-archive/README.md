## 目标

完成后，每篇文献在进入算子之前，必须先完成**建档**，达到**就绪**状态。建档按以下顺序产出：

1. **校订稿**：用部署 profile 的 MinerU 解析作初稿；程序在有文字层的页上用 PDF 文字层找出疑点，DSH 看原图矫正，扫描页由 DSH 逐页对照原图检查；不能确定的内容标为存疑，不阻断就绪；
2. **结构**：章节角色、图表清单；
3. **元数据**：出版形式与文章性质拆成两个字段，每个字段记录来源，人工修改后锁定；
4. **参考文献**；
5. **标签**：领域级，总数有上限，词表自然增长。

算子只从校订稿读取内容：
- **单篇算子**的结果按读取部分的内容版本复用；
- 算子用到的每个值由平台做一次用时核对，标注核对依据；
- **多篇算子**基于冻结的快照，先逐篇读取再汇总，快照变化后结果标记为“已过时”；
- **总结**改为一个普通的单篇算子。

## 范围与非目标

**范围**：
- 原始解析保存与部署 profile；
- 校订：页面分类、文字层疑点、DSH 矫正、存疑；
- 校订稿文档表示与页码区域证据；
- 结构与参考文献；
- 元数据字段拆分、来源与锁定；
- 标签词表与打标；
- 建档编排与就绪状态；
- 算子接入档案（含快照、多篇算子、总结算子）；
- Web 与 CLI/MCP 接入；
- 旧路径退役与现有库重建。

**非目标**：
- 判断科学结论是否正确；
- 提升 MinerU 自身的识别能力；
- Agent 直接从 PDF 从零生成全文（ADR 0037 未采用；如 02 的文字层指标显示明显更好，再修订 ADR）；
- 为扫描页另接 OCR 引擎；
- 单篇算子之间的串联依赖；
- 向量数据库；
- 旧总结与旧算子结果的兼容（Owner，2026-10-20：当前几乎没有，不考虑兼容）。

## 不变量

所有块都必须保持以下约束：

1. PDF 原件与原始解析一经发布即不可变，按内容寻址；重新解析产生新版本，不覆盖旧字节。
2. 算子只能从校订稿读取内容。原件和原始解析只供建档和人工追查使用。
3. 就绪判断只使用“满足或不满足”的条件，不引入经验阈值或比例门槛。
4. 人工确认过的区块、元数据字段和标签会被锁定，任何自动流程都不能覆盖。冲突只能标记出来，交给人处理。
5. 内容版本只由校订稿和结构决定，描述版本只由元数据和标签决定。描述版本变化不能让单篇算子结果失效。
6. 每条结果和标签都能经由片段定位到校订稿，再经页码区域定位到 PDF。
7. 测试只使用合成数据、测试目录中的 fake MinerU 服务和 fake 模型；生产 `loopback.ts` 作为真实协议适配器连接本机 fake。真实服务、真实模型和真实库只在相应 Gate 授权后使用。
8. 不放宽现有安全边界：凭据不进入日志与结果；Web CSP 不变；机器接口不暴露路径、SQL 或凭据。
9. CLI/MCP 覆盖 Web 的全部新增能力（ADR 0033）。
10. 依赖或 `pnpm-lock.yaml` 只在确有必要时变更，并记录理由。
