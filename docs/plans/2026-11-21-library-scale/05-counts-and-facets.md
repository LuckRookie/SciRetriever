# 05 · 计数、分面与列表总数

类型：计划（结果块）
负责：全库计数、快捷筛选的计数、分面与列表总数在千万篇时也能很快出来，且如实
状态：Pending（等 B2；依赖 04）

## 现状

- 全库计数（`libraryCounts`）对筛选结果逐行计算，再分组；不筛选时就是扫全库。外壳一打开就读它。
- 文献库列表每翻一页都重新算一次 `total_count`；分面（筛选面板的前 20 个值）也是对整个筛选结果分组。
- 即使状态有了索引（04），对一千万行分组计数仍要秒级以上。

性质：设计问题（B2）。“任意筛选下的准确总数”本身是 O(结果数) 的，要在口径上做取舍。

## Outcome

- 全库与快捷筛选的计数由写入时维护的计数器给出，耗时与总篇数无关。
- 任意筛选与搜索下的计数、分面与列表总数按 B2 的口径给出（例如超过上限显示“一万以上”，或先显示上限、后台算出准确数再补上）；界面如实说明。
- 列表翻页不再每页重算总数。

## 进入条件

B2 的决定；04（计数器建立在已存储的状态上）。计数器要加表，上线方式同 04。

## 责任边界

- 后端：计数器、截断计数、合同。前端：截断数与“正在计算”的显示。规格：[查询技术篇 2.1.8](../../architecture/technical/06-retrieval-context.md#218-文献库计数与全文取得情况)；页面规格的文献库一节。

## Tasks

B2 决定后补齐。至少包括：计数器与写入的一致性测试（并发写入、撤回、删除）、截断口径的合同与测试、前端显示、千万篇压力检查中的耗时。

## 退出条件

14.2 中计数、分面与列表总数达到 B11 的目标。
