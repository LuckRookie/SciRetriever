# 06 · 打开与加载

类型：计划（结果块）
负责：打开资料时进入实际具备的视图；加载的骨架与步骤进度；切换时不出现空白画面
状态：Completed（2026-11-15）

## Outcome

- 从文献库、命令面板打开一份资料：本机记得它上次的视图就打开那个视图；否则有文本的打开全文，只有 PDF 的打开 PDF，都没有的打开信息栏并说明缺什么。没有 PDF 的文献不再进入 PDF 模式。
- 加载时有骨架与步骤进度（下载 PDF、校验、解析、排版），正文出来时位置不跳动。
- 切换视图、切换资料时，屏幕上始终有原来的画面、新的画面或骨架之一；300 ms 内准备好的不出现骨架。

规格：[6.2 不出现空白画面](../../architecture/web/reading-experience.md#62-不出现空白画面)、[6.3 加载](../../architecture/web/reading-experience.md#63-加载)、[6.4 打开哪个视图](../../architecture/web/reading-experience.md#64-打开哪个视图)（第二条“已经有概览的打开概览”在 14 的 14.7 实现）、[3.9 没有加工或材料不全](../../architecture/web/reading-experience.md#39-没有加工或材料不全)（材料不全的三行）。

## Tasks

- [x] **6.1 打开时选视图**
  - 打开入口不再决定视图，只传文献标识；阅读页按规格第 6.4 节的第一、三条决定。
  - 判断“有文本”“有 PDF”用文献详情里已有的材料状态，不为此发新请求。
- [x] **6.2 材料不全时的页面**
  - 规格第 3.9 节“只有 PDF”“只有书目”两行：在现有版面里显示一句说明与对应按钮；只有书目的打开信息栏。
- [x] **6.3 骨架与步骤进度**
  - 位置按[规格第 10 节](../../architecture/web/reading-experience.md#10-新版面之前的规则)：在内容区里，位置和宽度同正文栏（PDF 视图同页列），取代现在加载时的状态文字，不在内容上方插入任何东西。
  - 步骤与它们的状态来自实际的加载过程：下载 PDF（有字节进度时显示）、校验、解析（页数）、排版。
  - 骨架条的行距与正文相同，段首缩进与段末短条按规格；正文出来时直接替换骨架，位置不跳动（04 的锚点在此生效）。
  - 骨架按设计内核“加载”一行延迟出现：300 ms 内准备好的不出现骨架。
- [x] **6.4 切换时不出现空白画面**
  - 视图切换与资料切换时，新内容准备好之前保留旧画面；超过 300 ms 换成骨架。
  - 用 02 的逐帧采样验证。

## 集成与影响

- 用户可见：没有 PDF 的文献直接看到全文；打开大文献时知道在做什么、做到哪一步。
- 文献库只改打开时传的参数，不改列表本身。

## 验证

- 扩展 `apps/web/test/next-library.test.ts`：没有 PDF 的文献从行打开进入全文；只有书目的打开信息栏；行渲染与虚拟列表的现有断言不变。
- 扩展 `next-reader.test.ts`：记住的视图优先；步骤进度的四个状态依次出现；骨架在 300 ms 内准备好时不出现。
- 测量工具：“不出现空白画面”一行的视图切换与标签页切换部分。
- 截图：加载中、只有 PDF、只有书目三种状态加入样例库（02 的 2.3），与基线对比其余页面不变。
