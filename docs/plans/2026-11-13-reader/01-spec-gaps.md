## Tasks

- [x] **1.1 补规格：第一次交付在现有版面里怎样成立**（规格第 4.1、4.4、6.3 节）
  - 已回答（2026-11-13）：[规格第 10 节“新版面之前的规则”](../../architecture/web/reading-experience.md#10-新版面之前的规则)，第 4.1、6.3 节指向它。
  - 问题：阅读线定义为“页眉细线下方、可见案头高度 28% 处”，跳转后的“↩ 回到”、一行说明和骨架都画在页眉或纸页上；第一次交付时还没有页眉和纸页。
  - 要回答：阅读线以什么为上沿（建议写成“可见阅读区的上沿；有页眉时为页眉细线”）；现有版面里步骤进度、骨架、一行说明、“↩ 回到”各放在哪里；“样子不变”以哪组截图为准（02 的基线截图）。
  - 等待它的 Task：02 的 2.5、2.6；04 的 4.1、4.5；06 的 6.3。
- [x] **1.2 补规格：顶栏在 390 px 宽时**（规格第 1.3 节）
  - 已回答（2026-11-13）：[规格第 1.3 节](../../architecture/web/reading-experience.md#13-顶栏)“收起规则”的 < 640 px 一档；页眉左侧在这时改写题名，见[第 1.2 节](../../architecture/web/reading-experience.md#12-页眉)。
  - 问题：顶栏宽度 < 760 px 时只把查找、排版、侧栏收进“更多”。390 px 宽时，导航按钮、当前标签页、四格分段控件、提问图标与“更多”合计约 440 px，放不下。
  - 要回答：在多宽以下、按什么顺序再收起（例如标签页只留图标，或分段控件改为下拉）。
  - 等待它的 Task：08 的 8.4。
- [x] **1.3 补规格：书脊的“篇幅”与分批载入的正文**（规格第 1.5 节）
  - 已回答（2026-11-13）：[规格第 1.5 节](../../architecture/web/reading-experience.md#15-书脊)的“章节段”与“视窗”：篇幅是所读版本的 UTF-8 字节数，取自大纲；视窗按首末可见块的字节位置换算；PDF 按页数。
  - 问题：“段的长度与该节在原文中的篇幅成正比”，没有说篇幅按 UTF-8 字节数还是按排版后的高度；现有正文分批载入（`reading/state.ts` 的 `loadedEnd`），排版高度要到整篇载入后才知道。视窗在尚未排版的部分怎样换算也没有规定。
  - 要回答：篇幅的计量；视窗在部分载入时的换算；字号改变后章节段是否变化。
  - 等待它的 Task：10 的 10.2、10.3。
- [ ] **1.4 补规格：阅读页读取加工结果的路径**（知识加工 8.12，必要时 8.16）
  - 问题：规格第 7 节列出了阅读页依赖的数据，知识加工 8.12 写了 CLI 与 MCP 的分层读取，但没有写 Web 调用的 HTTP 路径与响应，也没有写“一份资料当前有哪些结果”怎样查到。
  - 要回答，对一份资料：
    - 当前有效的概览与脉络（含过时标记与依据的文本版本），以及由脉络推出的内容（14.8：图表支撑的要点、段落与要点的对应、关键句、出处角标）；
    - 在这份资料上问过的问题与回答，按问题文字查找已有回答，以及回答进行中的进度；
    - 按要点的一致、矛盾、被引用关系（含候选与已确认的区分）；
    - 包含这份资料的主题页；
    - 长资料的章列表与各章的结果；
    - 服务怎样报告阅读层加工与问答加工是否可用（规格第 1.3 节“只显示能用的”要据此决定“概览”“脉络”两格与提问框是否出现）。
  - 写进知识加工规格，不写进阅读体验规格。
  - 等待它的 Task：13 的 13.1、13.3；14 的 14.7 与 15 的 15.1 中“能力可用时才出现”的部分；以及 14–17 接真实结果的 Task。
- [x] **1.5 补规格：第 8.2 节的测量口径**（规格第 8.2 节）
  - 已回答（2026-11-13）：[规格第 8.2 节](../../architecture/web/reading-experience.md#82-浏览器检查)的“测量口径”：静止、锚点移动、有画面、视图切换的耗时；计数读测试构建中的计数器，不用生产构建里的 `performance.mark`。
  - 问题：通过条件写了数字，没有写在什么时刻测、什么算“有画面”。不写清，不同的测量方法会得出相反的结论。
  - 要回答：
    - 锚点移动在变化后的哪一帧测（例如变化后第一帧与静止 500 ms 后各测一次，取较大值）；
    - “有画面”的判据：纸页上有已排版的文字、已绘制的画布（含拉伸的旧画面）或骨架条；
    - “视图切换在 200 ms 内完成”从什么开始、到什么结束；
    - “sha256 只计算一次”“worker 数”用什么观测（建议应用发出固定名称的 `performance.mark`，测量工具读取）。
  - 等待它的 Task：02 的 2.5、2.6。
- [x] **1.6 补规格：加工能力还不存在时的概览、脉络与提问框**（规格第 1.3、3.9 节）
  - 已回答（2026-11-13）：[规格第 1.3 节](../../architecture/web/reading-experience.md#13-顶栏)“只显示能用的”：两格与提问框只在服务报告能力可用时出现，不可用时不出现；关联标签页始终存在（[第 1.4 节](../../architecture/web/reading-experience.md#14-右侧面板)）。
  - 问题：第二次交付先于第三次交付，那时顶栏已有“概览”“脉络”两格和提问框，但产品里还不能读取或发起阅读层与问答（计划 16 未交付）。规格第 3.9 节只写了“未做过加工”的资料，没有写“产品还没有这项能力”的情形。
  - 要回答：这期间两格与提问框是隐藏、停用并说明原因，还是照常显示第 3.9 节的说明；发起加工的按钮是否出现。
  - 等待它的 Task：08 的 8.4。
