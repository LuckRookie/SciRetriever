# 计划 21：初稿成为正式文本

类型：计划
负责：ADR 0060 第 2–5 节在文档与证据模块中的落地
状态：Pending（2026-11-10 计划编写完成，01 规格补齐已完成；02–12 未开工；技术可行性未验证；功能未交付）

## 目标

按 [ADR 0060](../../architecture/decisions/0060-two-level-full-text.md)，一个 PDF 部分解析完成后，程序接着形成**初稿**：

- 不调用模型，不联网，不需要使用者另外发起；
- 初稿可以阅读、查找和加工；
- 初稿带文本等级 `draft`，每个片段带核对依据；
- 校订仍按需进行，由使用者明确发起。

本计划交付初稿的形成、存储、标注、读取，以及选择校订范围用的事实。知识加工怎样使用初稿归[计划 16](../2026-10-24-operator-plugins/README.md)；本计划只交付它要用的读取合同（07 块）。

## 仍需验证的前提

- 规格原有十余处不足以直接写代码，01 块已把它们写进规格（04 第 8 节含 8.10、8.11，06 §2.1.7，07 §2.3.4 与 §4.2）。后端块按规格实现，规则不在本计划重复。
- 现有程序合并断段和标题层级的代码依赖章节角色，初稿没有角色。规格已给出没有角色时的判定（04 §8.2），实现见 02 的 2.3、2.5。
- 现有的文字层对比（`pageReviewPlan`）只在逐页校订请求里运行：
  - 它从原始文字取词，表格的 HTML 标记也算作词；
  - 页面不可信时它丢弃全部差异；
  - 差异不保存。
  - 照原样使用，表格几乎都会被判为“与文字层有差异”，疑点数也无从读取。规格的对比规则 `draft-compare-v1` 已处理这几点（04 §8.3），实现见 02 的 2.4、03 的 3.2。
- 疑点比例与“依据初稿的加工结果和依据校订稿的差多少”没有实测（ADR 0060 后果）。11 块经授权后测量。

## schema 编号

- 当前代码是 schema 16：`SCHEMA_VERSION = 16`，迁移脚本 `scripts/migrate-import-v16.mjs`。它由计划 20 的 02、03 写入，正式库还在 15。
- 计划 20 的 02、03、08 的表都在 schema 16 里，只用一个迁移脚本。08 已合入（`afe75c3`），计划 20 于 2026-11-13 宣布 16 冻结。
- **本计划用 schema 17**，有自己的迁移模块和脚本（03 块）。不并入 16。理由：
  - 16 归计划 20 所有，并入会让两份计划共用一个迁移，任一方返工都要重测另一方；
  - 本计划要重建 `document_versions` 表并替换视图与触发器，风险不同，应当能单独演练与回退。
- 协调（C1）：
  - 03 的 3.1 可以先做（只写合同与测试数据）。3.2 起以 schema 16 的最终指纹为输入，要等计划 20 按 ADR 0063 改表的块全部合入、宣布 16 冻结之后才开始。
  - 03 合入后，任何其他计划再要加表，从 18 开始。
  - 部署时正式库按 15 → 16 → 17 顺序离线迁移，可以在同一次停服中完成，由 Owner 决定（12 块）。

## 范围与非目标

范围：

- 初稿的形成、身份、存储、默认文本、内容版本、过时与引用保护；
- 文本等级与核对依据在 describe、文献库、建档状态、查找命中、证据解析中的机器读取，HTTP、CLI、MCP 一致；
- 长文档未逐页校订页的核对依据；
- 已有原始解析的补形成操作；
- 选择校订范围的四项事实，及其作为文献库筛选与排序；
- Web 的等级标注、说明文字、初稿阅读与批注；
- 一次经授权的真实文献评估；收尾。

非目标：

- 算子的准入、复用键、覆盖说明与“只用校订稿”运行选项的实现，归计划 16（技术文档 05 第 8 节）。本计划只交付读取合同。
- 校订流程本身（整理、逐页校订、防护）不变。
- 只校订疑点页、降低校订花费：ADR 0060 留给以后。
- 初稿的人工改字：规格明确不接受。

## 不变量

所有块都必须保持：

- 形成初稿不调用模型、不联网。测试断言模型适配器与网络都没有被调用。
- 读取已有内容不形成初稿、不解析、不调用模型（04 §8.8）。
- 解析不触发建档；系统不自动校订。
- 原始解析不进入阅读正文，也不进入算子上下文。
- 校订稿的标准、防护、完成条件与 `READY` 的条件不变。
- 现有校订稿的字节、representation hash、内容版本 JSON 都不变；迁移不产生任何内容版本事件。
- 逐页校订请求的方法与 `page_input_sha256` 不变：共用对比代码时，校订一侧的行为逐字节不变。
- 初稿是不可变版本，相同输入和方法得到相同字节；EvidenceRef 不改指另一版本。
- 被有效结果引用的初稿版本及其原始解析不被回收。
- 测试只用合成 PDF、合成原始解析和假的外部服务。

### 为什么这样分

- **01 单独一块**：规格的空白必须先补，否则后端实施者只能自行决定，违反“计划不写规格”和“规格先改”。
- **02 与 03 分开**：构建器是纯程序，只用合成输入就能完整验收；03 要等 schema 编号协调（C1）。分开后 02 不被 C1 卡住。
- **04 与 05 分开**：04 是新解析的路径，05 是对已有数据的批量维护，有范围、预览、批量任务与正式库试跑，风险与授权都不同。
- **06 单独一块**：升级、重新解析、过时与回收保护是跨多个写入方的生命周期，要用合成的加工结果单独证明。
- **07 单独一块**：三端读取合同是计划 16 与 Web 的共同入口，要能单独交给它们。
- **08 单独一块**：它改的是校订稿（长文档）而不是初稿，只依赖对比函数，可以独立上线。
- **09 单独一块**：四项事实里有两项来自加工结果，需要新的投影；筛选与排序是查询合同的变化。
- **10 由总设计师负责**：Web 由总设计师设计并实现，页面规格（`docs/architecture/web/page-specs.md`）是排布的归属文档。
- **11 有独立的授权**：要用真实文献，可能调用模型。
- **12 收尾**：文档、全量与部署。

## 计划级验证与完成标准

- 02–10 的退出条件都满足。开发中只跑定向测试；收尾跑一次全量（HARNESS 5.4、6）。
- 用合成数据证明 04 §8.9 的每一条：
  - 解析后不调用模型、不联网就得到初稿；失败时原始解析与 PDF 不受影响；
  - 三种核对依据各有覆盖：文字一致、故意改错一处、扫描页、图里的文字、放错页；
  - 重复形成得到相同字节和版本；
  - 默认文本：只有初稿时是初稿，校订后是校订稿，重新解析后回到新初稿；
  - 升级后依据初稿的结果过时，证据仍解析到初稿片段；
  - 文本等级在 describe、文献库、查找命中、证据解析中与实际版本一致；
  - 按角色读初稿返回整篇并带覆盖说明，“只用校订稿”时初稿部分记为缺失；
  - 四项事实等于合成数据的已知值。
- 迁移在合成库上通过；在正式库只读副本上演练通过（G2 之后），记录耗时。
- 11 的评估报告交 Owner（G5）。评估不设通过线，不卡交付。
- 规格第 8 节改为现状，指南按实现更新（12 块）。

不能由局部证据推出的结论：

- 合成 PDF 上的核对依据正确，不说明真实文献上疑点信号有用。这要看 11。
- 定向测试通过不等于全量通过；全量只在 12 跑一次。
