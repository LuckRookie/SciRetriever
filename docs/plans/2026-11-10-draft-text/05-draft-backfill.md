# 05 · 为已有原始解析补形成初稿

类型：计划（结果块）
负责：按文献库筛选写明范围、显式发起的初稿补形成维护操作
状态：Pending

## Outcome

- 使用者或 Agent 用一次显式操作，为已经存在、但还没有初稿的原始解析形成初稿。范围用文献库筛选或一组文献写明（ADR 0052）。
- 提交前能看到预览：命中多少篇，要处理多少，已有初稿多少，没有原始解析多少，超出本次上限多少。
- 操作作为持久任务运行，可以取消；结束时给出本次结果：形成、复用、失败（逐篇原因）、未开始。
- 不调用模型，不联网，不解析。
- 正式库现有约 926 篇有全文的文献，可以经这个操作得到初稿（在正式库上运行要 G4 授权）。

规格：[04 §8.2](../../architecture/technical/04-document-evidence.md#82-初稿的形成)“已有的原始解析”；01 的 1.8。

## 进入条件

04 完成；01 的 1.8 已写进规格。5.6 需要 G2。

## 责任边界

- 负责：后端实施者。
- 拥有：维护操作的合同（`packages/contracts`）、应用层操作与持久任务、三端入口。
- 触达：
  - `packages/contracts/src/operations.ts`（任务操作种类）；
  - `apps/server/src/application/jobs/`（执行与进度）；
  - `apps/server/src/cli/main.ts`、`apps/server/src/workbench/http.ts`、`apps/server/src/mcp/tools.ts`；
  - 设备连接的用途表（MCP 工具按用途列出，见计划 20 的 07 块）。
- 复用：获取 PDF 的范围写法 `AcquirePdfSelector`（`packages/contracts/src/intake.ts`）与“按当前筛选整体提交”的服务端解析方式；04 的初稿发布服务。
- 不改：解析服务；建档；全文索引的刷新机制本身。

## Tasks

- [ ] **5.1 合同**：请求（范围、上限）、预览计数、任务回执，按 1.8。范围在提交时固定，任务保存范围说明（ADR 0052 第 3 节）。
- [ ] **5.2 预览**：只读计算预览计数，不写库，不形成初稿。
- [ ] **5.3 执行**：
  - 逐篇调用 04 的初稿发布服务；一篇失败不影响其它篇。
  - 每篇提交后记进度；中断后再次发起时已形成的得到 `reused`。
  - 取消：在途的一篇按 04 的取消语义结束，其余记为未开始。
- [ ] **5.4 全文索引**：多篇默认文本改变时，避免逐篇排起长队。按现有刷新机制在批末请求一次刷新，或按规格允许的方式合并；做法记入回执。
- [ ] **5.5 三端入口**：CLI、HTTP、MCP 共用同一应用边界；MCP 工具归“操作”用途，不在“读取”用途中出现。
- [ ] **5.6 正式库只读副本试跑**（G2）：在副本上对全部有原始解析的文献预览并执行一次，记录篇数、失败原因分布、总耗时、每页耗时、索引刷新耗时。结果交 11 的 E1 复用。

## 集成与影响

- 新增一种显式维护操作和一种持久任务。
- 大批量形成会触发大量内容版本事件（从无到有）。这些部分此前没有可读文档，也就没有依据它们的加工结果，事件不会让已有结果过时。验证中要证明这一点。

## 验证

新增 `apps/server/test/draft-backfill.test.ts`（合成库），证明：

- 预览计数与已知数据相等，预览不写库。
- 范围按筛选提交：只处理命中且有原始解析、没有初稿的文献；超出上限的按排序截断并计数。
- 一篇页面工具失败，其余照常；回执逐篇列出原因。
- 中断后再次发起：已形成的为 `reused`，不重复登记。
- 取消后未处理的记为未开始。
- 已有校订稿的文献：形成初稿，默认文本不变，没有加工结果被标为过时。
- 全程模型适配器、网络与解析器没有被调用。
- 三端回执一致：扩展 `interface-maintenance-parity.test.ts`；MCP 工具的用途：扩展 `mcp-http.test.ts`。

提交号；定向测试结果；5.6 的试跑报告位置与汇总数字（G2 之后）。

## 恢复与交接

任务中断不回滚已形成的初稿；重新发起即可续做。试跑失败时保留副本与报告，记录原因，不在正式库上重试。
