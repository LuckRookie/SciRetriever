类型：计划
负责：按 Owner 2026-11-24 定下的骨架改 Web：顶栏与侧栏、文献库三栏、搜索结果、用词，以及其余页面的对齐
状态：In progress（01 Done，已部署，待 Owner 看；02 未开始）

## 目标

Owner 2026-11-24 看了上线后的首页与阅读页：首页难看；看不出哪些文献算“收进来”；进了阅读页不好回去，“正在读”挂在侧栏不好；整体的行为逻辑、搜索与筛选、空间利用（首页只用了约六成宽度）与信息展示都不满意，有堆砌信息之嫌。经四版样稿讨论后定下骨架，并决定由总设计师亲自设计和修改前端，不再交给子代理。

设计的出发点（Owner）：从使用者最常做的事和本产品自己的机制出发；文件夹是使用者最关心的，是侧栏的主体；参考产品只借原则，不借外观与功能清单；每个常驻的东西都要说得出理由。

## 已定的骨架

规格以 [页面规格](../../architecture/web/page-specs.md) 为准；这里只列决定与出处。样稿与四版说明在 `sandbox/reports/design-samples/2026-11-24-frontend-redesign/`（`PROPOSAL.md`、`*-a6*.html`）。

- 顶栏每一页都有：标志、开合侧栏的按钮、工作区签（名字跟着当前页面变）、文献签；阅读页右端是阅读工具。
- 侧栏上半是文献库、最近读过、文件夹树；底部固定找文献、全文检索、任务、加工、设置。不列入库批次，不列打开着的文献。
- 侧栏全站可开合；阅读页之外默认展开并记住；阅读页默认收起，展开是抽屉，用完自动收起（Owner：“自动收起”）。
- 文献库三栏：侧栏、列表、右栏（当前这一篇，可收起）。标题下一行材料分类；勾选框在行首左侧，选择栏照旧。
- 搜索结果先“文献库里”，再“候选”，各类各算各的数。
- 用词：文献库 / 候选 / 加入文献库；“入库”一页改名“找文献”；“最近阅读”改为“最近读过”。
- 标签是 AI 标注的结果：在“筛选”里是一个条件，在右栏里是一行带依据的结果。
