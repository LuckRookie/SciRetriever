# 03 搜索结果：先文献库里，再候选

状态：Done（已部署，待 Owner 看）

## 输出

- 在整个文献库里搜索时，结果是同一张列表分两段：“文献库里”（按当前排序取前 5 篇，段头写篇数；多于 5 篇时有“只看文献库里的”）与“候选”（段头写篇数和一句说明）。
- 原来的单选“整个文献库 / 只看收进来的 · n”去掉。只看文献库里的时，搜索框下是一个可移除的条件。
- 在文件夹、批次、最近阅读里搜索不变：默认查这个范围，单选“「视图名」里 / 整个文献库”。

## 做法

- 文献库里的命中另查一次（同样的词、条件和排序，范围取文献库，最多 5 篇）；混排的命中里只留候选。两段拼成一张列表交给原来的虚拟列表，段头画在各段第一行的上方，所以勾选、连选、当前行、↑ ↓、右栏、双击打开都不用另写。
- 在这一页上被收进来的候选留在原位（行上写“已收进来”），不因为变成文献库里的而从候选段消失。
- 候选的篇数是“全部命中 − 文献库里的命中”；命中数被截断或只查了一批时，照页头的写法写“1 万篇以上”“至少 n 篇”。

## 留给后端的一项

搜索时材料分类（全部、有全文、有 PDF、只有书目）的数字在命中超过一万时全部写成“1 万+”，而其中某一类可能只有十几篇（上线后搜 `palladium`：“有 PDF”实际 12 篇）。服务端的计数只有一个“被截断”的标记，没有各类各自的准确数或各自的截断标记；要由服务端各类各算各的、各自截断，前端才能照写。交给后端实施者，另立一项。
