# 02 · 人类发起处理并打开结果

状态：Done（G1 已确认，生产表单、直接旅程与当前代码 Full 通过）。Outcome：用户从选中文献进入人类表单，提交标签或记录提取，查看真实任务并打开已发布结果摘要，无需准备底层 ProcessingTaskRequest。

## 进入条件与责任

依赖 1.1 基线及当前 ADR 0034 实现。生产接线涉及 `entry/processor-operations.ts`、`workbench/http.ts`、`bootstrap/workbench.ts`、`workspace/api.ts`、`actions.ts`、`settings.ts`、`tasks.ts` 和 `task-view.ts`。Application 继续冻结输入、选择模型、执行和保存结果；HTTP 与 Web 只做受控适配。原分析、提取交付和机器接口继续有效。

生产表单的范围与字段语义沿用已接受合同，但布局、交互与状态表达须经 2.7/G1 确认。2.1/2.2 的共享接口与测试准备不依赖该确认；正式表单不先实现再补签。

## Tasks

- [x] **2.1 · 明确人类操作与处理器映射。** 核对 registry 的 id/version、输入类型及规范；常见操作显示“概览、详细分析、问题分析、长文分析、标签、提取、综合”。确定现有分析表单的保留/复用关系，不创建第二套执行逻辑。目录与默认值可离线读取，未知处理器和不支持的规范应明确反馈，不降级为假成功或任意内部方法调用。
- [x] **2.2 · 接通正式 HTTP 应用边界。** 依赖 2.1。在既有工作台 adapter 接入 `queryProcessors` 的读取操作及 `submitProcessor`，新增封套/路由按现有风格落在公开边界并记录文档；名称在实施时固定为正式合同。复用 strict parser、认证、同源/CSRF、只读拒写、取消、错误映射与 runtime 对象图。单独核定处理器请求/结果的有界尺寸，不能放开所有 HTTP body；测试正常、过大、未知字段、未授权、旧 catalog 和连接取消。CLI/MCP 保持调用同一边界。
- [x] **2.7 · 表单样稿与 G1 确认。** 依赖 2.1。先提供标签与记录规范的局部可点击样稿或足以表达流程的截图，覆盖单篇/批量范围、字段增删、类型/单位、全文/检索范围、错误与 partial 提示、提交后的去向；用合成数据，不改定稿 HTML。请 Owner 评审具体版本，记录反馈、确认范围和后续修订。未确认时 2.3/2.4 不进入生产实现，可继续 2.2 的共享适配与直接测试。
- [x] **2.3 · 文献范围与标签表单。** 依赖 2.2 及 2.7/G1 的明确确认。从单篇、已选项或明确的当前筛选范围提交；保留现有范围上限并明确当前页/全部结果的区别。标签支持问题、boolean/string/enum 与枚举选项；文献没有文档时显示缺口，用户可另行启动解析，不隐式补齐。表单提交 ProcessorBatchRequest，冻结仍由后端完成。验收选定成员准确、有效输入被固定、同一幂等重试不重复建任务。
- [x] **2.4 · 记录规范表单。** 依赖 2.2 及 2.7/G1 的明确确认。提供记录含义、纳入条件、字段名/描述、string/boolean/number、单位说明，以及全文/检索范围。普通使用不写 JSON；原始规范可作高级查看。保留数字 raw/unit 和空字段原因的合同，不由浏览器推断单位、把缺失值填零或把检索范围视作全文覆盖。规范错误定位到字段，保存失败保留草稿；测试字段增删、非法名、重复名、问题缺失与显式 partial 范围。
- [x] **2.5 · 任务到结果的真实反馈。** 依赖 2.3/2.4。补充 `run-processor` 的名称、输入范围和 `collections` 投影；读取实际结果引用生成结果入口，不把 result_id 当旧 artifact_id。任务完成与集合可读之间允许明确的发布中状态及有界刷新，失败不能无限轮询。至少提供固定结果/集合摘要、内容类型、覆盖和已有正文/记录预览，03 再深化查询。首屏优先显示“新生成 N 项 / 复用 M 项”及 partial/失败，计数来自真实集合，computed 不冒充模型调用次数或所有尝试数。若 provenance 有真实 token/调用信息，放在可选详情并注明是产物生成用量还是本次运行用量；复用历史不累计成本次调用，无法确定的总量不编成零。移除用旧预算 0/1000 解释新任务的展示。
- [x] **2.6 · 失败、取消与恢复。** 依赖 2.5。新任务复用现有暂停/继续/取消/失败重试，保留已发布结果；partial 明确另起处理，完整同身份复用不提供虚假的强制重算。配置不足、旧库版本、输入失效和服务失败分别给出原因与适用入口，重启才能生效的配置保留真实反馈。验证重复点击、保存成功但启动失败、局部失败、取消后迟到结果及重启后固定输入恢复。
