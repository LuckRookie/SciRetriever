# 05 · 完整旅程与交付

状态：Pending。Outcome：日常加工与阅读两条旅程都由正式 Web 完成，CLI/MCP 分别覆盖新增业务，安装后的静态资源及当前使用文档一致，最终 Full 形成交付证据。

## 进入条件与责任

01–04 的退出条件、各自定向证据和 G1/G2/G3 明确确认记录齐备，3.6 共享后端合同完成独立审查。主执行者核对最终整合 diff、调用方、运行对象图与工作树原改动；不将多个局部测试通过简单相加为产品验收。本块负责三端与完整用户流程的汇合，不新增产品范围。

## Tasks

- [ ] **5.1 · 两条正式 Web 旅程。** 加工旅程使用合成已有文献，经真实 UI 配置标签、筛出文献、记录提取、字段查询与证据、选中记录综合、完整结果导出；中途包括缺材料、partial 与失败重试，所有步骤不依赖手写 JSON。阅读旅程在不启动任务的情况下打开 PDF/解析全文，查看已有辅助知识、切换两篇文献保留位置、从结果定位证据并返回。同时回归发现/导入、上传/获取、原分析/综合和主题/保存视图，明确前序材料来源并保留本轮不涉及能力的既有行为。
- [ ] **5.2 · 共享事实和运行边界。** 用实际 CLI 与 MCP 客户端读 Web 创建的任务、结果、字段证据和导出，反向在 Web 读机器入口产生的结果；输入、hash、覆盖和失败一致。验证只读 MCP/Web 不获得写权限，同源/CSRF、取消、幂等、配置冲突及受控字节交付有效。当前进程的 Browser 观看/介入和连接 runtime 行为继续按既有合同，不能从共享库路径推导自动共享活会话。
- [ ] **5.3 · 版本兼容、离线构建与安装。** 用合成旧版库验证旧材料仍可读、新处理器明确报告版本要求而不迁移；读取旧 artifact 与新 result 不互换 ID。正式 `pnpm build` 产物包含新增阅读 worker/字体/样式，安装包不依赖源码目录或 CDN；扩展 installed-public-journey 及静态资产断言。无原型字节变更、用户语料、凭据、构建产物或未说明依赖混入最终 diff。
- [ ] **5.4 · 同步实际行为与操作说明。** 按已验证内容更新 Web 指南、knowledge-processors/Agent 指南、统一产品接口技术文档及必要源码目录 README。解释单完整结果导出、片段证据与 PDF 坐标限制、会话内阅读状态、旧库升级入口和真实服务前提；修正“整个项目没有内置提取”的过期描述。维护能力矩阵，区分旧完成范围和本次新增覆盖；不把后续批注/翻译写成已发布。
- [ ] **5.5 · Full、语义复核与交接。** 在最终整合状态执行 Full，检查未运行/跳过项是否影响本轮关键旅程；关键浏览器路径若未执行，不能标记 Completed。按 ADR 0032/0033/0034 复核业务所有权、只读无副作用、不可变结果和机器能力覆盖。记录实际 revision/patch、测试数量、构建、依赖变化及剩余限制；只在全部退出条件满足后更新五块和总计划状态，Git 提交/发布与用户数据操作依会话授权单独处理。

```bash
pnpm exec vitest run apps/server/test/interface-query-parity.test.ts apps/server/test/interface-maintenance-parity.test.ts apps/server/test/interface-transfer-parity.test.ts apps/server/test/interface-browser-parity.test.ts apps/web/test/workspace-launch.test.ts apps/server/test/installed-public-journey.test.ts
```

必要时用仓库支持的 `VITEST_MAX_FORKS` / `VITEST_MIN_FORKS` 限制并发并记录原因，不减少测试发现范围、不放宽已有断言。真实服务和科学质量测试不属于本轮离线验收；如后续执行，独立记录数据授权、方法与结论。

完成报告应分别说明：日常业务可完成范围、阅读可完成范围、CLI/MCP 一致性、适用数据版本、测试与构建证据、未覆盖的真实环境，以及依赖/合同变化。另附中文检索限制与提示回归、G1/G2/G3 版本、G3 确认的性能目标及实际测量、10 次切换和全部关闭后的资源检查。旧 24 项回归、历史 Full 和原型截图不能替代本轮运行。
