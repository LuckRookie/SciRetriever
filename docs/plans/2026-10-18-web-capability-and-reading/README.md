## 目标与依据

沿用定稿原型，让个人研究者在电脑上仅使用 Web 完成常用文献业务，并获得适合连续阅读和证据核查的阅读空间。CLI/MCP 分别覆盖 Web 的业务操作与可读数据；阅读器等视觉交互由 Web 提供，维护和特殊操作可以留在 CLI。

8. 结果导出先覆盖后端已有的**单份完整结果** JSON/CSV/Markdown，明确不自动应用当前表格筛选。筛选行可作为后续综合输入；筛选行/整集合一键导出不冒充现有合同。

## 风险与验证口径

- **执行完成与结果发布的时间差**由 2.5 处理：等待集合真正可读，不把一次空投影当成永久无结果，也不伪造成功链接。
- **导出和传输上限**由 2.2/3.6 处理：当前普通 HTTP JSON body 为 64 KiB，新结果文件可达 8 MiB，MCP 有 4 MiB 响应预算。3.6 是独立的共享后端合同切片，分别审查读取合同、实现、三端适配和兼容测试；不能按一个 Web 下载按钮估计工作。遵守 ADR 0033 的现有边界，新增接口同步技术文档；只有改变已接受的覆盖、权限或所有权原则才修订 ADR。
- **证据定位和渲染后的文本映射**由 1.3/3.3/4.3–4.5 处理：UTF-8 locator 与 DOM 文本索引不同，渲染不能破坏来源绑定。
- **阅读依赖与打包**由 4.1/5.3 处理：基线没有 PDF/Markdown 渲染依赖，本轮已锁定 PDF.js、Marked 和 KaTeX 用于隔离验证，版本及许可见[依赖说明](../../notes/web-reading-dependencies.md)。生产阅读器、worker 与离线字体/资源已进入正式构建；安装与 Full 结果由 05 汇总，不能以样稿替代。
- **旧页面与新处理器并存**由 2.1/5.1 处理：保留旧产物和受支持入口，统一人类入口不能破坏旧合同。调用方新需求先补共享边界，再接三端。
- **阅读可用性与性能**由 4.1/4.6/4.7 处理：已固定合成 100 页 PDF、运行环境与冷/热加载口径，Owner 已确认限定场景目标；不将这些数字新增为跨机器 CI 门禁。位置恢复、控制不遮挡、10 次切换后的资源数量和全部关闭后的清理分别有可验证断言。

相关 Vitest 是每个切片的直接证据；代码切片执行 Quick，最终 `pnpm full` 包括全部既有回归和构建。测试使用合成临时 home/库、fake Parser/DSH transport、loopback HTTP 和正式入口打包出的 Chromium 页面，不接真实 Provider/MinerU/模型。场景内检查模型调用与写入计数，证明读取无副作用。

普通测试材料进入系统 `sciretriever-*` 临时目录；需要保留的一次性诊断进入 Git 忽略的 sandbox。公开计划不依赖私有报告链接；在对应块记录脱敏结论、运行 revision/patch、实际命令和未覆盖项。历史 Full 不替代本轮验收。
