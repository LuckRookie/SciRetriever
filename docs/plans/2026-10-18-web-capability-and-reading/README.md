# Web 日常能力与阅读体验完善

状态：Ready（可从基线整理和 01 开始；表单、结果表和阅读交互分别经过设计确认点；代码实施未开始）。日期：2026-10-18。

## 目标与依据

沿用定稿原型，让个人研究者在电脑上仅使用 Web 完成常用文献业务，并获得适合连续阅读和证据核查的阅读空间。CLI/MCP 分别覆盖 Web 的业务操作与可读数据；阅读器等视觉交互由 Web 提供，维护和特殊操作可以留在 CLI。

- 前轮评估的 10 文件 / 24 项定向回归及 1 项浏览器探针只作为调查线索；探针包含对已知缺陷的断言，不是修复验收，本计划须新增正向回归。
- [三端能力计划](../2026-10-15-interface-capability-parity/README.md)与[处理器首版](../../archive/2026-10-18-knowledge-processing-platform/README.md)的完成状态均不覆盖本轮新增的 Web 和阅读目标；不改写或归档其历史证据。

## 范围与不变量

本轮交付是计划及导航，不在编写计划时启动代码实施。后续代码工作按下列结果块推进，仍受当前会话授权与 HARNESS 约束；本计划不额外授权真实服务、用户库、凭据、Git 提交或迁移操作。

实施前先完成 1.1 的可恢复基线：区分处理器改动、Web 决策/计划和其它改动，记录已跟踪与未跟踪文件。推荐在得到明确授权后将已验证的处理器切片独立提交，但不能将整个脏工作树归为同一轮、代用户暂存或提交。提交未获授权时，可用限定文件清单、patch、未跟踪源码副本及哈希构成可重建快照；必须证明能恢复到实施前状态，不能只保存 `git diff`。不把“工作树必须全干净”新增为机械门禁。

1. 保留 `docs/architecture/web/prototype.html` 的原始字节、现有导航和已确认字号/主题基准；在生产组件内接功能，不重写一份替代 HTML。
2. 三端共用 Application/Entry、Analysis、Document、Storage、Configuration 等既有 owner。前端不执行模型、不形成第二份业务数据库、不复制输入冻结、复用或科学接纳规则。
3. 查询、阅读、证据和结果展开不隐式获取、解析、调用模型或重建索引；写操作显式发起。既定解析/分析没有总 token 或调用次数业务预算，不把旧任务计数重新作为新处理器限额。
4. `literature_id`、固定文档、旧 `artifact_id`、新 `result_id` 和 `collection_id` 分别处理；输入版本/hash、字段证据、partial/empty/failed 语义、不可变发布与原始资产保护不变。
5. Catalog v10 是新处理器的现有前提。旧库中可用的旧功能继续使用；缺能力时说明如何显式升级，Web 不执行迁移或覆盖用户数据。本计划预期不改 catalog schema。
6. 阅读位置、模式、缩放、布局和返回位置是 UI 状态；先保证同一工作区会话内恢复，并按库身份和固定材料版本隔离。主题等已有偏好保留；跨设备同步和永久阅读历史不在本轮。
7. 基础阅读包含 PDF、解析文档、已有知识/结果和证据往返。当前片段证据优先定位解析全文；没有可靠 PDF 页码/坐标时只打开同一原始资产并说明能力，不能猜测高亮。
8. 结果导出先覆盖后端已有的**单份完整结果** JSON/CSV/Markdown，明确不自动应用当前表格筛选。筛选行可作为后续综合输入；筛选行/整集合一键导出不冒充现有合同。

非目标：批注、笔记、翻译、术语解释、用户标签/课题数据、Zotero 插件、图片/曲线数值提取、PDF 坐标重建、向量检索、通用 DAG，以及数据库修复和迁移 UI。现有外部候选交付继续可用；长期候选托管和新索引重建保留机器入口，本轮只显示已保存结果及明确维护提示。

中文提示属于 01 的默认只读体验；自动查询翻译和模型同义词扩展不并入普通检索。若后续提供，应作为显式的“生成检索词”操作，保留原查询、展示可编辑候选并由用户选择是否使用，同时覆盖 CLI/MCP；不能在搜索按钮背后隐式调用 DSH 或外部翻译服务。

## 风险与验证口径

- **执行完成与结果发布的时间差**由 2.5 处理：等待集合真正可读，不把一次空投影当成永久无结果，也不伪造成功链接。
- **导出和传输上限**由 2.2/3.6 处理：当前普通 HTTP JSON body 为 64 KiB，新结果文件可达 8 MiB，MCP 有 4 MiB 响应预算。3.6 是独立的共享后端合同切片，分别审查读取合同、实现、三端适配和兼容测试；不能按一个 Web 下载按钮估计工作。遵守 ADR 0033 的现有边界，新增接口同步技术文档；只有改变已接受的覆盖、权限或所有权原则才修订 ADR。
- **证据定位和渲染后的文本映射**由 1.3/3.3/4.3–4.5 处理：UTF-8 locator 与 DOM 文本索引不同，渲染不能破坏来源绑定。
- **阅读依赖与打包**由 4.1/5.3 处理：目前 Web 无 PDF/Markdown 渲染依赖。PDF.js 是计划中的实现候选，须先完成受控技术验证；版本、worker、离线字体/资源、许可和构建影响落到实际依赖说明。验证未过时保留该任务未完成，不能把原生 iframe 回退当作全部阅读目标已达标。
- **旧页面与新处理器并存**由 2.1/5.1 处理：保留旧产物和受支持入口，统一人类入口不能破坏旧合同。调用方新需求先补共享边界，再接三端。
- **阅读可用性与性能**由 4.1/4.6/4.7 处理：先固定合成 100 页 PDF、运行环境与冷/热加载口径，测量首屏及交互时间，再在 G3 确认具体性能目标；本次不凭空指定跨机器的秒数门禁。位置恢复、控制不遮挡、10 次切换后的资源数量和全部关闭后的清理分别有可验证断言。

相关 Vitest 是每个切片的直接证据；代码切片执行 Quick，最终 `pnpm full` 包括全部既有回归和构建。测试使用合成临时 home/库、fake Parser/DSH transport、loopback HTTP 和正式入口打包出的 Chromium 页面，不接真实 Provider/MinerU/模型。场景内检查模型调用与写入计数，证明读取无副作用。

普通测试材料进入系统 `sciretriever-*` 临时目录；需要保留的一次性诊断进入 Git 忽略的 sandbox。公开计划不依赖私有报告链接；在对应块记录脱敏结论、运行 revision/patch、实际命令和未覆盖项。历史 Full 不替代本轮验收。
