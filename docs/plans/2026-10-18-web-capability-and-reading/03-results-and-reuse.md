# 03 · 结果查询、核对与再使用

状态：Done（G2 生产接入及直接验收完成，最终集成记录见 05）。Outcome：用户能发现结果集合、筛选记录和标签、逐层核查证据，将选定结果用于综合，并导出指定的完整结果。

## 进入条件与责任

依赖 2.2 的正式查询适配、2.5 的任务/结果引用及 1.3 的固定来源导航约定。主要触达 `workspace/settings.ts` 的现有提取入口、`workspace/retrieval.ts`、`workspace/synthesis.ts`、任务页和必要的新结果视图组件；后端复用 `queryProcessors`、processorRead、ProcessorCitation 与 ProcessorSelection。存储及科学接纳规则不迁到前端。

## Tasks

- [x] **3.0 · 结果交互样稿与 G2 确认。** 根据现有 schema 和 2.5 的结果引用准备局部样稿，覆盖结果集合、宽表/嵌套字段、空值、partial、筛选/跨页选择、证据侧栏及综合/导出范围。可比较标签作为库中可选列与在结果页筛选的体验，但不默认新增列或持久用户标签。先让 Owner 看具体样稿并记录确认版本，再实施 3.1–3.5 的 UI；共享查询/导出合同与 3.6 的准备可以独立继续。
- [x] **3.1 · 集合发现与结果表。** 依赖 3.0/G2。在现有“提取”等使用入口内提供运行/结果集合列表和稳定定位，不另造业务导航骨架。集合展示实际输入、成员、规范、缺口、复用和覆盖；按 content.kind 渲染记录、文本或旧知识引用。记录列由结果 schema 推导，数量/排序/分页交给服务端 query，清楚区分总量、当前页和选中项。验证重叠运行不夹带旧成员、跨页无重复、未知字段被拒绝、旧集合内容不随新运行改写。
- [x] **3.2 · 字段筛选、标签选择与检索。** 本任务分为下列三个独立子任务，全部完成才关闭 3.2。
  - [x] **3.2.1 · 字段筛选与排序。** 依赖 3.1。按 schema 映射可查询字段、类型及操作符，保留原数值/单位、null 和 missing。验证服务端筛选/排序、分页、非法字段反馈以及更换集合时不沿用无效筛选。
  - [x] **3.2.2 · 标签选择回到文献。** 依赖 3.2.1。区分 false、证据不足与 partial；筛选后展示真实关联文献并形成显式选择。验证同一文献多份结果去重、跨页选择范围及回到文献后的操作输入；不写 Literature 固定字段或伪造 LibraryQuery 的标签字段。
  - [x] **3.2.3 · 结果内容与集合检索。** 依赖 3.1 和 1.5。接入两种 FTS 并区分检索范围、空结果和陈旧索引，复用不阻断的中文/跨语言提示；验证分页、取消与晚到响应。提示显式维护，不自动重建、不调用模型，不将词法命中描述为语义召回。
- [x] **3.3 · 字段证据与来源展开。** 依赖 3.1 和 1.3。通过 `evidence` 校验完整 ProcessorCitation，展示结果字段→上游结果/旧知识→固定文档的来源链；每一步保留 ID/hash、字段 pointer 和覆盖。使用现有有界文档读取显示可核对的文本，不以文件链接替代字段依据。提供固定来源导航，04 接入精确阅读位置；遇到失效、缺失、hash 不符或仅文件级证据时如实反馈，不跳到后来默认文档冒充命中。
- [x] **3.4 · 选取结果继续综合。** 依赖 3.1–3.3、2.2。选择整份结果或明确记录 ID 子集，构造受支持的 ProcessorSelection 并经后端冻结；从集合发起时固定实际成员，不能把集合名称当作输入。提供研究问题和 require-all/allow-partial，展示实际来源数与部分输入；复用原 `knowledge-synthesis`，保留旧文献综合入口。验证只使用所选记录、多条同文献记录不增加独立来源数、原结果不变、新结果引用链可读。
- [x] **3.5 · 导出指定完整结果。** 依赖 3.1/3.3。以现有 `export {result_id,format}` 提供 JSON、CSV、Markdown 下载，按钮明确“导出这份完整结果”，展示范围，不让当前筛选/页码悄悄改变或冒充导出范围。JSON 保留不可变结果；CSV/Markdown 同时交付后端返回的 provenance/coverage metadata，不能下载正文后丢弃追溯信息。验证 UTF-8、引号/换行、嵌套 payload/evidence_json、原文与结果引用，以及下载不改变 catalog。整集合/筛选行一键导出留作独立扩展，不提供失真的按钮。
- [x] **3.6 · 大结果共享后端合同切片。** 包括以下独立子任务，不按一个 Web 按钮估计或验收；最终与 3.5 导出汇合。
  - [x] **3.6.1 · 合同和兼容评审。** 依赖 2.2 及现有 processorRead/export，不依赖 G2 的 UI。列明生产者、CLI/MCP/HTTP 消费者、稳定 ID/hash、字节范围/上限、continuation、取消和错误；用超过 4 MiB、仍在 8 MiB 结果上限内的合成内容确定需要新增的有界读取操作。优先复用记录分页，保留小结果合同，先写入产品接口技术说明。核对 ADR 0033 已有的受控资源边界；只有变更权限、所有权或覆盖原则时才修订 ADR，不因添加分页参数机械新增决策。
  - [x] **3.6.2 · 共享读取实现。** 依赖 3.6.1。在所属结果读取 owner 实现明确的内容/导出分块，绑定固定引用和有效范围；不公开任意文件路径或 SQL，不扩大所有响应限制。直接验证正确重组、UTF-8 边界、错误游标、版本/hash 不符、取消与资源清理。
  - [x] **3.6.3 · 三端适配及汇合。** 依赖 3.6.2，Web 下载汇合另需 3.5。CLI、MCP、HTTP 分别消费同一合同，MCP 不将大内容硬塞进一条模型消息；验证每端完整内容和错误一致，不把截断当完成，并同步当前接口指南。
