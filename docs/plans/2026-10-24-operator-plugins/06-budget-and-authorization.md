# 06 · 预算、授权与万篇规模

类型：计划（结果块）
负责：预算账本、软上限准入、Agent 任务授权、大批量运行的开放、快照拆分与跨快照的覆盖合计
状态：Pending

## Outcome

1. 所有调用模型的知识加工操作（运行、试运行、复核、规范起草、分组与合并提议）共用一本持久账本，按规格 8.6 的单元准入与透支规则记账；
2. 预算停止时不截断正在阅读的单篇，结果如实报告完成与未处理的单元；
3. 所有者可以为 Agent 授予任务范围、有效期与累计额度；持有授权的 Agent 经 CLI、MCP 发起付费步骤，在规格 8.6“发起与确认”的三项条件同时满足时自行确认，否则转为待所有者确认；
4. 人在 Web 上发起运行时设定本次预算；Web 与机器接口按同一账本与同一并发准入开放大批量运行；
5. 超过 10000 篇的选取可以拆成多个快照分别运行；各次运行的结果可以合起来报告总覆盖：每份快照一行，再加合计（规格 8.6“规模”）。

本块不新增产出类型；覆盖合计产出 `statistics`，用 07 的视图、分层读取与导出。

规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.6、8.13。

## 进入条件

- 6.7 另需 04 的 4.4、07 的 7.2 与 02 的 2.2。
- 6.4 中机器入口上的所有者操作（授予与撤销授权、确认待确认的请求）须先补根 README“规格待补”第 3 项；补齐前这些操作只在 Web 上进行。

## 责任边界

worker：账本存储、模型调用前的准入与调用后的结算（覆盖会话续轮、压缩与重试）、对账、授权合同与校验、快照拆分与覆盖合计、机器接口。总设计师：预算设定、账本与授权管理的 Web 页面，拆分与合计的页面。

## Tasks

- [ ] **6.1 账本与单元准入**〔worker〕
  - 落实规格 8.6 的单元准入：派发前预留准入额，余额不足不再准入；已准入单元的后续调用逐次结算。
  - 输出：账本记录（运行、授权、单元、调用、预留、结算）；运行结束状态增加“预算停止”。
  - 需要新表时停下交 Owner（G-schema）。
- [ ] **6.2 透支与对账**〔worker〕
  - 已准入单元透支的记账；崩溃与回执丢失时预留保持占用，恢复后按实际用量对账；单元费用上界未被证明时，界面与机器接口显示“未知”。
- [ ] **6.3 辅助调用纳入**〔worker〕
  - 03 的规范起草、12 与 08 的分组提议、09 的合并提议等辅助调用经同一准入与账本。在本块之前已交付的块，这些调用从“所有者逐次确认”改为“确认并计入账本”，行为测试随之补上账本断言。
- [ ] **6.4 Agent 任务授权**〔worker〕
  - 落实规格 8.6 的授权：创建、查询用量、撤销；授予是所有者操作。付费调用须附有效授权；越界、过期、撤销、额度不足时拒绝准入新单元并返回待所有者确认的请求，已准入单元的后续调用照常完成；扣减跨并发运行共享且幂等。
  - Agent 自行确认的三项条件按规格 8.6：步骤在授权范围内；授权未过期、未撤销；估算花费的区间上端已知且不超过剩余额度。
- [ ] **6.5 Web**〔前端〕
  - 页面规格草案后实现：运行确认时设定预算；运行详情的账本、“预算停止”与超出上限（数值或“未知”）说明；授权管理；待确认请求列表（02 的 2.12）增加确认时设定预算。
- [ ] **6.6 开放大批量**〔worker〕
  - 6.1–6.4 验收后，解除 02 的 2.0 对大批量运行的限制，Web 与机器接口一致。
- [ ] **6.7 快照拆分与覆盖合计**〔worker 后端，前端界面〕
  - 拆分：创建快照时可以显式请求拆分，按规格 8.6 以文献 ID 的稳定顺序切成每份不超过 10000 个成员，每份记下拆分来源（选取来源与 hash、总成员数、拆分规则、总份数、序号）；只建快照，不启动运行。三端可用。
  - 估算：同一次拆分的各份可一并估算，每份一行加合计；确认仍逐次运行。
  - 覆盖合计：在 07 的派生执行中增加内置函数“覆盖合计”，输入一组集合清单，产出 `statistics`，无模型费用；规则按规格 8.6：逐份列出、合计按文献去重、“版本不一”、拆分中未输入的份列为未覆盖。02 的 2.2 的多清单汇总使用同一合计规则。
  - Web：建快照时的拆分选项与各份列表；覆盖合计的结果用 07 的统计视图。
- [ ] **6.8 验证与审阅点 C 审阅包**
  - 运行下节测试；审阅包含预算设定、预算停止的运行详情、授权管理、拆分与覆盖合计的截图及行为说明。

## 集成与影响

- 调用方：02–05、07–10、12、13 的全部付费入口（运行、试运行、复核、起草、提议），Web 运行确认页，MCP 与 CLI 的 `estimate`、`run` 与授权操作。
- 存储：新增账本与授权记录、快照的拆分来源；不改写历史结果。
- 用户可见变化：付费运行可设预算；Agent 可凭授权自行运行；大批量运行开放；超过 10000 篇的选取可以拆分运行并看到总覆盖。

## 验证

命令按根 README 的验证路线；新增 `processor-ledger.test.ts`、`processor-authorization.test.ts`、`snapshot-split-coverage.test.ts`。

- 多轮会话跨越余额：已准入单元的下一轮调用不被拒绝，单元完成后不再准入新单元；
- 并发：多个运行共享同一授权时扣减不重复、不错误计费，准入不超出余额；
- 崩溃与回执丢失：预留保持占用，恢复后对账，结果与实际用量一致；
- 授权越界、过期、撤销、额度不足均被拒且不产生调用；撤销后在途单元完成；同一扣减重放幂等；估算上端未知时 Agent 不能自行确认；
- 辅助调用未经确认或授权不产生调用；
- 单元费用上界未知时显示“未知”，不显示数值；
- 拆分：25,000 个只有书目的合成成员切成 10000、10000、5000 三份，重复拆分得到相同的成员划分；拆分不产生运行；
- 覆盖合计：三份清单逐份列出并合计为 25,000；只输入其中两份时，第三份整份列为未覆盖；两个人工建的快照有重叠成员时按文献计一次，版本不同的列为“版本不一”；覆盖合计不产生模型调用。

未覆盖：真实 Provider 的价格与用量回执（G-real）；万篇规模的端到端运行（11 的 11.4）。

## 退出条件

账本、单元准入、对账与 Agent 授权在三端可用；越权负例全部被拒；大批量运行按授权开放；快照拆分与覆盖合计可用；审阅点 C（本块部分）获确认。
