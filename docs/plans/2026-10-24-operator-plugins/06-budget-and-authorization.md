# 06 · 预算与授权

类型：计划（结果块）
负责：预算账本、软上限准入、Agent 任务授权与大批量运行的开放
状态：Pending（须 G-adr）

## Outcome

1. 所有调用模型的操作（运行、试运行、复核、规范起草、分组与合并提议）共用一本持久账本，按草案 8.6 的单元准入与透支规则记账；
2. 预算停止时不截断正在阅读的单篇，结果如实报告完成与未处理的单元；
3. Owner 可以为 Agent 授予任务范围、有效期与累计额度，Agent 在额度内自行发起付费步骤；
4. 大批量运行在 Web 与机器接口同时按本块的账本与授权开放。

规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.6、8.13。本块对应草案冲突表中“预算账本、软上限与授权额度”一项，G-adr 通过前不开工。

## 进入条件

02 退出（运行流程与并发已就绪）；G-adr 通过。

## 责任边界

worker：账本存储、模型调用前的准入与调用后的结算（覆盖会话续轮、压缩与重试）、对账、授权合同与校验、机器接口。Claude：预算设定、账本与授权管理的 Web 页面。

## Tasks

- [ ] **6.1 账本与单元准入**〔worker〕
  - 落实草案 8.6 的单元准入：派发前预留准入额，余额不足不再准入；已准入单元的后续调用逐次结算。
  - 输出：账本记录（运行、授权、单元、调用、预留、结算）；运行结束状态增加“预算停止”。
  - 需要新表时停下交 Owner（G-schema）。
- [ ] **6.2 透支与对账**〔worker〕
  - 已准入单元透支的记账；崩溃与回执丢失时预留保持占用，恢复后按实际用量对账；单元费用上界未被证明时，界面与机器接口显示“未知”。
- [ ] **6.3 辅助调用纳入**〔worker〕
  - 03 的规范起草、08 的分组提议、09 的合并提议等辅助调用经同一准入与账本。
- [ ] **6.4 Agent 任务授权**〔worker〕
  - 落实草案 8.6 的授权：创建、查询用量、撤销；授予是 Owner 操作，三端在 Owner 授权下都可执行。付费调用须附有效授权；越界、过期、撤销、额度不足时拒绝准入新单元并返回待人确认的请求，已准入单元的后续调用照常完成（草案 8.6）；扣减跨并发运行共享且幂等。
- [ ] **6.5 Web**〔Claude〕
  - 页面规格草案后实现：运行确认时设定预算；运行详情的账本、“预算停止”与超出上限（数值或“未知”）说明；授权管理；待人确认请求列表。
- [ ] **6.6 开放大批量**〔worker〕
  - 6.1–6.4 验收后，解除 02 的 2.0 对大批量运行的限制，Web 与机器接口一致。
- [ ] **6.7 验证与 R3 审阅包**
  - 运行下节测试；R3 审阅包含预算设定、预算停止的运行详情与授权管理的截图及行为说明。

## 集成与影响

- 调用方：02–05、07–10 的全部付费入口（运行、试运行、复核、起草、提议），Web 运行确认页，MCP 与 CLI 的 `estimate`、`run` 与授权操作。
- 存储：新增账本与授权记录；不改写历史结果。
- 用户可见变化：付费运行可设预算；Agent 可凭授权自行运行；大批量运行开放。

## 验证

命令按根 README 的验证路线；新增 `processor-ledger.test.ts`、`processor-authorization.test.ts`。

- 多轮会话跨越余额：已准入单元的下一轮调用不被拒绝，单元完成后不再准入新单元；
- 并发：多个运行共享同一授权时扣减不重复、不错误计费，准入不超出余额；
- 崩溃与回执丢失：预留保持占用，恢复后对账，结果与实际用量一致；
- 授权越界、过期、撤销、额度不足均被拒且不产生调用；撤销后在途单元完成；同一扣减重放幂等；
- 辅助调用未经确认或授权不产生调用；
- 单元费用上界未知时显示“未知”，不显示数值。

未覆盖：真实 Provider 的价格与用量回执（G-real）。

## 退出条件

账本、单元准入、对账与 Agent 授权在三端可用；越权负例全部被拒；大批量运行按授权开放；R3（本块部分）获确认。

## 恢复与交接

6.1、6.2 可先交付（人确认的运行使用账本）；6.4 未完成前，Agent 只能生成待人确认的请求；6.6 不先于 6.1–6.4。
