# 09 · 实体归一

类型：计划（结果块）
负责：实体提及采集、`groups`（`entity` 变体）、归一提议、决定（确认、撤销、拆分）与版本解析
状态：Pending（须 G-adr）

## Outcome

1. 逐篇提取的实体提及可以在一个知识集内归一为实体；
2. 合并由模型带证据提议，平台去重并按影响排序；人或经授权的 Agent 确认，可以批量确认、撤销与拆分；
3. 每批决定产生新版本的归一结果，下游按所引用的版本解析；未确认的提及保持独立并在下游标为歧义；
4. 归一只作用于该知识集，不改变文献身份。

规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.1、8.2、8.8、8.11。属草案冲突表条目，须 G-adr；决定的存储若需新表，走 G-schema。

## 进入条件

03、06 退出；G-adr 通过。

## 责任边界

worker：实体提及规范、`entity` 变体合同、归一提议、决定合同（使用 01 定义的人工决定证据根）、版本解析、机器接口。Claude：归一工作台页面。

## Tasks

- [ ] **9.1 实体提及**〔worker〕
  - 内置 `records` 规范采集实体提及：名称原文、实体类型、上下文与证据。
- [ ] **9.2 `entity` 变体**〔worker〕
  - 落实草案 8.2 的 `groups` `entity` 变体：组即实体（类型、作用域），成员是提及，单归属；在类型注册表登记。
- [ ] **9.3 归一提议**〔worker〕
  - 模型基于冻结的提及集合提出合并提议，每条带证据与理由；不按规范化名称自动合并；提议去重，按影响（涉及提及数、下游引用数）排序。提议是辅助调用，经 06 的准入与账本。
- [ ] **9.4 决定与版本**〔worker〕
  - 落实草案 8.8 的决定：确认、撤销、拆分记为决定（操作者、依据、时间），每批决定产生新版本的归一结果，旧版本保留；支持批量确认；经授权的 Agent 可在任务范围内确认。
- [ ] **9.5 下游解析**〔worker〕
  - 下游引用实体时绑定归一结果的版本，解析时按引用版本；未确认的提及作为独立节点并标为歧义；新版本发布后，引用旧版本的下游结果标记过时，不自动重算。
- [ ] **9.6 Web**〔Claude〕
  - 页面规格草案后实现：归一工作台（按影响排序的提议队列、证据对照、批量确认、撤销与拆分、版本历史、已确认实体浏览）。
- [ ] **9.7 验证与 R3 审阅包**
  - 运行下节测试；R3 审阅包含提议队列、批量确认与拆分的截图及行为说明。

## 集成与影响

- 调用方：Web 归一工作台；10 的候选生成与关系图；08 的维基页面实体链接；MCP 与 CLI 的提议、决定与查询。
- 存储：决定与归一结果版本；需要新表时走 G-schema。
- 用户可见变化：可以在知识集内整理实体。

## 验证

命令按根 README 的验证路线；新增 `entity-normalization.test.ts`。

- 合成样例中同名不同实体不被自动合并；无确认的提议不进入已确认实体（证明协议，不证明真实消歧质量）；
- 撤销与拆分产生新版本，旧决定与旧版本不变；引用旧版本的下游结果仍按旧版本解析，并被标记过时；
- 批量确认幂等；越权确认被拒；
- 决定不改变文献身份与其它知识集。

未覆盖：真实语料上的消歧质量（11 的成套效果评估）。

## 退出条件

实体归一在三端可用，负例全部被拒；R3（本块部分）获确认。

## 恢复与交接

9.1–9.3 可先交付提及与提议（只读浏览）；决定流程未完成前，下游一律按未确认处理。
