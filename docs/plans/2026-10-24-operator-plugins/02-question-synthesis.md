# 02 · 问答、运行流程与问题综合

类型：计划（结果块）
负责：`qa@1`、运行流程与发起确认、摘要筛查、估算与单元用时、并发与分批、问题综合、覆盖修正、机器接口与分层读取、带出处的导出、结果页外框
状态：Pending

## Outcome

人在 Web 上，或 Agent 经 CLI、MCP，对一组文献提出一个问题，系统：

1. 用同一个问题逐篇完整阅读并回答，每个非空答案都有原文引用，空答案写明原因；
2. 汇总成带引用的报告，引用能回到原文片段；
3. 如实报告完成度：哪些篇读完了、哪些失败、哪些缺材料，以及依据初稿与依据校订稿的文献数；
4. 每次运行经过规格 8.6 的同一组检查点：定义 → 选取 → 冻结 → 授权 → 试运行（可选）→ 估算确认 → 执行 → 取用；同一问题、同一输入复用已有结果；
5. 可以只读题名与摘要做筛查（`qa` 的读取范围）：题名和摘要先取冻结的元数据，所以只有书目、还没有全文的文献也能筛查；排除只凭明确证据，其余进未定项；
6. 估算给出花费（模型调用次数、输入 token、输出 token）和用时的区间及依据；没有同口径历史时显示“未知”；
7. 快照内逐篇并发执行、分页分批，不再串行循环。

发起与取用：

- 人在 Web 上发起运行，在确认页看估算并确认，读回答页与报告页，从证据跳回原文，导出结果。
- Agent 经 CLI、MCP 发起同一运行。06 之前没有任务授权，Agent 的付费请求按规格 8.6“发起与确认”中“没有授权的 Agent”一行，生成待所有者确认的请求，不发生模型调用；所有者在 Web 的待确认列表里查看并确认。06 之后，持有任务授权的 Agent 可以按规格自行确认。
- 两种发起经过同一组检查点，得到同一份结果；任一方发起的结果另一方都能取用。

`answer` 与 `report` 两种类型的三样交付（规格 8.12）：

| 交付           | 内容                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| 人读的页面     | 回答页与报告页，共用结果页外框、证据抽屉与未定项面板；证据抽屉跳到原文所在位置                           |
| Agent 按层读取 | 外框 → 条目分页 → 证据 → 原文的有界读取；每层只读已有内容                                                |
| 带出处的导出   | Markdown（报告的引用写成脚注），引用带文献、版本、文本等级与定位，同时导出被引文献的书目；完整 JSON 封套 |

本块交付里程碑 M1 的问答闭环，是审阅点 A。规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.2、8.3、8.6、8.7、8.11–8.13。

## Tasks

- [ ] **2.0 并发与分批**〔worker〕（本块第一个 Task：试运行与基准运行都依赖它）
  - 现状：算子任务的目标并发写死为 1（`application/jobs/processing.ts`），`knowledge-synthesis@2` 的逐篇步骤在一个目标内串行循环（`analysis/processor.ts`）。逐篇运行的各目标改为经现有 Jobs 的共享有界准入并发执行，不另建调度平台；串行循环随 2.14 删除旧集合路径一并消失，不单独改。
  - 成员与结果按页与批次处理，满足内存约束。快照创建的成员上限保持不变（规格 8.6“规模”）。
  - 验收：并发下复用、取消、失败、恢复与串行时语义一致；接近上限的快照分批执行后结果集合与覆盖一致、无重复无遗漏；超上限的快照在创建时被拒；大批量运行在 06 验收前在 Web 与机器接口都不开放。
- [ ] **2.1 `qa@1`**〔worker〕
  - 在公共会话上实现问答，`answer_type` 覆盖 `labels@2` 现有的 `boolean | string | enum`，并增加 `text`（带引用的自由回答）。`text` 答案按句给出 `sentences[]`，每句至少一个引用，`answer` 是各句按序连接的全文（规格 8.2）；阅读页的“按问题阅读”按句显示（规格 8.16）。读取的文本等级按 04 的 4.3。
  - 完整读取声明范围，不因找到答案提前结束；`null` 附原因，含义是“声明范围内未得出答案”。
  - 验收：`labels@2` 现有测试（`next-processor-labels.test.ts` 对应的服务端用例）改用 `qa@1` 后断言目的不变。
- [ ] **2.2 汇总执行**〔worker〕
  - 落实规格 8.7 的显式汇总请求：输入是一份或多份冻结的集合清单，可以来自任何已冻结的运行；多份清单时成员按文献去重，外框逐份列出覆盖并给出合计（规格 8.6“规模”）。执行器检查 `mode` 与上游产出类型兼容，不从插件 spec 推断问题。本块实现 `question-report` 与 `compilation` 两种模式；模式按注册加入，03、12、14 分别加入 `comparison-table`、`per-group`、`overview` 与 `overview-by-chapter`，执行器不按模式名分支。产出的 `report` 按规格 8.2 使用 `refs[]`、`not_given[]` 与陈述的 `origin`，这些结构由 01 的 1.1a 定义。
  - 汇总前容量预检；超限时两级汇总，仍超限报缺口。各级保留原始证据链、同源去重、反证与少数意见。
  - 复用键：输入集合清单的 ID 与 hash、完整性策略、汇总方法与有效模型。
- [ ] **2.3 命名组合 `question-synthesis`**〔worker〕
  - `question-synthesis(question, policy)` 展开为两段显式运行：逐篇 `qa@1` 与 `question-report`，同一 `question` 写入两段；展开结果完整写入运行记录。第二段在第一段结果冻结后由人或 Agent 发起，界面与机器接口预填，不自动连跑。
- [ ] **2.4 覆盖与完整性修正**〔worker〕
  - 集合覆盖按声明范围内各成员的完成情况计算，不以汇总自身的 `read_segments` 判 `none`；完整读取后零结果算完成；下游记录实际消费的上游范围与缺口；覆盖与判断分开（规格 8.11）。
  - 下游按实际消费的上游条目合计依据初稿与依据校订稿的文献数（04 的 4.6）。
  - `require-all` 未满足时只有汇总阶段失败，单篇结果保留；取消、失败、缺材料分别报告。
  - 覆盖说明由声明的读取范围生成（规格 8.11），摘要范围不得写成正文已读；显式请求补充材料时在提交前报告暂不支持。
- [ ] **2.5 运行流程与发起确认**〔worker〕
  - 落实规格 8.6 的固定检查点；任何检查点都不自动启动下一步的花费。
  - 发起：Web、CLI、MCP 都能发起运行与辅助付费步骤，共用应用边界。
  - 06 之前不设预算账本：所有者在 Web 上确认后才发生模型调用；Agent 发起的付费请求一律生成待所有者确认的请求（含冻结的定义、选取与估算），不发生模型调用。所有者确认后，运行与所有者自己发起的相同。06 之后按 06 的 6.4 开放 Agent 自行确认。
  - 待确认请求有状态（待确认、已确认、已拒绝、已过期），三端都能查询；所有者确认在规格 8.6“所有者操作”列出的入口上进行（Web、本机 CLI、带 `--owner` 的 stdio MCP）；HTTP 版 MCP 与设备连接令牌不能确认。
  - 运行记录发起者、所依据的确认，以及展开的组合模板。
- [ ] **2.6 摘要筛查**〔worker；部分〔计划 21〕〕
  - 落实规格 8.6 的摘要筛查：`qa` 的“题录与摘要”选区，不是新算子。
  - 摘要的取法按规格 8.6：先取快照冻结的元数据中的题名与摘要（04 的 4.4），证据根是冻结元数据及其来源；元数据没有摘要时，取校订稿里摘要角色的片段，按规格 8.4 映射新旧两套章节角色；两处都没有才算缺摘要。
  - 缺摘要的成员直接进未定项，不调用模型；章节角色可疑、失败也进未定项。只有明确违反纳入标准的证据才建议排除，“摘要没提到”为不确定。
  - 读取的元数据进入复用键；摘要范围的回答不复用为全文回答；结果显示实际读取的片段或元数据字段，不自动升级为全文。
  - 〔计划 21〕只有初稿、元数据又没有摘要的成员：初稿没有章节角色，记为缺摘要，不读整篇。
- [ ] **2.7 试运行**〔worker〕
  - 从选取范围中按保存的抽样方式取样本（覆盖长文、图多、不同文章类型），样本 ID 与抽样方式随运行保存；同配置的试运行结果在正式运行中复用。样本命中率不写成召回率。
- [ ] **2.8 单元用时记录**〔worker〕
  - 现状：用量记录有输入与输出 token，没有每个执行单元的用时，因此无法估算用时。
  - 每个执行单元记录从开始执行到结束的墙钟时长（不含排队等待）、结束状态（完成、部分、失败、取消）、实际模型调用次数与 token 用量，以及它的口径（口径的定义见规格 8.6“试运行与估算”）。
  - 记录随运行保存，可以按口径查询历史；需要表结构变化时并入 G-schema 第一个窗口。
- [ ] **2.9 估算**〔worker〕
  - 落实规格 8.6“试运行与估算”：花费分调用次数、输入 token、输出 token 三项，各给区间；用时按同口径历史单元用时的中位数到 P90，乘以需新算的单元数，按当前并发上限折算成墙钟时长。
  - 依据写明样本数与口径；没有同口径历史时，该项显示“未知”并写明原因，不用其它算子的历史代替；产品不保存模型单价，不换算成金额。
  - 区分可复用与需新算的单元；计入重复上下文、压缩、输出、回查与各级汇总；派生显示“无模型费用”。
  - 辅助付费步骤（摘要筛查、试运行）开始前给出规格 8.6 表中列出的已知内容。
  - `estimate` 不调用模型。
- [ ] **2.10 机器接口与分层读取**〔worker〕
  - 在 01 的 `list_operators` 之上增加 `estimate`、`run`（逐篇目标为文献或快照，汇总目标为冻结结果）、待确认请求的创建与查询、`get_result`、按条目查询、沿证据跳转；CLI、MCP、HTTP 共用应用边界。
  - 分层读取按规格 8.12：`get_result` 只返回外框和条目总数，大小有界；条目查询分页，每页有条数与字节上限并给出续读位置；证据跳转返回所引片段及其文献、版本、文本等级、核对依据与可靠定位；原文经文档的有界读取。每一层都只读已有内容，不触发加工。
- [ ] **2.11 带出处的导出**〔worker〕

  - 本块接上 `report`（Markdown，引用写成脚注）与 `answer`（Markdown）；03、07、12 等块接上各自类型。导出只读已有结果，不调用模型；三端可用。

## 验证

最小验收（全部经生产对象图与正式机器入口，不直接调用 `run` 证明完成）：

- 三篇合成论文：一篇有答案、一篇完整读完后无答案、一篇处理失败；
- fake 模型断言每篇收到的是同一问题；完整读取后的 `null` 不被判为缺覆盖；
- `allow-partial` 准确报告部分完成；`require-all` 只令汇总失败、不产出假成功，单篇结果仍在；
- 同输入复用、改问题重新计算；恢复时不更换版本或模型；
- 综合引用能回到原片段；旧结果仍可读、可导出；
- 超出容量时走两级汇总，仍超限时报缺口，不静默截断；
- 多份清单为输入时，成员去重，外框逐份列出覆盖并合计；
- 未经确认不产生任何模型调用（fake 模型断言调用次数为 0）；试运行样本与抽样方式可重放；
- 发起与确认：Agent 经 CLI 与 MCP 发起的付费 `run` 生成待确认请求、调用次数为 0；所有者在 Web 确认后运行完成；同一结果经 Web 与机器入口读到的 ID 与内容一致；
- 摘要筛查：
  - 只有书目、没有全文的成员按冻结元数据的摘要得到回答，证据根为冻结元数据，核对字段与来源通过；
  - 元数据没有摘要、校订稿有摘要片段的成员读该片段；ADR 0041 前后的合成文档各自映射正确；
  - 两处都没有摘要的成员进未定项，对它不发生模型调用；章节角色错误进未定项；
  - 冻结后改元数据，旧运行不变；摘要改变后新运行不命中旧复用键；摘要范围的回答不命中全文复用；覆盖说明不写成正文已读；
  - 〔计划 21〕只有初稿且元数据无摘要的成员记为缺摘要；
- 估算：没有同口径历史时，调用、token 与用时都显示“未知”；一次 fake 运行记录单元用时后，同口径估算给出区间与样本数；不同口径的历史不被使用；可复用单元不计入新算；
- 分层读取：`get_result` 不含条目正文且大小有界；条目分页遵守条数与字节上限，续读无重复无遗漏；证据跳转返回文本等级；
- 导出：引用键与书目一致，书目可被既有书目导出的解析器读回；导出不产生模型调用；
