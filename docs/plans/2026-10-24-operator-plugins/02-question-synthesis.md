# 02 · 问答、运行流程与问题综合

类型：计划（结果块）
负责：`qa@1`、运行流程、并发与分批、问题综合、覆盖修正、机器接口与结果页外框
状态：Pending

## Outcome

用户给出一个问题和一组文献，系统：

1. 用同一个问题逐篇完整阅读并回答，每个非空答案都有原文引用，空答案写明原因；
2. 汇总成带引用的报告，引用能回到原文片段；
3. 如实报告完成度：哪些篇读完了、哪些失败、哪些缺材料；
4. 每次运行都经过固定检查点：选取、冻结、确认、可选试运行、估算区间与确认，再执行；同一问题、同一输入复用已有结果；
5. 可以只读摘要做筛查（`qa` 的读取范围），排除只凭明确证据，其余进未定项；
6. 快照内逐篇并发执行、分页分批，不再串行循环。

这是计划的第一个审阅点 R1，也是“让问题进入逐篇阅读”的最小闭环。规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.2、8.3、8.6、8.7、8.11–8.13。

## 进入条件

01 退出（2.0 不依赖新合同，最先做）；2.1 须 G-adr 通过（公共阅读会话取代 ADR 0037 的分块条款）。

## 责任边界

worker：contracts、`apps/server/src/analysis/`（新增 `qa` 与组合执行，替换 `processor-synthesis.ts`）、`processor-planning.ts` 与 `usage-estimate.ts`、存储、`entry/processor-operations.ts`、MCP、CLI、HTTP、`apps/web/src/app/data/`。Claude：Web 页面规格草案与 `apps/web/src/app/features/processing/`、`synthesis/`、`reader/PaperResults.tsx` 的界面实现。

## Tasks

- [ ] **2.0 并发与分批**〔worker〕（本块第一个 Task：试运行与基准运行都依赖它）
  - 现状：算子任务的目标并发写死为 1（`application/jobs/processing.ts`），`knowledge-synthesis@2` 的逐篇步骤在一个目标内串行循环（`analysis/processor.ts`）。逐篇运行的各目标改为经现有 Jobs 的共享有界准入并发执行，不另建调度平台；串行循环随 2.7 删除旧集合路径一并消失，不单独改。
  - 成员与结果按页与批次处理，满足内存约束。快照创建的成员上限保持不变（草案 8.6 规模）。
  - 验收：并发下复用、取消、失败、恢复与串行时语义一致；接近上限的快照分批执行后结果集合与覆盖一致、无重复无遗漏；超上限的快照在创建时被拒；大批量运行在 06 验收前在 Web 与机器接口都不开放。
- [ ] **2.1 `qa@1`**〔worker〕
  - 在公共会话上实现问答，`answer_type` 覆盖 `labels@2` 现有的 `boolean | string | enum`，并增加 `text`（带引用的自由回答）。
  - 完整读取声明范围，不因找到答案提前结束；`null` 附原因，含义是“声明范围内未得出答案”。
  - 验收：`labels@2` 现有测试（`next-processor-labels.test.ts` 对应的服务端用例）改用 `qa@1` 后断言目的不变。
- [ ] **2.2 汇总执行**〔worker〕
  - 落实草案 8.7 的显式汇总请求，输入是冻结的集合清单；G-adr 前只接受同一快照逐篇运行的清单（ADR 0034），其它来源在提交时拒绝；执行器检查 `mode` 与上游产出类型兼容，不从插件 spec 推断问题。本块实现 `question-report` 与 `compilation` 两种模式。
  - 汇总前容量预检；超限时两级汇总，仍超限报缺口。各级保留原始证据链、同源去重、反证与少数意见。
  - 复用键：输入集合清单的 ID 与 hash、完整性策略、汇总方法与有效模型。
- [ ] **2.3 命名组合 `question-synthesis`**〔worker〕
  - `question-synthesis(question, policy)` 展开为两段显式运行：逐篇 `qa@1` 与 `question-report`，同一 `question` 写入两段；展开结果完整写入运行记录。第二段在第一段结果冻结后由用户或授权方发起，界面预填，不自动连跑。
- [ ] **2.4 覆盖与完整性修正**〔worker〕
  - 集合覆盖按声明范围内各成员的完成情况计算，不以汇总自身的 `read_segments` 判 `none`；完整读取后零结果算完成；下游记录实际消费的上游范围与缺口；覆盖与判断分开（草案 8.11）。
  - `require-all` 未满足时只有汇总阶段失败，单篇结果保留；取消、失败、缺材料分别报告。
  - 覆盖说明由声明的读取范围生成（草案 8.11），摘要范围不得写成正文已读；显式请求补充材料时在提交前报告暂不支持。
- [ ] **2.5 运行流程**〔worker〕
  - 落实草案 8.6 的固定检查点。06 之前不设预算账本：任何模型调用（含试运行）都须人确认后才发生，三端在人工确认下一致；Agent 经机器接口只能生成待人确认的请求（06 之后可凭任务授权）。
  - 摘要筛查：落实草案 8.4 的“题录与摘要”选区及其到新旧章节角色的映射；缺摘要、章节角色可疑、失败进未定项；结果标明读取范围，不复用为全文回答。
  - 试运行：从选取范围中按保存的抽样方式取样本（覆盖长文、图多、不同文章类型），样本 ID 与抽样方式随运行保存；同配置的试运行结果在正式运行中复用。
  - 估算：给出区间及依据（重复上下文、压缩、输出、回查、各级汇总），区分可复用与需新算的单元。
- [ ] **2.5b 机器接口**〔worker〕
  - 在 01 的 `list_operators` 之上增加 `estimate`、`run`（逐篇目标为文献或快照，汇总目标为冻结结果）、`get_result`、按条目查询、沿证据跳转；CLI、MCP、HTTP 共用应用边界，返回运行与结果引用。
- [ ] **2.6 Web**〔Claude〕
  - 先在页面规格写草案节：运行页按算子提供专门表单（总结、问答）；运行流程页（选取来源、确认、试运行结果、估算区间与可复用数、确认提交）；问题综合入口为“一个问题 + 选择文献集合 + 完整性策略”；结果页公共外框（任务与规范、选取、覆盖、判断汇总、花费与复用）、证据抽屉、未定项面板，以及回答与报告两种视图（草案 8.12）。
  - 实现并补 Web 测试；`capture` 截图覆盖新增与改动页面的两种宽度。
- [ ] **2.7 删除旧集合路径**〔worker〕
  - 2.8 之后、旧队列排空时执行：删除 `Processor.map`、`uses_description`、`knowledge-synthesis` 与 01 的隔离旧执行入口；`knowledge-synthesis@2` 的历史结果经 01 的 1.2 解码器继续可读。排空前，旧排队任务经旧执行入口完成；无法排空的由 Owner 决定终止后重提。
- [ ] **2.8 停止旧问答新建**〔worker〕
  - 2.1 与 2.6 验收后，`labels@2` 与 `summary@2` 停止新建运行；排队任务按原版本完成。Web 与机器接口不再提供它们的运行入口。
- [ ] **2.9 R1 审阅包**〔Claude〕

## 集成与影响

- 用户可见行为变化：问题综合取代旧综合；“问答标注”成为“问答”；综合结果的完成度如实区分部分完成。
- 设计样例库（计划 14 的 02）需要新增问题综合与问答结果的合成样例；由 worker 在 2.6 之前补齐。
- 无 catalog 表结构变化预期；若组合运行记录需要新表，停下交 Owner（G-schema）。

## 验证

最小验收（全部经生产对象图与正式机器入口，不直接调用 `run` 证明完成）：

- 三篇合成论文：一篇有答案、一篇完整读完后无答案、一篇处理失败；
- fake 模型断言每篇收到的是同一问题；完整读取后的 `null` 不被判为缺覆盖；
- `allow-partial` 准确报告部分完成；`require-all` 只令汇总失败、不产出假成功，单篇结果仍在；
- 同输入复用、改问题重新计算；恢复时不更换版本或模型；
- 综合引用能回到原片段；旧结果仍可读、可导出；
- 超出容量时走两级汇总，仍超限时报缺口，不静默截断；
- 未经确认不产生任何模型调用（fake 模型断言调用次数为 0）；摘要范围的回答不命中全文复用；试运行样本与抽样方式可重放；
- 并发执行与串行执行的结果集合、覆盖与复用一致；
- 摘要选区：ADR 0041 前后的合成文档、空摘要、章节角色错误分别得到正确的读取范围或未定项，覆盖说明不写成正文已读；
- 旧任务：重启恢复的 `knowledge-synthesis@2`、`labels@2` 排队任务按原版本完成，旧执行入口拒绝新建。

命令按根 README 的验证路线。既有 `processor-snapshot-synthesis.test.ts`、`processor-interface-parity.test.ts`、`processor-workbench.test.ts` 改写为新组合后断言目的不变；新增 `processor-run-flow.test.ts`（检查点、试运行、估算、零调用）、`processor-concurrency.test.ts`（并发与分批）；Web 测试与截图按验证路线执行。

未覆盖：真实论文上的答案质量（G-real）。

- R1 获 Owner 确认。
