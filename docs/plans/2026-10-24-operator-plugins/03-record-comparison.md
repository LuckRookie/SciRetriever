# 03 · 记录提取与比较

类型：计划（结果块）
负责：`records@3`、对照表与可选叙述、从问题起草规范、记录表的三样交付
状态：Pending

## Outcome

人在 Web 上，或 Agent 经 CLI、MCP，说“比较这批论文在不同条件下的结果”，系统：

1. 帮使用者从这句话起草一份提取规范（字段、类型、单位、可选角色），使用者确认后冻结；
2. 用同一份规范逐篇提取记录，数值保留原串与原单位；
3. 由程序拼出对照表，每行是一条记录及其文献和核对状态，可以展开到原文；
4. 可选再写一段叙述，只引用表中的记录；叙述失败不影响表。

发起、确认与取用沿用 02 的 2.5：两种发起经过同一组检查点，得到同一份结果。

`records` 类型与对照表的三样交付（规格 8.12）：

| 交付           | 内容                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| 人读的页面     | 分页记录表与对照表，列按展示角色排序，每格显示逐值核对状态，证据展开到原文 |
| Agent 按层读取 | 外框 → 按记录分页、可按字段筛选；对照表经条目投影分页 → 证据 → 原文        |
| 带出处的导出   | CSV（每行带文献与证据列）、JSON，附被引文献的书目；叙述导出为 Markdown     |

这是审阅点 B。规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.2、8.4、8.6、8.7、8.12。运行流程（选取、确认、试运行、估算）复用 02，不另建。

## 责任边界

worker：`processor-records.ts`、组合执行中的 `comparison-table` 模式、`processor-export.ts`、存储、机器接口、规范起草的应用操作、`apps/web/src/app/data/`。总设计师：页面规格草案与规范编辑、对照表、起草流程的界面。

## Tasks

- [ ] **3.1 `records@3`**〔worker〕
  - 在公共会话上实现记录提取；记录有界分批产出，不因单次输出上限截断；字段增加可选展示角色 `subject | condition | result | note`。读取的文本等级按 04 的 4.3。
  - 数值保留原串与原单位，不做换算；重复测量不合并。
- [ ] **3.2 对照表**〔worker〕
  - 汇总执行增加 `comparison-table` 模式：程序确定性生成，不经过模型；每行一条单篇记录及其文献、各字段核对状态；行号只用于展示，引用绑定结果、记录、字段与 hash。
  - 按角色排列列序；同一字段出现不同单位时给出提示，不换算、不判定可比。
  - 结果不复制行：只存输入集合清单、列定义、排序规则、行数与行引用 hash；行经条目投影分页读取（规格 8.7）。
- [ ] **3.3 可选叙述**〔worker〕
  - `narrative` 为可选问题，是对照表汇总请求的可选部分，输入同一集合清单；叙述由模型基于表写成，只引用表中记录；保留反证、少数意见和条件差异；超容量时与 02 相同处理。
  - 叙述失败不撤销表，分别报告。
- [ ] **3.4 命名组合 `record-comparison` 与机器接口**〔worker〕
  - `record-comparison(spec, narrative)` 展开为逐篇 `records@3` 与对照表汇总两段显式运行并写入运行记录；对照表由程序生成，无模型费用；带叙述时汇总须确认；三端可发起。
  - 机器读取按 02 的 2.10 分层：记录按页读取、可按字段筛选，对照表经条目投影分页。
- [ ] **3.5 从问题起草规范**〔worker 后端，前端界面〕
  - 应用操作：输入一句话与可选样例文献，模型起草规范（字段、类型、单位、角色、记录含义与纳入条件）；只返回草稿，不运行提取。起草调用模型，是辅助付费步骤，按 02 的 2.5 先确认（06 之后计入账本，Agent 可凭授权）。规范校验与冻结走共享应用边界，CLI、MCP 同样可用。
  - Web：起草 → 逐字段编辑 → 确认冻结 → 预估用量 → 运行。规范编辑是专用表单，不用自动生成表单；字段类型只支持 `records` 已有的封闭集合，超出的在校验时拒绝。
- [ ] **3.6 记录表的页面与导出**〔总设计师 页面，worker 导出〕
  - 页面规格草案后实现：在 02 的结果页外框内登记记录表视图（按字段分组与排序、核对状态、单位不一致提示、显式选择两个数值字段的散点图、证据展开到原文）、叙述视图、导出入口。
  - 导出接上 02 的 2.11：CSV 每行带文献与证据列，JSON，附书目；对照表按页流式导出。
- [ ] **3.7 停止 `records@2` 新建**〔worker〕
  - 3.1 与 3.6 验收后执行；排队任务按原版本完成。
- [ ] **3.8 审阅点 B 审阅包**〔前端〕
  - 合成样例上的对照表、叙述与规范编辑截图，导出文件，以及起草、确认、运行的流程说明，交 Owner。
- [ ] **3.9 E1b 效果检查点**〔worker 运行，总设计师 对比；须 G-real、G-lib〕
  - 在 B0 基准上运行记录比较，对照期望记录；按根 README 的方法逐条标注、归类错因，写出改进建议，交 Owner 决定继续 05、08、09、10 或退回 03（必要时 01）。

## 集成与影响

- 外部 Agent 或程序自行提取并交付记录的路径（需求炼3：`submit_extraction` 交付、`retain_extraction` 长期托管）保持可用；托管结果符合同一规范时可作为对照表的行，生产者来源照常标明。
- 调用方：Web 处理页与结果页、MCP 与 CLI 的运行和查询、导出；07 的记录表统计（7.6）、09 的实体提及。
- 设计样例库补充记录比较的合成样例（多记录、重复试验、null 与零、不同单位）。

## 验证

- 多记录与重复试验不被合并；null 与 0 区分；原串与原单位逐字保留；
- 对照表在不同分页大小下行集合一致，导出与界面一致；超过 10,000 行的合成表可以生成、分页读取与导出，结果文件不超出单份结果上限，行引用 hash 核对通过；
- 叙述失败时表仍可读、可导出；叙述引用可展开到具体记录与原文片段；
- 起草操作不触发提取运行；未确认时起草不产生模型调用，取消与重放不重复调用；冻结后的规范 hash 进入复用键；Agent 发起的起草在 06 之前生成待确认请求；
- 导出的 CSV 每行的文献与证据列可以对上书目中的引用键；
- 既有 `processor-number.test.ts`、`processor-value-check.test.ts` 对 `records@3` 通过；新增 `processor-comparison-table.test.ts`；命令按根 README 的验证路线。
