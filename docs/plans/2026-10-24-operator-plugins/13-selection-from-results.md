# 13 · 按结果选取与常备产物

类型：计划（结果块）
负责：按一次运行的结果筛选成快照、“已有结果”选取层与常备产物、刷新与排除集复核
状态：Pending

## Outcome

1. 人在 Web 上，或 Agent 经 CLI、MCP，可以按一次运行的结果筛出新快照（例如问答为“纳入”的论文）。来源是该运行的集合清单（目标、结果引用与缺口）；新快照记下来源清单与规则；失败、未得出答案、缺材料、未处理的论文作为未定项交使用者决定；
2. 选取可以从已有结果（包括常备产物）出发：人在 Web 上浏览常备产物并据此缩小范围；Agent 经机器接口先查已有结果，再决定是否发起付费加工。两者读到的是同一份结果；
3. 常备产物的运行与其它运行相同，经过同一组检查点，不常驻、不自动补算；
4. 刷新到当前版本与排除集复核都是显式操作；复核调用模型，须确认。

本块不新增产出类型。原 04 的 4.4、4.4c、4.4b 移到本块，依次为 13.1、13.2、13.3。

规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.6（选取表的摘要筛查之后两层、常备产物）、8.10（按结果筛选成快照）。

## 责任边界

worker：快照的结果来源、已有结果的查询、刷新、排除集复核、机器接口。总设计师：结果页“筛选成快照”、常备产物浏览与刷新的界面。

## Tasks

- [ ] **13.1 按结果筛选成快照**（原 4.4）〔worker〕
  - 落实规格 8.10“按结果筛选成快照”：来源是一次运行的集合清单（目标成员、结果引用与缺口，复用现行集合清单机制）的 ID 与 hash，加筛选规则，写入快照；没有结果的目标成员由清单给出，不会被漏掉。
  - 成员继承来源结果的输入版本，刷新须显式选择；未得出答案、失败、缺材料、未处理的成员单独列为未定项；只建快照，不启动后续运行。三端共用应用边界。
  - 与 04 的 4.4 同属快照合同；需要表结构变化时一并走 G-schema。
- [ ] **13.2 已有结果与常备产物**（原 4.4c）〔worker〕
  - 落实规格 8.6 的“已有结果”选取层与常备产物：选取来源可以是某次运行的集合清单（复用 13.1）。
  - 机器接口能按一组文献查询已有的完整结果及其算子、规范、文本等级与过时状态，供 Agent 先查后算；现有按文献列结果与运行列表的接口能满足的，直接复用。查询只读已有内容，不触发加工（需求规1）。
  - 常备产物的运行沿用 02 的运行流程，不加常驻规则。全库常备产物的实际运行在正式库上写入结果，是真实服务步骤：在 06 验收后由 Owner 决定范围与预算，须 G-real、G-lib、G-deploy，不在本块的工程验收内。
- [ ] **13.3 刷新与排除集复核**（原 4.4b）〔worker〕
  - 刷新：把快照成员换到当前版本，生成新快照并记下刷新来源；旧快照不变。
  - 排除集复核：对排除集与检索未命中池按保存的抽样方式取样，作为一次经确认的 `qa` 运行；结果只用于提示扩大范围或修改规则，不改原快照。
- [ ] **13.4 Web**〔前端〕
  - 页面规格草案后实现：
    - 结果页的“筛选成快照”：选择规则，预览纳入、不纳入与未定项三组，未定项逐个或整组决定后再建快照；
    - 常备产物的浏览，并能以它为条件缩小选取范围；
    - 快照详情里的“刷新到当前版本”与“复核排除集”。
- [ ] **13.5 验证与审阅点 C 审阅包**
  - 运行下节测试；审阅包含筛选成快照、常备产物浏览、刷新与复核的截图及行为说明。

## 集成与影响

- 调用方：02 的结果页；Web 快照页；MCP 与 CLI 的快照创建、已有结果查询与运行。
- 用户可见变化：可以从一次筛查的结果直接建下一步的快照；可以先查已有结果再决定是否付费。

## 验证

命令按根 README 的验证路线；新增 `snapshot-from-results.test.ts`。

- 按结果筛选：来源清单含成功、失败、未开始、缺材料的成员时，后三者全部进入未定项，成员总数与清单一致；新快照记录来源清单 ID、hash 与规则；成员版本等于来源结果的输入版本，来源文献之后更新也不改变；失败、未得出答案、缺材料的成员不被归入“不纳入”；来源结果 hash 不符时拒绝；建快照不产生任何运行；
- 已有结果查询：返回完整结果与过时状态；查询不产生模型调用，不创建任务；Web 与机器接口读到同一份结果；
- 刷新生成新快照、旧快照不变；排除集复核未经确认不产生调用。
