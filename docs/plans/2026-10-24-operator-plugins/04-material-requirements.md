# 04 · 按需材料门槛与文本等级

类型：计划（结果块）
负责：算子按声明的材料准入；读取初稿或校订稿；快照冻结材料事实、文本等级、元数据与选取来源
状态：Pending

## Outcome

1. 正文有默认文本（初稿或校订稿）的文献，即使没有标签、元数据不全、没有建档，也能被只需要正文的算子加工；`READY` 只表示库整理完成，用于筛选和展示。
2. 算子按 `requires` 准入（规格 8.4）：
   - `main-text`：两级都有时读校订稿，只有初稿时读初稿；
   - `main-proofread`：只读校订稿；
   - 运行可以限定“只用校订稿”，这时没有校订稿的成员记为缺材料并计入覆盖，不改读初稿。
3. 每份结果记录每篇输入读的文本等级，外框给出依据初稿与依据校订稿的文献数；文本等级进入复用键；初稿升级为校订稿后，依据初稿的旧结果标为过时，不自动重算。
4. 快照收入全部选中成员，包括只有书目、没有全文的文献；冻结每篇的版本、材料事实、选定的文本等级，以及题名、摘要和它们的来源（供 02 的摘要筛查）。运行按算子声明对照冻结事实判定，缺材料的成员计入覆盖。
5. 入队之后补材料、改标签或元数据、初稿升级为校订稿，都不改变已发起的运行。
6. 快照记下选取来源：元数据条件（含文本等级）、原文检索（查询、规则版本、命中片段，可重放）、同义词并集、人工补入；未索引材料单独列出。
7. 人在 Web 上看到每篇文献“可加工”“已整理”两个状态，建快照时看到各成员缺什么材料、读哪一级文本；Agent 经 CLI、MCP 的文献库读取与快照读取得到同样的事实。

本块不交付新的产出类型。按结果筛选成快照、已有结果与常备产物、刷新与排除集复核在 [13](13-selection-from-results.md)。

规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.4、8.6（选取表的元数据与原文检索两层）、8.10、8.11；文本的读取合同见[文档与证据规格](../../architecture/technical/04-document-evidence.md)第 8.5、8.6 节。“可加工”“已整理”的定义在规格 8.10。

## 与计划 21 的关系

初稿由计划 21（[计划 21](../2026-11-10-draft-text/README.md)）交付，范围是文档与证据规格第 8.2–8.6 节：初稿的形成、片段的核对依据、默认文本与内容版本、加工读取合同。本块不形成初稿，也不改初稿的标注。

计划 21 之前，本块只用校订稿就能实现和测试的部分：

- 4.1–4.8 中没有标〔计划 21〕的内容；
- 这时所有文本都是校订稿，`main-text` 与 `main-proofread` 对同一篇得出相同结论，“有无初稿”恒为无；
- “只用校订稿”的冻结、进入复用键、`main-proofread` 不受它影响，都可以测试；
- 外框三个数中依据初稿的数恒为 0，但记录、合计与显示的规则可以测试。

标〔计划 21〕的内容等计划 21 交付第 8.2–8.6 节并合入后再做：读取初稿；初稿片段的核对依据进入会话与证据；初稿上按章节角色读取时读整篇；`body-section` 在初稿上的规则；“只用校订稿”时初稿成员记为缺材料；初稿升级后的过时；以初稿为默认文本的合成 fixture。在此之前本块记为 Partial。

## Tasks

- [ ] **4.1 材料事实**〔worker〕
  - 由事实 owner 派生 `requires` 对应的事实：正文有无初稿、有无校订稿、校订稿是否完成并为默认文本、正文章节数、标签数、元数据字段是否齐全；不新增可变状态。
  - 派生规格 8.10 的“可加工”“已整理”两个状态，经文献库读取在 HTTP、CLI、MCP 返回。
  - 验收：合成 fixture 上各事实与已知值相等；只有书目的文献两个状态都不满足。
- [ ] **4.2 单篇准入**〔worker〕
  - 执行器与输入构造不再判断 `READY`，改为在提交时按算子 `requires` 判定当前事实，判定结果随输入冻结。`EXCLUDED` 仍作为独立选取政策排除。
  - 摘要范围的 `qa` 运行不按 `main-text` 判定：规格 8.6 规定只有书目的文献也能筛查，摘要的取法由 02 的 2.6 处理。
- [ ] **4.3 文本等级与“只用校订稿”**〔worker；部分〔计划 21〕〕
  - 按规格 8.4 为每个成员选定文本等级。读取经文档与证据规格 8.6 的合同取默认文本、`text_level` 与内容版本；计划 21 之前直接读校订稿，记为 `proofread`。
  - 运行选项“只用校订稿”：随运行冻结，进入复用键；没有校订稿的成员记为缺材料并计入覆盖；`requires: main-proofread` 的算子不受这个选项影响。
  - 文本等级是内容版本的一部分，进入复用键。
  - 〔计划 21〕初稿上按章节角色限定读取时读整篇正文，覆盖说明写“初稿没有章节角色，读取了整篇”，不返回 `structure-role-unavailable`；`body-section` 在初稿上不把成员记为缺材料；初稿片段的核对依据进入公共阅读会话（1.3）与证据。
  - 〔计划 21〕初稿升级为校订稿、重新解析形成新初稿后，依据旧内容版本的结果标为过时，不自动重算；旧证据仍解析到原来的初稿片段。
- [ ] **4.4 快照**〔worker〕
  - 快照收入全部选中成员，包括只有书目的文献；冻结各自的版本、材料事实、选定的文本等级，以及题名、摘要及其来源（冻结元数据，是摘要筛查的证据根之一）。
  - 运行时按算子的 `requires` 对照冻结事实判定，执行时只复核完整性；之后补齐材料不改变旧快照上的运行，需新建快照。
  - 成员上限 10000 不变（规格 8.6）；更大选取的拆分在 06 的 6.7。
  - 需要表结构变化时停下交 Owner（G-schema），按停服、备份、副本迁移、核对、切换执行。
- [ ] **4.5 选取来源**〔worker〕
  - 落实规格 8.6 选取表的元数据与原文检索两层：元数据条件（文件夹、标签、状态、文本等级等）、原文检索（查询、检索范围、检索与分词规则版本、排序与截断规则、最终成员与文档 hash、命中片段）、同义词并集、人工补入（记录操作者），随快照冻结。
  - 重放读冻结结果，不重跑查询；未索引材料单独列出，不当作未命中。三端共用应用边界。
  - 摘要筛查一层在 02 的 2.6，“已有结果”一层在 13 的 13.2。
- [ ] **4.6 文本等级的记录与三个数**〔worker；部分〔计划 21〕〕
  - 每份新结果记录每篇输入文献的文本等级；外框给出依据初稿、依据校订稿与只读元数据的文献数（规格 8.11）。下游按实际消费的上游条目合计这三个数，由 02 的 2.4 使用。
  - 证据读取返回所引片段的文本等级；〔计划 21〕初稿片段另带核对依据。
  - 摘要筛查的输入取自冻结元数据时记为“元数据”，计入第三个数，不计入前两个数（规格 8.4、8.11）。
- [ ] **4.7 Web**〔前端〕
  - 先在页面规格写草案节，再实现：
    - 文献状态按规格 8.10 表达“可加工”“已整理”；文本等级的标注沿用文档与证据规格 8.4 与页面规格；
    - 建快照时显示各成员缺什么材料、读哪一级文本；
    - 选取页：元数据条件（含文本等级）、原文检索（提示“未命中不等于不相关”）、同义词并集、人工补入、未索引列表；快照详情显示选取来源。
  - 页面规格“文献库的连续选择与批量操作”草案里“运行算子 → 已就绪的”一句，改为按所选算子的 `requires` 计数。
  - 运行前“将被跳过的成员数与原因”显示在 02 的运行确认页（2.12），数据由本块提供。
- [ ] **4.8 验证与审阅点 C 审阅包**
  - 运行下节测试；审阅包含文献状态、选取页、快照详情与缺材料提示的截图及行为说明。
- [ ] **4.9 初稿与校订稿的结果对比**〔〔计划 21〕；worker 运行，总设计师 对比；须 G-real、G-lib〕
  - 回答 ADR 0060“后果”中待实测的一问：依据初稿的加工结果与依据校订稿的结果相差多少。
  - 在正式库的隔离副本上，取 B0 基准中两级文本都有的论文，用同一问题分别读初稿与校订稿（评估脚本在副本中冻结指定的文档版本，脚本在 `sandbox/`，不进产品），按根 README 的对比方法标注、归类错因，结论交 Owner。

## 集成与影响

- 用户可见变化：未打标签、未建档但有初稿或校订稿的文献也能运行算子；快照成员数可能多于以前的 `READY` 数；结果页显示三个数。
- 旧快照仍可读；旧快照上的新运行按其冻结内容执行，不回溯补收成员。
- 调用方：02 的运行流程与摘要筛查、03 的逐篇提取、05 的声明式算子、13 的按结果筛选。

## 验证

命令按根 README 的验证路线。新增 `snapshot-selection-provenance.test.ts`、`processor-text-level.test.ts`；既有 `snapshots.test.ts`、`snapshot-labels.test.ts`、`processor-archive.test.ts`、`processor-description.test.ts` 改写后断言目的不变。

只用校订稿（计划 21 之前）：

- 缺标签、元数据不全的文献可被只需正文的算子加工；声明需要标签的 fake 算子对其报缺材料；
- 缺材料成员计入覆盖，不被静默忽略；
- 入队后补材料、改元数据或标签，旧运行的输入与结果不变；新快照上的新运行反映新事实；
- 只有书目的文献进入快照，冻结的题名、摘要与来源与元数据一致；之后改元数据不改变快照；
- “只用校订稿”改变复用键；`main-proofread` 算子在两种选项下结果相同；
- 结果外框的三个数与输入一致，下游合计正确；
- 选取来源：检索选取按冻结结果重放，索引更新后不变；未索引材料不计为未命中；人工补入记录操作者；
- 文献库读取在三端返回相同的“可加工”“已整理”状态。

〔计划 21〕用以初稿为默认文本的合成 fixture：

- 只有初稿的成员读初稿，两级都有的读校订稿；“只用校订稿”时只有初稿的成员记为缺材料，不调用模型；
- 按章节角色读取初稿时读整篇，覆盖说明如实，没有 `structure-role-unavailable`；
- 初稿升级为校订稿后，依据初稿的结果标为过时，证据仍解析到原初稿片段；
- 证据读取返回初稿片段的核对依据，三种取值各有覆盖。

未覆盖：真实论文上初稿与校订稿结果的差距（4.9，须授权）。

## 恢复与交接

若表结构迁移未获授权，4.1–4.3 可先合入（单篇准入改为按需），快照保持只收 `READY`，在进度中记录这一限制；这时 02 的摘要筛查只覆盖快照内的成员，不能筛查只有书目的文献。计划 21 推迟时，本块停在退出 A，问答闭环先在校订稿上交付。
