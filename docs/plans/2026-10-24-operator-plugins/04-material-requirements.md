# 04 · 按需材料门槛与选取来源

类型：计划（结果块）
负责：算子按声明的材料判定能否加工，快照冻结材料事实与选取来源
状态：Pending（须 G-adr）

## Outcome

1. 正文已校订、有正文章节的文献，即使没有标签或元数据不全，也能被只需要正文的算子加工；
2. 快照收入全部选中的文献，冻结每篇的版本与材料事实；运行时按算子声明对照冻结事实判定，缺材料的成员计入覆盖；
3. 入队之后补材料、改标签或元数据，都不改变已发起的运行；
4. `READY` 仍表示库整理完成，用于筛选和展示；
5. 用户可以按一次运行的结果筛出新快照（例如问答为“纳入”的论文），来源是该运行的集合清单（目标、结果引用与缺口），新快照记下来源清单与规则，失败或未得出答案的论文作为未定项交用户决定；
6. 快照记下选取来源：元数据条件、原文检索（查询、规则版本、命中片段，可重放）、同义词并集、人工补入；未索引材料单独列出；
7. 刷新到当前版本与排除集复核都是显式、经授权的操作；
8. 选取可以从已有结果（包括常备产物）出发，Agent 能先查已有结果再决定是否付费加工。

规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.6、8.10。本块与 ADR 0037 §8、§10 冲突，G-adr 通过前不开工。

## 进入条件

01 退出；G-adr 通过。4.4 需要 02 的 2.2（集合清单作为来源）；4.4b 需要 02 的 2.1 与 2.5。

## 责任边界

worker：`processor-archive.ts`、`processor.ts` 的准入、`snapshots.ts`、`packages/contracts/src/snapshots.ts`、`storage/sqlite/snapshot-engine.ts`、建档状态读取。Claude：文献库与快照页面的状态表达。

## Tasks

- [ ] **4.1 材料事实**〔worker〕
  - 由事实 owner 派生 `requires` 对应的事实：正文校订完成并为默认文档、正文章节数、标签数、元数据字段是否齐全；不新增可变状态。
- [ ] **4.2 单篇准入**〔worker〕
  - 执行器与输入构造不再判断 `READY`，改为在提交时按算子 `requires` 判定当前事实，判定结果随输入冻结。`EXCLUDED` 仍作为独立选取政策排除。
- [ ] **4.3 快照**〔worker〕
  - 快照收入全部选中成员，冻结版本与材料事实；运行时按 map 算子的 `requires` 对照冻结事实判定，执行时只复核完整性。
  - 若需要表结构变化，停下交 Owner（G-schema），按停服、备份、副本迁移、核对、切换执行。
- [ ] **4.4 按结果筛选成快照**〔worker〕
  - 落实草案 8.10“按结果筛选成快照”：来源是一次运行的集合清单（目标成员、结果引用与缺口，复用现行集合清单机制）的 ID 与 hash，加筛选规则，写入快照；没有结果的目标成员由清单给出，不会被漏掉；成员继承来源结果的输入版本，刷新须显式选择；未得出答案、失败、缺材料、未处理的成员单独列为未定项；只建快照，不启动后续运行。三端共用应用边界。
  - 本任务不阻塞 02、03；与 4.3 同属快照合同，需要表结构变化时一并走 G-schema。
- [ ] **4.4a 选取来源**〔worker〕
  - 落实草案 8.6 的选取表：元数据、原文检索、并集、人工补入的来源随快照冻结；重放读冻结结果，不重跑查询；未索引材料单独列出。
- [ ] **4.4c 已有结果与常备产物**〔worker〕
  - 落实草案 8.6 的“已有结果”选取层与常备产物：选取来源可以是某次运行的集合清单（复用 4.4）；机器接口能按一组文献查询已有的完整结果及其算子、规范与过时状态，供 Agent 先查后算，现有按文献列结果与运行列表的接口能满足的直接复用。
  - 常备产物的运行沿用 02 的运行流程，不加常驻规则；全库常备产物的实际运行是 G-real 操作，在 06 验收后由 Owner 决定，不在本块。
- [ ] **4.4b 刷新与排除集复核**〔worker〕
  - 刷新：把快照成员换到当前版本，生成新快照并记下刷新来源；旧快照不变。
  - 排除集复核：对排除集与检索未命中池按保存的抽样方式取样，作为一次经确认的 `qa` 运行；结果只用于提示扩大范围或修改规则，不改原快照。
- [ ] **4.5 Web**〔Claude〕
  - 页面规格草案后实现：文献状态区分“可加工”与“已整理”；建快照时显示各成员缺什么材料；运行前显示将被跳过的成员数与原因。
  - 结果页的“筛选成快照”：选择规则，预览纳入、不纳入与未定项三组，未定项逐个或整组决定后再建快照。
  - 选取页：元数据条件、原文检索（提示“未命中不等于不相关”）、同义词并集、人工补入、未索引列表；快照详情显示选取来源。
- [ ] **4.6 验证与 R3 审阅包**
  - 运行下节测试；R3 审阅包含选取页、快照详情、筛选成快照与缺材料提示的截图及行为说明。

## 集成与影响

- 用户可见变化：未打标签的文献也能运行算子；快照成员数可能多于以前的 `READY` 数。
- 旧快照仍可读；旧快照上的新运行按其冻结内容执行，不回溯补收成员。

## 验证

- 缺标签、元数据不全的文献可被只需正文的算子加工；声明需要标签的 fake 算子对其报缺材料；
- 缺材料成员计入覆盖，不被静默忽略；
- 入队后补材料、改元数据或标签，旧运行的输入与结果不变；新快照上的新运行反映新事实；
- 选取来源：检索选取按冻结结果重放，索引更新后不变；未索引材料不计为未命中；人工补入记录操作者；
- 刷新生成新快照、旧快照不变；排除集复核未经确认不产生调用；
- 按结果筛选：来源清单含成功、失败、未开始、缺材料的成员时，后三者全部进入未定项，成员总数与清单一致；新快照记录来源清单 ID、hash 与规则；成员版本等于来源结果的输入版本，来源文献之后更新也不改变；失败、未得出答案、缺材料的成员不被归入“不纳入”；来源结果 hash 不符时拒绝；建快照不产生任何运行；
- 命令按根 README 的验证路线；新增 `snapshot-selection-provenance.test.ts`、`snapshot-from-results.test.ts`；
- 既有 `snapshots.test.ts`、`snapshot-labels.test.ts`、`processor-archive.test.ts`、`processor-description.test.ts` 改写后断言目的不变。

## 退出条件

- `READY` 不再出现在算子准入路径；快照冻结材料事实与选取来源；按结果筛选、刷新与排除集复核在三端可用；R3（本块部分）获确认。

## 恢复与交接

若表结构迁移未获授权，4.1、4.2 可先合入（单篇准入改为按需），快照保持只收 `READY`，在进度中记录该限制。
