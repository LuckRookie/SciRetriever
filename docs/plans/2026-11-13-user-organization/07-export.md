# 07 · 分组与筛选的导出

类型：计划（结果块）
负责：文件夹树、成员与保存的筛选整体导出为 JSON
状态：Pending

## Outcome

- 一次操作把文件夹树、成员和保存的筛选导出为一份 JSON；成员写出 `LiteratureId` 与已有的稳定标识，便于在别的工具里对应（规格 9.6）。
- 导出不写库。批注仍按单篇导出（规格 5.6）。
- 入口、格式与规模处理按 01 的 1.4。

规格：[用户整理 9.6](../../architecture/technical/09-user-organization.md#96-分组与筛选的导出)，经 01 的 1.4 补齐。

## 进入条件

01 的 1.4 已写进规格；03 完成。7.6 要 G-lib。

## 责任边界

- 负责：后端实施者；若 1.4 规定 Web 有下载入口，7.5 由前端实施者完成。
- 拥有：导出的合同与实现（放在模块⑨的服务旁边）。
- 触达：CLI、MCP、HTTP 入口；文献的稳定标识只经文献模块的公开读取取得（规格 1.2），不直接查文献表。
- 不改：文件夹与保存筛选的读写；批注导出；书目导出。

## Tasks

- [ ] **7.1 合同**：按 1.4 写出导出的请求、JSON 结构与版本号、解析函数。
- [ ] **7.2 实现**：只读事务内读取文件夹、成员与保存的筛选，保证同一份导出内部一致；按 1.4 处理规模。
- [ ] **7.3 稳定标识**：按 1.4 的取法写出成员的标识；没有标识的成员按 1.4 处理。
- [ ] **7.4 三端入口**：按 1.4 的名称与设备用途。
- [ ] **7.5 Web 入口**（若 1.4 要求）：页面规格由总设计师先写，前端实施者实现。
- [ ] **7.6 正式库只读副本核对**（G-lib，可选）：在副本上导出一次，记录大小与耗时，抽查几篇成员的标识。

## 集成与影响

新增一个只读操作，是公开合同变化。

## 验证

新增 `apps/server/test/user-organization-export.test.ts`（合成库），证明：

- 导出的文件夹树、成员与保存筛选与合成数据一致；多归属的文献在每个文件夹里都出现；
- 成员的稳定标识按 1.4；没有标识的按 1.4；
- 导出前后 catalog 不变（含 `reading_history` 与操作记录）；
- 解析函数能读回导出的 JSON；
- 1.4 规定的规模处理（例如分页或写文件）在大合成库上成立；
- 三端结果相同；设备用途不足时被拒。

## 证据

提交号（G-commit 之后）；定向测试结果；7.6 的大小与耗时（G-lib 之后）。

## 退出条件

## 恢复与交接
