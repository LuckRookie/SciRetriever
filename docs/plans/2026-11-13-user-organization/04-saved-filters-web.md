# 04 · Web 的保存筛选与浏览器导入

类型：计划（结果块）
负责：文献库“筛选”菜单改用 catalog 中的保存筛选，以及浏览器里已有筛选的明确导入
状态：Pending

## Outcome

- 文献库的“筛选”菜单里，“应用已保存的筛选”“保存当前筛选”“删除当前筛选”都读写 catalog（03），换浏览器、清除站点数据后不丢失；在 CLI 或 MCP 里建的筛选在 Web 上也能看到。
- 浏览器里还有旧的保存筛选时，Web 按 1.2 给出“导入”入口；使用者点了才导入，导入后给出报告：导入几项、跳过几项及原因。
- 不自动搬迁，不读写其他浏览器或机器上的数据。

规格：[用户整理 9.1](../../architecture/technical/09-user-organization.md#91-保存的筛选进入文献库) 与[第 4 节](../../architecture/technical/09-user-organization.md#4-保存的筛选)（经 01 的 1.1、1.2 补齐）；排布见[页面规格“文献库”](../../architecture/web/page-specs.md#文献库)。

## 进入条件

- 03 完成；01 的 1.2 已写进规格。
- 4.3 起要 C3：计划 21 的 10.6 此时没有在改 `Library.tsx` 的筛选菜单。

## 责任边界

- 负责：页面规格由总设计师修改（4.1）；实现由前端实施者完成。
- 触达：`apps/web/src/app/features/library/Library.tsx`（`SavedView`、`loadViews` 与 `preferenceKey` 一段，以及“筛选”菜单）；`apps/web/src/app/data/` 中对应的读写；`apps/web/src/app/data/preferences.ts` 只在 1.2 要求清除旧数据时触达。
- 不改：文献库的虚拟列表与行渲染（计划 24 的不变量）；筛选条件本身的编辑界面；服务端。

## Tasks

- [ ] **4.1 页面规格**（总设计师）：按 1.2 在页面规格“文献库”一节写明导入入口的位置、提示与报告的样子；“筛选”菜单的四项不变。
- [ ] **4.2 数据层**：Web 用 03 的 HTTP 接口读写保存的筛选；类型来自 `packages/contracts`，不在 Web 复制。
- [ ] **4.3 菜单改用服务端**（C3）：应用、保存、删除走 4.2；失败时如实提示，不退回浏览器存储。
- [ ] **4.4 浏览器导入**：按 1.2 读出浏览器里的旧数据，逐项或整份判断，调用 03 的写操作，给出报告；按 1.2 处理导入后的旧数据与再次导入。
- [ ] **4.5 指南**：同步 [Web 指南](../../guides/web-workbench.md)中保存筛选的描述（实现合入后写）。

## 集成与影响

用户可见：保存的筛选不再只属于这台浏览器。第一次打开新版本时，浏览器里有旧数据的使用者会看到导入入口。

## 验证

- 扩展 `apps/web/test/next-library.test.ts`（或新增 `next-saved-filters.test.ts`），证明：
  - 菜单的应用、保存、删除调用服务端，刷新页面后仍在；
  - 服务端已有、由 CLI 建立的筛选出现在菜单里；
  - 浏览器里有旧数据时出现导入入口；导入后报告的计数与合成数据一致；重名、不合法、超长的项按 1.2 处理并列在报告里；
  - 再次导入按 1.2 的规则，不重复建立；
  - 没有旧数据时不出现导入入口；
  - 打开文献库、应用筛选不写库。
- `design-rules.test.ts`、`design-consistency.test.ts` 照常通过。
- 截图：筛选菜单与导入报告，放 `sandbox/reports/`。
