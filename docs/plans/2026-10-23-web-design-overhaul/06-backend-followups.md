# 06 · 后端遗留问题

## Outcome

上一计划移交的三项后端问题有结论：

1. 建档完成后更新检索索引，不再让其它写操作排队等待；
2. 总结在引用校验失败时，不会把已有内容大幅删减；
3. “在线找元数据 → 自动下载 PDF”用真实来源做过一次小样本验收，结果如实记录。

## 进入条件

01 完成。6.3 另需 G-real 授权。

## 责任边界

worker 执行；涉及语义或数据的取舍先交 Claude，Claude 拿不准的交 Owner。只在 worker 等待界面审阅的空档进行，不阻塞 03–05。

## Tasks

- [ ] **6.1 索引更新不阻塞写入**
  - 复现：在合成库上连续建档两篇，同时做文件夹或标签写入，记录写入的等待时间；找出全库同步重建发生的位置与持锁范围。
  - 改法方向：建档后只增量更新受影响文献的索引条目，或把重建移到后台、分批提交、每批之间让出写锁。索引落后期间，检索结果的口径要能说明（例如显示“索引更新中”）。
  - 验收：同一复现下写入等待降到 1 秒以内；增量更新后的检索结果与全量重建逐条一致（直接测试比较两者）。
- [ ] **6.2 总结在引用校验失败后被缩减**
  - 先调查，不先改：用 2026-10-23 真实闭环中光氧化论文那份总结的会话记录（只读）还原过程，说明七条缩成一条的具体环节：是校验把条目判为无效后删除、还是 DSH 收到失败反馈后自行重写。
  - 调查结论交 Claude。Claude 的方向是：引用不可用的条目保留，标记为“引用不可用”（沿用六种核对状态），不让校验失败导致内容消失；具体改法待调查结论确定。
  - 验收：合成用例覆盖“部分条目引用失败”，结果条目数不减少、失败条目有正确标记。
- [ ] **6.3 真实获取小样本验收**〔须 G-real〕
  - 授权后，在只读副本或独立 sandbox 库上，用真实来源对不超过 5 个 DOI 走一遍：在线找元数据 → 自动获取 PDF → 入库。不写正式库。
  - 记录每篇每一步的来源、结果、失败原因与耗时；不把运行条件就绪写成下载成功。
  - 发现的缺陷按 bug 修复并补回归；外部限制（付费墙、反爬）如实记录，不算作缺陷。

## 集成与影响

6.1 触达建档编排与检索索引；6.2 触达总结算子与核对；6.3 只读或独立库，不影响正式库。

## 验证

- 6.1、6.2 的直接测试与相关模块测试（并发按 HARNESS 5.4）；
- 6.3 的逐篇记录写进交接记录，原始日志放 `sandbox/reports/2026-10-23-plan14-acquisition/`。

## 退出条件

6.1、6.2 合并进主线并有直接测试；6.3 有真实结果记录（或在交接记录写明尚未获授权）。
