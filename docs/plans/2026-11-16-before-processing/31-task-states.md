# 31 · 任务：状态、名称与需处理

类型：计划（结果块）
负责：任务的状态用词与按钮、未启动与排队中的区分、任务名与进度、需处理的分组
状态：Not started

来源：2026-11-19 前端审查两轮（`sandbox/reports/2026-11-19-frontend-audit/REPORT.md`，示意图 `seven-decisions.html`）与 Owner 同日的决定：方案全部同意，第二轮审查后“按照你的建议就全做了”。

## Outcome

- 任务页分得清未启动、排队中、进行中、等你处理、已中断、失败；每种状态只出现它能用的按钮。
- 排队中的任务在服务重启后自动接着排。
- 任务名写出是哪篇文献。

规格：[页面规格](../../architecture/web/page-specs.md)“任务与 Agent 会话”的目标一段与“界面用词”，[任务协调](../../architecture/technical/02-task-coordination.md)。

## 进入条件

后端部分与前端部分可以分开做；前端在后端给出“是否请求过启动”之前，先把两者都显示为“排队中”以外的现状不变。

## 责任边界

- 后端实施者（经后端会话）：31.1、31.2。
- 前端实施者：31.3 到 31.6。
- 不改文献库结构：请求启动记在任务的活动记录里。

## Tasks

- [ ] **31.1 记下请求启动**：`start` 被接受时在该任务的活动记录里追加一条“请求启动”；任务列表与详情的读取结果带上“是否请求过启动”。
- [ ] **31.2 重启后续排**：服务启动时，把请求过启动、仍在排队、没有执行记录的任务重新放回等待队列；已中断的任务不自动继续。
- [ ] **31.3 状态与按钮**：状态徽标与按钮按规格；未启动不计用时。
- [ ] **31.4 任务名与进度**：任务名写出对象；只有一项的任务不画进度条；“发起方”全相同时不显示；时间按设计内核规则 6。
- [ ] **31.5 需处理**：分组标题写问题本身；每行一个主要动作，其余进菜单；行下说明改成人话。
- [ ] **31.6 取消已中断的任务**：后端修好“已中断的任务取消不生效”后，前端对冲突错误给出提示（后端会话负责后端部分）。
