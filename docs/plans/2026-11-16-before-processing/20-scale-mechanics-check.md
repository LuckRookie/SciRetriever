# 20 · 万篇机制验收

类型：计划（结果块）
负责：用合成数据与本机假来源，验证至少一万篇文献的收集机制并记录时长、吞吐、内存与磁盘
状态：In progress（20.1–20.7 完成，2026-11-17；20.8 完整规模待运行）

来源：原计划 23 的 04（任务 4.x 改为 20.x）。

## Outcome

- 一个可重复运行的机制检查：至少一万篇合成文献走过入库、重复收敛、按范围获取全文（本机假来源）、中断后继续、局部失败与库内查询。
- 计划 README 的不变量逐条有断言：已接纳的数据不丢失、中断后能继续、查询不触发扩充、临时错误不算试完、范围在提交时固定。
- 一份 JSON 报告记录收4 要求的数字：所用数据、各阶段时长、吞吐、内存、磁盘；外部调用花费为零（全部是假来源），报告写明这一点。
- 不联网，不读正式库，不需要授权；不进入普通的 `pnpm test` 与全量。

规格：[任务协调 9.4 万篇机制检查](../../architecture/technical/02-task-coordination.md#94-万篇机制检查目标尚未实现)（数据、假来源、入库、中断与故障、测量、不变量）；计数见[查询技术篇 2.1.8](../../architecture/technical/06-retrieval-context.md#218-文献库计数与全文取得情况)；获取流程见[文献与材料第 4 节](../../architecture/technical/03-literature-materials.md#45-获取流程)；批量运行、中断与恢复见[任务协调 5.1、5.2](../../architecture/technical/02-task-coordination.md#52-并发中断与恢复)；测量要求见 [tests/README](../../../tests/README.md)“测试时间限制”。

## 进入条件

规格已补齐。20.6 中关于 `full_text` 的断言需要 18；20.1–20.5 不等 18。

## 存放位置

- 测试放在 `apps/server/test/scale-collection.test.ts`，按仓库已有的做法用环境变量开启：`describe.runIf(!!process.env.SCIRETRIEVER_SCALE_RECORDS)`。同样的做法见 `browser-large-production-sample.test.ts` 的 `SCIRETRIEVER_BROWSER_513_MIB` 与各个 `SCIRETRIEVER_CLOAK_BUNDLE` 测试。没有设这个变量时，`pnpm test` 与全量把它报告为跳过，不运行。
- 篇数由环境变量给出（完整规模为 9.4 的 10,000 篇论文；小规模只用于先跑通）；报告目录由 `SCIRETRIEVER_SCALE_REPORT` 给出，默认在系统临时目录 `sciretriever-scale-*` 下。执行者运行时指到 `sandbox/reports/<日期>-scale-collection/`（Git 忽略）。
- 按 tests/README，这是“完整流程的正确性”加“明确的性能验收”：整体用 `timeout: 0`，只测 1.4 规定的操作，不把生成数据和启动服务计入；操作级的期限与取消照常验证。
- 合成数据在运行时生成，不把一万篇的数据提交进 `tests/fixtures/`；只有生成器（带固定随机种子）进 Git。
- 本机是多人共用的 8 核机器（HARNESS 第 6 节）：运行这一测试时不并行跑别的 Vitest，执行者在报告里写明当时的机器负载。

## Tasks

- [x] **20.1 生成器**：按 9.4“数据”用固定随机种子生成 10,000 篇论文：每五篇一篇另从第二个来源到达，每十篇一篇有两个版本，15% 没有 DOI；同时给出期望值（论文数、版本数、按来源的重复数），供断言使用。输出一份书目导入文件与一组假元数据来源的响应。
- [x] **20.2 假全文来源**：本机回环服务，按 9.4“假的全文来源”：60% 合格 PDF（大多 50–500 KB，约 1% 约 20 MB），30% 没有全文，10% 临时失败、其中一半重试成功；结果由种子决定，可复现。记录每个请求，供“查询不触发扩充”的断言使用。
- [x] **20.3 运行环境**：系统临时目录里的隔离 home 与 catalog；服务作为独立进程运行（要能在 20.5 终止它），用已构建的服务端（先 `pnpm build`）；来源配置只指向假来源；网络政策只允许回环。
- [x] **20.4 入库与去重**：按 9.4“入库”走两条途径：一次书目导入（导入会话），一次重放的发现（假元数据来源）。断言论文（MetaLiterature）与版本（Literature）数等于期望值；再导入一次，不新增文献。
- [x] **20.5 获取、中断与故障**：
  - 按范围提交获取（单个任务最多 10,000 篇；按版本超过时分批，每批是一个写明范围的任务）；
  - 进行到约 40% 时终止服务进程，再启动并继续；
  - 注入一次存储失败。做法限于测试一侧（例如在一段时间内让文件存储目录不可写）；若不改生产代码就做不到，停下交总设计师；
  - 断言：已接纳的记录与文件一个不少；继续时不重做已完成的工作；临时失败结束的篇目没有耗尽事实；第二次全库补全默认跳过已试完的篇目。
- [x] **20.6 库内读取**：结束时做三次读取并计时：计数（含 `full_text`）、列表第一页、一个筛选。断言运行前后的计数与期望值一致（`total = obtained + missing`，`exhausted` 等于全部途径都正常未命中的论文数）；断言整个读取期间假来源没有收到请求、没有新任务被创建。
- [x] **20.7 测量与报告**：按 9.4“测量”：每阶段从操作开始到给出报告的墙钟时间、吞吐（论文数 / 分钟）、服务进程常驻内存峰值、运行后 catalog 与已保存文件各自的字节数、三次读取的用时；外部花费记为零。报告是一份 JSON 加一页摘要。数字只记录，不设通过线。
- [ ] **20.8 运行并记录**（执行者）：在本机运行一次完整规模；把报告放 `sandbox/reports/`，把摘要数字与运行环境（机器、负载、Node 版本、提交号）记入本块“证据”。

- 断言覆盖 9.4“不变量”的每一条；报告字段覆盖 9.4“测量”的每一项。
- `pnpm quick`（测试的类型检查与格式）。

## 证据

- 2026-11-17，20.1–20.7 由后端实施者实现（`apps/server/test/scale-*.ts`，只加测试），总设计师审查后提交。500 篇小规模跑通：总 260 s；书目 2,557 篇/分钟；中途终止两个进程后恢复，已接纳的 137 份 PDF 保留，恢复后无重复请求；三次读取 29–100 ms；全部不变量通过，未发现产品缺陷（`sandbox/reports/2026-11-17-plan25-20/small-500/scale-report.json`）。没有设环境变量时规模测试跳过。

- 参考数字（2026-11-15，计划 20 的 14.6，合成数据）：一个 5,000 条书目的入库批次在后台约 187 s 入库完成，约 37 ms 一条。照此估计，一次三万多条的导入约 20 分钟。本块实测时与它对照；明显变慢时在报告里说明。
