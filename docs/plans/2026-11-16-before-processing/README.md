## 目标

Owner 2026-11-16：“先把阅读、用户体验、元数据下载、pdf导入、pdf下载等前置内容做好。”“把剩余没有做完的都塞进去。然后一个一个来做。”

本计划把计划 18–24 中还没有做完的部分收成一个计划，按一个顺序逐块完成：

1. **阅读与体验**（01–05）：阅读页的键鼠交互，第二次交付余下的右侧面板、书脊与目录、排版与标记，验收。

3. **入库**（12–13）：入库页与批次页；撤回一个批次。
4. **Zotero**（14–17）：探测、适配器、扩展导入、批注。
5. **全文取得与规模**（18–22）：全文取得情况的读取与显示；万篇机制验收；真实获取运行与后续。
6. **真实核对与收尾**（23–24）：只能在真实文件、正式库副本或 Owner 电脑上做的核对与试用；规格、指南、部署与全量。

**本计划不含任何知识加工的内容**（Owner 2026-11-16）。原计划 16 的全部、原计划 24 的第三次交付（13–18）、原计划 21 中只为加工服务的部分，已收进[知识加工提案](../../proposals/2026-11-16-knowledge-processing/README.md)。阅读页上依赖加工结果的视图、标记和入口，按规格“只显示能用的”处理：没有加工能力时不出现，本计划不实现它们。

## 不变量

所有块、所有运行都必须保持：

- **知识加工不在范围内**：不实现、不接入加工的读取、视图与入口；不改加工的执行器与结果。
- **不改变文献事实**：用户整理的写入只碰用户整理规格 1.1 列出的数据；文献状态缓存与已有结果的新旧状态不变。保存的筛选表不进入 `LIBRARY_STATE_INPUT_TABLES`。
- **入库只新增**：不删除文献，不替换已有主 PDF，不改动用户在文献库里的整理。唯一的例外是撤回：只能由网页登录的使用者发起，只移除这一批新增、之后没有被动过的内容（ADR 0063 第 9 节）。预览不写文献库。
- **入库不触发后续**：入库本身不触发获取全文、解析等会联网或花费的操作（需求规2）；认篇只用程序和文献信息来源，不调用模型。
- **服务端不连 Zotero** 或其他外部文献管理工具；适配器不联网、不写库；catalog 里没有来源专用的表。
- **已接纳的数据不丢失**：已接纳的书目、来源记录、PDF 与关系，不因中断、重复运行、局部失败或另一来源失败而被删除或替换；中断后从缺失的部分继续。
- **查询不触发扩充**：计数、筛选、读取、导出和任何只读操作都不联网、不调用模型、不创建任务，不写库。
- **临时错误不算试完**：网络、权限、配置、存储错误与使用者中断不产生自动获取耗尽事实。
- **批注**：旧锚点不被改写；对不上时如实标明，不放到别处；两种材料之间的比对规则与阈值（`mark-locate.ts`、用户整理规格 5.3）不变。
- **阅读页**：PDF 只有可见页及前后各一页持有画布和文字层，关闭时释放 worker、画布与对象 URL，`next-reader-boundaries.test.ts` 只能加强；`tokens.css` 现有令牌与主题不改值；文献库的虚拟列表不改；阅读页不发起任何付费操作；阅读位置在每一种版面变化中保持。
- **设备连接令牌**：服务端只存派生值，令牌只放在请求头里，不进日志、事件、报告或 Web 数据；不能登录 Web、不能读写配置与凭据、不能撤回批次。
- 三个入口（Web、CLI、MCP）用同一套合同，结果相同。
- 测试只用合成数据；不读取 Owner 的浏览器数据，不连接真实服务；真实运行只用 Owner 授权的来源与范围。
