# 10 · 阅读器里的重新定位

类型：计划（结果块）
负责：PDF 不同、文本版本不同时，阅读器按原文重新定位批注并按规格记录结果
状态：Completed（2026-11-17；见“证据”）

来源：原计划 22 的 06（任务 6.1–6.6 改为 10.1–10.6）。

## Outcome

- 一篇文献的 PDF 换了（sha256 不同）时，旧 PDF 上做的高亮按原文和前后文在当前 PDF 上重新查找，规则与相似度分档同规格 5.3；只在同一部分的 PDF 上找。对不上的沿用“仅 PDF”“仅全文”的标注，不放到别处。现在这些批注既不显示也不查找。
- 带旧文档版本锚点的批注，在当前版本上找到位置后在后台记下（08 的 `place`），下次打开直接使用，不再查找；没找到的同一次会话只查找一次。
- 框选在 PDF 不同时不放到当前 PDF 上，在批注栏里照常列出，标明属于原来那份文件。
- 初稿升级为校订稿时同样适用（规格 5.4，不另设规则）。
- 批注画成什么样、批注标签页里怎样标注，按阅读体验第 1.4、2.5 节，由 02、04 实现。

规格：[用户整理 9.4](../../architecture/technical/09-user-organization.md#94-材料换版本时重新定位并记录)（什么时候查找、只在同一部分里找、框选、记录），比对规则见 [5.3](../../architecture/technical/09-user-organization.md#53-两种材料之间对位)；[阅读体验](../../architecture/web/reading-experience.md)第 1.4、2.5、4.3、5.2 节。

- 触达（10.3 起）：`apps/web/src/reading/marks.ts`（`createPdfMarkSurface` 现在用 `onPage = m.pdf?.sha256 === sha256` 只画同一 sha256 的批注，`placeMissing` 只为没有 PDF 锚点的批注查找；全文一侧对旧版本锚点每次查找、从不保存）；`apps/web/src/app/features/reader/marks/`（调用 08 的记录操作）。
- 不改：`apps/web/src/reading/mark-locate.ts` 的比对规则与阈值；批注的画法与批注标签页的样子（02、03、04）。

## Tasks

- [x] **10.1 纯函数**：在新文件里写重新定位：输入一条批注与当前材料（PDF 各页文字层或文档区块），复用 `mark-locate.ts` 的 `canon`、`indexText`、`locate`、`PLACE`、`APPROXIMATE`，按 09 §9.4 只在同一部分里找，输出位置、相似度与档次（按位置、近似、对不上），以及方法版本 `mark-locate-v1`。不碰 DOM 以外的状态，不发请求。
- [x] **10.2 纯函数的测试**：见“验证”第一项。
- [x] **10.3 接入 PDF 一侧**：sha256 不同的高亮先读 `places` 里这份 PDF 的记录；没有记录才交给 10.1；找到的（相似度不低于 0.7）按档次显示并用 `place` 记下；对不上的照现有标注。框选不查找，在批注栏里标明属于原来那份文件。
- [x] **10.4 接入全文一侧**：旧版本锚点的批注同样先读记录、再查找、找到后记下。现有“只有 PDF 锚点的高亮补存全文锚点”的规则（5.3）不变。
- [x] **10.5 不推动正文**：记录结果后刷新批注列表时，阅读位置不变（阅读体验第 5.2 节）；不重建阅读器（阅读器常驻，计划 24 的 03）。
- [x] **10.6 性能**：长文档上按页面绘制时逐页查找，不在打开时整篇比对；已记录的位置不再查找；同一会话里没找到的不重复查找。

## 集成与影响

用户可见：换过 PDF 或文本出了新版本的文献，旧批注重新出现在对得上的地方；对不上的如实标明。打开次数多的文献不再每次重新查找。

## 验证

- 新增 `apps/web/test/mark-relocate.test.ts`（纯函数，合成文字），证明：
  - 另一版 PDF 的文字层与原文一致：按位置；有小改动：近似；删去了这段：对不上；
  - 前后文能区分同一句话的两次出现；
  - 只在同一部分里找：主 PDF 的批注不在补充材料上找；
  - 框选不查找；
  - 旧文档版本与新版本、初稿与校订稿两种情形。
- 扩展 `apps/web/test/next-reader-marks.test.ts`（10.3 起）：
  - sha256 不同的批注被重新定位并显示，原锚点不变；
  - 找到的位置记录一次，第二次打开不再查找（计数断言）；方法版本改变后重新查找并覆盖；
  - 对不上的不画在页面上，标注沿用“仅 PDF”“仅全文”；框选在另一版 PDF 上不画、批注栏标明属于原文件；只在同一部分的 PDF 上查找；
  - 记录结果后阅读位置不变；
  - 现有断言不变。
- `next-reader-boundaries.test.ts` 照常通过（PDF 的画布与文字层上限不变）。

## 证据

- 2026-11-17，前端实施者实现，总设计师审查后提交。审查退回两处：认不出批注属于哪一部分时不查找、不画（不再“按主 PDF 推断”）；旧文档版本的归属用 `document describe` 返回的 `source_material_ref` 认出（按版本去重、会话内缓存），初稿升级为校订稿后初稿上的批注照常重新定位。
- 复跑中 `next-reader-marks` 不稳定，查出一个产品缺陷并修好：批注的创建与笔记修改同时发出、创建的回复晚到时会盖掉笔记，页边批注读到已不存在的批注报 TypeError，阅读视图崩溃。现在同一篇文献的批注写入按顺序排队，每条批注只采用最后一条命令的回复，`place` 只合并 places；`MarginNotes` 跳过已不存在的批注。新增的测试让这个竞争每次发生，修改前失败（`sandbox/reports/2026-11-17-plan25-10/FIX.md`）。
- 总设计师复跑：`pnpm quick` 通过；`next-reader-marks` 单独连跑 3 次全过；`mark-relocate`、`next-reader`、`next-reader-layout`、`next-reader-boundaries`、`next-reader-input` 45 项通过、4 项跳过。全文一侧只有纯函数测试（测试资料只有一个文本版本）。

## 退出条件

两种材料变化下批注都能重新定位并按规格记录；02 的批注标签页沿用现有标注即可，另需显示“属于原来那份文件”的框选。
