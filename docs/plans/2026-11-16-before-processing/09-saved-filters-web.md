# 09 · Web 的保存筛选与浏览器导入

类型：计划（结果块）
负责：文献库“筛选”菜单改用 catalog 中的保存筛选，以及浏览器里已有筛选的明确导入
状态：Pending

来源：原计划 22 的 04（任务 4.1–4.5 改为 9.1–9.5）。

## Outcome

- 文献库的“筛选”菜单里，应用、保存、用当前条件更新、删除都读写 catalog（07），换浏览器、清除站点数据后不丢失；在 CLI 或 MCP 里建的筛选在 Web 上也能看到。条件里的文件夹已被删除的项注明“文件夹已删除”。
- 浏览器里还有未导入的旧筛选时，菜单末尾显示“导入这个浏览器里保存的筛选（n 项）”；使用者点了才导入，导入后用对话框列出导入、改名、跳过与未导入的项及原因。
- 不自动搬迁，不读写其他浏览器或机器上的数据。

规格：[用户整理 9.1](../../architecture/technical/09-user-organization.md#91-保存的筛选进入文献库) 与[第 4 节](../../architecture/technical/09-user-organization.md#4-保存的筛选)（“浏览器中已有筛选的导入”）；菜单项与对话框见[页面规格“文献库”](../../architecture/web/page-specs.md#文献库)的“筛选”菜单一条。

## 集成与影响

用户可见：保存的筛选不再只属于这台浏览器。第一次打开新版本时，浏览器里有旧数据的使用者会看到导入入口。

## 验证

- 扩展 `apps/web/test/next-library.test.ts`（或新增 `next-saved-filters.test.ts`），证明：
  - 菜单的应用、保存、删除调用服务端，刷新页面后仍在；
  - 服务端已有、由 CLI 建立的筛选出现在菜单里；
  - 浏览器里有未导入的旧数据时出现入口，项数正确；导入后对话框的计数与合成数据一致；不合格的项列出原因、不影响其余项；
  - 导入后入口消失；旧数据仍在且标为已导入；再次导入不新建；
  - 没有旧数据时不出现导入入口；
  - 打开文献库、应用筛选不写库。
- `design-rules.test.ts`、`design-consistency.test.ts` 照常通过。
