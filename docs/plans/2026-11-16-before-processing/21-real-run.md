# 21 · 真实获取运行

类型：计划（结果块）
负责：经 Owner 逐项授权，在Owner 选定的范围和来源上获取全文，并测量覆盖、失败、吞吐与试完篇数
状态：Pending

来源：原计划 23 的 05（任务 5.x 改为 21.x）。

## Outcome

- 至少一次真实运行：在 Owner 选定的范围上，用 Owner 允许的来源获取全文。
- 一份运行报告交 Owner，回答：
  - 覆盖：按途径（来源与层级）、按出版社，各取得多少、没取得多少；
  - 失败分类：无全文权限、正常未命中、限流、临时网络错误、配置缺失、浏览器受阻等各多少；
  - 吞吐：每篇用时的中位数与 P90、论文数 / 分钟（与 20 同一单位）；
  - 试完：多少篇进入“已试完自动途径”，其中是否有临时错误被误记（不变量）；
  - 运行前后全文取得情况（`full_text`，18）的变化。
- 报告只给数字，供 Owner 决定；不设覆盖率或吞吐的通过线。硬性条件只有计划 README 的不变量。

规格：获取流程见[文献与材料第 4 节](../../architecture/technical/03-literature-materials.md#45-获取流程)；任务的逐篇轨迹与渠道统计见 [PDF 获取指南](../../guides/pdf-acquisition.md)与[页面规格“获取任务详情”](../../architecture/web/page-specs.md#获取任务详情)；来源统计见[页面规格“来源统计”](../../architecture/web/page-specs.md#来源统计)。

## 进入条件

- 20 完成，全部不变量通过。
- 18 完成（运行前后读 `full_text`）；18 与它依赖的版本已部署到要运行的服务上（G-deploy），或运行用的是本机构建。
- G-lib（21.1、21.2）；G-target、G-sources、G-window（21.4 起）；用到浏览器途径时 G-browser。

## 责任边界

- 负责：执行者运行与记录；总设计师写报告结论。Owner 选范围、配置来源与凭据、授权各项 Gate。
- 只经正式入口（Web、CLI、MCP）发起与读取；评估脚本只读副本或只读打开正式库，不写库。
- 不改：代码、配置、凭据。执行者不读取 Owner 的 `config.toml`、密钥、令牌或 Cookie。
- 不做：在运行中途调整来源顺序、重试策略或范围；需要调整时停下，写进报告。

## Tasks

- [ ] **21.1 基线**（G-lib）：只读读出正式库当前的全文取得情况（`literature counts` 的 `full_text`）与来源统计（近 30 天、全部），记入报告。
- [ ] **21.2 评估脚本**（G-lib）：在 `sandbox/cases/<日期>-scale-collection/` 写只读脚本，从副本或只读连接读取任务的逐篇轨迹（`acquisition_traces`）与文献的出版社、DOI 前缀，按途径与出版社汇总。出版社按书目的出版社字段，缺失时按 DOI 前缀，规则写在报告里。脚本先在 20 的合成库上核对一次，汇总与 20 的报告一致。
- [ ] **21.3 运行单**：执行者写一页运行单交 Owner：范围（一个筛选、入库批次或文件夹，写出篇数与预览计数）、写入目标（正式库或副本，G-target）、允许的来源（G-sources）、是否用浏览器与是否有人协助（G-browser）、时间窗、每批篇数与速率、是否人为中断一次以验证继续（G-window）。Owner 确认后，原话记入本块。
- [ ] **21.4 运行**：按运行单分批提交获取（单个任务最多 10,000 篇）。运行中只看任务详情与来源统计，不改设置。遇到限流或封禁迹象时按运行单的规定暂停，并告知 Owner。
- [ ] **21.5 中断与继续**（若运行单允许）：在一批中途取消一次，再次发起，核对只处理缺失的部分、已取得的不丢失。
- [ ] **21.6 核对不变量**：运行后用 21.2 的脚本核对：没有已接纳的 PDF 或关系丢失；以临时错误、配置或取消结束的篇目没有耗尽事实；运行期间的查询没有创建任务。
- [ ] **21.7 报告**：数字、方法、运行单、异常与观察；放 `sandbox/reports/<日期>-scale-collection/`，摘要写进本块与计划 README 的进度。交 Owner，并交 22。

## 记录什么、放在哪里

- 运行材料：`sandbox/runs/<日期>-scale-collection/`（运行单、命令、任务编号、脚本输出）；报告：`sandbox/reports/<日期>-scale-collection/`。两者都在 Git 忽略的 `sandbox/` 里，不提交。
- 计划只记录脱敏的摘要数字、任务编号与报告位置；不记录全文、凭据、Cookie、签名 URL 或个人信息。
- 副本在运行结束、报告交出后由 Owner 决定保留或删除。

## 验证

- 报告的每个数字能从运行材料复算（脚本可重跑）。
- 21.6 的不变量核对逐条有结果。
- 结束后核对：正式库只在 G-target 允许时被写入；被写入时，写入只有获取产生的 PDF、资产关系、耗尽事实与任务记录。

## 证据

各 Gate 的授权记录（日期、内容、Owner 原话）；运行单；任务编号；报告位置与摘要数字；实际用时与外部调用（出版社接口的请求数，如有花费另记）。

## 退出条件

报告交给 Owner 与 22。Owner 决定不做真实运行时，记下依据，本块标为 Cancelled，计划仍可收尾。

## 恢复与交接

- 运行中断：已提交的结果保留；按运行单再次发起，从缺失的部分继续（收4）。
- 出现不变量被违反的迹象（例如 PDF 丢失、临时错误被记成试完）：立即停止全部运行，保留现场，交总设计师；不在正式库上重试。
- 出现限流或封禁：停止该来源的运行，告知 Owner，由 Owner 决定是否继续。
