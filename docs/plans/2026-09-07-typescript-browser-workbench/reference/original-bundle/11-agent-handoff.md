# 11｜交给实施 Agent / 开发者的工作指令

## 1. 任务授权边界

本交付是执行计划，不是已经授权对真实库升级、发布或访问出版社。实际实施需基于当前仓库确认工作范围。尊重现有AGENTS/HARNESS、用户未提交改动与secret边界；未经明确授权不commit/push/PR，不迁移真实Catalog，不重启用户生产浏览器。[R02](10-sources.md#r02)[R03](10-sources.md#r03)

## 2. 开始实施时

读取 `AGENTS.md`、`HARNESS.md`、本计划00/01/02/07、相关ADR和模块代码。检查Git状态与当前提交。若已不在e1a33d5，比较变更并更新证据/任务落点，不能覆写新实现，也不能把旧审查结论当最新事实。

运行T001–T008，先生成：实际活动文件/测试/Provider/CLI清单、完整迁移映射、受支持基线goldens、关键依赖spike结果。测试只用合成数据与本地fixture，不读取用户文献和密钥。

一轮选择一个具备全部前置条件的任务或同一能力切片。`tasks.json`的依赖是执行约束，不是建议顺序；任务ID稳定，新增任务不得覆盖原ID。修改依赖需重新检查无环及阶段gate。

## 3. 单任务交付格式

```text
Task: Txxx
Baseline: <当前 commit 与工作树说明>
Scope: <对应source/target与合同>
Changes: <实际完成的行为，不列空泛重构>
Validation: <实际命令、结果、fixture或报告路径>
Compatibility: <数据、CLI、配置、网络与Profile影响>
Remaining: <未完成内容与原因；没有则明确none>
Status: done / blocked / in-progress
```

`done`要求产物、直接测试、生产组装和必要文档同步。任务状态不从模型叙述自动推进；必须附证据。不能因为文档写了接口就把实现任务标完成。

## 4. 不得采用的捷径

不能让TS调用Python后端后宣称全TS；不能两个运行时同时写真实Catalog/Profile；不能删有效测试或略过source adapter来减少迁移范围；不能用空PDF+URL就证明文件归属；不能将未知访问错误归为未订阅；不能强制人工接管弥补Agent缺动作。

不能对所有导航fetch/fulfill以修复捕获；不能删除CONNECT/SSRF边界后把网站可达当完成；不能对login/验证码写无限重试或伪造结果；不能在网页提示影响下扩大授权；不能把任何上述未知结果记录为成功。

不能自动改schema版本、重建用户库、重算旧哈希或覆盖资产；不能将路径字符串检查描述为等价于descriptor-relative保护；不能在普通应用启动时安装未批准系统软件或静默下载漂移binary。

## 5. 阶段完成与质量门禁

M0结束后发布架构决策与风险结果，不急于写全部模块。M1以v1数据兼容为准；M2以真实浏览器fixture的人机工作区为准；M3以自动获取和不误报成功为准；M4以全部现有业务能力迁完为准；M5以崩溃恢复和v2升级演练为准；M6才执行完整发布切换。

保留旧Python离线oracle直到相关模块的行为差分和intentional-change ledger都关闭。最后一次清理必须检查源码、测试、入口、依赖、安装包、文档示例、生成缓存，确保没有残留生产Python后门。

真实站点测试另行取得明确授权，固定目标清单、速率、出口、Profile与观察记录；不把它偷偷塞进Full或配置status。

## 6. 工作量失控时

收缩一次任务的实现范围，而不是降低最终数据与安全要求。先完成本地受控的端到端切片，再增加Provider和复杂呈现。遇到平台原语缺口先出spike和ADR，不建立无人维护的兼容后门。每个阻塞给出具体证据、影响阶段与下一验证项。
