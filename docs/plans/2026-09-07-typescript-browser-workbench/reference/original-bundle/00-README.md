## 1. 最终产品定义

> SciRetriever 是部署在用户实际具有访问条件的机器上的文献获取与文献数据库维护服务。用户通过一个端口提交任务、设置策略、观看 AI 操作，并可随时接管同一浏览器。AI 在预先授权的资源和预算内自主操作；无法取得的文献按策略跳过，不把人工介入当作正常运行的前提。

目标是减少重复劳动，不是保证任何网站都放行。更换语言、浏览器后端或投屏方式，都不构成提高网站放行率的保证。原有文献发现、引用、导入导出、内容解析与分析能力不能因聚焦浏览器而静默丢失。

## 2. 本计划建议定案的选择

| 选择 | 建议 |
|---|---|
| 应用语言 | 全量 TypeScript；Python 只在迁移期作为离线行为基线，不进入最终运行依赖 |
| 产品组织 | 模块化单体；一个用户入口，不引入 Redis、独立数据库服务或多 Agent 框架作为前提 |
| 执行环境 | Node.js 24 LTS 系列作为验证基线；具体补丁版本在 M0 固定，不能混用浮动版本 |
| 浏览器 | TS 运行时唯一持有 Playwright/CloakBrowser 对象；支持经验证的浏览器后端，但不自动变更浏览器身份 |
| 实时工作台 | 页面级 screencast + WebSocket + 内置网页；noVNC 不是必装组件 |
| 数据 | 保留 SQLite Catalog + 不可变 ArtifactStore；先证明 v1 兼容，再独立升级为支持运行任务的 v2 |
| 决策 | 用户定义授权与偏好，AI 选择操作和处置；程序执行硬约束、控制权和文件验收 |
| 人工 | 默认可旁观；是否请求人工由策略决定；支持完全无人打扰模式 |
| 网络 | 保留 SSRF、DNS/IP、凭据作用域等边界；普通导航不再默认走全量 `route.fetch/fulfill` |
| 迁移策略 | 逐能力切片替换，最终清除 Python；不长期维护双实现，不让新旧程序同时写生产库 |

Node 的支持状态、投屏接口和驱动选择已经对照当前官方文档核查，但本机二进制组合仍须实测。[W01](10-sources.md#w01)[W02](10-sources.md#w02)[W03](10-sources.md#w03)

## 4. 阶段与第一项可交付成果

```text
M0  冻结基线、确认新合同、验证高风险依赖
 │
M1  TS 骨架、领域合同、SQLite v1 与文件兼容
 ├──────────────┐
M2  可旁观可接管的浏览器工作区       M4  其余业务模块迁移
 │                              │
M3  策略 + Agent + PDF 获取闭环 ────┘
 │
M5  v2 持久任务、恢复、单一服务入口
 │
M6  全流程验收、打包、切换与清除 Python
```

**首个浏览器里程碑不是“多下载几家出版社”，而是：** 一个端口中可看到同一真实浏览器；手动与 AI 不会争抢控制；受控测试页产生的 PDF 能保存并交接；断开工作台不取消任务；普通导航保持原生请求路径。这个闭环通过后再扩大真实站点样本。

**首个存储里程碑是：** TS 能打开冻结的 v1 测试库，并产生与 Python 相同的 ID、元数据/内容哈希、查询结果和资产引用。不能用“新建库能插入数据”代替兼容验收。

## 5. 五项阻断全量切换的问题

1. 没有可复现的 TS/CloakBrowser/Chromium/投屏兼容矩阵。
2. 数据库 schema 指纹、canonical JSON、Unicode 身份归一或文件哈希不等价。
3. 现有文件路径与锁安全保证在目标平台上没有等价实现，也没有明确调整合同。
4. 控制权切换后旧动作仍可能执行，或已保存候选在交接前被删除。
5. 仅有 mock 测试，没有真实 Chromium 的离线下载 fixture 与安装后验收。

## 6. 如何使用这份计划

将文档放入建议目录 `docs/plans/2026-09-07-typescript-browser-workbench/`，作为活动计划；这个目录目前只是建议。先用 M0 的 ADR 任务把已确定的新选择转入 requirements / architecture，再修改实现。不要直接把本计划标成 Accepted，也不要把尚未实现的 `serve`、`jobs`、迁移命令写成已有 CLI。[R02](10-sources.md#r02)[R03](10-sources.md#r03)

交付时以阶段证据为准，不以任务打勾数量替代完成。执行中的新发现写入决策记录；修改影响数据、安全或公开合同的选择时，按仓库既有授权流程处理。
