# 06 · Skill 与给 Agent 的说明

类型：计划（结果块）
负责：ADR 0058 第 7 节，按 ADR 0063 第 6 节收窄：skill 只讲怎样使用这组入库接口与 HTTP 版 MCP
状态：In progress（2026-11-11：通用部分完成，6.7 试跑通过；2026-11-14 按 ADR 0063 改写，6.9 起未开工）
ADR 0063 之后：人的导入不再经过 Agent（ADR 0063 第 6 节）；Zotero 由扩展读取（19）。skill 只讲怎样用这组入库接口与 HTTP 版 MCP，不再讲各来源的取数办法。上传脚本不再是人的主路，留作 Agent 的辅助，照 6.10 修好并补测试。6.1–6.8 是按 ADR 0058 完成的历史记录，保留不动。

## Outcome

- 仓库里有文献库自带的 skill：一组 Markdown 文件，随服务构建打包，经 02 的路由下载。
- skill 讲三件事：
  - 连接；
  - 经入库接口代使用者入库（需求收3）：哪一步要先问使用者，只入库使用者指定的范围；
  - 经 HTTP 版 MCP 使用文献库，以及失败与恢复。
- skill 不抄接口细节，只指向文献库自己提供的接口说明（12.11 定下的入口）。
- 设置页“连接 Agent”里那段可以直接复制给 Agent 的话，按 14 的合同更新。
- 一个全新的 Agent 只凭这段话和 skill，能对合成的文献库完成一次入库。

## Tasks

- [x] **6.1 位置与打包**：skill 源文件放在仓库根下新的 `skills/sciretriever/`；构建时打包成 02 的下载路由读取的产物；目录说明写进 README 与设计文档。
- [x] **6.2 连接**：用连接码换令牌；令牌直接写进只有本人可读的文件，不进对话、不打印；连不上时检查地址与端口映射。
- [x] **6.3 导入**：
  - 会话的步骤，按 03 的 `curl` 脚本整理；
  - 哪一步要先问用户：范围不明确时，以及用户要求把关时的确认；
  - 只导入用户指定的范围；
  - 文件多时用循环批量上传，中断后按服务端的缺失清单继续。
- [ ] **6.4 Zotero 的取数办法**：Superseded。ADR 0063 第 6 节把 Zotero 导入交给扩展（19.4），skill 不再写这一项。
- [x] **6.5 使用文献库**：怎样配置 HTTP 版 MCP（依据 07 的合同），以及常用的工作流程。
- [x] **6.6 失败与恢复**：重新读取当前状态再继续，不凭旧结果行动；各错误码该怎么办。
- [x] **6.7 试跑**：起一个全新的 Agent 会话（子代理），只给“复制给 Agent 的话”，让它对假的 Zotero 服务和测试用的文献库完成一次导入。记录它卡住和做错的地方，改 skill，直到一次通过。
- [x] **6.8 指南**：Agent 接口指南写设备连接、skill 与导入的入口。
- [ ] **6.9 按入库接口改写（等 14）**
  - 动作：`connect.md`、`import.md`、`use.md`、`recovery.md` 改用 14 的名称、用途“入库”与后台确认；`SKILL.md` 的说明改为“代使用者入库、使用文献库”。不出现“导入会话”。
  - 验收：skill 里的每条命令都对测试服务实际执行过；没有与接口说明重复的字段细节。
- [ ] **6.10 上传脚本：修好并补测试（D-06 已定）**
  - 审查 M2 指出：`scripts/upload_files.py` 遇到第一个错误就整体退出，重跑会卡在同一个文件；只凭文件名的兜底匹配可能上传错误的 PDF，而错误的主 PDF 以后不能替换。两种做法：
    - **甲 · 修好并补测试**：遇到单个文件的错误时，记下并继续；最后汇总列出失败的文件与原因；去掉只凭文件名的兜底，或者只在文件名唯一且大小一致时采用；处理 408、429 时按服务端的提示重试；在 `skills/sciretriever/scripts/` 旁加测试，用假服务端覆盖：单个文件失败、同名文件、中断后重跑、令牌被撤销。
    - **乙 · 删除**：从 skill 包里移除脚本，在 `import.md` 里写一个逐个上传的最小循环，并写明遇到错误时怎样跳过。人的批量上传交给网页与扩展（ADR 0063 第 6 节）。
  - **总设计师 2026-11-14 决定选甲。** 理由：Agent 是服务对象之一，成批上传是确定的活，应当由一个经过测试的程序完成，不让 Agent 临场循环；文件名的兜底只在文件名唯一且大小一致时采用，否则跳过并列入汇总。
  - 验收：测试通过，脚本在审查 M2 的情形下都不卡住，也不会传错文件。
- [ ] **6.11 删去或改写 `source-zotero.md`（审查 M4）**
  - 动作：改为一句话，说明 Zotero 用扩展导入，并指向扩展指南；删去“再导一次时……不会重复入库”这一与实际不符的说法（审查 M4，正确的规则见 16）。
  - 验收：skill 里没有关于 Zotero 接口的取数办法，也没有关于重复的错误承诺。
- [ ] **6.12 重新试跑**
  - 动作：照 6.7，起一个全新的 Agent，只给“复制给 Agent 的话”，对合成的文献库完成一次入库，包括后台确认与交文件；再用 HTTP 版 MCP 查一篇文献。

  - 验收：一次通过；令牌没有出现在输出里。
