# 03 · Zotero PDF 导入（后端）

类型：计划（结果块）
负责：ADR 0057 第 1 节的取 PDF 与第 3 节的 PDF 规则
状态：Pending（等 02 的 2.1）

## Outcome

- 导入任务在书目入库后补 PDF，三条通道：
  - 同机：按本地 API 给出的本机路径直接读文件，存储的和链接的附件都可以；
  - Zotero 官方存储：经网络 API 下载；
  - 网页上传：服务端列出还缺主 PDF 的附件编号，网页按 `storage/<附件编号>/` 上传对应文件。
- 取 Zotero 的首选附件作为主 PDF；同一条目的其他 PDF 只计数。
- 已有主 PDF 不替换，文件不同记为冲突；新 PDF 标为“文章身份未验证”。
- 同机时 CLI 可以用 `--storage-dir` 给出 `storage` 目录，代替网页上传。

## 进入条件

02 的 2.1 合同；01 关于附件与文件下载的结论。

## 责任边界

Codex：`apps/server`、`packages/contracts` 及测试，技术文档 01、03 的相应部分。

## Tasks

- [ ] **3.1 合同**：“待上传附件”清单与单文件上传接口（按附件编号、大小上限、按文件续传）；PDF 通道与结果写进报告；回执 `contract.md` 补充，供 04 接上传。
- [ ] **3.2 本机路径**：读取本地 API 给出的路径；catalog 不保存绝对路径（技术文档 07）；路径不存在记入报告。
- [ ] **3.3 Zotero 存储下载**：仅对存在 Zotero 官方存储的附件下载；其余转为“待上传”。
- [ ] **3.4 网页上传**：校验附件编号属于本次导入、文件按 ADR 0029 验收，走现有 Candidate → publication → primary-pdf 路径。
- [ ] **3.5 首选附件与冲突**：按 `links.attachment` 选主 PDF；已有主 PDF 时比较 sha256，不同就记冲突。
- [ ] **3.6 报告与预览**：预览里的 PDF 数改为实际可带入数，按通道分列；报告列出缺失、冲突与跳过的原因。

## 验证

直接测试：三条通道、链接附件路径缺失、非 PDF 与损坏文件被拒、重复上传幂等、中断后只传剩下的、已有主 PDF 不替换、附件编号不属于本次导入时拒绝。

## 退出条件

回执给出提交与合同补充；04 可以接上传；07 可以依赖“主 PDF 与 Zotero 附件的对应”。

## 恢复与交接

单个文件失败不影响整批；报告列出失败的附件，用户可以重试上传或改用“获取 PDF”。
