# 17 · 撤回

类型：计划（结果块）
负责：ADR 0063 第 9 节：撤回一个入库批次
状态：Pending

## Outcome

- 网页登录的使用者可以撤回一个批次。撤回只移除这一批新增的、之后没有被动过的内容：文献、文件、分组、批注。
- 入库之前已经在库的、之后被其他批次命中的、之后被使用者整理、批注或加工过的内容都不移除，并在撤回报告里列出。
- 撤回之前写明将移除多少、保留多少。
- 撤回之后，这些文献不再出现在文献库、查询与加工的范围里。
- 凭令牌不能撤回。

## 进入条件

- 14 完成。
- 17.1 不等规格，14 完成即可开始；它的结论是 12.20 的输入。
- 17.2 起等 12.20、12.23。

## 责任边界

- 负责：后端实施者。
- 拥有：撤回服务（新文件）；撤回的预估与执行接口；本块的表结构。
- 触达：存储中的文献、资产、文件夹、批注、外部编号对应、检索索引与加工范围的读取；文件回收（`apps/server/src/storage/files/reclamation.ts` 一类）。
- 不改：网页（18 的撤回界面随本块）；其他批次的数据。

## Tasks

- [ ] **17.1 查清存储能否干净地撤回（ADR 0063“还没有验证的前提”第 4 条）**
  - 动作：
    - 列出一个入库批次写入的全部表与文件：文献、MetaLiterature、来源记录、身份合并、资产与内容寻址的文件、文件夹与成员、批注、外部编号对应、批次成员、检索索引、状态投影；
    - 逐项判断能否移除而不影响其他数据，以及“之后被动过”能否从现有数据里判断出来；
    - 用合成库实际演练一遍，不写进代码库。
  - 输出：一份核查结论，写进本块，交总设计师作为 12.20 的输入。
  - 验收：
    - 每一项都有“能干净移除”“只能标记”或“做不到”的结论，并附依据（表、外键、引用计数）；
    - **有任何一项做不到时，停在这里，交总设计师**，不开始 17.2。
- [ ] **17.2 表结构：撤回记录（改表，等 12.20、12.23）**
  - 动作：按 12.23 写出 DDL，并入 `IMPORT_SCHEMA_V16` 与迁移测试。
  - 验收：迁移测试通过。
  - 本 Task 必须在 16 冻结之前合入（见计划 README 的 C-schema）。
- [ ] **17.3 撤回之前的预估（等 12.20）**
  - 动作：给出将移除与将保留的内容，各自的数量与原因；预估不写库。
  - 验收：合成批次中包含以下几类内容，预估数字正确，前后库内容逐行不变：
    - 新增后未动过；
    - 之后被另一个批次命中；
    - 之后加进了文件夹；
    - 之后加了批注；
    - 之后被解析过；
    - 入库前已在库。
- [ ] **17.4 撤回执行与报告（等 12.20）**
  - 动作：按 12.20 移除或标记；批次状态改为“已撤回”；报告列出保留的内容及原因；共享的文件按 12.20 处理。
  - 验收：
    - 撤回后，被移除的文献不出现在文献库列表、查询、检索与加工范围中；
    - 保留的内容不受影响；
    - 中途失败时库保持撤回前的状态，或者能够继续完成（按 12.20）；
    - 撤回后再入库同一份数据，能正常入库。
- [ ] **17.5 只有网页登录的使用者能撤回**
  - 动作：撤回接口不登记任何设备用途；HTTP 版 MCP 不提供撤回工具。
  - 验收：任何用途的令牌调用撤回都被拒绝；MCP 的工具列表里没有撤回。

## 集成与影响

- 入库不再只新增：撤回是唯一的例外，只能由网页登录的使用者发起（计划 README 的不变量）。
- 查询、检索与加工的范围排除被撤回的内容。

## 验证

- 定向测试：新增的撤回测试，以及 `import-sessions.test.ts`、`import-schema-migration.test.ts`。
- 失败注入：撤回中途进程退出。
- `pnpm quick`。
