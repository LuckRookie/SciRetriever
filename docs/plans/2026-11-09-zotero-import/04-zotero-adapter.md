# 04 · Zotero 适配器

类型：计划（结果块）
负责：ADR 0063 第 5、6 节中的 Zotero 适配器，以及 ADR 0057 第 3 节中书目、标签与首选附件的规则
状态：Pending（等 01、14、12.21）
ADR 0063 之后：数据由扩展读取 Zotero 本地接口后交来（19.4），不再假定由 Agent 交来。适配器本身不变：不联网、不写库，本地接口与网络 API 交来的数据走同一段代码。

## Outcome

- 适配器把 Zotero 接口返回的 JSON 转成条目。本地接口与网络 API 的数据走同一段代码。
- 书目、标识、分组、标签与首选附件都能转换；不导入的内容（笔记、非 PDF 附件、链接附件等）按种类计数。
- 没有父条目的独立 PDF 转成只有文件的条目（ADR 0063 第 2 节取代 ADR 0057 第 3 节的“不导入”），交给 15 认篇。
- 批注在本块只计数，10 再导入。

## 进入条件

- 01 的结论与合成样本。
- 14 完成，即统一的批次与条目合同。
- 12.21 的回答（Zotero 条目到条目的映射规则，原来本块的 4.1）。
- 独立 PDF 的部分还要等 15.2。

## 责任边界

- 负责：后端实施者。
- 拥有：`apps/server/src/literature/import-adapters.ts` 中的 Zotero 适配器、`packages/contracts` 中对应的格式名，以及测试。
- 不改：`apps/web/`、扩展（19）、skill、指南。映射规则写在规格里（12.21），本块不另写规格。

## Tasks

- [ ] **4.1 规格**：改为等 12.21，由总设计师写进技术文档 03。本 Task 只核对规格能否按 01 的样本实现；不能实现的地方交总设计师。
- [ ] **4.2 书目与标识**：数据里带 Zotero 转换出的 CSL JSON 时，经现有的 CSL JSON 规则落库；没有时按 Zotero 字段映射；解析 Extra 字段里的 DOI、arXiv 号与 PMID。
- [ ] **4.3 分组与标签**：分类转成带层级和外部编号的分组；自动标签转成作者关键词，手动标签转成用户标签。
- [ ] **4.4 文件**：
  - 首选附件：条目带 `links.attachment` 时用它，没有时按 12.21 选取；
  - 引用名用附件编号，带上文件名与 Zotero 给出的 md5；
  - 同一条目的其他 PDF 只计数。
- [ ] **4.5 独立 PDF 与不导入的内容**：
  - 独立 PDF 转成只有文件的条目（等 15.2）；
  - 笔记、非 PDF 附件、链接附件、回收站里的条目，按种类计数，进入预览与报告。
- [ ] **4.6 样本**：把 01 的合成样本移进测试 fixture。

## 验证

- 直接测试（01 的合成样本），覆盖以下情形：
  - 没有 DOI 的条目；
  - Extra 字段里的 arXiv 号；
  - 多个 PDF、链接附件；
  - 独立 PDF；
  - 群组库；
  - 多级分类与多处归属；
  - 两种标签。
- 本地接口样本与网络 API 样本转换结果一致。
- 定向测试与 `pnpm quick`。

## 退出条件

合成的 Zotero 数据能经 14 的入库接口完整入库；19.4 可以把扩展读到的数据原样交上来。

## 恢复与交接

- 01 里标为“未验证”的格式，按网络 API 的格式实现，并在证据里列出，在 G-zotero 的真实导入中补验。
- 被阻塞时，在本块写明 BLOCKED 与原因。
