# 11 · 部署、真实环境验证与收尾

类型：计划（结果块）
负责：各里程碑的 4174 部署、唯一一次正式库 15→16 迁移、各里程碑的真实试用、收尾全量
状态：Pending（等 M1）
ADR 0063 之后：里程碑改为 M1–M4（见计划 README）。HTTP 版 MCP 保留，随入库一起上线；“操作”用途不默认勾选。部署与正式库迁移的每一步都由 Owner 单独授权。

## Outcome

- 每个里程碑完成，并得到 Owner 授权后，4174 换到新版本。
- 正式库只迁移一次：从 schema 15 到冻结后的 16（C-schema），迁移前有备份。
- 每个里程碑的真实试用都有记录：
  - M1：网页导入导出文件、扩展收藏、Agent 经入库接口与 HTTP 版 MCP 使用文献库；
  - M2：把文件直接放进入库页；
  - M3：用扩展从 Zotero 导入一个小分组，连同批注；
  - M4：撤回一个批次。
- 收尾跑一次全量，结果记入计划进度。

## 进入条件

- 对应里程碑的结果块完成。
- Owner 授权这一次部署（G-deploy）。第一次部署另需 C-schema（16 已冻结）与 G-migrate。

## 责任边界

- 负责：总设计师与实施者：部署、迁移、验证与记录。
- Owner：
  - 授权每一次部署与迁移；
  - 在设置页生成连接码，交给自己的扩展或 Agent；
  - 在 Zotero 里开启本地接口；
  - 在自己的浏览器里试用。
- 实施者不读取连接码、令牌与 Owner 的 Zotero key。

## Tasks

- [ ] **11.1 迁移演练（G-lib）**
  - 动作：在 16 冻结之后，在正式库的只读副本上运行 `scripts/migrate-import-v16.mjs`，记录耗时与核对结果。
  - 输出：副本与回执放在 `sandbox/runs/`、`sandbox/reports/`，不提交。
- [ ] **11.2 M1 部署（G-deploy、G-migrate）**
  - 动作：
    - 跑一次全量；失败时先分清是本计划引起的，还是原有的不稳定；
    - 按现有的重部署流程执行：候选构建、预演、预检无运行中任务、停服、备份、离线迁移、启动、就绪；
    - HTTP 版 MCP 随本次上线。
- [ ] **11.3 M1 试用（G-trial）**
  - 动作：Owner 在自己的电脑上试用：网页上传一份导出文件连同 PDF 文件夹；用扩展收藏 3–5 个页面；让 Agent 经入库接口导入一小批，并经 HTTP 版 MCP 查一篇文献。
  - 输出：实施者只看批次与报告，核对篇数、文件、冲突，以及再入库一次的幂等；经真实 SSH 隧道上传一个大文件，补验 13.1。
- [ ] **11.4 M2 部署与试用（G-deploy、G-trial）**：放置区直接放入 PDF 与文件夹，核对认篇与可能重复的结果。schema 已冻结，本次不迁移。
- [ ] **11.5 M3 部署与试用（G-deploy、G-zotero）**：Owner 用扩展从 Zotero 导入一个小分组，连同批注。01 里标为“未验证”的格式在这里补验；在阅读器里核对批注位置。
- [ ] **11.6 M4 部署与试用（G-deploy、G-trial）**：Owner 撤回一个试用批次，核对移除与保留的内容。
- [ ] **11.7 收尾**：`pnpm full` 一次；需求、技术文档、页面规格与指南做最后核对；证据位置写进本块与计划进度。
