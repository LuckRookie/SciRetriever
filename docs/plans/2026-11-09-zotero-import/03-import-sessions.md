# 03 · 导入模型与导入会话

类型：计划（结果块）
负责：ADR 0058 第 3、4、5 节的服务端部分
状态：Done（2026-11-10，`b21afbc`）

## Outcome

- 文献库有自己的导入模型和适配器接口。现有的 BibTeX/BibLaTeX、RIS、CSL JSON 解析改成首批适配器。
- 导入会话对外是一组 HTTP 接口：建会话、交数据、预览、确认、交文件、结束、取消、读状态与报告。用 `curl` 能完成一次完整导入。
- 外部编号对应是通用的，不含来源专用的表。分组导成文件夹。再次导入同一个来源库是幂等的。
- 文件边收边写盘，不设大小上限；服务端随时能列出还缺哪些文件。
- 每次确认形成一个入库批次（ADR 0052）。
- 现有的书目导入入口（Web、CLI、MCP）保留，内部改走导入会话。

- [x] **3.2 导入模型与适配器接口**：
  - 适配器是纯函数：原始数据进，导入记录与“不导入的内容”清单出；不联网、不读文件、不写库；
  - 现有三种书目格式改成适配器，解析规则不变。
- [x] **3.3 会话**：
  - 状态：收集中、待确认、导入中、完成、已取消；
  - 持久保存，服务重启后能继续；
  - 分次交数据，重发同一序号就是替换；
  - 同一个来源库同时只能有一个进行中的会话；
  - 没确认的会话 7 天后自动取消，“导入中”的会话 7 天没有新文件就自动结束；
  - 暂存的原始数据在会话结束或取消时删除。
- [x] **3.4 预览**：用只读的身份判定，不经过会写库的路径。给出：
  - 新增、已在库、冲突的篇数；
  - 要上传的文件数；
  - 能导入与不能导入的批注数（10 之前先只计数）；
  - 不导入的内容及数量。
- [x] **3.5 确认与落库**：
  - 确认时重新判定，报告以实际结果为准；
  - 书目作为用户来源记录保存；
  - 保存外部编号对应与记录内容的哈希，内容没变的跳过，有变化的形成新的来源记录；
  - 来源库的身份：来源给出全局唯一编号时用它，否则用设备连接的编号加来源里的本地编号；
  - 分组导成以来源库命名的根文件夹下的文件夹：按外部编号对应，只建一次，只补成员，同级重名加序号，超过 128 个字符截断；
  - 用户标签导成根文件夹下的“标签”子文件夹，请求里可以关闭；
  - 形成入库批次。
- [x] **3.6 文件通道**：
  - 列出需要的文件，分两种：要上传内容的（文献还没有主 PDF），只需报 sha256 的（文献已有主 PDF）；
  - 上传时边收边写盘并计算 sha256，验收（ADR 0029）从磁盘文件读，不整个读进内存；
  - 已有主 PDF 不替换；哈希不同记为冲突；
  - 不设大小上限；磁盘剩余空间不足时拒收，错误码明确；
  - 重复上传同一个文件不重复入库。
- [x] **3.7 结束与报告**：客户端声明结束或文件到齐时结束；报告按预览的分类写明实际结果，没交来的文件逐个列出。
