# 15 · 认出是哪一篇

类型：计划（结果块）
负责：ADR 0063 第 2、5、11 节：只有文件的条目、文件适配器、网页书目标签适配器、认篇的四步、“书目待补”、解析之后再认一次
状态：Pending

## Outcome

- 只有文件的条目可以入库：一个 PDF 交上来，就是一个条目。
- 文件适配器从文件信息、文件名和首页读出线索；网页书目标签适配器在服务端解读扩展原样交来的页面标签。按站点补规则时只改服务端。
- 按 ADR 0063 第 11 节的四步认出是哪一篇。前一步成功，后一步不做。认不出时，以线索里的标题或文件名入库，标为“书目待补”。
- 只有文件的条目在预览阶段认篇，显示进度；预览不写文献库。
- 一篇“书目待补”的文献解析之后，用解析出的标题和作者再认一次，不另外花费。
- 认篇不调用模型。认出的结果只决定书目；文件仍按 ADR 0029 标为“文章身份未验证”。
- 同一个文件（按 sha256）不重复入库。

  - 验收：迁移测试通过；新表、新列在合成的 15 库上为空，旧表行数不变。
- [ ] **15.2 只有文件的条目（等 12.12、12.17）**
  - 动作：
    - 文件在预览之前进入暂存区，按 12.12 计入上限，取消或过期时删除；
    - 确认之后按 12.12 成为主 PDF；
    - 按 sha256 命中已有文件时，按 12.17 处理；

  - 验收：
    - 只交一个 PDF 就能完成一个批次；
    - 同一个 PDF 交两次不重复入库；
    - 取消后暂存文件被删除；
    - 导出文件与文件夹一起交来时配对正确；没有配上的 PDF 按 03 §6.4.3 在预览里单列为“未配对的文件”，默认不入库，逐个决定 `include` 后才成为只有文件的条目。
- [x] **15.3 文件适配器（等 12.13）**
  - 动作：读文件信息、文件名与首页文字；首页上有几个不同的标识时不取；读取按 12.13 有超时。
  - 验收：用合成 PDF 测试以下情形：
    - 文件信息里有 DOI；
    - 只有首页有 DOI；
    - 首页有几个 DOI（例如被引文献）；
    - 只有 arXiv 号；
    - 文件名里有 DOI；
    - 没有标识，只有标题；
    - 扫描件（没有文字层）；
    - 加密 PDF。
- [ ] **15.4 网页书目标签适配器（等 12.14）**
  - 动作：把 `apps/browser-extension/src/page.ts` 中的解读规则按 12.14 搬到服务端，接收原始标签；页面本身是 PDF 时按文件处理；按 12.14 记录真实的 PDF 地址（接续 13.4）。
  - 验收：现有 `page.test.ts` 中的合成页面改为服务端的测试，结果与原来一致或按 12.14 改变；新增 schema.org 结构化数据与只有页面标题的情形。
- [ ] **15.5 认篇的第 1、2 步：找标识，取书目并核对（等 12.15）**
  - 动作：从线索里取标识，向文献信息来源取书目；取回的标题要能在线索里找到，对不上的当作没有标识。
  - 验收：使用假的文献信息来源，覆盖以下情形：
    - 标识正确且标题对得上；
    - 首页的标识属于被引文献，标题对不上，于是不采纳；
    - 来源查询失败；
    - 来源限流。
- [ ] **15.6 认篇的第 3、4 步：按标题找；没有认出（等 12.15）**
  - 动作：
    - 按标题查询；标题一致，并且作者或年份也能在线索里找到时采纳；
    - 只是标题相近的，列为“可能是这一篇”，由使用者在批次页上选择；
    - 没有认出的，以线索里的标题入库，没有标题时用文件名，标为“书目待补”；
    - 预览阶段显示进度，可以取消，不写文献库。
  - 验收：
    - 假来源返回一条一致的结果，采纳；
    - 返回几条相近的结果，列为候选，不自动采纳；
    - 没有结果，标为“书目待补”；
    - 预览前后，文献、来源记录与状态投影的表逐行不变；
    - 取消预览后不留下查询任务。
- [ ] **15.7 “书目待补”（等 12.16）**
  - 动作：按 12.16 记录、显示与清除；使用者自己填写书目后清除。
  - 验收：查询与报告里能区分“书目待补”；使用者编辑标题后标记按 12.16 清除。
- [ ] **15.8 解析之后再认一次（等 12.16）**
  - 动作：在 12.16 指定的解析步骤之后，用解析出的标题和作者再走一次第 3、4 步；不另外花费，不调用模型。
  - 验收：一篇“书目待补”的合成文献解析后被认出，来源记录按 12.16 写明；解析失败时标记保留；已经认出的文献不再重复认。
- [ ] **15.9 在真实文件上验证认出的比例（ADR 0063“还没有验证的前提”第 2 条，G-files）**
  - 动作：在 Owner 授权的一组真实 PDF（建议 50–100 篇，包括中文期刊和扫描件）的副本上运行认篇，只在本机进行，不写正式库。
  - 输出：分别统计四步各认出多少、认错多少，以及首页标识被引文献干扰的次数。脱敏结论写进本块。
  - 验收：结论交总设计师。认错率高到不能接受时，按 ADR 0063 回到决定本身修改，不在实现里自行放宽。
