# 计划 20：导入系统、Agent 接入与网页收藏

类型：计划
负责：ADR 0058 与 ADR 0057 保留部分的落地
状态：In progress（2026-11-10 按 ADR 0058 重排；01 进行中；功能未交付）

## 目标

按 [ADR 0058](../../architecture/decisions/0058-import-system-and-agent-access.md)，以及 [ADR 0057](../../architecture/decisions/0057-zotero-import-and-browser-capture.md) 仍然有效的部分（Zotero 各类内容的落库规则、浏览器扩展收藏），做四件事：

- **导入系统**：与来源无关的导入模型、服务端适配器和导入会话。用户或桌面上的 Agent 经一组 HTTP 接口，把外部文献管理工具里的书目、分组和 PDF 导进文献库。Zotero 是第一个适配的来源，现有的 BibTeX、RIS、CSL JSON 导入并进来。
- **Agent 接入**：文献库自带的 skill，以及同一地址上的 HTTP 版 MCP。
- **网页收藏**：用户在自己的浏览器里用扩展把文献连同 PDF 收进文献库。
- **批注导入**：把 Zotero 的批注导成本系统的批注。

分四个里程碑交付，每个里程碑完成后可以单独部署：

| 里程碑 | 结果块 | 交付                                                                           |
| ------ | ------ | ------------------------------------------------------------------------------ |
| M1     | 01–06  | 设备连接、导入会话、Zotero 适配器、入库页“导入”、skill：书目、分组、PDF 能导入 |
| M2     | 07     | HTTP 版 MCP                                                                    |
| M3     | 08、09 | 浏览器扩展收藏                                                                 |
| M4     | 10     | 批注导入                                                                       |
| 收尾   | 11     | 各次部署、真实环境验证、收尾全量                                               |

其他来源的适配器（EndNote、Zotero RDF 等）不在本计划内，需要时另立计划。

## 不变量

- 预览不写库。
- 导入只新增：不删除文献，不替换已有主 PDF，不改动用户在文献库里的整理。
- 服务端不连 Zotero 或其他外部文献管理工具。适配器不联网、不读文件、不写库。
- catalog 里没有来源专用的表。
- 再次导入同一个来源库不重复入库、不重复建来源记录。
- 导入的 PDF 按 ADR 0029 标为“文章身份未验证”；上传的文件边收边写盘，不整个读进内存。
- 设备连接令牌：
  - 服务端只存派生值；
  - 只放在请求头里；
  - 不进日志、事件、报告或 Web 数据；
  - 不能登录 Web，不能读写配置与凭据，不能管理设备连接。
- HTTP 版 MCP 与 stdio 版用同一套工具实现，不复制一份。
- 用户浏览器里的 Cookie 与登录信息不发往服务端。
- 不使用 Zotero 翻译器，不实现 Zotero Connector 协议。
- 测试只用合成数据和假的外部服务，不连真实 Zotero。

## 主要风险

| 风险                                                                       | 负责块 |
| -------------------------------------------------------------------------- | ------ |
| Zotero 本地 API 的格式、库编号的形式、未同步时的版本号，都还没在真机上看过 | 01     |
| 令牌是第二种认证方式，用途范围或撤销出错会扩大攻击面                       | 02、07 |
| 预览要做只读的身份判定；预览与确认之间文献库可能变化                       | 03     |
| 没有 DOI 等标识的记录可能误合并或重复入库                                  | 03     |
| 几千篇、几个 GB 的导入中断后要能继续                                       | 03     |
| 现有三端的书目导入入口改走会话后，行为与结果格式要保持兼容                 | 03     |
| 首选附件在匿名或本地读取时可能没有 `links.attachment`，要自行选取          | 04     |
| 一个全新的 Agent 只凭 skill 能不能把导入做对                               | 06     |
| HTTP 版 MCP 与 stdio 版的工具集出现分叉                                    | 07     |
| 出版社页面的书目标签不统一，扩展可能读不到 DOI 或 PDF 地址                 | 09     |
| 批注坐标换算（页面框、旋转）出错会让批注错位                               | 10     |
| 正式库从 schema 15 升级，需要停服离线迁移                                  | 11     |

## 完成标准

- 01–11 的退出条件都满足；定向测试通过，M1 部署前和收尾各跑一次全量。
- 用合成数据和假的外部服务覆盖：
  - 预览不写库、确认后以实际结果为准；
  - 中断后继续、再次导入幂等；
  - 已有主 PDF 不被替换；
  - 令牌按用途限权、撤销立即失效、令牌不外泄；
  - HTTP 版 MCP 的工具随用途变化。
- G2–G4 的真实环境验证通过。
- 需求、ADR 0058 指定的技术文档、页面规格与指南按实现更新，没有残留“不保存外部导入记录 ID”的现行表述（[存储技术文档](../../architecture/technical/07-versioned-storage.md)不保存清单）。
