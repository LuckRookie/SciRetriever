# 02 · Zotero 书目与分类导入（后端）

类型：计划（结果块）
负责：ADR 0057 第 1–4 节中书目、身份、编号、分类、标签与导入流程的后端
状态：Pending（等 01）

## Outcome

- 服务端能从 Zotero 本地 API 或网络 API 读取个人库或群组库，按分类给出预览，再把书目与分类导入成一个入库批次。
- 再次导入同一库时按 Zotero 编号对应，不重复入库、不重复建来源记录，只补新增。
- CLI、MCP、HTTP 都能完成选择、预览、导入三步；设置能保存 Zotero 的连接配置并测试连接。

## 进入条件

01 的结论与合成样本；ADR 0057 Accepted。

## 责任边界

Codex（`sciretriever-web`）：`packages/contracts`、`apps/server` 及测试，迁移脚本，[技术文档](../../architecture/technical.md) 01、03、06、07 中相应部分。不改 `apps/web/`、`docs/guides/`、页面规格与需求。

## Tasks

- [ ] **2.1 合同与规格**：
  - 配置：本机 Zotero 地址；网络 API 的用户编号；key 存 `credentials.toml`；
  - 选择、预览、导入的请求与结果，报告分类，错误码（如 Zotero 未开启本地 API、key 无效、库不可见）；
  - 写进技术文档 01（CLI `import zotero`、MCP、HTTP）、03（Zotero 条目到来源记录的映射、身份、编号）、06（批次方式“Zotero 导入”）、07（新表；删去不保存清单中的“外部导入对象/记录 ID、导入批次历史”）；
  - 回执 `contract.md`，供 04 接界面。
- [ ] **2.2 Zotero 客户端**：
  - 本地 API 适配：配置的本机地址，始终直连；
  - 网络 API 适配：遵守 `Backoff` 与 `Retry-After`；按 ADR 0056 在“文献来源”组里列一项 `zotero`；
  - 两者共用分页、版本与条目解析；测试用假 Zotero 服务。
- [ ] **2.3 映射**：
  - 书目字段取 Zotero 的 CSL JSON，走现有 CSL JSON 导入规则；
  - 解析 Extra 里的 DOI、arXiv、PMID；
  - 自动标签作为这条来源记录的作者关键词，手动标签留给 2.5 建文件夹。
- [ ] **2.4 预览**：不写库。给出新增、已在库、冲突篇数，PDF 可带入数（03 前先只计数），批注数（07 前先只计数），不导入的笔记、独立 PDF、非 PDF 附件的数量。
- [ ] **2.5 导入任务**：
  - durable 任务，可中断后继续；形成一个入库批次；
  - 保存库编号与条目编号的对应；
  - 分类导成以库名命名的根文件夹，保持层级，多处归属；手动标签导成根文件夹下的“标签”子文件夹，可在请求中关闭；
  - 再次导入只补新增，书目变化形成新的来源记录，不删除文件夹成员。
- [ ] **2.6 schema 16**：新表与离线迁移脚本 `scripts/migrate-zotero-v16.mjs`（按 `migrate-intake-v15.mjs` 的做法），打开旧库不自动迁移。
- [ ] **2.7 三端入口与设置**：CLI `import zotero`、MCP 工具、HTTP 路由；Zotero 配置的读写与“测试连接”。

## 集成与影响

新增外部来源 `zotero`；catalog schema 15 → 16；入库批次新增一种方式；`credentials.toml` 新增一个字段。

- 直接测试（假 Zotero 服务）：两种来源、群组库、分页与版本、`Backoff` 等待、预览不写库、中断后继续、再次导入幂等、无 DOI 条目按编号对应、分类层级与多处归属、手动标签开关、key 不出现在日志与结果里。
- 迁移：在合成库上测试；再用正式库的只读副本试跑一次迁移，记录耗时。
