# 14 · 一组入库接口

类型：计划（结果块）
负责：ADR 0063 第 1、3、4、7 节的服务端部分：一个入库过程、一组接口、一种用途、批次归属
状态：In progress（2026-11-15：14.1–14.10 完成，余 14.11–14.13）

## Outcome

- 收藏并入入库过程：扩展的单篇收藏是“只有一条的清单”，采用逐条确认，每台设备每天一个开放的批次。单独的收藏接口不再存在。
- 设备连接的用途“收藏”“导入”合成“入库”；“读取”“操作”不变。
- 凭令牌只能看到和操作本设备发起的批次；网页登录的使用者能看到和操作全部批次（审查 L1）。
- 确认立即返回，入库在后台进行，进度随时可读；服务重启后继续（审查 M3）。
- 撤销令牌时，正在进行的上传被中断（审查 L2）。
- 为已在库的文献补 PDF，也走同一条文件通道，原来 16 MiB 的上限取消。
- 对外只有“入库批次”一个概念：接口、MCP 工具、CLI 与说明里都不再出现“导入会话”。
- 批次带有全文取得情况；“接着做什么”所需的批次范围操作在服务端可用。
- schema 16 中本块的表变化已合入同一个 15→16 迁移。

规格：等 12 的回答（各 Task 注明）。现行的规则见[产品接口 2.4.1–2.4.3](../../architecture/technical/01-product-interface.md#241-设备连接与按用途准入)与[文献与材料 6.1](../../architecture/technical/03-literature-materials.md#61-书目交换规则)。

## 集成与影响

- 公开接口改变：路径、字段、用途值与错误码。现有的网页、扩展与 skill 在 18.1、19.1、06 适配之前不可用。
- 表结构：本块的 DDL 并入 schema 16（14.3、14.4）。
- 用户行为改变：确认不再等待；收藏不再要求 DOI；设备只看得到自己的批次。
