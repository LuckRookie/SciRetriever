## 1. 产品目标

SciRetriever 是通用的文献知识库，让人和 Agent 都能从任何领域的海量文献中得到自己需要的可靠知识，用于学习、写作和研究。

它有两种用法，共用同一个文献库：研究者把它当作自己的文献库，在其中收集、整理、阅读和总结文献；它也可以作为科研 Agent 系统中的文献材料与知识服务组件。产品不只为其中一种用法设计。

产品要交付五件事：

| 简称 | 交付什么                                               |
| ---- | ------------------------------------------------------ |
| 收   | 把一个领域的文献成规模地收进库，并拿到全文             |
| 读   | 人和 Agent 都能读到每篇文献的全文                      |
| 理   | 人能把它当作自己的文献库来整理                         |
| 炼   | 按人或 Agent 提出的需要，把成批文献加工成知识          |
| 用   | 找到并取走需要的知识，人用于学习和写作，Agent 用于研究 |

“可靠”不是第六件事，它是贯穿五件事的品质：全文是真的，知识能回到原文核对，覆盖了多少、缺多少说得清。

当前的核心是两件事：获取已有的知识（目前是文献的 PDF），以及对知识的加工和处理。

## 2. 服务对象与使用场景

产品有两类并列的服务对象：人和 Agent。

**人**通过 Web 使用：

- 把它当作长期使用的个人文献库，收集、整理、阅读、批注并总结自己的文献；
- 为学习一个领域、写综述或做研究，取得跨文献整理的知识，并沿证据回到原文核对；
- 配置系统，监督并在愿意时纠正系统的执行，例如观看系统操作浏览器并直接介入。

**Agent** 通过命令行和 MCP 使用同一个文献库，科研 Agent 是主要的程序使用者：

- 按主题或种子文献发现文献并取得全文；
- 读取论文的正文和资源，不必先有总结；
- 快速浏览大量论文的概览，按需深入单篇，或针对研究问题加工；
- 在明确的文献范围内比较共识、分歧、适用条件和局限；
- 在上下文限额内取得相关知识，并沿引用展开到原始证据；
- 按自己定义的记录结构批量提取数据。

作为 Agent 系统的组件时，上层科研 Agent 决定研究目标和整体推理，SciRetriever 负责文献操作以及材料和知识产物的完整性。

## 3. 产品交付

每一条只写要达到的结果。条目编号（如“收2”）供其他文档引用。

### 3.1 收：把文献成规模地收进库，并拿到全文

#### 收1 成规模发现文献

- 使用者给出领域条件，或给出一篇或一组种子文献，就能成批发现相关文献。种子文献沿引用关系向外扩展。
- 一次发现可以同时使用多个文献信息来源。一个来源失败时，其他来源已经取得的结果照常保留，并说明哪个来源没有完成。
- 每次发现都有明确的输入和停止边界。引用扩展只在使用者给定的方向、层数和数量内进行，不无限递归。
- 同一篇文献从不同来源得到时，库里只有一条记录，并保留各来源的差异。证据不足时不把不同的文献合并。同一篇文献的不同版本（例如预印本和正式发表版）可以区分。
- 信息不完整的文献可以先进库，以后再补全。
- 文献偏离最初的搜索主题时仍是有效文献，不因此被删除。
- 每篇文献为什么进库是查得到的：哪一次发现、什么条件、沿哪条引用关系。
- 同一发现条件可以再次执行，用来补充新文献。

#### 收2 取得全文

- 系统能用已有的文献信息自动寻找并取得全文文件，可以依次尝试多条途径。一条途径失败不影响其他途径。
- 取得的必须是真实、能打开、有页面的全文文件。链接、下载事件、文件名和文件类型声明都不能代替对文件本身的检查。文件是否已经核实属于目标文献，要有标明。
- 自动获取不要求人在线。人愿意帮忙时，可以从头到尾观看系统操作真实的浏览器，并在同一画面里直接操作，例如登录。人介入后得到的文件接受同样的检查。
- 使用者能为一篇具体的文献提供自己手里的 PDF。原文件不被移动、修改或删除；已有的全文不被悄悄替换。
- 自动途径全部正常试过仍没有取得全文的文献可以被识别出来，使用者可以稍后自己补文件；全库自动补全默认不再反复尝试它们。临时的网络、权限、配置或存储错误，以及使用者中断，不算“试过”。
- 使用者能看到一个范围内全文的取得情况：多少已经取得，多少还没有，其中多少已经试完了自动途径。
- 已经取得的全文在重复运行和后续步骤失败后保持可用。模型对内容的判断不能单独成为删除文件的理由。

#### 收3 带入已有的文献

- 能从外部文献管理工具导入书目、分组、PDF 和批注，首先适配 Zotero。文献库与外部工具在不在同一台电脑上都要支持。只单向导入，不写回外部工具。
- 支持主流的书目交换格式。
- 手里的全文文件可以直接放进库，不要求库里先有这篇文献的书目。认不出是哪一篇的，先进库，书目以后再补。
- 人不借助 Agent 就能完成任何一种带入。
- 在自己的浏览器里浏览文献网页时，能把这篇文献连同 PDF 直接收进库。PDF 用使用者自己的网络和登录状态取得，登录信息不离开使用者的浏览器。
- Agent 能代使用者完成导入。
- 带入的文献与其他途径进库的文献在同一个库里，一起查询和补全。
- 重复带入相同的内容不产生重复的文献。再次导入同一个外部库时，能对应上一次导入的内容。
- 一次带入可以撤回。撤回只移除这一次新增、之后没有被动过的内容。
- 使用者自己提供的书目信息优先于供应商的信息；供应商只补充使用者没有提供的部分。

#### 收4 规模与持续积累

- 文献库为大批量文献而设计：书目按一千万篇设计，有全文的文献按一百万篇设计；当前规模不是设计目标。完成程度不同的文献长期共存：有的只有书目，有的有全文，有的已经加工。
- 全库的量由 Agent 与批量操作处理：按条件取出待处理的一批，逐篇读取和写入，中断后从断点继续。
- 人面对的是有边界的工作集：一次搜索的结果、一个集合、一个任务的产出、最近读过的、待审核的一批，以及文献库。面对全库时，人用搜索、几项总数和进入各个工作集的入口，不翻全库的列表。
- 文献库与候选分开显示：使用者点名要的文献（导入、收藏）和他使用过的文献（加标签、放进集合、提供或要求全文、发起加工）在文献库里；程序找来、他还没有表态的是候选，不出现在人的文献列表里，仍能通过搜索、任务的产出和引用关系找到。文献库里的文献可以移回候选。两者在同一个库里，去重与引用关系照旧。规则见 [ADR 0067](decisions/0067-library-and-candidates.md)。
- 库变大时，日常使用不变慢：打开一篇文献、查看任务、搜索，以及在工作集里浏览、筛选、计数的耗时不随库的总篇数增长；大批量写入进行时也是如此。
- 收集和处理按批进行。部分失败不撤销同一批里已经成功的部分。
- 中断或失败后可以再次运行，从缺失的部分继续，不重做仍然有效的部分。
- 使用者可以对整个库、一次发现、一次导入、一个查询结果或选定的文献，补齐缺少的全文、文本或加工结果，不需要重新发现。
- 同一篇文献有多个版本时，默认只需要其中一个达到目标；使用者指定了版本时，按指定的版本处理。
- 每次由使用者发起的操作结束时都给出本次的结果：实际处理了哪些，完成多少，稳定缺失多少，失败多少，没有开始多少。

### 3.2 读：人和 Agent 都能读到每篇文献的全文

#### 读1 可信的全文文本

- 有全文的文献可以形成供阅读和加工的文本，包括正文、章节结构、图、表和公式。形成文本不以先生成总结为前提。
- 文本忠实于原文。产品不宣称文本没有错误，但错误应当可控、可发现、可追溯；拿不准的地方和按简化方式处理的文献有标明。
- 文本与原始文件相互区分。文本记录它来自哪份文件、用什么方法形成。
- 全文缺失、截断、乱码和只处理了一部分的情况如实说明。
- 保留了图片或表格，不等于已经读懂其中的内容；超出当前能力的部分明确说明。
- 一篇文献处理失败不影响其他文献，也不删除原始文件。

#### 读2 人的阅读

- 人能阅读原版面的 PDF：翻页、缩放、目录、文内查找。
- 人能阅读文本版：章节、正文、图片、表格和公式都能呈现。原材料不具备的导航或内容，明确告知。
- 在多篇文献之间切换时，各篇保留自己的阅读位置。阅读空间有合适的字号、行宽和主题。
- 外文文献可以对照译文阅读。
- 阅读已有的内容不需要先发起加工，也不会暗中发起加工。

#### 读3 Agent 的读取

- Agent 能按章节、片段和资源读取文本，每次读取有范围和大小限制。大材料按需读取，不整篇塞进上下文。
- Agent 不需要了解解析工具的私有格式。
- 读到的内容带有文献、版本和来源，可以用于引用。

### 3.3 理：人能把它当作自己的文献库来整理

#### 理1 分组、标签与筛选

- 人能按自己的方式给文献分组，一篇文献可以属于多个分组。
- 文献有标签。人能按标签、关键词、分组和文献状态筛选，并保存常用的筛选条件。
- 从外部工具带入的分组和标签保留下来。

#### 理2 查看和修正单篇文献

- 打开一篇文献，能在同一处看到当前的书目信息及其来源、版本、全文文件、文本、已有的加工结果和引用关系，以及还缺什么。
- 人能修正书目信息。修正后的值不被自动来源覆盖。

#### 理3 批注与笔记

- 人能在阅读时高亮、框选和写笔记。
- 批注和笔记是使用者自己的数据：稳定保存，可以导出，Agent 在同等授权下可以读取。
- 从外部工具带入的批注，在文件一致时保留。

#### 理4 导出书目

- 书目信息能导出为主流文献管理工具可用的格式。
- 导出不以取得全文或完成加工为前提。

### 3.4 炼：按需要把成批文献加工成知识

#### 炼1 单篇加工

- 对单篇文献可以得到概览、详细分析和针对具体问题的回答。不同用途的结果各自保存，不互相覆盖成一份含义不清的“最终总结”。
- 概览用于筛选。详细分析保留研究问题、方法、数据或论据、结论、条件和局限。针对问题的回答写明所回答的问题。
- 加工不承诺无损，但影响结论的条件、否定信息、数值、单位、公式和出处必须忠实。缺失和无法判断要明说，不编造。

#### 炼2 跨篇加工

- 对一个明确的文献范围可以得到跨篇的知识：围绕问题的综合，记录之间的比较，发表情况的统计，按主题整理成可以阅读的知识页面，实体和它们之间的关系。
- 跨篇结果保留共识、分歧、适用条件的差异和知识缺口，写明实际覆盖了哪些文献，不把局部说成整个领域。
- 已有的加工结果可以作为后续加工的输入。

#### 炼3 调用方定义的提取

- 调用方定义一条记录代表什么、有哪些字段、怎样解释、怎样算纳入。产品不预设“一篇文献一条记录”，也不需要先列举所有领域。
- 提取可以由产品内置的通用方法完成，也可以由外部 Agent 或程序按自己的策略完成。两种方式使用同一套材料、证据和结果交付。
- 提取可以直接读取原始文件和文本，不以先完成总结为前提。
- 每条记录和每个字段的依据可以核对。缺失或没有处理不能冒充实际的值。零记录、部分覆盖、失败和取消要能区分。
- 记录的结构和证据检查通过，只说明通用完整性合格。科学解释、记录合并、领域规则、最终数据集和机器学习由下游负责。

#### 炼4 发起、规模与花费

- 人和 Agent 都能发起加工，并取用同一份结果。
- 加工只在明确发起时进行。开始前能知道这次大约的花费和用时。
- 万篇规模的加工能跑完。中断后可以继续，不重做仍然有效的部分。
- 每份结果绑定它的输入范围、输入版本和生成方法。输入变化后，旧结果标明已经过时，不被悄悄改写或删除。
- 新的加工失败时，此前的有效结果保持不变。

### 3.5 用：找到并取走需要的知识

#### 用1 查找

- 能按问题和文献范围查找文献、正文片段和已有的加工结果。加工结果可以按说明、正文和记录字段查找。
- 没有加工过的文献照样能查到、能阅读。
- 查找结果写明来源、内容类型、实际覆盖和是否被截断。同一篇文献的多个版本不重复计入。
- 相关不等于正确：查找只负责找到，不替使用者判断科学结论。

#### 用2 Agent 取用知识

- Agent 能在给定的上下文限额内取得与问题相关的知识，并从概览逐层展开到证据和原文。
- Agent 能组合使用发现、获取、读取、加工、查找和提取，不需要了解内部结构。
- 每项操作有明确的输入、输出、范围和副作用。读取已有内容与生成新内容可以区分，部分结果与完整结果可以区分。
- Agent 不直接获得数据库、凭据、任意浏览器操作或底层写入能力。

#### 用3 人的学习与写作

- 加工结果以人能直接阅读的页面呈现。
- 人能从一个主题读到单篇文献，再读到原文中的依据，并原路返回。
- 从结论或提取字段能进入对应文献的正确版本和位置。不能精确定位时明说，不伪造页码、坐标或高亮。
- 加工结果连同出处可以导出，供人在外部的写作和笔记工具中使用。

#### 用4 三个入口

- 人使用 Web，Agent 使用命令行和 MCP。三者共用一个库和一套业务含义。
- 人只用 Web 就能完成日常工作：发现与导入、查询、获取与补充全文、形成文本、加工、查看和核对结果、导出，以及必要的配置。不需要命令行，也不需要手写底层请求。
- Web 能做的业务，命令行和 MCP 各自也都能做。阅读器、证据高亮等视觉交互只在 Web 提供，但相关的材料、结果和证据在机器入口可以读取。
- 数据库迁移、损坏修复和底层诊断可以只在命令行提供。

## 4. 可靠

以下品质贯穿第 3 节的五件事。

#### 可1 出处可追溯

使用者能够判断：

- 文献由哪次发现、哪些条件、哪篇种子文献或哪条引用关系得到；
- 书目信息来自哪些来源；
- 全文文件从何处取得；
- 文本依据哪份文件、用什么方法形成；
- 加工结果依据哪些文献、哪个版本的文本、哪些证据、用什么方法形成；
- 已确认的引用关系依据供应商给出的结构化关系，还是依据某一条参考文献原文。

#### 可2 证据可核对

- 人和 Agent 能从一条知识要点读到支持它的原文片段，并知道它属于哪篇文献、哪个版本、哪份材料。只给一个无法复核的文件名不算。
- 文本更新后，旧的证据引用不会悄悄指向另一段内容。页码和坐标只在定位可靠时提供，否则如实说明能定位到哪一层。
- 被有效的加工结果引用的材料保持可读；确需失效时明确告知，不无声断开。
- “证据定位正确”与“解释受证据支持”是两件事，分别检查。

#### 可3 覆盖和缺口说得清

- 任何一步部分成功时，保留已经得到的有效结果，并明确指出没有完成的部分。
- 结果写明实际处理的范围，不把只处理了一部分说成处理了全部。
- 使用者能区分各类内容是已经得到、仍然缺失，还是本次操作失败。

#### 可4 已有的成果不被破坏

- 已经确认的书目信息、全文文件、文本和加工结果，不因另一个来源失败、运行中断、重复运行或重复导入而被无声破坏。
- 新结果产生新版本，不在原处覆盖旧结果。

#### 可5 不同性质的内容相互区分

- 原文、由原文形成的文本、模型的解释和跨篇综合可以区分，不混为一谈。

#### 可6 不猜测

- 来源没有明确提供的信息不根据其他线索猜测。例如不根据姓名猜作者身份，不把无法可靠识别目标的参考文献文本连接到某篇文献。

## 5. 产品规则

这些是产品对使用者的承诺，所有设计都要遵守。

#### 规1 查询不触发扩充和加工

- 查询和阅读只使用库里已有的内容。查不到、缺全文或缺加工结果时，只报告缺口，不自动联网搜索、下载、调用模型或排队补库。
- Agent 不能因为自己认为库里的内容不够，就自行扩充文献库。

#### 规2 联网、花钱和写入由使用者明确发起

- 每一次发现、获取全文、形成文本和加工，都由使用者明确发起。一次发起可以处理一批文献，批内不需要逐篇确认。
- 发现、获取全文和加工可以分别发起，也可以按使用者明确选择的步骤组合。发现不自动带来下载，下载不自动带来加工。

#### 规3 一个库

- 所有入口、所有进库途径和所有加工结果共用同一个持续积累的文献库，不各自形成彼此隔离的集合。

#### 规4 领域通用

- 收、读、炼、用的规则不预设某一个学科的文献形态。换一个领域，不需要改变产品的含义。
- 反应、分子、产率、材料性质这类领域记录由调用方定义，不成为文献库的固定字段。领域数据集、预测、规划和机器学习由下游负责。

#### 规5 做法可以替换

- 增加或替换文献信息来源、全文获取途径、文本形成方法、模型服务或书目交换格式时，不需要重新定义产品的工作方式和文献库的基本含义。

#### 规6 配置与凭据

- 使用者能自己完成全部必要的配置，并能主动测试一项配置是否可用。测试不改变文献库里的任何内容。
- 密钥与普通配置分开保存，不出现在界面、输出、日志和文献库里。
- Web 首次启动不需要配置向导，也不需要先执行命令行初始化；首次建库不覆盖已有的数据。

#### 规7 访问控制

- 文献库不对未经认证的访问开放，本机访问也需要认证。
- Agent 和浏览器扩展通过限定用途的连接接入，不能借此登录 Web、读写配置和凭据。

## 6. 范围边界

同一篇文献的不同明确版本作为同一文献的版本组织。产品不要求建立引用关系之外的通用文献关系图谱；更正、撤稿等关系只有在形成明确的使用者需求后才进入产品。知识加工可以产出带证据的实体与关系结果，它们是派生知识，不改变文献的身份、版本组织与引用关系。

项目不内建各领域的算法。领域数据集、预测、规划和机器学习由下游负责。

方向（Owner 2026-11-10 确认，当前不设计、不验收）：文献进入产品，是因为它是目前可以稳定获取和解析的知识，产品的知识来源不以文献为界。人和 Agent 也创造知识，例如笔记、总结和研究过程中的产出，后续应当能进入知识库并参与加工。写作和笔记工具不在产品内自建，由外部知识库工具承担，产品负责与它们的导入和导出衔接。

## 7. 验收

满足以下场景时，对应的需求才算成立。各项做法自己的验收（例如获取途径的顺序、浏览器操作的限额、配置的分层）由对应的 ADR 和技术文档规定，不在本表。

| 条目 | 场景                 | 必须观察到的结果                                                                                                                                                                                                               |
| ---- | -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 收1  | 按领域发现           | 给出领域条件后，多个来源分别查找，结果进入同一个库；重复的文献只有一条；一个来源失败时其他来源的结果保留，并能看到失败信息                                                                                                     |
| 收1  | 按种子文献发现       | 给出种子文献后，沿引用关系发现相关文献，并保留它们被发现的关系；扩展不超出使用者给定的边界                                                                                                                                     |
| 收2  | 自动取得全文         | 系统从书目信息出发取得真实、能打开、有页面的全文文件；无人介入时也能结束并如实报告                                                                                                                                             |
| 收2  | 人工介入与自己补文件 | 人能观看同一个浏览器的全过程并直接操作；人也能为具体文献提供自己的 PDF，原文件不变，已有全文不被悄悄替换                                                                                                                       |
| 收2  | 全文取得情况         | 对一个范围能看到已取得、未取得和已试完自动途径的数量；临时错误不会把文献误标为已试完                                                                                                                                           |
| 收3  | 从外部工具导入       | 外部文献库的书目、分组、PDF 和批注进入本库；再次导入不产生重复；带入的文献能与其他文献一起查询和补全                                                                                                                           |
| 收3  | 浏览时收藏           | 在自己的浏览器里把当前网页的文献连同 PDF 收进库，登录信息不离开浏览器                                                                                                                                                          |
| 收4  | 大规模的收集         | 在一百万篇书目（其中十万篇有全文）的合成库上，文献的持续接纳、重复收敛、缺失补全、中断后继续、局部失败隔离和库内查询都成立；一千万篇书目（其中一百万篇有全文）上做压力检查；记录所用数据、时长、吞吐、内存、磁盘和外部调用花费 |
| 收4  | 大规模下的使用       | 同一组日常操作（打开一篇、查看任务、搜索，以及在工作集里浏览、筛选、计数）在一万篇和一百万篇的合成库上耗时相近，并在持续写入时达到规格给出的目标耗时；只被发现的文献默认不出现在人的文献列表里；一千万篇上做压力检查           |
| 收4  | 重复运行与局部失败   | 再次运行同一操作时不重做仍然有效的部分；一批中部分失败时其余照常完成，已完成的结果不丢失                                                                                                                                       |
| 读1  | 可信的全文文本       | 不经过加工就能读到由全文形成的文本和资源；部分结果、失败和拿不准的地方如实表达                                                                                                                                                 |
| 读2  | 人的连续阅读         | 不发起任何加工就能连续阅读已有的文献，在多篇之间切换时保留各自的位置                                                                                                                                                           |
| 读3  | Agent 的读取         | Agent 按片段有界读取正文，读到的内容带有版本和来源                                                                                                                                                                             |
| 理1  | 整理自己的库         | 人能分组、打标签、按条件筛选并保存筛选；外部工具带入的分组保留                                                                                                                                                                 |
| 理3  | 批注与笔记           | 批注和笔记稳定保存，可以导出，Agent 在同等授权下可以读到                                                                                                                                                                       |
| 理4  | 导出书目             | 有书目信息的文献不必等全文或加工完成，就能导出为主流工具可用的格式                                                                                                                                                             |
| 炼1  | 单篇加工             | 不同用途的结果各自绑定输入和证据，保留条件和局限；不适用或失败不删除材料                                                                                                                                                       |
| 炼2  | 跨篇加工             | 在指定的文献范围内，共识、分歧和条件差异可以追溯到具体文献；结果写明实际覆盖，不假装覆盖整个领域                                                                                                                               |
| 炼3  | 调用方定义的提取     | 外部程序按不同的记录定义读取材料并提交有证据的记录，不需要新增领域字段；零记录与部分失败可以区分                                                                                                                               |
| 炼4  | 万篇规模的加工       | 对万篇规模的范围发起加工，开始前给出花费和时间的估计，能跑完；中断后继续时不重做有效部分                                                                                                                                       |
| 用2  | Agent 的知识旅程     | Agent 独立完成获取、读取和按需加工，在限额内取得知识，并从要点展开到正确版本的原文；过程中没有隐藏的生成花费                                                                                                                   |
| 用3  | 人的学习             | 一个人只用 Web，从主题页面读到单篇，再读到原文中的依据并返回，由此了解一个领域的概况                                                                                                                                           |
| 用3  | 带着出处导出         | 加工结果连同出处导出后，可以在外部写作或笔记工具中使用                                                                                                                                                                         |
| 用4  | 入口一致             | 同一项业务在 Web、命令行和 MCP 上都能完成，结果一致；人只用 Web 能走完从选取文献到核对、导出结果的全过程                                                                                                                       |
| 可2  | 证据不失效           | 文本更新、过期和回收之后，有效结果的证据引用仍然指向原来的内容，或者明确显示已失效                                                                                                                                             |
| 规1  | 查询不触发扩充       | 空库、缺全文、缺加工结果、证据失效和索引不可用时，查询都不联网、不调用模型、不创建补库任务                                                                                                                                     |
| 规4  | 领域通用             | 用至少两个差别明显的学科的文献走完收、读、炼、用，不需要为其中任何一个学科修改产品规则                                                                                                                                         |
