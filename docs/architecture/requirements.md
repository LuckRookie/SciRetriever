## 1. 产品目标

SciRetriever 是科研 Agent 系统中的文献材料与知识服务组件。核心目的有两个：提供可靠、可追溯的原始知识材料；对大量文献形成有证据的压缩知识，帮助 Agent 在有限上下文中理解、比较与总结知识。

系统还提供通用提取能力，使调用方按自己的记录定义、结构和策略形成带证据的候选数据；最终领域数据集与机器学习由下游负责。

2026-09-26 Owner 澄清：有效获得真实且属于目标论文的 PDF 是非常重要的能力，获取成功不能由链接、元数据或浏览器动作代替。解析、分析和提取以已有合适材料为前提；这一数据前置不把获取提升为统领其他模块的整体中心，也不缩减其他已确认能力。已有或人工提供的材料同样可以独立进入后续处理。

获取、分析与提取可以独立使用。系统应支持从简短概览展开到具体证据和原文，让使用者可以核对解释。原始材料、可读文档和分析产物共同在统一文献库中持续积累、查询和复用，数据库是可靠基础，知识供给是产品目的。

上层科研 Agent 决定研究目标与整体推理，SciRetriever 负责文献操作、材料与知识产物的完整性。人类是正式使用者，通过独立完整的 Web 围绕文献库查询、选择和操作，也能配置、观看浏览器并自愿介入。按 [ADR 0032](decisions/0032-library-centered-web-workspace.md)，文献库是 Web 的中心，不以固定处理管线组织使用流程；日常加工、连续阅读和证据核对同属正式职责，阅读交互细节后续专项设计。按 [ADR 0033](decisions/0033-machine-interfaces-cover-web-capabilities.md)，CLI/MCP 分别覆盖 Web 的业务能力，阅读器等视觉交互由 Web 提供，维护和特殊操作可留在机器入口。既有书目交换能力保留，本轮不要求 Zotero 插件兼容。

按 [ADR 0028](decisions/0028-query-and-expansion-separation.md)，数据库查询与扩充是两类独立产品操作。查询只消费已有内容并报告缺口；每次增加元数据或 PDF 全文的任务由用户明确开启，不能由查询、分析问题或提取缺口自动触发。用户启动一个有界批量任务后，系统仍可自动执行该任务，不要求逐篇确认。

## 2. 用户与使用场景

主要程序消费者是科研 Agent；研究者和操作者通过 Web 独立完成日常文献与知识操作、连续阅读和证据核对，也能配置、监督与纠正执行方向。

- 按主题或种子文献有界发现与获取原始材料；
- 无需模型总结就能读取已有论文、正文和相关资源；
- 快速浏览大量论文概览，按需深入单篇或针对研究问题分析；
- 在明确文献范围内比较共识、分歧、适用条件和局限；
- 在上下文预算内获得相关知识，并沿引用展开原始证据；
- 外部 Agent 或程序按调用方定义的内容批量提取记录，复用材料、证据和结果交付接口；
- 从开始到结束观看 AI 操作真实浏览器，愿意帮助时直接操作或提供指导；无人介入时也能得到明确的自动获取结果；
- 人类与 Agent 查询、读取同一材料及分析结果，失败或中断后复用已有成果。

## 3. 用户输入与产品输出

### 3.1 用户输入

输入包括领域条件、种子文献、明确文献/版本或查询范围、用户提供的材料、分析用途/研究问题、处理意图与读取上下文预算，调用方定义的提取内容/记录结构和策略，以及人类针对当前浏览器流程的指导。范围、处理意图与已有结果读取应当可以区分。

### 3.2 产品输出

1. 原始知识材料：文献身份/版本、来源元数据、原始文件和获取来源；
2. 可读取文档：从原始材料转换的正文、结构与资源，明确属于解析表示，并可定位证据；
3. 压缩知识：单篇概览、详细分析、问题相关结果和指定文献集合的综合，绑定输入、证据与生成方法，表达局限与覆盖；
4. 知识访问结果：有界检索、上下文和继续展开引用；
5. 操作反馈：本次执行结果，以及人类可理解的真实浏览器过程、指导受理和控制状态；
6. 提取交付：绑定调用方规范、材料和证据的候选记录与通用检查结果，其领域含义及最终接纳归下游。

所有输出共用同一文献身份、来源和材料事实；不同界面不得形成隔离的知识结果集合。

## 4. 核心工作流

```text
科研 Agent / 人类的意图 + 当前文献事实
  ├─ 发现：领域/种子 → 多来源有界检索 → 元数据与发现原因接纳
  ├─ 材料：明确范围 → 获取原始文件 → 可选解析 → 独立读取文档/资源
  ├─ 分析：选定材料 + 用途/问题 → 有界分析与压缩 → 有证据的派生产物
  ├─ 提取：调用方规范 + 材料/证据接口 → 外部策略提取 → 候选交付 → 下游领域接纳
  ├─ 知识读取：问题/范围/预算 → 检索 → 上下文 → 证据/原文逐层展开
  └─ 人类协作：配置；观看当前 Browser → 指导/必要接管 → 交还 → 统一验收
```

查询路径只读取已有文献、材料和知识，缺口作为结果返回，不创建扩充/加工任务。元数据发现、补充/导入、PDF 获取/接纳须由用户单独明确启动；发现不自动启动全文获取。明确的维护命令可以执行其已声明的扩充步骤，普通查询或独立分析/提取不能借“确保目标”补入外部材料。已有材料的解析/分析/提取也以显式加工操作发起，结果再供后续查询使用。

## 5. 功能需求

### R1. 发起文献收集

- 用户必须能够提交一组领域条件，批量收集与目标领域相关的文献。
- 用户必须能够提交一篇或一组种子文献，通过引用关系迭代收集相关文献。
- 引用扩展按用户来源优先级逐节点顺延；默认在已启用集合中优先使用已配置凭据的 API，再使用无需密钥的免费 API，不因凭据存在自动启用来源。空结果、局部记录或目标错误不得中断其它目标与分支；某来源无法继续时保留失败并尝试下一独立来源。两层扩展必须在用户边界内处理第一层接纳的所有节点，再统一去重；未完成或存在缺口时不得把阶段数量表述为完整两层结果。
- 每次访问外部来源的主题搜索或引用扩展必须具有明确输入和停止边界，并保存本次发现条件、来源结果摘要、实际发现的文献和发现原因；普通本地数据库查询不需要形成这种外部发现记录。
- 外部发现和 PDF/内容补全必须能够分别发起。一次发现只负责把满足最低身份条件的元数据结果接纳到数据库并保存发现原因，不自动下载 PDF、解析或启动语言模型总结。
- 引用扩展获得的相关文献必须先按普通元数据规则进入数据库，再与来源文献建立引用关系；供应商记录 ID 或无法可靠识别目标的原始文本不能直接成为数据库中的文献关系。
- 供应商一次返回的大量引用关系不得无条件把全部目标创建为文献或触发递归；只有进入用户指定方向、深度和数量边界的目标才继续取得元数据并按普通规则入库，未进入当前范围的供应商关系可以留待后续扩展。
- 同一发现条件可以再次执行以补充新文献；PDF 或内容缺失通过独立数据库补全操作处理，不要求恢复或依附上一次发现运行。
- 系统必须保留文献由何种收集方式、哪些条件或哪些引用关系发现，使用户能够理解文献进入数据库的原因。

### R2. 多来源元数据搜索

- 系统必须能够在一次领域发现中查询多个已配置的文献元数据供应商；每个供应商分别运行到结果耗尽或达到该供应商的本次原始扫描上限。过滤、身份准入和去重前返回的每条原始结果都消耗该上限，不能仅按最终接纳数量限制搜索。
- Metadata 与 Acquisition Source 必须分别支持版本维护的默认安全选择和用户指定的精确选择。未固定列表时使用当前版本可离线确定的默认集合；固定列表时严格保留用户的集合并允许为空；Metadata 主题搜索按所选顺序；引用发现 Auto 在已选集合内优先已配置凭据的 API，Custom 保留精确顺序；Acquisition 以各阶段的用户顺序为基础，仅在出版社 API 阶段按唯一名称候选稳定优先。默认集合不得通过启动时联网探测、凭据是否存在或临时服务状态推导；凭据存在不能暗中启用 Search 或 Download。Metadata 只配置一个正整数逐 Source 原始扫描上限，默认 500，独立应用到每个参与的 Source；它不是所有来源共享的总量或 HTTP 请求次数。
- 对已经正式接入且具有领域元数据检索能力的供应商，用户必须能够选择启用并在同一次领域发现中共同查询；供应商只覆盖特定出版社、学科或索引范围时，由该供应商返回自己的结果，不要求用户先根据出版社逐篇路由元数据搜索。
- 系统必须保留各供应商成功返回的结果；单个供应商失败不得使其它成功结果失效。
- 出版社名称治理必须保留来源原文，以明确别名与确定性规则优先解析。用户可以显式按范围汇总未知/冲突名称，并选择 AI 提出有上下文、输入 hash 与模型来源的候选；建议不自动生效，需另行明确接纳并检查冲突后写入可纠正的普通配置。名称结果只帮助提出服务候选，不证明具体文章的访问权限；治理不成为入库或每次下载的模型前置步骤，不要求期刊预先登记。
- 系统必须把不同来源中代表同一文献的结果收敛到同一文献记录，同时保留来源差异和来源信息。
- 系统必须允许元数据不完整的文献先进入数据库，并在后续明确发现或补充操作中继续完善。
- 元数据发现阶段只要求非空标题或 DOI 至少存在一个，不负责证明文献与目标领域语义相关。产品不要求在这一阶段使用语言模型、搜索分数、关键词命中、摘要分类或连续低收益规则过滤或提前停止；后续最终关键词和数据库查询用于帮助用户判断与分类。
- 一篇文献具有可用实际内容但偏离最初搜索主题时，仍然是有效文献，不能因此被解释为没有实际内容或自动删除。
- 一次领域发现完成后，不得仅因为某篇文献已经被发现，就自动对它再执行一轮全部供应商的逐篇精确补查；新的外部补充由用户后续明确发起。
- 系统必须按文献中的署名顺序保存结构化作者信息，并在来源明确提供时保留姓名组成、ORCID、署名单位及其 ROR。缺失信息不得根据姓名或单位名称猜测；当前产品不要求建立跨文献的全局作者身份或作者消歧系统。
- 对需要 API key、token 或其它认证材料的供应商，用户必须能够安全配置或移除凭据、查看哪些供应商已配置或缺失必要凭据，并显式执行最小只读连通性测试。凭据和测试结果不属于文献数据库；本地字段存在、认证成功和具体内容授权必须能够区分。
- 普通运行配置必须固定为同一用户级文件；用户从不同工作目录运行时必须得到同一配置，可以通过统一配置入口管理，也可以直接编辑该文件。普通配置与凭据必须继续分离；系统不得要求用户理解环境变量或当前目录优先级，也不得从多个旧位置猜测并自动迁移配置。
- 统一配置入口必须把模型连接、模型选择和任务使用分成三层。`Provider` 只保存本地名称、API 协议、Base URL 与 exact-origin API key 作用域；`Model` 以唯一 `provider/model` 身份保存思考程度、是否可读取图片以及是否使用流式响应；`Analyze` 与 `Browser` 只选择 Model 和管理各自业务参数，不重复配置 Provider、key、远端 model、reasoning 或 stream，也不得因一次选择而修改 Model 或另一个任务。思考程度必须包含 `default/none/minimal/low/medium/high/xhigh/max`；`default` 必须省略 wire 字段，显式值不得静默降级或映射。`stream` 必须默认 `true`，并由 `openai-responses`、`openai-chat-completions` 与 `anthropic-messages` 三种协议共同继承；用户可以在具体 Model 将其关闭。流式响应必须在 Agents 私有边界内从有界 SSE 重建为一个完整结果，不把事件流暴露给消费模块；任一模式失败后不得自动切换模式补发请求。context/output、structured output、tool decision、图片格式/数量/大小等调用合同必须由消费模块拥有并通过显式 probe 验证，不能要求用户把这些内部技术值录入 Model。Browser 只允许选择图片 Model，其开关、Model、固定身份 Profile、本机并发和通用 policy 收紧统一保存在一级 `[browser]`；`[download]` 只管理 Acquisition Source。模型 Provider key 必须由 `Models` 管理；Metadata/Acquisition Provider 的普通设置、key 和 test 必须归属于 `Search`/`Download` 中的具体 Source 对象；MinerU endpoint、上传授权和 token 必须由 `Parse → Setup` 连续管理。不得建立职责重叠的全局 key 页面，secret 只进入独立凭据文件。新增远程 Provider/Model 时必须在同一流程隐藏输入 key，并自动执行一次有界只读模型目录请求；只有目录失败或无可用结果时才回退手工输入。首页、状态查看和普通命令不得隐式发起该请求，目录结果不得持久化或被当成 capability 证明。配置不得建立 Model Profile、Preset、Entry 或任务级 reasoning/stream override；保存前必须展示不含 secret 的配置摘要。
- 配置测试必须继续归属于 `config`，并按 `Provider / Model / Search / Download / Parse / Analyze / Browser` 的 owner 语义组织；交互 TUI 与结构化 CLI 必须调用同一套不含 Storage 的 Probe 服务。配置测试只验证当前最小 readiness，不创建或修改文献业务事实。人类结果必须紧凑地优先显示测试对象、本次安全请求 method/endpoint、实际 Model、结果、失败原因和下一步，不得只显示内部错误码；能够安全确认的 HTTP status、Network 类别和 Provider 结构化错误类别可以进入当次结果，但 Key、header、query、响应正文、供应商任意 message 和原始异常不得进入。证据只能说明“Model 或 endpoint 不存在”时不得擅自断言一定是 Model 名错误。Provider 目录不能替代具体 Model 调用，Download 没有安全且与具体文献无关的外部 probe 时必须明确报告 unavailable，不能借用 Metadata probe、下载任意 PDF 或声称文章 entitlement 已验证；真正的 Search、PDF 获取、Parse/Analyze 能力分别由 `discover topic`、`complete pdf`、`complete content` 的正式业务路径验证。

### R3. 文献资产获取

- 系统必须能够使用已收集的元数据信息寻找并下载对应文献资产。
- 自动获取依次执行已有 PDF 直链/稳定公开地址、出版社专用 API、聚合/开放获取通用 API、公共网站与 Browser 五层；是否需要凭据与执行阶段分别表达。每篇完成当前层后才推进自身的下一层；不同文章在有界执行槽中独立推进，完成一篇即可补入下一篇，来源同层以配置顺序为基础，出版社 API 可按唯一名称候选稳定优先，已选但不可用的来源保留失败。任一层取得文件后立即进入统一检查与发布，有效文件不重新排队或重复下载。
- Direct 可以依据明确 PDF 线索或 URL pathname 中忽略大小写的 `.pdf` 后缀发现候选，保留查询参数并按既有规则处理阅读器 fragment；没有后缀但明确为 PDF 的地址仍可用。明确补充材料、其它资产角色和目标版本冲突须在候选选择时排除，已登记授权 API 地址仍交所属适配器，不扫描任意外部 URL。
- 任一获取来源的 HTTP/API 请求、认证、权限、限流、服务或外部响应格式失败，只影响该来源；保存原因后继续独立的已配置渠道及已获准 Browser。限流停止本来源的剩余候选并遵守共享额度组/平台冷却，不能切换入口绕过；候选 URL 或 PDF 不合法只拒绝该候选。重试本来源与尝试其它来源分别判断。后续成功则接纳 PDF，后续全部未取得 PDF 则保留故障，不误记自动耗尽。取消、存储/发布和内部合同错误保留停止语义，见 [ADR 0015 §7](decisions/0015-publisher-aware-tiered-pdf-acquisition.md#7-升级暂停与熔断语义)。
- 自动获取必须根据文献的稳定标识符、来源明确提供的资产线索、供应商专属定位或安全解析后的实际落地站点选择适用来源，不能仅依据不统一的出版社名称、元数据来自哪家聚合供应商或单独 DOI 前缀盲目调用出版社 API。能够提供元数据和能够提供原文是两项独立能力，同一家供应商可以同时具有两者。
- Sci-Hub Source 必须默认关闭。用户显式启用后可以直接使用随版本维护的内置有序镜像列表，也可以用自己的有序 HTTPS 列表完整覆盖；恢复内置列表必须删除而不是复制 custom override。系统不得自动发现或并发轰炸镜像，也不得为该 Source 增加 Key、Cookie、session、selector、脚本或访问控制绕过配置；它的出口与其他来源一样，按统一的出网选择决定直连或经代理（[ADR 0056](decisions/0056-outbound-proxy-by-requester.md)）。内置列表可随版本维护，但不得改写用户的 custom override。
- 当最后的受控浏览器路线进入站点验证页时，系统必须把它作为普通网页状态纳入与文章页相同的 Observation、动作执行、捕获和清理合同，并允许已经核实的必要验证资源在当前固定 Profile、当前文章流程和同一供应商串行许可内正常加载。系统必须把“Challenge page observed”“Challenge cleared”“Challenge unresolved”“本地 Network 策略阻断资源”和“普通访问被拒绝”分别反馈。Challenge 清除后仍须继续执行文章访问、当前任务关联和 PDF 文件验收，不能把验证页通过等同于当前文章已经获得全文访问权。
- 受控浏览器必须只使用通用 Agent controller，不得要求目标先命中 Publisher 点击规则，也不得保留 Rules controller、Publisher-specific 页面程序或失败后的隐藏 fallback。Agent 从每一份稳定且绑定当前文章的 Browser Observation 只决定下一项封闭动作；模型不能取得浏览器、Cookie、登录材料、任意 URL、selector、脚本、持久 memory 或事实写入能力，也不能宣布下载成功或绕过共享 `browser-generic` 聚合政策、同平台网络串行与结束后 30 秒冷却、Network 安全边界、实际资源保护及统一 PDF 文件验收和当前任务关联。不同平台允许独立 worker 并行，文章 session、页面/弹窗、transfer 和 candidate 归属不能随前台切换改变。Challenge 与普通页面共享 Observation、动作、capture 和终态合同，不产生专属 target、动作、controller、预算或交互状态机。
- Browser 首次模型派发前必须复用已有访问结果准备有依据的有限文章入口，不新增必经 HEAD/GET 检查。下载端点与文章落地页分别保留；普通 HTTP 403/404 不成为 Browser 的永久坏链判定。Browser 实际导航明确 404/410 或 DNS/连接失败时，可以在同一逻辑任务、剩余预算与平台准入下尝试备用；先结算真实在途下载，首次模型派发后不得在模型背后自动换入口。
- Browser Agent 动作结束至下一轮模型决策至少 5 秒，与页面反馈等待重叠。单篇默认累计活跃时间为 300 秒、真实模型派发最多 30 次，先到上限即停止进一步探索；默认不设独立动作上限，保留动作统计。等 worker/模型许可、平台冷却、人工接管、后台下载及本地验收/发布不计入活跃预算，开页、观察和主动反馈等待消耗活跃时间，备用入口、恢复与人工交还不重置 clock 或计数。模型请求尚未实际发出不能计 call；最后一次合法调用允许完成动作、既有有界页面反馈及下载交接，时间和控制版本检查仍有效，迟到或过期动作不能执行。该预算以约 90% 的经验验收目标覆盖大多数正常任务，接受复杂或当前无权限任务未完成，不承诺实测成功率；预算耗尽不推断永久无权限或全渠道耗尽。默认两个独立 worker、五个保留会话，每会话最多一个主下载；实际限制与旧显式串行意图由同一配置 owner 执行并展示。
- 下载开始后暂停该篇模型决策并让出 worker，保留原页面。传输、文件检查或操作内排除 hash 失败后携带原因与剩余预算恢复；文件有效后沿原 acceptance/publication 发布，不能因本地 publication 失败重新下载。Browser 先交付候选，Entry 确定 publication 结果后结清会话，不得互相等待尚未能开始的调用。已提交资产不因页面清理失败回滚；取消单篇不取消其它文章或关闭共享 context。目标合同见 [ADR 0023](decisions/0023-generic-browser-agent-executor.md)、[ADR 0030](decisions/0030-browser-transport-and-progress.md)，实际交付状态以实现和验收记录为准。
- 用户必须能够明确选择一篇具体文献并提供本地 PDF。系统复制而不是移动用户文件，对内部副本执行与自动获取相同的基本 PDF 检查，并且绝不修改或删除用户原文件。
- 手动提供的有效 PDF 通过正常资产关系进入数据库，但不属于自动获取来源顺序；无效文件作为用户输入错误拒绝。已有当前主 PDF 时默认拒绝手动接纳，不能静默替换。
- 一篇文献可以具有多个资产或多个可能来源，系统必须明确资产与文献的关系。
- 下载阶段只对 PDF 做必要的文件检查：实际字节非空；根据字节而不是扩展名、文件名、HTTP `Content-Type` 或下载事件确认其为 PDF；标准 PDF reader 能够打开；页面树可读取且至少有一页；获取路径关联当前目标文献任务。按 [ADR 0029](decisions/0029-unverified-pdf-acquisition.md)，下载阶段取消 PDF 内容的文章身份校验；有效 PDF 正常入库并标记“文章身份未验证”。DOI 缺失、排版差异、无可提取文字或与元数据的内容标识符不一致均不阻断下载。身份检验可在后续解析阶段增加，解析成功本身不把标签变为已验证。需要密码但没有可用密码、因而无法读取的加密 PDF 不能通过检查；轻微不规范但仍能正常打开和读取页面的 PDF 可以通过。
- 下载阶段不得设置固定最小字节数、最小页数或正文字符数，也不判断 PDF 是否具有正文、摘要、目录、封面或足够的学术内容。
- 材料是否足以支持某种分析由分析阶段说明；分析不适用、仅有部分内容或模型失败不能单独授权删除已接纳原始材料。错误文件/错误文章的拒绝、资产失效和删除须有独立明确规则，不能将模型的内容判断直接等同于清理授权。
- 已接纳有效资产必须在后续重跑中保持可用，不因重复收集或分析失败被无声破坏。
- 对一次主 PDF 获取，产品业务结果只区分“已经获得”与“没有获得”；没有获得时不要求长期保存网络、来源或候选级原因。数据库或文件系统无法安全提交属于系统失败，不能伪装成“没有获得”。
- 当系统已经正常遍历某篇具体文献在当前元数据和已配置自动能力下的全部 PDF 获取路径、仍没有获得主 PDF 时，数据库必须把它标记为需要用户人工提供 PDF。全库自动补全默认不再反复选择这种文献；新增可用于获取的元数据、成功接纳主 PDF 或用户明确要求重新尝试时，必须解除该标记。
- 用户中断、网络或 API 临时错误、权限或配置错误、数据库或文件系统错误，以及尚未完成全部自动路径时，不能把文献标记为需要人工提供 PDF。这些情况只属于本次操作没有完成。

### R4. 文献解析

- 系统必须独立解析受支持资产，提供人类和 Agent 可读取的正文、基本结构与实际引用资源；无需等待总结成功。
- 解析表示必须与原始材料区分，保留输入与解析来源；不得把提取文本当作原始文件字节。
- 可读表示支持有界章节/片段/资源读取和 R9 的证据定位；不要求使用者理解 parser 私有协议。
- 摘要、全文缺失、截断、乱码和部分解析应准确说明；单篇失败不阻止其它文献，解析失败不删除原始资产。
- 保留图片或表格资源不等于已经解释其科学含义；超出当前文本分析覆盖时明确限制。

### R5. 语言模型内容判断与总结

- 系统必须提供有证据的单篇概览、详细分析、问题相关分析，以及明确文献集合中的综合。不同粒度和用途不得静默互相覆盖成一份含义模糊的最终结果。
- 概览帮助筛选，详细分析保留研究问题、方法、数据/论据、结论、条件与局限；问题相关分析明确所针对的问题；跨论文综合保留共识、分歧、适用条件差异、输入范围与知识缺口。
- 压缩不承诺无损。影响结论的重要条件、否定信息、数值、单位、公式及来源必须忠实；缺失与无法判断明确表达，不编造证据或把局部材料描述为完整全文分析。
- 分析要点可以展开到支持它的材料片段，结果绑定具体输入版本、用途、生成方法与覆盖；引用可解析与科学解释正确分别验证。
- 固定输入的解析、总结、长文分析和综合不设置业务 token、调用次数或总时长预算；长文按输入执行有限分块/整合并记录真实成本。取消或局部失败不能伪装完整处理。机器验证格式、真实引用目标和版本/hash，不以逐字匹配、条件原句或共识/分歧条数规则替代模型语义判断。
- 分析成功不自动修改文献身份或覆盖可靠来源元数据；确有元数据补充时仍由 Literature 的独立规则验收。分析失败不损坏已接纳材料及有效旧结果。
- 知识结果提供稳定结构化读取与适用的人类可读表示。既有七标题 Markdown/两阶段单篇格式作为兼容产物保留，不作为全部新分析的唯一模板或完成条件。按 [ADR 0037](decisions/0037-literature-archive-and-proofread-text.md)，该兼容格式将由建档与普通的总结算子取代，并在实施计划中退役。
- 文献参考文献原文继续保留；从中提取的临时查找线索不能直接变成权威目标或引用关系。
- 原文、解析文本、模型解释和跨论文综合必须可区分。当前 LLM `NoUsableContent` 自动清理实现需要按 R3 修订，不能据旧行为改变新需求。

### R6. 文献数据库

- 产品面向长期持续积累，文献库以万篇文献起步并持续增长；几百篇或少量样例不是产品的容量目标。规模涵盖元数据、已取得的原始资产、可读文档、派生产物和来源关系，允许各篇文献完成度不同。单次请求、扫描或执行批次的资源预算不得被当作文献库总量上限。
- 主题收集、引用扩展、书目导入、内容处理、查询和导出必须使用同一套持续积累的文献数据库，不能各自形成彼此隔离的文献结果集合。
- 文献数据库允许长期存在完成度不同的文献。用户必须能够不重新执行外部发现，直接针对整个数据库、一次历史发现、一次导入、查询结果或明确选择的文献补齐缺失主 PDF、可读文档或所需分析产物。
- 用户必须能够在数据库中查找和检查已经收集的文献；查询与扩充为独立入口，共享同一数据库，不要求先开启扩充任务。
- 查询遇到空结果、缺元数据、缺 PDF 或缺知识产物时只报告缺口；不得自动外部搜索、下载、生成或排队补库。每次扩充任务须由用户明确开启；一次有界任务内可自动处理多条记录，普通 Agent 查询不获得自主扩库权限。
- 本地文献查询只读取已经接纳的数据库事实，不得隐式访问元数据供应商、创建外部发现运行或修改文献数据库；不同供应商对同一具体文献的来源记录不能制造重复查询结果，同一文献的不同明确版本仍须作为不同具体文献供用户区分。
- 每篇文献必须能够看到当前元数据、有序作者/已获得的标识与单位、原始资产、可读表示、已生成的分析类型及引用关系；不同产物的输入版本和有效性清楚。
- 用户打开一篇具体文献时，必须在同一一致读取中看到该文献的当前元数据及来源、版本上下文、当前主 PDF、可读表示与各用途分析的输入/有效性、所选处理目标的下一缺失步骤、是否需要人工 PDF 以及本地已确认引用数量；大型文件字节和可能无界增长的引用边可以通过独立读取获得。
- 已经确认的引用关系必须能够追溯到元数据供应商明确返回的结构化关系，或供应商、PDF 中的具体一条参考文献原文；多个来源支持同一关系时不得制造平行引用关系。
- 参考文献原文已经保存但尚未可靠解析到目标文献时，原文必须继续可用且不得建立错误关系或占位文献；后续运行可以再次尝试解析。
- 用户必须能够区分各类信息当前是否已经获得、哪些内容仍然缺失，以及哪些缺少主 PDF 的具体文献已经正常耗尽自动获取能力并需要人工提供文件。本次操作中的普通处理失败由该次操作的报告说明；日志只提供实时进度和诊断，不能替代报告，也不要求成为数据库中的长期文献事实。
- 数据库必须支持持续追加和补全，而不是要求每次重新建立全部结果。
- 再次运行收集或处理时，系统必须以数据库中已经确认的结果为基础复用已有内容，并从仍然缺失的部分继续。

### R7. 书目信息导入与导出

本项降为既有兼容能力，不再驱动主线架构或 Zotero 深度集成。以下已支持交换语义继续保留，未因此删除。

- 用户必须能够把 Zotero 等主流文献管理工具中的书目信息导入文献数据库。
- 用户必须能够把文献数据库中的书目信息导出到 Zotero 等主流文献管理工具能够使用的格式。
- 文献经过元数据信息收集并形成可用的统一书目信息后即可导出，不得把全文获取、解析或语言模型总结完成作为书目导出的前置条件。
- 产品必须覆盖主流文献交换格式；具体格式范围由后续产品设计明确。
- 导入的文献必须能够与通过主题或引用关系收集的文献共同查询和继续补充，不形成彼此隔离的结果集合。
- 每条带来新来源事实并通过接纳的导入记录必须作为该文献的一项独立来源事实保留；其中非空书目信息优先于供应商来源，供应商只能补齐导入记录缺失的字段。重复导入相同信息只形成 matched，不得持续制造重复文献或重复来源事实。
- 新导入信息不得使已有知识产物与其记录的输入发生错配；旧单篇内容按兼容合同保持整体接纳，新知识产物依其输入版本标记有效性或重新生成。
- 产品不要求长期保存原始书目文件、文件路径、外部工具对象、外部工具记录 ID、导入批次历史或其它导入导出过程来源细节；数据库只需保留“该元数据由用户通过书目导入明确提供”这一最小来源事实。

### R8. 大批量处理

- 产品必须面向一批文献运行，而不是只支持逐篇手工处理。
- 大规模积累的验收必须覆盖至少万篇文献及其材料关系，检查持续增量接纳、重复来源收敛、缺失内容补全、处理中断后的继续、局部失败隔离及库内查询。记录所用数据、运行时长、吞吐、内存、磁盘和外部调用成本；小样本流程通过或单元测试数量不能代替规模与长期运行验收。具体性能阈值、常驻运行方式和更大规模边界由后续设计与实测确定，不据本条宣称当前实现已通过。
- 每次批量补全开始时必须在当前操作期间冻结实际目标；运行期间后来进入数据库或范围的文献不动态加入本次操作。不同目标可以有界并行，每个目标都必须从当前第一个缺失步骤继续并保留已经确认的前序事实；具体阶段如何在批量目标之间协调由 Accepted 设计在不改变冻结范围、局部成功和报告边界的前提下决定。
- 普通发现、查询或全库范围按同一文献的明确版本组去重，默认只要求至少一个版本达到目标。系统优先复用完成度更高的版本；完成度相同时优先正式发表版、作者接受稿、预印本和其它版本。
- 只有某个版本已经稳定缺少主 PDF，或者经独立材料有效性规则确认当前版本不可用且其余候选也已耗尽时，才尝试同一文献的下一版本。网络或存储系统错误、解析失败、语言模型失败、取消和无法判断不能证明版本不可用，也不能触发跨版本回退。用户明确选择具体版本时不回退到其它版本。
- 批量运行必须保留已经成功完成的文献，局部失败不能回滚整批有效结果。
- 中断或失败后，用户必须能够再次运行相同流程；系统必须根据数据库中仍然有效的结果继续补充缺失内容，而不要求重建已经完成的外部调用现场，也不制造无意义重复。
- 每次元数据发现、数据库补全、手动 PDF、书目导入和导出等用户发起的处理操作都必须向用户给出操作特有的本次运行报告。PDF 获取、Parsing 和 Analysis 作为数据库补全阶段时，其完成、分析不适用、材料缺失和失败必须在同一补全报告中可区分，不要求为内部阶段再套一层报告；纯查询结果本身就是读取输出。报告至少应说明本次实际选择、完成、稳定缺失、普通失败、未开始或受控中断的大致情况，以判断是否需要继续处理。
- 运行报告必须独立于逐条日志形成；日志只提供实时进度和诊断，不能被解析成报告或业务状态。二者都只描述本次操作，不要求长期保存为批次历史，也不参与下次目标选择。正常结束、普通失败和用户受控中断应尽可能返回已经形成的报告；断电、进程被强制终止等无法执行收尾逻辑的情况不保证产生最终报告，已经提交的数据库事实仍然有效。

### R9. 可定位证据与材料生命周期

长期加工结果应独立保护所引用的材料和上游结果，不随临时提取回执过期失去证据；新运行不得改写旧结果引用。

- 人类和 Agent 能从知识要点读取对应原文片段，并识别文献版本、原始材料和文档表示；不能只返回无法复核的整篇文件名。
- 文档更新不得让同一证据引用静默指向另一段内容；页码/坐标仅在可靠映射时提供，否则准确说明定位层级。
- 被有效知识产物引用的表示应可读取；保留、失效与重新生成策略必须明确，不以可重建为由无声断开引用。无需无限保留所有中间尝试。

### R10. 知识检索与上下文交付

加工结果应可按集合说明发现，也可按正文和记录字段查找；命中绑定稳定结果/记录引用，索引可重建，查询不得产生隐式模型成本。

- 支持围绕问题、文献范围与上下文预算检索元数据、可读正文和压缩知识；未分析文献仍可检索和阅读。
- 返回去重后的相关材料、来源/证据、内容类型、实际覆盖与截断，并支持从概览逐步展开到原文。
- 相关性不等于科学正确性；多个版本不应夸大证据支持。索引失效不能改变源事实。
- 查询已有知识不得隐式发起外部发现、下载、解析或分析；新的处理是显式操作。

### R11. 科研 Agent 产品接口

CLI/MCP 应通过相同处理器合同提供批量提交、结果读取与查询、证据展开和导出；已有结果可显式作为后续加工输入。

- 模型与 Agent 执行基础统一使用 DSH，覆盖既有单次文本/结构化/图片/工具调用及持续交互能力，不维护并列自建 Agents 后端。替换后的能力覆盖与内容质量分别验证；费用、耗时和调用次数不作为本次内容质量优劣依据。统一底座不改变业务事实、材料与结果接纳的责任，见 ADR 0031。

- 按 [ADR 0033](decisions/0033-machine-interfaces-cover-web-capabilities.md)，同一授权、配置和运行条件下，CLI 与 MCP 分别覆盖 Web 的业务能力。机器入口须支持非交互、结构化操作、结果读取与诊断恢复；PDF 渲染、证据高亮、阅读标签、对照布局等视觉交互及界面偏好无需复制，但相关材料、结果和证据应可读取。三端通过共同应用边界保持语义一致，Web 无需呈现全部运维命令。

- 库内查询工具与扩充/加工工具必须区分。Agent 可代用户执行其明确启动的扩充任务，但不能因自身认为数据库不足就调用扩充工具；query miss 不自动调用 completion、discovery 或 Browser。

- 科研 Agent 可组合发现、获取、解析、读取、分析、范围内综合、检索、通用提取能力及执行控制，不必掌握内部模块或数据表。
- 操作有类型化输入输出、稳定引用、范围/预算、取消/重试及明确副作用；读取与生成、局部结果与完整结果可区分。
- 大型材料按需读取，不默认塞入模型上下文；Agent 不直接获得 SQL、凭据、任意 Browser/脚本或底层发布能力。
- 同类操作在人类与 Agent 入口有相同业务语义；外部 Agent 会话不是文献事实或恢复依据。

### R12. 人类配置、浏览器协作与阅读接口

- 按 [ADR 0035](decisions/0035-authenticated-remote-web-access.md)，个人工作台默认允许通过服务器 IP 和端口访问，只有一种启动与登录方式，本机访问也须认证。指定密码则使用该密码，未指定则在成功启动的终端输出中显示自动生成的 API key；不要求配置公开 origin 或执行交互式启动设置。查询、资料、配置及写操作共用访问边界。本轮不要求账户体系、域名或 HTTPS 部署。

- Web 是面向人的独立完整操作入口，CLI/MCP 主要面向 Agent 与自动化调用。Web 首次启动无需配置向导或预先执行 CLI 初始化：缺省文献数据库与资产位于 `~/.sciretriever/`，用户可随后修改位置。已有显式路径优先，三个入口使用同一份配置与逻辑文献库；首次建空库不得覆盖、升级或搬迁已有数据。

- 文献库是主空间，用户围绕单篇、选中项或明确查询范围执行操作，不被绑定到固定加工顺序。主界面保持简洁，不默认设置“缺 PDF”“需人工 PDF”等待办分区或反复要求帮助 Agent；材料可用性与问题可在记录、详情和可选筛选中查看。任务进展辅助库内操作，日常加工与阅读服务分别形成完整体验。

- Web 应覆盖发现与导入、文献查询、PDF 获取与补充、解析、分析、批量标签、记录提取、综合、结果查询和导出等日常业务。用户能在 Web 配置问题、记录含义、字段与处理范围，提交后读取结果集合、按字段筛选和排序、核对证据、选取结果继续加工及导出；普通业务不以 CLI 或手写底层 JSON 为必经步骤。
- Web 的任务反馈须能打开对应结果，区分执行状态、实际覆盖、复用、失败和未处理。普通失败原因、常用配置补全及显式重试在 Web 内可理解、可操作；数据库迁移、损坏修复、底层诊断、批量脚本及实验性操作可由 CLI 或受控机器入口承担，并通过稳定引用衔接。

- 查询阅读与数据库维护具有清楚的入口和副作用说明，可以在同一页面围绕同一文献组织；“库内检索”不等于“外部文献发现”。由用户主动启动扩充；打开详情、点击证据展开或查询无结果不启动收集，不以缺口提示强制用户立即加工。

- 人类必须能在 Web 管理项目设置、凭据及显式测试，清楚看到保存结果、实际生效对象和失败下一步；界面复用同一配置 owner。
- 人类必须能从开始到结束观察同一生产 Browser 获取流程：目标文献、真实页面、动作结果、等待/失败和候选验收，而非另一个演示浏览器。
- Browser 是 Agent 操作界面：默认观看，不因观看而暂停；人愿意帮助时可以在同一画面直接点击或输入，自然触发控制权交接。指导是可选能力，受理/生效/过期可辨；自然语言指导与网页文字输入是不同操作。
- 若接管页面操作，同一时刻只有一个动作控制者；人工输入须在服务端确认控制权及当前文章、会话、页面绑定后执行，过期点击不重放到新页面。接管前过期决定不能迟到执行，交还后 AI 重新观察。已在途动作如实处理，不假装撤回；人工得到的文件仍统一验收。
- 自动获取不要求人类在线或配合；无法继续时按本次实际结果结束并反馈，用户可稍后从对应文献主动上传 PDF。自动路线正常耗尽、临时失败、探索限制、取消与未尝试须区分，不能一律变成持久“无法获取”或必需的人工待办。主动人工介入后的暂停与恢复另按控制协议执行。
- 人类可查询、阅读同一数据库的原始材料、可读表示和分析/提取结果，沿证据回到来源；无需发起加工即可阅读已有材料，阅读不隐式生成。
- 基础阅读支持 PDF 翻页、缩放、目录和文档内查找，以及解析全文的章节、正文、图片、表格和公式呈现；实际材料不具备的导航、文本或资源能力须明确反馈。多文献切换保留各自阅读位置，阅读空间提供合适的字号、行宽、主题和可收放辅助区域。
- 阅读同时服务连续阅读与带问题核查：用户能从检索、综合结论或提取字段进入正确版本的相关来源，查看必要上下文并返回原结果；不能伪造证据页码、坐标或高亮。材料或证据无法精确定位时明确说明，不用任务完成状态替代阅读可用性。
- 阅读位置、缩放和布局是 UI 状态；后续保存的批注、笔记等内容属于用户数据，应有来源、稳定保存、导出及同等授权下的机器访问。批注与笔记的归属、锚点、保存与机器访问见 [ADR 0046](decisions/0046-reading-marks.md)；选段翻译见 [ADR 0049](decisions/0049-reader-translation.md)；术语解释另行设计。
- 观看、指导、取消、断线/重连和切换文章有可解释反馈；指导不泄漏到其它文献，也不扩大模型权限。
- 已确认实时全过程可观察；按 ADR 0032 已确认的目标体验，用户主动关闭观看界面以交还 Agent 为目标，须确认交还结果。意外断线与切换文章的恢复、长期录像、截图/指导历史、事后重放期限、阅读器实现和登录/MFA 等人工操作范围待进一步设计，不把关闭画面一律等同于成功交还。

### R13. 通用提取能力与调用方定义的记录

按 [ADR 0034](decisions/0034-unified-processors-and-results.md)，新增可替换的默认标签/记录提取与候选长期托管目标：冻结输入与方法配置、按完整输入复用、分别表达覆盖和执行状态，外部交付仍可独立使用。领域定义和最终数据集接纳不转移给平台。

- 系统必须提供实际可用的材料、证据与结果交付接口，供外部 Agent 或程序按自己的策略批量提取；项目不负责覆盖所有领域的提取算法。
- 调用方定义一条记录代表什么、输出结构、字段解释及纳入条件；平台不固定为一文一条或统一实验实体，也不需要先枚举所有领域。
- 提取可独立消费原始材料和可读文档，不以通用总结完成或选择内部模型为前提。
- 提取器能按需读取正文、表格上下文及受支持图片/补充资源，定位证据并查询能力缺口；平台不能把仅保留图片当作已取得其中数值。
- 候选结果必须关联规范版本、实际材料、证据、覆盖与生产者来源；记录和字段的依据可核对，缺失或未处理不能伪装成实际报告值。
- 结构/证据检查、提取执行完成和领域接纳必须可区分。科学解释、实验记录合并、领域单位规则、最终数据集和机器学习由下游负责。
- 调用方可以替换提取方法并复用通用交付；内部默认模型策略的提供方式另行设计，不成为唯一入口。
- 候选按独立提取产物交付或托管，不成为 Literature 固定领域字段或来源事实；具体存储、保留和接口形式待设计。
- 批量结果准确表达零记录、部分覆盖、失败和取消；重复提交与新版本有明确行为，不能制造伪完成或无声覆盖。

## 6. 产品质量要求

### 6.1 覆盖与部分成功

多来源和两种收集方式的目的在于提高覆盖率。任何单一来源、文献获取、解析或语言模型总结失败时，系统都应尽可能保留其它已经获得的有效结果，并明确指出尚未完成的部分。

### 6.2 一致性

同一文献不应仅因来自不同来源、不同收集方式或书目信息导入而在数据库中无控制地重复出现。系统也不得在证据不足时把不同文献错误合并，或把无法可靠识别目标的参考文献文本直接连接到某篇文献。重复执行相同收集或重复导入相同数据不应持续制造重复记录、重复资产或平行引用关系。

### 6.3 可追溯性

用户必须能够判断：

- 文献由哪次外部发现、哪些领域条件、种子文献或直接引用原因获得；
- 元数据来自哪些供应商；
- 资产从何处获得；
- 可读文档依据哪个原始资产与解析方法形成，知识产物依据哪些文档版本、证据和生成方法形成；
- 已确认引用关系依据哪项供应商结构化关系或哪条来源参考文献原文形成；
- 本次操作中哪些文献未能获取、解析或完成语言模型总结，以及它们在本次运行中的失败边界；
- 哪些文献已经正常耗尽当前自动 PDF 获取能力，用户可选择稍后人工提供文件。

数据库中的长期可追溯性只针对实际接纳的结果、外部发现原因和会影响后续选择的当前事实；普通运行失败进入本次报告，逐候选过程和批量统计只服务本次运行，日志仅提供非权威实时诊断。材料失效/清理遵守 R3/R9，不由单次分析结论直接触发；自动获取耗尽只说明当前自动能力已用尽、可人工补充 PDF，不保存候选、来源或失败原因，也不要求建立人工待办。

### 6.4 数据完整性

已经写入数据库的有效元数据、资产关系和轻结构化文档不得因另一个来源失败、运行中断、重复运行或重复导入而被无声破坏。

### 6.5 知识与交互质量

证据定位正确与解释受证据支持分别评估；压缩需检查重要条件/局限保留、冲突表达与覆盖；检索记录实际样本与预算，不编造召回或压缩率。人类协作需验证正式流程观察、指导生效、控制互斥和交还恢复，不能以按钮存在代替验收。

Web 分别验收日常加工与阅读服务：前者须仅用 Web 从选取文献、配置处理到读取、核对、再次使用和导出结果，并覆盖普通失败恢复；后者须无需加工即可连续阅读已有材料，在多篇文献间保留位置，并从结果往返正确版本的证据。后台处理器成功或 CLI/MCP 已有接口不能替代这两类人类体验验收，详细边界见 ADR 0032/0033。

### 6.6 可扩展接入

增加或替换元数据来源、文献获取方式、解析能力、语言模型服务或书目信息交换格式时，不应要求重新定义产品工作流或文献数据库的基本含义。

## 7. 范围边界

当前核心产品范围包括原始材料、可读文档与证据、多粒度压缩知识、检索/上下文、通用提取接口、Agent 操作接口和人类协作接口；既有书目交换作为兼容能力。同一文献的不同明确版本需要作为同一文献的版本组织，但产品不要求建立引用关系之外的通用文献关系图谱；更正、撤稿和其它供应商关系只有在未来形成明确用户需求时才进入产品数据边界。

产品提供通用文献信息、知识压缩及提取能力。反应、分子、路线、产率、材料性质等领域记录由调用方定义规范并选择策略；其候选可通过通用提取合同交付，但不扩展为文献主库的固定领域字段。项目不内建所有领域算法，领域数据集、预测、规划和机器学习由下游负责。

以下内容不由需求文档决定：

- 内部数据模型、文献标识和版本表示方式；
- 使用何种数据库、文件存储、消息机制或并发模型；
- 供应商调用协议、请求额度和限速策略；
- 使用何种文献获取工具、解析器、语言模型或客户端；
- CLI、GUI、Web API 等具体交互形式；
- 内部阶段名称、状态枚举、表结构和模块名称。

这些内容只有在能够更好地满足本需求时，才由设计文档和技术文档作出选择。

## 8. 产品验收

查询/扩充边界必须有直接反例验收：空库、缺全文、缺总结、失效证据和索引不可用均不触发外部发现/获取、生成调用或补库任务。独立分析/提取缺材料只报告缺口；用户另行明确启动发现或 PDF 维护后，对应批量操作才可运行，正常已授权任务不要求逐记录确认。

库中心 Web 验收还应覆盖：从筛选/选择启动操作、查看结果并回到同一文献、主动补充 PDF；无人观看或介入时获取仍能结束并如实报告。Browser 直接点击/输入须验证控制权交接、页面变化、多窗口竞争、交还和断线，不能只验证按钮存在。界面精简不改变材料状态及失败分类，也不静默取消既有可选协作能力。

满足以下场景时，核心需求才算成立：

| 场景                  | 必须观察到的结果                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 领域收集              | 用户给出领域条件后，全部本次已配置来源分别执行有界搜索；原始结果在过滤与去重前消耗各自扫描上限，满足标题或 DOI 最低条件的结果进入数据库；单个来源失败不撤销成功结果，也不对每条发现结果自动发起逐篇全源补查或在元数据阶段执行语义相关性过滤                                                                                                                                                                                                                                                                                                                                                                                     |
| 引用迭代收集          | 用户给出种子文献后，系统能够通过引用关系继续发现相关文献，并保留文献被发现的关系；供应商一次返回大量关系时只在用户边界内物化目标，不自动无界递归                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 发现与内容处理分离    | 一次外部发现具有独立输入、逐来源结果、发现对象和原因；发现结束不会自动启动 PDF、Parsing 或 Analysis，也不创建领域占位集合                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 参考文献解析          | 参考文献原文可以独立保留；只有目标文献经过元数据接纳并获得本地身份后才建立引用关系，关系保留其具体来源支持，无法可靠解析时不创建占位文献或错误关系                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 多来源搜索            | 至少两个供应商返回结果时，成功结果都被保留，重复文献不会简单按供应商复制成多篇                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| Source 默认与扫描边界 | 空 Source 配置使用当前版本声明的 Metadata/Acquisition Auto 集合且不联网判定集合；切到 Custom 后只运行用户保存的精确集合并允许空列表，Metadata 保持列表顺序、Acquisition 以各获取阶段的列表顺序为基础，出版社 API 可按唯一名称候选稳定优先；Key 的存在不改变选择；Metadata 的单一 limit 分别约束每个 Source 的过滤前原始 item                                                                                                                                                                                                                                                                                                    |
| 出版社名称维护        | 规则与别名归类保留来源原文；范围扫描展示 resolved/unknown/conflict，AI 建议保留输入 hash/provenance 并需显式接纳；配置 revision 或站点/别名冲突拒绝旧建议；名称不能独自启动文章 API 或证明授权                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| 部分来源失败          | 一个供应商失败时，其它供应商的有效文献仍进入数据库，并能看到失败信息                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Provider 凭据与连通性 | 用户可以通过受控入口或直接编辑同一用户级凭据文件配置和移除 Provider 密钥；能够在不显示密钥的情况下查看必需、可选、已配置、部分配置、缺失或不需要凭据的状态，并显式执行遵守统一访问政策的最小只读测试；测试不创建文献、运行或数据库事实，也不把认证成功冒充具体全文授权                                                                                                                                                                                                                                                                                                                                                          |
| 用户级运行配置        | 所有正常命令和配置状态只读取同一用户级普通配置文件；裸配置入口管理并可首次创建该文件，用户也可直接编辑；工作目录和旧配置环境变量不改变配置身份，普通配置与 secret 继续分文件保存                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Models 与任务配置     | Models 可以保存多个 Provider 与唯一 `provider/model` Model；Provider 只拥有 API/endpoint/exact-origin key，Model 只拥有 reasoning/image/stream，Analyze/Browser 直接选择 Model，调用 capability/limits 由各模块派生且不形成任务级 override；`xhigh/max` 可保存，default 省略且显式值原样发送；stream 默认开启、三协议精确继承、可按 Model 关闭且失败不自动切换模式；Browser 只列出图片 Model；新增远程 Provider/Model 时同流程隐藏输入 key 并自动执行有界模型目录读取，只有失败或空结果才出现 Manual；首页/status 纯本地，配置与输出不显示 secret，也不存在 Service/Model Profile/Preset/Entry 兼容层                           |
| 文献下载              | 系统能够从元数据继续获得实际字节非空、标准 PDF reader 可打开、页面树可读取且至少一页、获取路径与目标文献相符的 PDF；扩展名、文件名、HTTP 类型或下载事件不能替代字节检查，不可读取的加密文件不能通过                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 原文来源路由          | 聚合元数据来源与出版社内容能力保持解耦；系统优先使用明确资产线索和稳定标识，再按安全解析后的实际站点选择适用的公开、授权 API 或 Browser route，不因 Scopus 等聚合来源返回记录就错误调用同机构内容 API，也不对每篇文献盲目尝试全部出版社                                                                                                                                                                                                                                                                                                                                                                                         |
| Sci-Hub 可选来源      | Source 默认关闭；显式启用且没有 custom override 时使用当前版本内置有序镜像，custom 列表完整覆盖内置列表并在升级时保持不变；Reset 恢复跟随内置列表，禁用保留 custom；请求按序而非并发执行且继续经过统一 Network/PDF 验收，不配置凭据、会话或绕过能力，出口按统一的出网选择                                                                                                                                                                                                                                                                                                                                                       |
| 受控 Browser          | 最后一级使用固定长期设备身份与一个共享 process/context，唯一通用 Agent 路线按文章 session 隔离；不同平台两个 worker 可并行，同平台网络活动一篇且结束后冷却 30 秒；默认五个保留会话，每篇一个主下载，旧显式全局串行政策继续生效；动作结束到下一轮模型至少 5 秒，单篇 300 秒累计活跃时间/30 次实际模型派发，动作只统计而默认不独立设限；下载让出 worker，失败从原页面与剩余预算恢复，文件有效后交原 publication；前台切换、人工接管、取消和迟到事件不串线，publication 失败不重下，提交后清理失败不回滚；合法文章起点不要求 Publisher 点击规则，Challenge 共用观察和封闭动作，所有访问与文件接纳继续经过 Network/Acquisition 边界 |
| 自动 PDF 获取耗尽     | 只有当前全部自动路径正常结束仍未获得 PDF 时，具体文献才显示需要人工提供 PDF，并从全库自动重试范围排除；新增元数据、成功主 PDF 或明确重试会解除标记，网络、权限、配置、存储错误和用户中断不会误标                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 手动 PDF 接纳         | 用户明确选择具体文献后可以复制接纳本地有效 PDF；内部副本通过相同基本检查和正常资产关系发布，用户原文件不被移动、修改或删除，已有主 PDF 不被静默替换                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 文献解析              | 无需分析即可读取由已接纳材料生成的可读文档和资源，部分结果/失败准确表达                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 内容判断与总结        | 不同用途/粒度产物绑定输入与证据，保留条件/局限和覆盖；不适用或失败不单独删除材料；既有单篇格式继续兼容                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 书目导入              | 用户能够导入主流文献管理工具的书目信息；每条带来新事实的接纳记录作为用户来源 observation 参与统一元数据，非空导入值不被供应商覆盖，重复 matched 不制造重复事实，并可与数据库已有文献共同查询和补充                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 书目导出              | 已经完成元数据信息收集并形成可用统一书目信息的文献，无需等待全文处理即可导出为 Zotero 等主流文献管理工具可继续使用的格式                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 批量局部失败          | 某些文献获取、解析或语言模型总结失败时，其它文献继续完成，已完成结果不丢失                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 数据库补全            | 用户可以按全库、历史发现、导入、查询结果或明确文献发起缺失 PDF/内容补全；本次实际目标只在当前操作中冻结，每个目标从当前第一个缺失步骤继续，不要求保存批次历史                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 多版本补全            | 普通逻辑文献范围默认只补齐一个可用版本，先复用完成度更高的版本并按既定版本顺序选择；只有稳定缺失才尝试下一版本，系统、解析或模型失败不触发跨版本回退                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 重复运行              | 再次执行相同收集或处理时，系统重新读取文献数据库，复用仍然有效的结果并补充缺失内容，不依赖恢复上一次外部调用现场，也不产生无意义重复                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 运行报告与日志        | 元数据发现、数据库补全、手动 PDF 和书目交换在正常结束、普通失败或受控中断时以操作特有报告说明本次选择与完成情况；补全报告区分 PDF 获取、Parsing 和 Analysis 结果，日志只提供独立实时反馈；二者都不进入数据库，硬崩溃可以没有最终报告但不损坏已提交事实                                                                                                                                                                                                                                                                                                                                                                          |
| 数据库使用            | 用户以文献库为主空间查询、选择和操作，按需了解元数据、资产、可读表示、知识、关系和自动获取结果；可主动补 PDF，不默认展示人工待办                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| Agent 知识旅程        | 独立获取/解析/读取后按需分析，在预算内检索并从要点展开到正确材料版本；没有隐藏生成成本                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 跨论文综合            | 指定输入集合下的共识/分歧和条件差异可追溯，不假装覆盖整个领域                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| 人类协作              | 在同一正式 Browser 观看全程，自愿直接点击/输入时先完成控制权交接，旧动作失效、交还重新观察；无人介入也能结束获取并如实反馈，最终人工与 Agent 读取同一知识                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 证据生命周期          | 表示更新、过期和回收不静默破坏有效引用；读取与解释类型明确                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 通用提取              | 外部程序按不同记录规范读取材料并提交有证据的候选，无需新增核心领域字段或配置内部分析模型；结构检查不替代领域接纳，零结果与部分失败可辨认                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
