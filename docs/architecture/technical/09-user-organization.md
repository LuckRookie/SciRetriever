## 1. 模块边界与连接

### 1.1 本模块拥有什么

| 数据         | 含义                                                 | 代码 owner                                                        |
| ------------ | ---------------------------------------------------- | ----------------------------------------------------------------- |
| 文件夹       | 使用者建立的多级分组，一篇文献可以在多个文件夹里     | `apps/server/src/literature/folders.ts` 的 `FolderService`        |
| 最近阅读记录 | 使用者明确打开过哪篇文献、最近一次的时间、打开次数   | 同上                                                              |
| 保存的筛选   | 起了名字的一组文献库筛选条件与排序                   | `apps/web/src/app/features/library/Library.tsx`（当前只在浏览器） |
| 批注与笔记   | 一篇文献上的高亮、框选和附在批注上的笔记（ADR 0046） | `apps/server/src/literature/marks.ts` 的 `MarkService`            |

合同在 `packages/contracts/src/folders.ts` 与 `packages/contracts/src/marks.ts`；SQL 只在 `apps/server/src/storage/sqlite/folder-engine.ts` 与 `marks-engine.ts`。表结构在唯一的 `schema.ts`，持久化与迁移规则归[⑦ 存储](07-versioned-storage.md#7-运行审查存储)。

代码里用 `marks` 指批注，不用 annotation，以免与建档的结构注释混淆（ADR 0046 第 1 条）。

### 1.2 本模块不拥有什么

- **文献事实**：身份、书目、来源、版本、全文文件与引用关系归 ③，见[文献与材料](03-literature-materials.md)。本模块只引用 `LiteratureId`、PDF 的 sha256 和文档版本号。
- **标签**：受控词表与文献的标签赋值归建档，见[标签与算子输入](05-knowledge-processing.md#7-标签与算子输入)；规则按 ADR 0037 与 ADR 0053。笔记里的 `#标签` 只是笔记文字推出的词，不进入词表，也不写入标签赋值。
- **入库批次**：归文献库查询，见[入库批次](06-retrieval-context.md#216-入库批次范围词频与-pdf-获取范围)。批次记录文献从哪里来，文件夹记录使用者想怎样放。
- **快照**：文件夹可以作为算子范围，提交时冻结为快照，快照归 ⑤，见[运行流程、选取与预算](05-knowledge-processing.md#86-运行流程选取与预算)。快照不跟着文件夹变化。
- **界面状态**：阅读位置、缩放、栏宽、阅读字号和行宽属于 Web 的本机偏好（ADR 0032 第 6 节），见[产品接口](01-product-interface.md#4-人类工作台与知识阅读)。
- **页面排布**：文件夹树、批注栏、保存筛选菜单的样子归[页面规格](../web/page-specs.md)。

### 1.3 与其他模块的连接

- 从 ③ 取得文献是否存在、有哪些 PDF；从 ④ 取得文档版本和它的字节长度，用来校验批注锚点。
- 向 ⑥ 提供两个筛选条件：按文件夹（`LibraryQuery.folder`）和最近阅读（`LibraryQuery.recently_opened`）；向文献行和详情提供 `folder_ids` 与 `last_opened_at`。
- 入库批次的过程（实现为 Entry 的 `ImportSessionService`）通过 `FolderService` 建文件夹、加成员，不直接写表，见 [2.5](#25-导入建立的文件夹)。
- 写入经 ① 的维护入口，都记进操作记录，见 [6.4](#64-操作人与操作记录)。

## 2. 文件夹

文件夹就是需求里的“分组”（ADR 0032 第 8 节第 9 条、ADR 0058 第 5 节）。

### 2.1 表

| 表               | 字段与约束                                                                                                                                                                       |
| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `folders`        | `folder_id` 主键（新建时为随机 UUID）；`parent_id` 可空，外键指向 `folders`，级联删除，不能指向自己；`name`；`position` 非负整数；`created_at`、`updated_at`。同一上级下名称唯一 |
| `folder_members` | 主键 `(folder_id, literature_id)`；`added_at`；`actor`。删除文件夹或删除文献时，成员行级联删除                                                                                   |

文件夹不保存外部编号。导入来源与文件夹的对应在通用的 `external_object_mappings` 里（对象种类 `group`），见[入库存储](07-versioned-storage.md#9-导入会话与外部编号对应)。

### 2.2 层级、多归属与命名

- **层级**：任意多级。移动时拒绝把文件夹移到自己或自己的子孙下（`folder-cycle`）。当前没有层级深度上限。
- **多归属**：一篇文献可以在任意多个文件夹里。同一文献在同一文件夹里只算一次，重复加入不报错、不重复计数。
- **命名**：
  - 不能为空，不超过 128 个字符（按 UTF-16 单位计），不能含控制字符或格式字符；
  - 保存时去掉首尾空白，做 NFC 规范化；
  - 同一上级下不能重名，按规范化后的文字逐字比较，区分大小写；冲突返回 `folder-name-conflict`。
- **顺序**：同级按 `position` 排列。新建不给位置时排在最后；新建或移动后，同级位置重新编为 0、1、2……。
- **计数**：列表返回每个文件夹的 `own_count`（直接成员数）和 `total_count`（含全部子孙文件夹的去重文献数）。

### 2.3 操作

合同为 `FolderOperation`，所有写入都在一个 SQLite 写事务内完成。

| 操作             | 输入                               | 结果与规则                                                                                                       |
| ---------------- | ---------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `list`           | `{}`                               | 全部文件夹及计数，只读                                                                                           |
| `delete-preview` | `{folder_id}`                      | 将删除的文件夹数、子孙数、涉及的文献数和成员数，只读                                                             |
| `create`         | `{name, parent_id?, position?}`    | 新文件夹                                                                                                         |
| `rename`         | `{folder_id, name}`                | 改名后的文件夹                                                                                                   |
| `move`           | `{folder_id, parent_id, position}` | 换上级或换位置；`parent_id` 为 null 表示移到顶层                                                                 |
| `delete`         | `{folder_id}`                      | 删除这个文件夹及全部子孙，只解除成员关系，不删除文献；返回与预览相同的计数                                       |
| `add` / `remove` | `{folder_id, literature_ids}`      | 一次 1–1,000 篇，去重后处理；任一文献不存在则整批拒绝；返回 `changed` 与实际变化的 `changed_ids`，可用来精确撤销 |

`FolderService.query` 只接受两种读操作，`manage` 只接受写操作，混用返回 `folder-read-operation-invalid` 或 `folder-write-operation-invalid`。

### 2.4 作为筛选条件

- `LibraryQuery.folder = {id, include_descendants}`：选这个文件夹的成员；`include_descendants` 为真时含全部子孙文件夹的成员。一次查询只能指定一个文件夹。
- 文件夹已被删除时，这个条件命中零篇，不放宽成全库。
- 由文件夹条件生成的快照，名称写“文件夹 某某”；文件夹已删除时写“文件夹（已删除）”（`analysis/snapshot-names.ts`）。

字段的边界解析在 `packages/contracts/src/index.ts`；文献库查询的其它条件见[LibraryQuery](06-retrieval-context.md#211-libraryquery)。

### 2.5 导入建立的文件夹

外部工具的分组按入库的规则落成文件夹，对应规则、重名加序号、128 字符截断和报告分类由[书目交换规则](03-literature-materials.md#61-书目交换规则)负责。从本模块看，结果是：

- 导入经 `FolderService.manage` 建文件夹、加成员，和使用者手动操作走同一套校验与事务。
- 建好之后，它们就是普通的文件夹：使用者可以改名、移动、删除、增减成员。再次导入只补成员，不跟着来源改名或移动，也不恢复使用者删掉的文件夹（报告为 `import-folder-target-missing`）。
- 没有来源库编号的一次性导入（`adhoc`）不建文件夹，分组只计数。
- 导入只新增成员，不移出成员。

## 3. 最近阅读记录

- 表 `reading_history`：`literature_id` 主键，`last_opened_at`，`open_count`（至少 1）。文献删除时级联删除。
- 只在明确的“打开”操作时写入：Web 在使用者打开一篇文献的阅读页时调用一次，在已打开的文献之间切换标签不记；CLI 为 `literature open ID`，MCP 为 `reading_open`。查询、读取全文和读取批注都不写它。
- 写入时 `last_opened_at` 只前进不后退，`open_count` 加一。
- 筛选 `recently_opened: true` 取最近 30 天内打开过、且满足其它条件的文献，计数最多显示 100；排序 `opened-desc` 按最近打开时间。
- 它是使用者的阅读足迹，不是文献事实，不影响文献状态和检索投影。
- 它全库共用一份，不区分是谁打开的。

## 4. 保存的筛选

当前的实现：

- 只保存在浏览器的 `localStorage`，键为 `sciretriever:react:sciretriever:library-views:v1:<catalog>`，按文献库分开。
- 每项保存 `id`、`name`（最多 100 个字符）、`LibraryQuery` 与排序；最多 50 项，超出时去掉最早的。
- 读取时每一项都按 `parseLibrarySearchRequest` 重新解析；有任何一项不合法，整份列表按空处理，不报错。
- 保存的是条件，不是成员名单：每次应用都按当前库重新查询（ADR 0032 第 6 节）。条件里引用的文件夹被删除后，应用这条筛选命中零篇。
- 换浏览器、清除站点数据后丢失；CLI、MCP 和 HTTP 读不到，也不能导出。

这不满足理1 在三个入口上的要求（需求[用4](../requirements.md#用4-三个入口)），目标见 [9.1](#91-保存的筛选进入文献库)；导出见 [9.5](#95-分组与筛选的导出)。

## 5. 批注与笔记

规则的理由见 [ADR 0046](../decisions/0046-reading-marks.md)，本节只写字段和行为。

### 5.1 表

`reading_marks`（schema 14 起）：

| 字段                                                              | 约束                                                                                   |
| ----------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| `mark_id`                                                         | 36 位 UUID 主键                                                                        |
| `literature_id`                                                   | 外键，文献删除时级联删除                                                               |
| `kind`                                                            | `highlight`（高亮）或 `region`（框选）                                                 |
| `color`                                                           | `yellow`、`blue`、`green`、`red`、`purple`；默认含义依次为重点、方法、结论、疑问、待查 |
| `note`                                                            | 纯文本，最多 20,000 字符                                                               |
| `quote`、`quote_prefix`、`quote_suffix`                           | 原文最多 4,000 字符，前后文各最多 200 字符                                             |
| `pdf_sha256`、`pdf_page`、`pdf_rects_json`                        | PDF 锚点，三项同时有或同时没有                                                         |
| `document_version_id`、`document_start_utf8`、`document_end_utf8` | 全文锚点，三项同时有或同时没有；结束位置大于开始位置                                   |
| `created_at`、`updated_at`、`deleted_at`、`actor`                 | `deleted_at` 非空表示已删除                                                            |

表级约束：至少有一个锚点；框选必须有 PDF 锚点。`document_version_id` 不设外键，文档出新版本时旧批注照样保留。

文字字段拒绝换行和制表符以外的控制字符，保存前做 NFC 规范化。

### 5.2 锚点

- **PDF 锚点**：PDF 的 sha256、页码（从 1 起）、1–400 个矩形。矩形为 `[x, y, 宽, 高]`，PDF 页面单位、缩放为 1、原点在左上，保留两位小数，宽高必须大于 0。
- **全文锚点**：文档版本号，加这一版 Markdown 里的 UTF-8 字节范围。
- **只能指向自己的材料**：PDF 锚点的 sha256 必须是这篇文献的某个 PDF 资产；全文锚点的文档版本必须属于这篇文献，范围不能超出这一版的字节长度。否则返回 `mark-anchor-invalid`。
- **高亮**必须有原文，并且至少有一个锚点；**框选**必须有 PDF 锚点，不能只有全文锚点。

### 5.3 两种材料之间对位

对位在 Web 阅读器里进行（`apps/web/src/reading/mark-locate.ts`、`marks.ts`），服务端只校验并保存结果：

- 比对前统一写法：忽略空白、连字、各种短横线和引号的差异、PDF 行尾断词连字符，以及 Markdown 标记符号；再按编辑距离找最相近的一段，用前后文辅助。
- 先缩小范围：全文锚点有效时只在它覆盖的区块里找；只有 PDF 锚点时，先找页码相差不超过 1 的区块；找不到再全篇找。
- 相似度不低于 0.85：按位置显示；0.7 到 0.85：显示为“近似位置”；低于 0.7：不显示在这份材料上，批注栏标为“仅 PDF”或“仅全文”。
- 只有全文锚点的高亮在 PDF 某页上相似度达到 0.85 时，补存 PDF 锚点；只有 PDF 锚点的高亮在当前文档版本上达到 0.85 时，补存全文锚点。补存只发生一次，之后读取已存的锚点。
- 框选只属于 PDF，不在全文上显示。

### 5.4 文本变化时

一个部分的文本发布新的文档版本（例如人工保存校订稿），已有批注的处理是：

- 旧的全文锚点原样保留，不改写，也不删除批注。
- 阅读新版本时，按原文和前后文重新查找，规则与 [5.3](#53-两种材料之间对位) 相同；对不上就标为“仅 PDF”，不放到别处。
- 已经带有旧版本全文锚点的批注，在新版本上找到位置后不另存新锚点，每次打开时重新查找。这是当前实现，与 ADR 0046 第 5 条“对位成功后补存，不在打开文献时重算”不一致；目标见 [9.4](#94-材料换版本时重新定位并记录)。
- PDF 锚点只在显示的 PDF 与锚点的 sha256 相同时显示。主 PDF 已有时不会被导入或上传悄悄替换（③ 的规则），所以 PDF 锚点通常不受文本变化影响。

**初稿上的批注。** 初稿是可阅读的文本（[ADR 0060](../decisions/0060-two-level-full-text.md)）。在初稿上做的批注，全文锚点指向初稿的文档版本，与校订稿上的批注用同一张表和同一套校验。一个部分从初稿升级为校订稿时，按本节的同一规则处理：初稿锚点原样保留，在校订稿上按原文重新查找；对不上标为“仅 PDF”，不放到别处，不另设初稿与校订稿之间的专门对位规则。批注栏写明批注是在哪一级文本上做的。

### 5.5 笔记、标签与删除

- 笔记附在一条批注上。当前没有不依附批注的整篇笔记。
- 笔记里的 `#词`（字母、数字、下划线、短横线，1–40 个字符）按首次出现的顺序推出为批注的 `tags`，不另外保存，也不进入标签词表。
- 删除只写 `deleted_at`，30 天内可以 `restore`。每次写批注之前，先清除删除已满 30 天的批注；清除后再恢复返回 `mark-not-found`。已删除的批注不能 `update`（`mark-deleted`）。
- `list` 与 `export` 只返回未删除的批注。

### 5.6 读取与导出

- `list {literature_id}`：按阅读顺序返回——先按页码，再按页内从上到下，只在全文上的排在最后，最后按创建时间。
- `export {literature_id, format}`：
  - `markdown`：标题、作者等书目一行，然后按页分组；每条写颜色含义和原文，框选写“框选区域（第 n 页）”，笔记缩进写在下面。
  - `json`：`{items}`，字段与 `list` 相同。
- 导出按单篇进行。导出不写库，不改变批注。

## 6. 使用者数据的共同规则

### 6.1 不改变文献事实

- 文件夹、阅读记录和批注的写入只碰 [1.1](#11-本模块拥有什么) 列出的表，不修改文献的身份、书目、来源、资产、文本、标签或状态。
- 文献状态投影的输入表不含这些表（`schema.ts` 的 `LIBRARY_STATE_INPUT_TABLES`），所以整理和标注不会让文献状态缓存失效，也不会让加工结果过时。
- 删除文件夹不删除文献；删除文献时，它的成员关系、阅读记录和批注一起删除。

### 6.2 稳定保存

- 文件夹、阅读记录和批注都在 catalog 里，随 catalog 一起备份、恢复和迁移，不在页面或浏览器里保存。
- 每次写入是一个事务；失败时整体回滚。
- 打开旧库不自动加表。`reading_marks` 由 13→14 的离线迁移脚本加入，见[⑦ 第 7 节](07-versioned-storage.md#7-运行审查存储)。
- 保存的筛选当前例外，见[第 4 节](#4-保存的筛选)。

### 6.3 Agent 的同等授权

Agent 与人使用同一套合同和同一份数据，没有专供 Agent 的副本。能做什么由入口和授权决定：

| 入口与授权                   | 文件夹                                           | 阅读记录             | 批注与笔记                    |
| ---------------------------- | ------------------------------------------------ | -------------------- | ----------------------------- |
| Web 登录                     | 读、写                                           | 写（打开阅读页时）   | 读、写、导出 Markdown         |
| 本机 CLI                     | 读、写                                           | 写                   | 读、写、导出                  |
| stdio MCP 只读模式           | 读（`folders_query`）                            | —                    | 读、导出（`marks_query`）     |
| stdio MCP `--maintenance`    | 读、写（另加 `folders_manage`）                  | 写（`reading_open`） | 读、写（另加 `marks_manage`） |
| HTTP MCP，设备用途 `read`    | 读                                               | —                    | 读、导出                      |
| HTTP MCP，设备用途 `operate` | 写                                               | 写                   | 写                            |
| 设备用途 `intake`            | 经入库新建文件夹、加入成员；收藏时加入所选文件夹 | —                    | —（导入的批注当前只计数）     |

- 设备用途彼此不隐含：只有 `operate` 的令牌不能读，要读需同时勾选 `read`。用途的登记与校验见[设备连接](01-product-interface.md#241-设备连接与按用途准入)和 [HTTP 版 MCP](01-product-interface.md#http-版-mcp)。
- 设备令牌不能调用 `/api/v1/query/*` 与 `/api/v1/maintenance/*`；这些 HTTP 路径只对 Web 登录开放。
- Agent 删除文件夹或批注的效果与人相同：删除文件夹只解除成员，删除批注 30 天内可以恢复。

### 6.4 操作人与操作记录

- 每次写入都经 `executeMaintenance`，在 `operation_records` 里记操作名、操作人和允许的 ID（例如 `folder_id`、`parent_id`、`literature_id`），不记笔记正文。
- `folder_members.actor` 与 `reading_marks.actor` 保存发起写入的实际身份：Web 为独立会话标识，CLI 与 stdio MCP 为各自入口，HTTP MCP 为 `mcp:device:<connection_id>`。`folders` 表本身不保存操作人。

### 9.1 保存的筛选进入文献库

保存的筛选归本模块，保存在 catalog，随库备份，不再只放在浏览器里。

**是什么。**

- 一项保存的筛选是名称、一个 `LibraryQuery` 和一个 `LibrarySort`。保存的是条件，应用时按当前库重新查询，不保存成员名单，不成为 Collection（ADR 0032 第 6 节）。
- 条件在保存时按 `parseLibrarySearchRequest` 校验，不合格的拒绝（`filter-condition-invalid`）。服务端保存的是解析后的规范形式。
- 名称规则与文件夹相同（[2.2](#22-层级多归属与命名)）：去掉首尾空白、NFC 规范化，1–128 个字符（UTF-16 单位），不含控制字符或格式字符；在全部保存的筛选中唯一，按规范化后的文字逐字比较，区分大小写，冲突返回 `filter-name-conflict`。
- 最多 200 项。新建或导入会超过时拒绝（`filter-limit`）。
- 名称为空、超过 128 个字符或含控制字符、格式字符时，与文件夹相同，按请求校验错误拒绝；只有重名单独返回 `filter-name-conflict`。导入时的名称另按下文截短或跳过，不报错。
- 列表按规范化名称的码位顺序排列。本版不提供手动排序。

**条件引用的文件夹被删除。** 这条筛选保留，条件不自动改写。列表中这一项带 `missing_folder_id`（条件里的文件夹编号，文件夹存在时为 null）。应用它时，文献库查询按 [2.4](#24-作为筛选条件) 命中零篇；入口在结果旁说明“筛选里的文件夹已被删除”。

**操作。** 合同为 `FilterOperation`，所有写入都在一个 SQLite 写事务内完成，形式同 `FolderOperation`（[2.3](#23-操作)）：

| 操作     | 输入                       | 结果与规则                                                                                                           |
| -------- | -------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| `list`   | `{}`                       | 全部保存的筛选：`filter_id`、`name`、`query`、`sort`、`missing_folder_id`、`created_at`、`updated_at`；只读          |
| `export` | `{}`                       | 导出文件，见 [9.5](#95-分组与筛选的导出)；只读                                                                       |
| `create` | `{name, query, sort}`      | 新的筛选；`filter_id` 为随机 UUID                                                                                    |
| `rename` | `{filter_id, name}`        | 改名后的筛选                                                                                                         |
| `update` | `{filter_id, query, sort}` | 用新的条件与排序替换这一项原有的条件与排序，名称不变                                                                 |
| `delete` | `{filter_id}`              | 删除这一项；不影响任何文献与文件夹                                                                                   |
| `import` | `{items}`                  | 浏览器导入（见下文），1–200 项；逐项返回 `imported`、`renamed`、`skipped` 或 `invalid` 与原因；只有 `invalid` 不写入 |

- 编号不存在返回 `filter-not-found`。`FilterService.query` 只接受 `list` 与 `export`，`manage` 只接受写操作，混用返回 `filter-read-operation-invalid` 或 `filter-write-operation-invalid`。
- 每次写入经 `executeMaintenance` 记进操作记录（[6.4](#64-操作人与操作记录)），记 `filter_id`，不记条件全文。表本身不保存操作人，同 `folders`。
- 表结构见[存储第 7 节](07-versioned-storage.md#7-运行审查存储)的 `saved_filters`。它不进入文献状态投影的输入表（[6.1](#61-不改变文献事实)）。

**入口。** 与文件夹相同的形式：

| 能力     | Web              | CLI                                                             | MCP              | HTTP（Web 登录）                   |
| -------- | ---------------- | --------------------------------------------------------------- | ---------------- | ---------------------------------- |
| 读、导出 | 文献库“筛选”菜单 | `filters list`、`filters export`                                | `filters_query`  | `POST /api/v1/query/filters`       |
| 写       | 文献库“筛选”菜单 | `filters create\|rename\|update\|delete\|import --request FILE` | `filters_manage` | `POST /api/v1/maintenance/filters` |

- 设备用途与文件夹相同：`filters_query` 归 `read`，`filters_manage` 归 `operate`（[6.3](#63-agent-的同等授权)）。
- 需要 catalog 增加一张表，按⑦的规则显式离线迁移。

**浏览器中已有筛选的导入。** 浏览器里已有的保存筛选（[第 4 节](#4-保存的筛选)）只由使用者在 Web 上明确导入，不自动搬迁：

- 入口在文献库的“筛选”菜单：“导入这个浏览器里保存的筛选（n 项）”，只在这个浏览器里还有未导入的项时显示，n 是未导入的项数。排布见[页面规格“文献库”](../web/page-specs.md#文献库)。
- 只有坐在这个浏览器前的人能发起；服务端与实施者都不读取使用者浏览器里的数据。Web 读出本地数据后调用 `import`。
- 逐项判断：合格的导入，不合格的列在报告里并写明原因；一项不合格不影响其余项。浏览器版“任一项不合格整份按空处理”的读法不用于导入。
- 名称超过 128 个字符的截为 128 个字符（不截断代理对）。
- 名称与已有的筛选相同、条件与排序也相同：跳过（`skipped`）。名称相同而条件或排序不同：导入的这一项加序号（`名称 (2)`、`名称 (3)`……，加序号后超长时先截短原名），结果为 `renamed`，规则同导入建立的文件夹（[2.5](#25-导入建立的文件夹)）。
- 导入后浏览器里的数据保留，每项标为已导入，入口随之消失；再次导入同一份数据不新建任何项。导入后 Web 不再向浏览器写入保存的筛选。

### 9.2 导入的批注

[ADR 0057](../decisions/0057-zotero-import-and-browser-capture.md) 第 3 节的规则：

- 只在本库主 PDF 与来源附件的 sha256 相同时导入；高亮、下划线导成高亮，区域批注导成框选，评论导成笔记；原点由左下换成左上；颜色就近归到五种。
- 导入的批注按 `annotation` 种类写入外部编号对应；再次导入同一条只对应，不重复建立，也不覆盖使用者在本库里改过的颜色和笔记。
- 导入只新增批注，不删除、不修改已有批注。导入报告里的 `imported` 计实际写入的条数。

### 9.3 网页收藏时选择文件夹

[ADR 0057](../decisions/0057-zotero-import-and-browser-capture.md) 第 5 节与 ADR 0058 第 2 节：`capture` 用途的令牌可以列出文件夹，并在保存文献时把它加入一个已有的文件夹。它不能新建、改名、移动或删除文件夹，也不能读写批注。

### 9.4 材料换版本时重新定位并记录

[ADR 0046](../decisions/0046-reading-marks.md) 第 4、5 条：材料换了版本时按原文与前后文重新定位；对位成功后记下，不在打开文献时重算。本节取代 [5.4](#54-文本变化时) 第三条的当前做法。

**什么时候查找。** 一条批注在下面两种目标材料上没有自己的锚点时，在它上面查找：

- 一份 PDF，其 sha256 与批注的 PDF 锚点不同；
- 一个文档版本，与批注的全文锚点不是同一版本（包括初稿升级为校订稿，[5.4](#54-文本变化时)）。

比对规则、缩小范围的顺序和三档相似度都与 [5.3](#53-两种材料之间对位) 相同。显示沿用现有标注：不低于 0.85 按位置，0.7 到 0.85 为“近似位置”，低于 0.7 不显示在这份材料上，批注栏标为“仅 PDF”或“仅全文”。

**只在同一部分里找。** 一篇文献有多个 PDF 时，批注只在同一部分的 PDF 与文档版本上查找：主 PDF 的批注只在主 PDF 及其文档上找，某个补充材料的批注只在同一补充材料上找，不跨部分。批注所属的部分按它的锚点确定：全文锚点所在文档版本的来源资产，或 PDF 锚点 sha256 对应的资产在这篇文献中的角色。原 PDF 已不再属于这篇文献时，按主 PDF 处理。

**框选。** 框选没有原文，不能按文字查找。PDF 不同时它不放到当前 PDF 上，在批注栏里照常列出，标明它属于原来那份文件。

**记录。**

- 批注自己的锚点从不改写。找到的位置另行保存，按“批注 × 目标材料”一条：目标是一份 PDF（sha256）或一个文档版本；PDF 目标存页码与矩形，文档目标存 UTF-8 范围，形式同 [5.2](#52-锚点)；另存相似度（0.7 至 1）与方法版本（当前为 `mark-locate-v1`）。
- 它是缓存：可以由批注的原文、前后文与目标材料重新算出；批注被清除时一起删除；方法版本改变时不再使用，按新方法重新查找后覆盖。
- 写入时机：阅读器在某个目标上定位成功（相似度不低于 0.7）后在后台写入，不移动正文（[阅读体验 5.2](../web/reading-experience.md#52-后台刷新)）。写入的校验同 [5.2](#52-锚点)：目标必须是这篇文献、同一部分的 PDF 或文档版本，范围不超出。
- 下次打开时直接使用记下的位置，不再查找。在一个目标上没有找到的批注，同一次会话里只查找一次，不记下“没有找到”。
- 记录的写入是 `MarkOperation` 的 `place`：`{mark_id, target, similarity, method}`，`target` 为 `{pdf: {sha256, page, rects}}` 或 `{document: {document_version_id, start_utf8, end_utf8}}`；同一批注、同一目标再写入时替换。已删除的批注不能写入（`mark-deleted`）。它与其它写操作一样记进操作记录，设备用途 `operate`。
- `list` 的每条批注带 `places`：当前方法版本下记下的位置，各带目标、位置、相似度与方法版本。`export` 的 JSON 字段与 `list` 相同；Markdown 导出不变。
- 表结构见[存储第 7 节](07-versioned-storage.md#7-运行审查存储)的 `reading_mark_places`。

### 9.5 分组与筛选的导出

文件夹与保存的筛选可以导出为 JSON，便于备份和在别的工具里对应。导出只读，不写库。批注仍按单篇导出（[5.6](#56-读取与导出)）；跨文献的批注总览不在本节（ADR 0046“不在本决定内”）。

**两个导出。** 分组的导出不依赖保存的筛选，两者各自独立：

| 导出       | 操作                          | 文件格式名                     | 内容                                                                             |
| ---------- | ----------------------------- | ------------------------------ | -------------------------------------------------------------------------------- |
| 分组       | `FolderOperation` 的 `export` | `sciretriever-folders`，版本 1 | 文件夹树：每个文件夹的 `folder_id`、`name`、`parent_id`、`position` 与 `members` |
| 保存的筛选 | `FilterOperation` 的 `export` | `sciretriever-filters`，版本 1 | 每项的 `name`、`query`、`sort`（[9.1](#91-保存的筛选进入文献库)）                |

- 文件的顶层是 `{format, version, exported_at, ...}`；分组为 `folders`，保存的筛选为 `filters`。
- `export` 是读操作：`FolderService.query` 在 `list`、`delete-preview` 之外接受它，`FilterService.query` 见 9.1。
- 每个成员写 `literature_id`、`identifiers`、`title` 与 `year`。`identifiers` 只列这篇文献已有的 `doi`、`arxiv`、`pmid`、`pmcid`，没有的不写；`title` 与 `year` 取当前书目，供人看，缺失时为 null。一篇文献在几个文件夹里，就在每个文件夹下各出现一次。
- 稳定标识经③的公开读取取得（[1.2](#12-本模块不拥有什么)）。

**规模。**

- 机器入口分页：分组导出的请求为 `{cursor, limit}`，`limit` 为 1–1,000，首次 `cursor` 为 null。第一页给出完整的文件夹树（不含成员）；每页给出一批成员，每条另带 `folder_id`，按 `(folder_id, literature_id)` 排序；`next_cursor` 为 null 时结束。后续页可以看到期间提交的变化，规则同文献库分页。保存的筛选最多 200 项，一次返回。
- Web 的下载由服务端流式写成一个文件：成员嵌在各自的文件夹下。HTTP 为 `POST /api/v1/query/folders-export`，响应为 `application/json` 附件；保存的筛选用 `POST /api/v1/query/filters` 的 `export`。

**入口。**

| 导出       | Web                                | CLI                             | MCP                         | 设备用途 |
| ---------- | ---------------------------------- | ------------------------------- | --------------------------- | -------- |
| 分组       | 侧栏“文件夹”一组的菜单：“导出分组” | `folders export --request FILE` | `folders_query` 的 `export` | `read`   |
| 保存的筛选 | 文献库“筛选”菜单：“导出筛选”       | `filters export`                | `filters_query` 的 `export` | `read`   |

## 10. 方向：人和 Agent 产出的知识

人和 Agent 自己产出的知识——笔记、总结和研究过程中的产出——以后应当能进入知识库并参与加工，落脚点是本模块（需求[第 6 节](../requirements.md#6-范围边界)、ADR 0059 第 5 节）。这只是方向，当前不设计、不验收；本模块的合同和表结构不得写死“只接受文献上的批注”。
