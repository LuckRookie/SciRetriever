# ADR 0067：文献库与候选

类型：决策（ADR）
负责：文献库与候选的含义和两者的关系；一篇文献进来时落在哪一边；候选怎样进入文献库、文献库里的怎样回到候选；删除与两者的关系；人的界面上候选在哪里出现
状态：Accepted（2026-11-25，Owner 决定）；第 7 节的后两条同日被 Owner 改掉：文献库页的候选篇数打开全部候选的列表，不再进入“找文献”页（原话：“这里我点击候选之后，应该出现所有候选的文献，而不是转跳到‘找文献’。”），现行写法见[页面规格](../web/page-specs.md)的“文献库”

- Date: 2026-11-25
- 依据：Owner 2026-11-25 的原话：

  > 整个流程中候选是什么意思？以及我们之前导入的20多万个元数据在哪显示？

  > 这个候选与我们文献库的关系是什么？以及一个数据刚进来到底是候选还是文献库？以及文献库中的数据是否能塞入到候选里面？这些内容都要敲定啊，请你出一个方案出来吧

  > 按建议定（2026-11-25，对方案里要他决定的五条：新增移出文献库；打开阅读不算加入；发现任务不恢复已删除的文献；文献库页写出候选的篇数与入口；“早期入库”保持候选）

- Related：[ADR 0065](0065-scale-rules.md) 第 2 节人与 Agent 的分工（人的界面只面对有边界的工作集）；[ADR 0063](0063-unified-intake.md) 入库批次与撤回；[ADR 0013](0013-decoupled-discovery-and-database-maintenance.md)、[ADR 0064](0064-citation-expansion-bounded-by-depth.md) 发现任务。

## 背景

一次引用扩展可以带回几十万篇书目。2026-11-25 正式库里有 351,458 篇文献，其中使用者自己的只有 147 篇，其余都是主题搜索、引用扩展和旧库迁移带进来的。为了让使用者的文献不被淹没，[ADR 0065](0065-scale-rules.md) 把文献分成“收进来的”与“只被发现的”，文献列表默认只显示前者。

这个区分定下来之后，留下了四个问题：

- 规则分散在 ADR 0065、查询技术篇和页面规格里，两边各有一套叫法，没有一处讲清楚两者是什么关系；
- 文献只能进文献库，不能出来。加错了只能删除，而删除会让它从搜索和引用关系里一起消失；
- 打开阅读一篇候选，它就自动进了文献库，使用者并没有表示要它；
- 页面上只写文献库的篇数，几十万篇候选在哪里、有多少，没有任何提示。

## 决定

### 1. 一个库，一个标记

- 文献库里的文献与候选是同一个库里的同一种记录。书目、来源记录、PDF、全文、引用关系都存在同一处，查重、补全与引用关系对两者一视同仁。
- 两者只差一个标记：这篇文献在不在文献库里。加入与移出只改这个标记，不复制、不搬动任何数据。
- 一篇文献在任一时刻只属于一边。

### 2. 名称

- **文献库**：使用者要的文献。
- **候选**：库里有、但还不在文献库里的文献。它不限于发现任务带来的：从文献库移出的文献也是候选。
- **全部文献**：文献库与候选合在一起。
- 文档与界面只用这三个名称。接口里已有的字段名（`collected`、`collection_scope`）不改。

### 3. 进来时落在哪一边

使用者点名的进文献库，程序找来的是候选。操作的是人还是 Agent，不影响结果。

- **点名**：导入书目文件、导入 PDF、从 Zotero 导入、浏览时收藏、命令行与 Agent 的导入。这些文献进文献库。
- **找来**：主题搜索、引用扩展。这些文献是候选。
- 同一篇文献两种方式都来过，它在文献库里。已经在文献库里的文献被发现任务再次找到，仍在文献库里。

### 4. 候选进入文献库

- **明说**：对它执行“加入文献库”。
- **使用**：手动给它加标签；把它放进文件夹或快照；为它提供或要求 PDF；要求生成全文；对它发起加工。对一篇文献有了投入，就算要它。
- 查看不算：搜索到它、预览它、打开阅读它，都不让它进入文献库。
- 进入文献库的时间取这一次加入的时间。

### 5. 文献库里的文献回到候选

- 提供“移出文献库”。文献库里的任何一篇都可以移出，不论它当初怎样进来。
- 移出只去掉第 1 节的标记。书目、来源记录、PDF、全文、批注、标签、阅读记录与加工结果都保留。
- 移出时，它同时离开所有文件夹：文件夹里只放文献库里的文献。已有的快照是当时的记录，不改。
- 移出之后，它与其他候选没有区别：可以被搜索到，可以按第 4 节再次进入文献库。再次进入时，原来的文件夹归属不恢复。

### 6. 删除

- 文献库里的文献与候选都可以删除，进入“最近删除”；恢复时回到删除之前所在的一边。
- 被删除的文献不出现在搜索、列表和引用关系里。
- 发现任务再次找到一篇已删除的文献时，不恢复它。使用者再次点名导入它时，恢复它，并按第 3 节进入文献库。
- 撤回一个批次的规则不变，见 [ADR 0063](0063-unified-intake.md)。

### 7. 人的界面

- 文献库的列表只列文献库里的文献。
- 候选在这些地方出现：搜索结果（先列文献库里的，再列候选）；“找文献”页的批次；阅读页的引用关系；最近读过。候选在不分段的列表里带“候选”字样。
- 文献库页写出候选的篇数，并由它进入“找文献”页的批次。
- 不提供全部候选的浏览列表，理由见 [ADR 0065](0065-scale-rules.md) 第 2 节。

### 8. 没有来历的旧文献

旧库迁移来的文献里，没有任何选用记录的，按候选处理。把它们整批加入文献库，是使用者自己的操作，程序不替他决定。

## 后果

- 使用者可以用四种操作说清楚自己对一篇文献的态度：加入文献库、移出文献库、删除、恢复。
- 打开阅读不再改变文献所在的一边，“最近读过”里会出现候选。
- 命令行与 Agent 得到与页面相同的“移出文献库”操作。
- 已经因为打开阅读而进入文献库的文献不回退；使用者认为不该在的，可以移出。
- [查询技术篇](../technical/06-retrieval-context.md)、[用户组织技术篇](../technical/09-user-organization.md)、[页面规格](../web/page-specs.md)与使用指南改用第 2 节的名称，并写入第 4 至 7 节的规则。

## 考虑过但没有采用的方案

- **不加移出，只用删除。** 删除表示“不想再看到”，它会让文献从搜索和引用关系里消失；“不算我的”与“不想看到”是两种态度，合成一个操作会让使用者在整理文献库时丢掉发现任务的成果。
- **打开阅读即加入。** 使用者点开一篇候选多半是为了判断要不要它；自动加入使文献库里混进没有表态的文献，也使移出之后一点开就又回来。
- **把候选存进另一个库。** 查重、引用关系与补全都要跨两个库进行，加入文献库要搬动数据；一个库加一个标记可以做到同样的显示效果。
