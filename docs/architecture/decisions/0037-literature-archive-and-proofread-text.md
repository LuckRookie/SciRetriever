## 背景

[ADR 0034](0034-unified-processors-and-results.md) 已经确定文献级和集合级两类处理器，以及基于版本的复用。但 Owner 反馈，处理器“和写一个脚本没什么区别”。原因有两点：

1. 处理器读到的文本本身不可信；
2. 文献在进入处理器之前处于什么状态，没有明确定义。

2026-07-24 的解析对比测试覆盖 4 篇论文、49 页，结果见[提案 1.2](../../archive/2026-10-20-literature-archive-proposal/proposal.md#12-解析结果不能直接作为可信源头)。MinerU 的每种模式单独使用都会出错，例如：把温度单位识别成百分号、丢失下标、照搬过期的文字层、把连字输出成私用区字符。

本 ADR 第一版据此采用“两种解析逐块对齐、分歧交给仲裁、全部区块通过才就绪”。2026-10-20 用 4 篇真实 PDF（19 页）实测后，这条路线的前提不成立：

- **区块位置不可靠。** VLM 把跨页的 30 条参考文献放进同一页；部分文字落在标注区域之外。按页码和坐标对齐，会把不相干的区块配对，或者产生大量单边区块。
- **按区块裁图会丢依据。** 表格区域不含表题和脚注，仲裁拿不到完整信息。8 个真实仲裁中，2 个因截图不完整拒绝作答，1 个在两个本就配错的候选之间做了选择。
- **两个不可靠的来源无法互相证明。** pipeline 与 VLM 都不是权威，系统大部分精力花在判断“两段是不是同一段”，而不是判断文字对不对。
- **要求建档时认证全文正确，必然引出“谁来审”。** 再加一个更强的模型审查只是把问题后移，无法提供可靠依据。

第二版因此改为：MinerU 只提供初稿；能找到权威参照的地方（PDF 文字层）由程序找出疑点；DSH 看整页原图矫正；不能确定的内容就地标为存疑，不阻断就绪；算子用到具体内容时再做针对性的核对。目标是错误可控、可发现、可追溯，而不是宣称全文无误。

[ADR 0008](../../archive/decisions/0008-summarized-markdown-literature-content.md) 的两阶段总结同时承担了三件事：近似校订、确定元数据、承载关键词，并且是“内容就绪”的标准。[ADR 0010](../../archive/decisions/0010-parser-neutral-markdown-current-result.md) 规定每个资产只保留一个当前解析结果，并清理私有输出。这两条都与下述设计冲突。

## 术语

| 术语 | 含义 |
| --- | --- |
| 部分 | 一篇文献的正文 PDF 或一个补充材料 PDF。每个部分独立解析、独立校订 |
| 原始解析 | 某个部分在某个解析 profile 下的不可变结果 |
| 初稿 | 建档时选用的原始解析，经规则清理、按页归属后的文本区块序列 |
| 页面类型 | 每一页的客观属性：`text-layer`（有可用文字层）、`image-only`（扫描页、只有不可见 OCR 层的页、文字层不可用的页）或 `blank` |
| 疑点 | 程序在 `text-layer` 页上对比文字层与初稿后列出的具体差异 |
| 矫正 | DSH 对照页面原图处理疑点或检查 `image-only` 页，并以编辑操作提交修订 |
| 存疑 | 2026-10-22 取消。矫正后仍不能确定的疑点只在处置记录中写明原因，不再标注在片段上 |
| 核对依据 | 每个片段经过的核对方式：文字层核对、仅图像核对、人工 |
| 校订稿 | 初稿应用全部矫正与人工决定后，由程序生成的区块列表及其渲染出的 Markdown |
| 结构注释 | 校订稿的章节角色与图表清单 |
| 建档 | 解析之后、算子之前的内置流程，依次为：校订、文档表示、结构、元数据、参考文献、标签 |
| 文献档案 | 建档的全部产物 |
| 就绪 | 文献可以被算子选中的状态 |
| 内容版本 | 每个部分一个，由校订稿和结构注释决定 |
| 描述版本 | 每篇文献一个，由元数据和标签决定 |
| 快照 | 冻结的一组文献，以及每篇文献的内容版本和描述版本 |
| 算子 | 即 ADR 0034 中的处理器 |

## 决策

### 1. 三个独立阶段

获取 PDF、解析、建档是三个独立阶段，每个阶段都必须手动发起，系统不会自动衔接：
- 获取 PDF 不会触发解析；
- 解析完成不会触发建档。
- 解析回执仅包含固定 PDF 身份和逐 profile 的原始解析结果或失败；不生成 `DocumentVersion`，不修改默认阅读版本。旧的必填 Document 回执、解析时发布 ParserResult/全文的调用链一并移除，不提供兼容分支（Owner，2026-10-20 追加确认）。

只有正文部分已具备建档所需的原始解析，才能发起建档。建档步骤从不调用解析服务。这一点延续了 [ADR 0028](0028-query-and-expansion-separation.md) 的显式操作原则。

建档是内置流程，不是算子，每篇文献都经过同样的步骤。

数据库补全（ADR 0013、ADR 0019）是用户显式声明目标的维护操作，可以在一次操作中先获取 PDF 再解析，但不包含建档。原有的 `CONTENT_READY` 补全目标随之退役。

阅读、检索校订稿不以就绪为前提，部分完成校订后即可阅读。就绪只用于控制算子能否选中这篇文献。

建档不以文章身份核验为前提。[ADR 0029](0029-unverified-pdf-acquisition.md) 的规定不变：下载不验身份，身份核验属于解析阶段的独立能力。

### 2. 原始解析与初稿

- MinerU 适配保留 `pipeline` 和 `vlm-engine` 两种 profile，服务仍由运维方管理（ADR 0003）。
- **建档只需要一份原始解析。** 使用哪个 profile 是部署级设置，由 Owner 根据验证结果（见“验证与当前边界”）确定，不是逐文献的用户选项，也不要求两种 profile 都完成。另一种 profile 的结果如果存在，只作为人工查看的参考，不参与校订。
- 每个原始解析只保留以下内容，其余私有输出不保留：
  - 由 `content_list_v2.json` 转换出的中性区块列表，包含页码、页内顺序、类型、文字、0–1000 归一化坐标；原始 `content_list_v2.json` 字节作为追查证据一并保留；
  - Markdown；
  - 实际被引用的图片；
  - 页面尺寸。

  不保留的私有输出包括：调试用的可视化 PDF、原 PDF 副本、模型原始输出、`middle.json`。
- **页码与坐标只是定位提示，不作为正确性依据。** 实测表明区块的页归属和区域可能出错；校订以页面原图为准，初稿的页归属在 `text-layer` 页上用文字层核对、纠正。
- 原始解析不可变，按内容寻址。重新解析产生新版本，旧版本只要仍被校订稿引用，就不能回收。
- MinerU 的私有格式不成为公共合同，适配器负责转换为中性区块列表。这一点延续 ADR 0010 的 parser-neutral 原则。
- 现有文献只保存了 VLM 的 Markdown，登记为“仅 Markdown 的 VLM 原始解析”，可以直接作为初稿：段落的页归属由文字层对照确定。存在无法确定页归属的段落时（例如扫描件），该部分需要用部署选定的 profile 重新解析后再建档。

### 3. 校订

校订的目标是**抄录保真**：忠实保留原文的文字、数字、符号、表格与结构，不总结、不补写、不润色，也不判断科学结论是否正确。校订完成表示检查流程完整、发现的问题都已处置、剩余疑点有记录，不表示全文无误。

1. **规则清理**：去掉页眉、页脚、页码；合并跨栏、跨页的段落；处理断词连字符；标记私用区字符与控制字符。规则移除的内容有记录，后续对比时计入“已归类”。
2. **页面分类**：按 PDF 本身的客观属性逐页判断，不使用经验阈值：
   - 页面有可见文字，且其中有能映射为 Unicode 的字符：`text-layer`；
   - 页面只有图像、只有不可见渲染的文字（常见于扫描件上叠加的 OCR 层），或可见字符全部无法映射：`image-only`。

   同一篇文献可以混有两类页面。无法映射的字符（`U+FFFD`、私用区、控制字符，常见于数学符号和连字）逐个排除，不参与对比，也不因此把整页改判为 `image-only`。
3. **找疑点（仅 `text-layer` 页）**：程序逐页比较文字层与初稿中归属该页的内容，以词和数字为单位，不做区块对齐。列出四类疑点：
   - 文字层有、初稿没有（可能漏掉）；
   - 初稿有、文字层没有（可能错字或多出）；
   - 数字、单位、化学式不一致；
   - 内容出现在别的页（页归属错误）。
4. **矫正**：由 DSH 完成，模型需支持视觉，工具包括整页渲染、局部放大、翻看相邻页，以及读取初稿片段与前后文。
   - `text-layer` 页：只处理疑点。
   - `image-only` 页：没有参照，逐页对照原图检查初稿。
   - **页面原图是最终依据。** 文字层只用来找疑点，可能过期或与渲染不一致；文字层与原图冲突时以原图为准，并记录原因。
   - 矫正以编辑操作提交：替换片段文字、插入、删除、移动、调整页归属。每个操作注明依据的页码。程序应用这些操作并生成完整校订稿，不让模型一次输出全文。
   - 看不清、无法确定的内容不猜测：疑点保留初稿并在处置记录中写明原因；`image-only` 页上没能转写出的内容，如实记为该处无文字。不在片段上添加“存疑”一类无法客观定义的标记（2026-10-22 修订）。
5. **处置完整性**（程序检查，只判断是否满足）：
   - 每条疑点都必须有处置：已修正、确认初稿无误（附原因，例如文字层过期或属于非正文）、无法确定（保留初稿，附原因）；
   - 每个 `image-only` 页都必须有检查记录；
   - 编辑操作必须指向存在的片段和页，图片引用必须有效；
   - 删除文字层中存在的内容，必须附原因。

   未满足时校订尚未完成，可以继续矫正，不进入就绪。
6. **校订失败**只在以下情况发生：
   - 缺少建档所需的原始解析；
   - 某页在 PDF 中有文字或图像，校订稿中却没有任何归属该页的内容，矫正也没有给出“该页无正文内容”的处置；
   - 矫正任务异常中止，可重试。
7. **“无法确定”的处置不阻断就绪。** 它只记录在处置中，不附在片段上，不使整篇文献失败。
8. **来源与核对依据**：每个片段记录文字来源（`parser`、`rule`、`agent`、`manual`）与核对依据（`text-layer`、`image-only`、`manual`），只如实记录，不换算成可信度分数。2026-10-22 起删除 `uncertain` 及 `uncertainty` 字段；正式库中已有的 `uncertain` 数据随代码直接移除，不统计、不迁移。
9. **人工决定**：人工修改会被锁定，重新校订时保留。初稿或原始解析发生变化时，标记为冲突，交给人工处理。

[ADR 0026](0026-agent-knowledge-and-human-collaboration.md) §3 关于“不以全文数字比对证明科研正确性”的限制，仍然适用于分析与综合产物。本节的文字层对比只用于找出抄录疑点，不用于证明全文正确，两者不冲突。

### 4. 部分

- 正文部分必须存在；补充材料部分可以有零个或多个。
- 补充材料常常比正文晚获取。新增补充材料只会增加一个部分，不改变正文部分的版本。
- **就绪只看正文部分。** 补充材料未解析或建档失败时，这一部分记为“不可用”，并在问题队列中标注“不影响就绪”。

### 5. 结构与参考文献

- 章节角色不写入文档表示，单独保存为**结构注释**。这样，识别方法改变时不会改变文档表示的 hash，也不会使证据失效。
  - 先用规则识别；规则没有命中的顶层章节交给模型。
  - 每个章节都必须有角色。不属于固定类别的正文章节取通用角色 `body`。
- 参考文献从正文部分的 `references` 章节解析，每一条都指向校订稿片段。库内关联沿用现有的身份规则，只有能可靠匹配时才建立关系。
- **参考文献缺失或解析失败不阻断就绪**，记入问题队列。
- 由参考文献建立的引用关系，使用新增的支持类型 `ArchiveReferenceTextSupport`，即“文档版本 + 片段 + 序号”。`ContentReferenceTextSupport` 随 `LiteratureContent` 一起退役。

### 6. 元数据

- `document_type` 拆为两个封闭枚举字段：
  - **出版形式**：期刊论文、会议论文、书籍或章节、学位论文、专利、报告或标准、数据集。
  - **文章性质**：研究论文、综述、快报或通讯、观点或评论、勘误或社论。
- 预印本属于 `version_role`，不属于出版形式。
- 数据源的原始类型字符串保留在 observation 中，映射表带版本号。
- 每个字段记录来源（权威来源、校订稿、人工），优先级按字段规定：
  - 书目字段：人工 > 权威来源 > 校订稿；
  - 文章性质、作者关键词、摘要、语言：人工 > 校订稿 > 来源。
- 来源之间不一致时标为冲突，不静默覆盖。人工修改的字段会被锁定。
- 建档的元数据步骤读取正文的 `front-matter`、`abstract`、`keywords` 片段，逐字段给出提议，每个提议附片段证据，再按以上优先级裁决。必填字段为：题名、作者、年份、出版形式、文章性质。
- 就绪之后到来的新 observation：
  - 只补空字段，并标出冲突；
  - 不改写已裁决的非空值；
  - 下一次显式发起建档的元数据步骤时，才重新裁决。
- [ADR 0002](0002-literature-identity-and-incremental-processing.md) 决策第 6 条的严格后备匹配，原本要求 `document_type` 一致，改为要求出版形式一致。后备身份索引随迁移重算。

### 7. 标签

- 标签是领域级的主题关键词，可以描述领域、方法或工作类型、文章性质（例如 benchmark），以及主要化合物。
- **不设维度。** 每篇文献至少 1 个标签、不超过上限（配置项，初值 6），不要求填满。标签按重要性排序，第一个为主标签。
- **粒度**：取文章自己会用作主要关键词的层级，以作者关键词为首要参考。细分主题只有在全文以它为主导时才成为标签。
- **以下内容不做标签**：数值、实验条件、试剂、溶剂、次要化合物，以及出版形式和文章性质。
- **主要化合物**：化合物名必须在题名或摘要中作为研究对象出现。名称用正式名或通用名；代号写入同义词；不得使用文中编号作为名称。
- **打标流程**：先写出主题，再检索已有标签，优先吸附，确实不合适时才新建。新建时必须逐一说明已有候选为何不合适，并给出中英文名、同义词、定义（包含与不包含什么）、可选的上级（最多两层）、示例。
- 词表自然增长，不预设；每次变更都产生新的词表版本并写入日志。
- **整理**：每批建档后自动执行合并、补充上级、归类、修正定义，不需要人工审批。每次操作都可以撤销，遇到人工锁定的标签时跳过。
- **回溯**：只能手动执行。执行前先显示候选数量和预计调用次数。按标签筛选时，如果有在该标签创建之前打标、且尚未回溯的文献，会给出提示。
- 筛选时，可以按主标签或任一标签；选择上级标签时包含下级。
- 词表是库数据，不放在代码仓库中。

本节修订 ADR 0008 §6“关键词不再建立平行分类或标签”。作者关键词仍保存在元数据中；标签是另一套用于筛选范围的受控结果，不是关键词的副本。

### 8. 就绪与状态

文献状态共六种：

| 状态 | 含义 |
| --- | --- |
| `UNREVIEWED` | 没有主 PDF |
| `ASSET_READY` | 有主 PDF，尚未就绪，`missing_step` 指出下一步是解析还是建档 |
| `ARCHIVING` | 建档中 |
| `ARCHIVE_FAILED` | 正文部分有未解决的失败 |
| `READY` | 已就绪 |
| `EXCLUDED` | 文章性质为观点或评论、勘误或社论，不作为文献，不进入算子。人工改判文章性质后会重新推导状态 |

`READY` 必须同时满足以下条件：
1. 正文部分的校订完成（第 3 节第 5 条全部满足），并已成为默认文档；
2. 结构注释中至少有一个正文类章节；
3. 必填元数据齐全；
4. 标签数在 1 到上限之间。

所有条件都只判断满足或不满足，不使用经验阈值。“无法确定”的处置、参考文献问题、补充材料不可用都不影响就绪。`READY` 取代 `CONTENT_READY`，成为“可用”的标准。

### 9. 版本

- **内容版本**：每个部分一个，等于 hash(文档版本, 结构注释)。
- **描述版本**：每篇文献一个，等于 hash(元数据 revision 与 hash, 标签分配 hash)。

内容版本变化会使读取了该部分的算子结果过时。描述版本变化（例如调整标签、整理词表、回溯）不会使单篇结果失效。

### 10. 算子

- **输入**：算子只能读取就绪文献的校订稿，读取范围由声明的部分和章节角色限定。片段的核对依据随片段一起提供。原始解析只供人工查看，不进入算子上下文。
- **分块**（2026-10-22）：默认整篇一次调用；超过门槛才分块，门槛取 200K token 与“模型上下文窗口 − 提示词与输出预留”中的较小者，未配置上下文时按 1M 计。token 按固定字节换算保守估算，换算系数写进算子定义。分块按 Markdown 结构进行：先按一级标题切并合并相邻章节，超限再按下一级标题切，没有更细的标题时在段落之间切；表格与图注脚注、图片与图注、跨页续表、公式块各算一个整体，永不拆开，单个整体超限时记为缺口。每块开头附文章标题与章节路径。分块规则计入方法哈希；用户规范不再有 `max_chunk_bytes`。
- **单篇算子**：
  - 不依赖其他单篇算子；
  - 复用键为：读取部分的内容版本 + 算子版本 + 规范 + 方法 + 模型配置；
  - 结果按值量化（2026-10-22）：每个字段要么有值，要么为空（null），不再区分“原文未报告”与“无该部分”。读取是否完整单独记录：补充材料不可用等情况记为读取不完整，原因作为缺口保留（如 `part-unavailable`）。运行记录按“有结果／结果为空／读取不完整”三种计数。
- **用时核对**（2026-10-22 修订）：提取出的每个值都引用校订稿片段。由平台（不是各个算子）对所有片段一律做文字比对，不再按核对依据分流，也不再调用视觉模型；结果记在该值上，共六种：
  - 可找到：值中的数字、单位或文本在被引用的片段中都能找到（不含数字的值按归一化后的文本判断）；
  - 找不到：片段存在、值非空，但片段中找不到该值；
  - 值为空：值为 null；
  - 无引用：值非空但没有引用任何片段；
  - 引用片段不可用：引用的片段在当前校订稿中已不存在；
  - 综合值：值来自其他结果，不做比对，链接到来源结果。

  状态旁显示片段的文字来源（解析、Agent、人工）。核对方法改变后，旧结果按方法变化处理为过时，不迁移。
- **快照**：不可变；只选取 `READY` 的文献；可以由筛选条件生成；两个快照之间可以比较差异。
- **多篇算子**：
  - 先逐篇读取：通过声明的 `map` 单篇算子执行，结果可以复用；
  - 再汇总：只基于单篇结果，需要核实时可以按证据回读片段；
  - 输出为带引用的 Markdown 报告或结构化表格，引用保留各值的核对标注。
- **过时**：版本事件只会把结果标记为过时，不会自动重算。重算的方式是：基于新的快照或当前版本，发起一次新的运行。这修订了 ADR 0034 中“集合输入变化后整体综合”的规定。
- **总结**：原来的知识总结是一个普通的单篇算子，读取正文。它不自动运行，不参与建档，也不作为其他单篇算子的输入。

### 12. 单一当前数据库结构

Owner 明确要求合并全部数据库版本，不再保留历史 schema 定义、逐级迁移链或开发中间态兼容（2026-10-20）。

- 生产代码只提供一份当前结构及初始化/检查入口，表结构按模块责任组织；开发任务和测试修复不能各自生成一个数据库版本。版本标识只描述当前整体结构，指纹与实际 DDL 必须一致。
- 现有本机库一次性转换：08–10 的表结构定稿后、计划收尾前，先完整备份，在副本上转换并核对元数据、来源观测、原始资产及关系；核对后由 Owner 确认停服切换。转换材料和证据留在本机测试目录，不成为长期兼容代码。结构收口前不反复转换本机库。
- 副本转换时直接删除第 11 节的四类旧数据，无需保留这些派生结果的哈希关系；VLM Markdown 作为原始解析保留。原始 PDF 与解析原件不能被删除或覆盖；不兼容的派生结果不能冒充新建档或新算子的有效结果。
- 此授权不包括立即切换本地库或调用真实服务。
- 后果：此后表结构变化没有自动升级路径，需要按同样方式一次性转换。

## 未采用的方案

| 方案 | 原因 |
| --- | --- |
| 两种解析逐块对齐、分歧交给区块仲裁（本 ADR 第一版） | 实测中区块页归属与区域不可靠，对齐会配错；按区块裁图丢失表题等依据；两个不可靠来源无法互相证明 |
| 全文严格校订通过才就绪 | 参考文献或装饰标题上的一个疑点就会挡住整篇文献；没有可靠裁判时，这个要求无法兑现 |
| 建档后由更强的模型审查全文 | 审查者本身同样无法被证明可靠，只是把“谁来审”后移，并增加成本 |
| Agent 直接读 PDF 从零生成全文 | 没有可复现的初稿；最典型的错误是悄悄省略和改写，最难发现；全库规模成本高。可用文字层指标在验证中复核，如结果明显更好再修订本 ADR |
| 让 Agent 一次性重写整篇 | 长文受输出上限限制，容易漏段、截断、改坏图片引用；改动范围无法审查 |
| 为扫描页另接一个 OCR 引擎作为参照 | OCR 本身不权威，增加一个外部系统；Owner 决定扫描页依靠 MinerU 初稿加 Agent 看图矫正 |
| 设“不可信区块”和质量阈值 | 阈值是经验值，没有依据；改为每条疑点必须有处置，不确定的就地标为存疑 |
| 固定维度、受控词表加“其他” | 固定维度装不下 benchmark 这类标签；“其他”会成为模型的默认选项 |
| 获取 PDF 后自动建档 | 违背阶段划分；获取 PDF 并不意味着解析服务可用，也不意味着已经解析 |

## 后果

- 解析只需一种 profile，GPU 时间与现状相当。现有文献的 VLM Markdown 可直接作为初稿；扫描件等无法确定页归属的部分需要重新解析。
- 新增模型调用：矫正（随疑点数和 `image-only` 页数增长）、用时核对、元数据、章节角色兜底、打标、整理、回溯。调用次数、token 与耗时逐步记录。
- 新增确定性能力：PDF 页面分类、文字层提取、页面渲染与局部放大。所用的库是否需要新增依赖，在实施计划中提交 Owner 确认。
- **残余风险如实承认：**
  - `text-layer` 页上，文字层只能发现文字与数字的问题，无法发现阅读顺序、表格行列对应、公式排版的错误；
  - `image-only` 页没有参照，正确性依赖 MinerU 与 Agent 的看图能力；
  - 校订稿仍可能有错。系统只展示可客观判断的事实（文字来源、该页有无文字层、谁在何时修改过），不展示任何没有依据的准确率。
- 可接受范围在验证阶段判断，不写成运行时关卡；运行时只判断处理是否完成。
- 以下公开合同有破坏性变化，不做兼容：
  - 解析请求/回执：移除默认文档 CAS 和旧 Document 字段，返回逐 profile 原始结果；
  - 元数据字段；
  - 文献状态；
  - CLI 参数 `--document-type`；
  - 数据库补全的 `CONTENT_READY` 目标；
  - 处理器的输入种类、复用键与证据核对字段。
- 真实库需要迁移并重建，只能在 Owner 授权后先在隔离副本上执行。

## 验证与当前边界

- 第二版的验证（计划中的 GV）包括：
  1. 只读统计库内 PDF 的页面类型比例，以及文字层是否可用。2026-10-20 已完成：1,006 个 PDF、20,805 页中，95.5% 的 PDF 全部为电子原生页，约 8% 的页为扫描页，主要来自 2000 年以前的文献；文字层页中 85.8% 没有无法映射的字符（见计划 02 的 2.1）；
