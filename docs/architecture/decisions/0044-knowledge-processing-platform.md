# ADR 0044：知识加工平台——封闭类型、预置形态与显式授权运行

类型：决策（ADR）
负责：知识加工的产出类型、执行形态、运行授权与预算、算子准入
状态：Proposed（2026-10-28 提出，2026-11-10 按 ADR 0059 修订，待 Owner 接受）

- Date: 2026-10-28
- 依据：Owner 2026-10-24 至 10-28 的决定：保留算子并插件化；SciRetriever 定位为知识蓄水池，服务端批量加工，外部 Agent 请求取用；算子绝不自动执行，每次运行走含选取的固定流程；“做全，做完再看效果”；预算采用软上限，只停止派发新单元、不截断正在阅读的单篇；验收节奏为各块验工程、成套验效果。设计经 Claude 与 Codex 会话“审视 PDF 获取后的算子设计”八轮讨论与审核（本机 `sandbox/prompts/operator-design-review-*.md`）。2026-11-10 Owner 确认人和 Agent 是并列的服务对象（[ADR 0059](0059-general-literature-knowledge-base.md)），第 1 节据此修订：人和 Agent 都能发起加工并取用结果。
- 部分取代（未列出的内容保持不变）：
  - [ADR 0034](0034-unified-processors-and-results.md)“决定”第 1 段：
    - “范围为文献级（单篇）和集合级（多篇）处理，不建立通用算子形状、配方或用户代码沙箱”——改为允许本 ADR 第 3 节的封闭执行形态与第 7 节的声明式单篇定义；任意形状协议、配方语言与用户代码沙箱的禁令保留；
    - “单篇算子只读取就绪文献的校订稿”中的“就绪”——改为按声明的材料准入（第 5 节）；只读校订稿、按声明的部分与章节角色读取、单篇算子之间不互相依赖保留；
    - “多篇算子以冻结的快照为输入，先用声明的单篇算子逐篇读取，再只基于单篇结果汇总”——快照上的逐篇加汇总保留，另允许汇总以任意冻结的集合清单为输入，以及分组、成对、派生形态（第 3 节）。
  - ADR 0034“决定”第 2 段“单篇结果的复用键使用被读取部分的内容版本，描述版本（元数据与标签）不参与”——声明读取元数据或标签的算子，所读内容进入复用键；不读的算子不变。
  - [ADR 0037](0037-literature-archive-and-proofread-text.md) 第 9 节“描述版本变化（例如调整标签、整理词表、回溯）不会使单篇结果失效”——对声明读取元数据或标签的算子不再适用。
  - ADR 0037 第 10 节：
    - “输入”中“算子只能读取就绪文献的校订稿”的“就绪”——同上改为按材料准入；
    - “分块”（2026-10-22）的“默认整篇一次调用”与分块规则——单篇算子改为在公共阅读会话中按声明范围分页读取；现有切块单次调用实现暂留为内部实现，不再是单篇算子的方法；
    - “单篇算子”的复用键——增加所读的元数据或标签；
    - “快照”中“只选取 `READY` 的文献”——改为收入全部选中成员并冻结材料事实与选取来源；
    - “多篇算子”中“输出为带引用的 Markdown 报告或结构化表格”——改为第 3 节的封闭产出类型。
  - ADR 0037 第 8 节 `READY` 的定义与条件不变，只是不再作为算子门槛。ADR 0037 第 10 节“用时核对”对校订稿片段的文字比对保留，新增证据根的核对见第 4 节。
  - [ADR 0026](0026-agent-knowledge-and-human-collaboration.md) 第 3 节 2026-10-12 Owner 修订中“不设 token、累计调用次数或整篇执行时长的业务预算”——对知识加工及其辅助模型操作改为第 6 节的软预算；对解析等其它范围不变。

## 背景

ADR 0034 与 0037 建立了扎实的执行与保存机制：冻结输入、不可变结果、证据、覆盖、复用与过时标记。2026-10-24 的审查发现任务设计薄弱，并在代码中核实：多篇综合的逐篇步骤写死为不带问题的通用概览；单篇输入一律要求 `READY`，标签与必填元数据阻断正文分析；持续阅读会话只有总结能用；记录不能进入综合；综合的覆盖会把部分完成记成无。

Owner 随后确定了产品方向：SciRetriever 是知识蓄水池，几万篇文献的加工只能由服务端并发完成；加工包括总结、问答、提取、问题综合、记录比较、发表统计、主题维基、实体归一与知识图谱；结果按类型自动获得 Web 页面，并经机器接口供 Agent 取用；但运行成本必须可预知、可控制，不能在不知情时爆炸。

讨论中的初发现约束本 ADR：研究问题决定逐篇读什么、提取什么；库管理条件不阻断正文分析；维持少量明确机制，不做任意依赖图、配方语言或插件平台；“比较这批论文在不同条件下的结果”必须能被自然承接并交付可核查的比较。

## 决定

规格细节见[知识加工规格](../technical/05-knowledge-processing.md)第 8 节；本节只记录约束后续设计的选择。

### 1. 定位

服务端把校订稿加工成有类型、可核查的结果。人和 Agent 都能发起加工，并取用同一份结果（ADR 0059 第 2 节）：

- 人在 Web 上发起。结果按类型呈现为可以直接阅读的页面（第 4 节的“类型 → 视图”注册表）。
- Agent 经命令行和 MCP 发起，读取结构化的结果。
- 两者经过同一组检查点（第 2 节）。谁可以花钱由第 6 节的授权决定。

[ADR 0027](0027-extraction-capabilities-and-caller-defined-records.md) 与需求“炼3”的外部提取交付和长期托管保持可用。

### 2. 不自动执行，固定检查点

任何付费运行都不会自动发起：没有常驻规则；版本事件、阅读与页面访问只标记过时。每次运行经过同一组检查点：定义、选取、冻结、授权、可选试运行、估算确认、执行、取用。固定的是检查点，不是逐层强制筛选。估算同时给出花费和用时的区间及依据。授权在第一笔花费之前；摘要筛查、试运行、规范起草、分组与合并提议都是付费步骤。选取来源随运行冻结并可重放。

### 3. 封闭的产出类型与预置形态

- 产出类型是封闭集合：报告、回答、记录表、统计、分组（主题、实体两种变体）、关系、页面集。新增类型须先证明现有类型不能合理承载，并另经 ADR。
- 执行形态是平台预置的执行策略：逐篇、汇总、分组、成对、派生，共用同一执行器；不是对研究任务的完备形式化。
- 多步任务是一串独立运行，每段的输入是上游已冻结的结果，每段单独经过检查点；命名组合只是预填下一段的模板。不做任意依赖图、配方语言、自动循环或执行外部代码。
- 汇总可以接受任意冻结的集合清单为输入，不再限于同一快照的逐篇结果；汇总时可以按已有证据回读被引用的片段核实，补读未引用的内容须另起运行。
- 派生只运行平台内置的确定性函数。
- 成对只处理按冻结规则生成的候选对，不做全量两两。
- 实体不按规范化名称自动合并；实体合并的确认与边的确认都是带操作者与依据的决定，二者分开，实体合并确认不代替边确认。

### 4. 结果合同

- 结果身份与复用键分开：结果有独立 ID 与内容 hash；复用键只用于判断能否复用完整结果，复用不覆盖旧结果。
- 覆盖（处理范围）与判断（未定、待确认、候选等）分开记录；下游记录实际消费的上游范围及相关上游缺口。
- 证据根有三种：校订稿位置、冻结元数据及其来源、人工决定。从原文提取的值仍引用校订稿片段并做文字核对（ADR 0037 第 10 节“用时核对”）；以元数据为根的值核对冻结元数据的字段与来源；以人工决定为根的条目核对决定存在、操作者与授权；派生与汇总值按“综合值”链接上游。来源链闭合只说明可追溯，不说明结论成立。
- 平台维护封闭的“类型 → 视图”注册表；算子只声明类型与封闭集合内的字段类型，不提供校验或界面代码。

### 5. 按需材料门槛

算子按声明需要的材料准入，不再以 `READY` 为门槛。`READY` 继续表示库整理完成，用于筛选与展示；`EXCLUDED` 仍是独立的选取政策。快照收入全部选中成员，冻结版本、选取来源与材料事实。声明读取元数据或标签的算子，所读内容进入复用键；不读的算子不受描述版本影响。

### 6. 预算与授权

- 预算适用于知识加工及其辅助模型操作（运行、试运行、复核、规范起草、分组与合并提议）；建档（ADR 0041 第 6 节）、获取与 Browser（[ADR 0023](0023-generic-browser-agent-executor.md)）的预算合同不变。这些操作共用持久账本，预算是软上限，准入以执行单元为粒度：余额不足时不再准入新单元；已准入单元可以透支，不截断正在阅读的单篇。单元费用上界未被证明时，超出上限显示为未知，不冒充硬上限。
- 预算账本保存授权、费用与对账事实，不因此长期保存普通失败日志或批量过程记录。
- Owner 可以为 Agent 授予一项任务的范围、有效期与累计额度；Agent 不能自行续额或扩大范围。未获授权的付费步骤由人确认。首版不建设长期 Agent 账户配额。
- 授予额度、发布声明式算子是 Owner 操作，三端在 Owner 授权下都可执行（[ADR 0033](0033-machine-interfaces-cover-web-capabilities.md)）。

### 7. 声明式算子

单篇算子可以由声明定义（读取范围、所需材料、产出类型、规范与产出 schema、方法），由通用执行器经公共阅读会话运行，不执行定义方提供的代码。产出类型限于单篇可产出的报告、回答、记录表。草稿只对创建者可运行；经 Owner 确认后发布，发布版本不可修改，发布不授权全库执行。

## 对既有决定的处理

- ADR 0034、0037、0026 的正文不改，各自状态行增加“部分被 ADR 0044 取代”及所取代的条目。
- 需求“炼4”要求加工开始前能知道大约的花费和时间。预算的做法由本 ADR 第 6 节规定，ADR 0026 第 3 节的无预算规定按上文部分取代。
- 以下需求修订由 Owner 作出，与本 ADR 同时生效：需求第 6 节“产品不要求建立引用关系之外的通用文献关系图谱”之后补一句：知识加工可以产出带证据的实体与关系结果（本 ADR 第 3 节），它们是派生知识，不改变文献身份、版本组织与权威引用关系。
- 需求“炼3”的外部提取能力不变。
- 已有结果与快照不迁移、不重算；旧版本结果由版本化解码器读取；旧版本的排队任务经隔离的旧执行入口按原版本完成。

## 未采用的方案

| 方案                                              | 原因                                                                                         |
| ------------------------------------------------- | -------------------------------------------------------------------------------------------- |
| 取消算子，只保留总结、问答、提取三项固定能力      | 失去声明式扩展；Owner 要求 Agent 可自制算子                                                  |
| 只做三种产出类型与两个固定组合（2026-10-26 定案） | Owner 决定做全，维基、统计、图谱都是真实需求                                                 |
| 开放产出形态协议，算子自带界面                    | 平台失控，新类型无法获得可靠的核对与汇总；以封闭类型与视图注册表代替                         |
| 任意依赖图、配方语言或自动连跑                    | 成本不可预知，违背“不自动执行”；以逐段独立运行与命名组合模板代替                             |
| 以外部 Agent 自己读论文加工作为默认批量路径       | 服务端统一并发、复用与费用治理更适合几万篇的批量加工；外部提取能力（第 1 节、需求“炼3”）保留 |
| 常驻规则：新文献进入范围或版本过时时自动处理      | 成本会在不知情时爆炸                                                                         |
| 硬预算：每次请求预留费用上界，余额不足立即拒绝    | 会截断正在阅读的单篇，使已经花费的部分作废；当前会话策略尚未证明单篇费用上界                 |
| 实体按规范化名称自动合并；成对做全量两两          | 同名不等于同一实体；全量两两成本不可承受                                                     |

## 后果

- 研究问题与提取规范从逐篇阅读开始生效；未打标签的文献可以被只需正文的算子加工。
- 新能力分块交付，每块登记自己的类型与视图，不先搭齐全部类型；块的顺序与依赖见计划 16。
- 运行多了确认与授权步骤；Agent 需要 Owner 授权才能自行花费。
- 人发起的加工和 Agent 发起的加工走同一组检查点，得到同一份结果；每种产出类型都要同时交付人读的页面和机器读的结构。
- 残余风险如实承认：
  - 软预算可能超出，超出量取决于在途单元，费用上界未知时无法给出数值；
  - 摘要筛查、候选规则与检索选取都可能漏召回，平台只能提示与支持抽样复核，不能证明没有遗漏；
  - 实体确认的人工量取决于语料，提议排序与批量确认只能减轻；
  - 合成 fixture 与 fake 模型只证明机制；真实质量、成本与可用性只能在获授权的成套效果评估中得出。
- Accepted 不表示实现或质量已验收。
