# ADR 0064：引用扩展以层数为界，数量上限可以不填

类型：决策（ADR）
负责：引用扩展的边界：层数、结果上限、每个来源的扫描上限
状态：Accepted（2026-11-19，Owner 决定）

- Date: 2026-11-19
- 依据：Owner 2026-11-19 的原话：

  > 这种任务明显是那种侧重“层数”这个参数的任务啊，数量应该作为次级参数才对，数量限制改为默认不填写，不填写就不限制。但是层数默认是1层。保守一些

- 部分取代：[ADR 0013](0013-decoupled-discovery-and-database-maintenance.md) 第 3 节“引用扩展必须具有明确的……去重后结果数量和逐 Provider 原始扫描边界”：改为第 1、2 节。第 3 节的其余规则（结果计数口径、上限按整个 Run 计、不无界递归、继续扩展须另起 Run），以及第 2 节对主题发现的扫描边界，继续有效。
- Related：[任务与协作控制：引用发现](../technical/02-task-coordination.md#312-引用发现)

## 背景

引用扩展的目的是沿引用网成批取得文献。ADR 0013 要求每次引用扩展都写明结果上限和每个来源的扫描上限，两者都按整个 Run 计、依种子顺序和层次消耗。实际使用中：

- 使用者关心的是扩几层，而不是取多少条；上限填小了，排在前面的种子和较浅的层先用掉额度，后面的种子取不全；
- 层数有限时引用网本身有限，任务在来源取完后自然结束，停止并不依赖数量上限；
- 数量上限只起控制成本的作用，应当由使用者按需选择。

## 决定

### 1. 层数是引用扩展的主参数

- 每次引用扩展的层数有限，并写入 Run。
- 调用方不写层数时取 1，即只取种子的直接参考文献或直接施引文献。
- 层数上限、`0` 的含义等其余规则不变。

### 2. 结果上限和扫描上限可以不填

- 引用扩展的 `result_limit` 和每个来源的 `scan_limit` 都可以不填；不填表示不限，任务在本次层数内取到各来源取完为止。
- 填写时必须是不少于 1 的整数，含义仍按 ADR 0013：按整个 Run 计，不在每个种子、每层或每次请求上重置。
- 所有入口（网页、HTTP 接口、MCP、命令行）都不再为引用扩展预填数量上限；网页和接口展示时写明“不限”。
- Run 如实保存“未设上限”，不以某个大数代替。

### 3. 主题发现不变

主题发现没有层数，每个来源的 `scan_limit` 仍是它唯一的边界，本决定不改变它。

## 后果

- 库结构要允许引用扩展的结果上限和扫描上限为空，需要一次结构迁移；已有 Run 的数值原样保留。
- 不设上限的引用扩展可能运行很久、消耗较多来源配额；它仍可随时取消或中断，已接纳的结果保留。
- 多层扩展时，填了上限后怎样在种子和各层之间分配，留待做多层扩展时另行决定。
