# ADR 0058：文献库只有一个地址，由桌面一侧把 Zotero 推进来

类型：决策（ADR）
负责：浏览器扩展与桌面 Agent 怎样连上文献库；不同机时 Zotero 数据怎样进入文献库；导入会话；设备连接令牌
状态：Proposed（2026-11-10，待 Owner 接受）

- Date: 2026-11-10

  > 当然目前是Agents时代，尽量用Agents来去干活。

  > 是不是插件应该有一个设置端口？无论文献库在本地还是远程最终都是通过本地端口来进行通讯？这个基础是肯定要定下来吧

## 背景

ADR 0057 假定：服务与 Zotero 不在同一台电脑上时，由服务端用网络 API 去 `api.zotero.org` 取数据，PDF 只能取 Zotero 官方存储里的，其余由用户在网页上传 `storage` 文件夹。

Owner 的实际用法是另一种：

- 文献库跑在集群的服务器上，Zotero 装在 Owner 自己的电脑上，用默认端口。
- Owner 把服务器的 4174 端口映射到本机，在浏览器里打开 `http://localhost:4174` 使用文献库。

Zotero 和用户的浏览器总在用户自己的电脑上（下称“桌面”）。浏览器能打开的文献库地址，桌面上的任何程序也能打开。桌面上的程序还能读 Zotero 本地 API 和 Zotero 的 `storage` 文件夹。服务器则读不到桌面上的文件。所以不同机时，应该由桌面这一侧读 Zotero，再经文献库地址推给文献库。

另一种办法是反向隧道：把桌面的 23119 端口映射到服务器，让服务端像同机一样读本地 API。不采用，原因有两个：

- 本地 API 给出的附件路径在桌面上，服务端照样读不到 PDF；
- 隧道要一直开着。

现在搬运这类活适合交给 Agent：用户说要导入什么，桌面上的 Agent 去读 Zotero、推数据、处理例外，再向用户汇报。人则在网页上看进度和结果。

## 决定

### 1. 文献库只有一个地址

- 文献库对外只有一个地址，就是用户在浏览器里打开 Web 工作台用的地址。浏览器扩展和桌面桥（第 6 节）都只连这个地址。文献库在本机还是在远程，对它们没有区别。
- 远程时，由用户自己让这个地址在桌面上可达，例如端口映射（`ssh -L 4174:localhost:4174 <服务器>`）、局域网或 VPN。本系统不建隧道，也不自动发现服务。
- 设置的是完整地址（协议、主机、端口），不只是端口，默认 `http://localhost:4174`。地址规则与现有机器入口的 `--workbench-url` 相同：显式 IPv4 HTTP 地址加端口，`localhost` 规范为 `127.0.0.1`。域名与 HTTPS 另议。
- 连不上时，提示里写明所连的地址，并提醒用户检查端口映射是否开着。
- 与 ADR 0035 一样，HTTP 不加密，只在可信网络或隧道内使用。

### 2. 连接码：用户不手动填地址

- 用户在 Web 设置页“设备连接”分区点“连接浏览器扩展”或“连接 Agent”。页面取自己的地址，生成一串**连接码**，包含：
  - 文献库地址；
  - 一次性配对码：10 分钟内有效，只能用一次。
- 扩展或桌面桥收到连接码后，向其中的地址换取长期令牌，并记住这个地址。
- 映射端口变了时，在扩展或桌面桥里改地址即可，令牌不变；令牌被撤销后，要重新生成连接码。
- 令牌由扩展保存在自己的本地存储里，由桌面桥保存在用户目录下只有本人可读的文件里。

### 3. 设备连接令牌

本节取代 ADR 0057 第 6 节的扩展配对令牌。

- 每个设备连接有名称、用途、创建时间和最近使用时间。服务端只保存令牌的加盐派生值。设置页列出全部连接，可以随时撤销。
- 用途决定令牌能调用哪些接口：
  - **收藏**：ADR 0057 第 6 节那组接口，即按标识查询文献状态、列出文件夹、保存书目、上传 PDF；
  - **Zotero 导入**：第 5 节的导入会话接口与文件上传。
- 扩展默认两种用途都有，Agent 默认只有 Zotero 导入；生成连接码时可以改。
- 令牌不能登录 Web 工作台，也不能调用其他接口。这些接口按令牌认证，不校验 Origin；其他接口照 ADR 0035 不变。
- 桌面上不保存 Web 登录密码。

### 4. 不同机时，由桌面一侧推送 Zotero 数据

| 情况                         | 谁读 Zotero    | 书目、分类、标签、批注 | PDF                                              |
| ---------------------------- | -------------- | ---------------------- | ------------------------------------------------ |
| 服务和 Zotero 在同一台电脑上 | 服务端         | 本地 API               | 按本地 API 给出的路径直接读（ADR 0057 不变）     |
| 不在同一台（主路径）         | 桌面桥         | 在桌面读本地 API       | 在桌面读附件文件，经文献库地址上传               |
| 桌面不在线，或群组只在云端   | 服务端         | 网络 API               | Zotero 官方存储里的由服务端下载（ADR 0057 不变） |
| 都不可用时的兜底             | 用户在网页上传 | RDF 导出               | 随 RDF 导出的文件夹，或网页上传 `storage` 文件夹 |

- 桌面桥只读 Zotero：不写回，不读 `zotero.sqlite`。读 PDF 时只读本地 API 给出的附件路径。本地 API 不需要 key。
- 桌面桥不解析、不映射，把本地 API 返回的 JSON 原样上传（与网络 API 同一格式）。解析、身份匹配、编号对应与去重都在服务端完成，用 ADR 0057 第 1 节说的同一套解析代码。
- 首版只有桌面桥一个推送者。扩展能否读本地 API，以计划 20 的探测结果为准；扩展作为第二个推送者给不用 Agent 的人，放在后面做。

### 5. 导入会话

所有来源都落到同一个导入会话：服务端拉取本地 API 或网络 API、桌面推送、上传 RDF。

1. **建会话**：写明来源（哪个 Zotero 库、由谁读取）与范围（所选分类、整库，或“上次导入之后的变化”）。
2. **收集**：分页取得或接收条目、分类、标签、附件与批注的 JSON。中断后从断点继续。
3. **预览**：内容同 ADR 0057 第 2 节，不写库。
4. **确认**：写库，形成入库批次“Zotero 导入”，书目先入库。
5. **补文件**：
   - 服务端列出需要的 PDF：附件编号、md5、大小；
   - 推送者先报 sha256，库里已有同一文件的不再上传；
   - 文件按附件编号分块上传，可以续传；
   - 验收同 ADR 0057 第 3 节。
6. **结束**：报告按预览的分类写明实际结果。

- 会话持久保存，服务重启或连接中断后都能继续。Web“从 Zotero 导入”页实时显示进行中的会话，不论是谁发起的。
- **增量**：会话记下所读 Zotero 库的版本号。“同步”就是从上次的版本号开始建一个新会话。本地 API 是否支持按版本号取变化，以计划 20 的探测为准；不支持时按编号整体比对。
- **确认可以由 Agent 做**，令牌有 Zotero 导入用途即可。理由：
  - 预览不写库；
  - 已有主 PDF 不被替换；
  - 冲突只记录，不自动处理。

  用户想把关时，在网页上看同一个会话再确认；用户要求 Agent 等人确认时，Agent 就等。

### 6. 桌面桥

- 单文件脚本，由文献库提供下载，只依赖 Node（LTS 版本），桌面上不需要装 SciRetriever 仓库。
- 命令：`pair`、`status`、`collections`、`preview`、`import`、`sync`、`sessions`。
  - 不交互，输出 JSON，退出码区分可重试与不可重试的失败，适合 Agent 调用；人也可以直接用。
  - `status` 分别报告本机 Zotero 与文献库能否连上。
- 只连两处：本机 Zotero 本地 API，和连接码里的文献库地址。
- 会话接口带协议版本号。桌面桥与服务不兼容时，提示用户重新下载。
- 桌面桥是会话接口在桌面一侧的客户端，不替代 ADR 0033 的 CLI/MCP。服务端的 CLI/MCP 照样能发起服务端拉取的会话，也能读取会话状态与报告。
- Web 设置页“连接 Agent”给出一段可以直接复制给桌面 Agent 的话，包含连接码、下载地址和指南链接。

### 7. 界面

- 设置页的“浏览器扩展”分区改为“设备连接”，包含：
  - 连接浏览器扩展、连接 Agent；
  - 下载扩展安装包与桌面桥；
  - 已连接设备列表与撤销。
- 设置页“Zotero”分区：本机 Zotero（同机时用）；网络 API 晚些做。
- 入库页“从 Zotero 导入”：
  - 顶部列出进行中和最近的会话；
  - 新建会话时按情况提供：让 Agent 导入（复制给 Agent 的话）、服务端直接读（同机时）、网络 API、上传 RDF；
  - 会话页显示预览、进度、冲突与报告，并有确认按钮。

## 后果

- 交付顺序改为：
  1. 设备连接、导入会话、服务端读本地 API（同机）、桌面桥、会话页：书目、分类、PDF；
  2. 浏览器扩展收藏；
  3. 批注导入；
  4. 网络 API、RDF 兜底，以及扩展作为 Zotero 推送者。
- catalog 升级时，除 Zotero 编号对应外，还要保存导入会话与设备连接，取代 ADR 0057 设想的扩展配对令牌表。
- 计划 20 按本决定重排。它的 01 探测仍然要做：本地 API 成了不同机时的主数据来源，它的格式与能否被扩展访问更加关键。
- 大文献库经隧道上传可能达到几 GB，所以上传前先比对 sha256，按块续传。
- 令牌以明文保存在桌面的用户目录或扩展存储里；桌面被他人使用时，用户可以在设置页撤销。
- 规格写进[文献与材料技术文档](../technical/03-literature-materials.md)、[页面规格](../web/page-specs.md)的入库与设置部分、[Agent 接口指南](../../guides/agent-interface.md)，以及新的桌面桥指南。
- 不在本决定内：域名与 HTTPS 地址；一个扩展连多个文献库；定时同步；Firefox 版。
