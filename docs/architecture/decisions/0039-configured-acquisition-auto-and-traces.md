# ADR 0039：配置齐全的 PDF 来源默认启用与安全获取轨迹

类型：决策（ADR）
负责：PDF Auto 选源与来源级持久诊断
状态：Accepted

- Date: 2026-10-26
- 依据：Owner 明确决定“配好凭据的 PDF 获取来源默认启用；补逐来源获取轨迹”。
- 部分取代：[ADR 0022](0022-default-safe-source-selection-and-per-source-limits.md) 中 Acquisition Auto 仅使用版本固定集合、凭据不影响选择的部分；Metadata Auto、Custom 和扫描上限不变。

## 背景

API 凭据配置齐全而来源仍未启用，使用户误以为获取已经尝试专用 API。已有任务只保留整篇结果、Browser 会话与传输记录，无法逐来源解释未命中、不可用和冷却。

## 决定

1. PDF Acquisition Auto 使用默认公开集合，加上必要凭据或普通参数已配置齐全的授权及通用 API。配置不齐的来源不加入、不报错；镜像不自动启用。Custom 仍是精确列表。选择只使用本地存在性，不授权读取凭据值，不联网测试权限，也不改变单篇适用证据与五层短路顺序。
2. Application 冻结当前生效选择。共享配置状态区分当前进程路线与已保存但需重启生效的选择；没有获取运行时的配置进程明确返回空的运行时身份，不推测其它进程状态。
3. 来源级安全轨迹通过现有 durable task events 保存，供 HTTP、CLI、MCP 共用；Browser 会话可携带有界前置轨迹。记录来源、阶段、时间、是否派发请求、结果、稳定码与计数，不记录 URL、请求头、凭据、响应或页面文字。
4. 轨迹不是文献事实或候选历史，不决定权限、正常耗尽或发布。保留已有网络准入、配额、失败隔离与不可变资产边界；后续成功保留前序诊断，历史任务不补造记录。

## 后果

添加必要配置会改变下次启动的 Auto 路线，可能增加真实获取时的 API 请求；当前进程不会自动重组。配置齐全不保证认证有效、全文权限或命中，真实验证仍需明确发起获取。当前字段、界限与实现规则归[文献材料技术篇](../technical/03-literature-materials.md)，用户操作归[PDF 获取指南](../../guides/pdf-acquisition.md)。
