## 背景与授权依据

Owner 明确 SciRetriever 是科研 Agent 系统的论文获取与分析组件，核心结果为原始知识材料和帮助理解海量文献的压缩知识；获取与分析可分开。Owner 认可文档证据、分层分析、检索/上下文和正式 Agent 接口的架构方向，并补充人类配置、观看 AI 浏览器全过程并指导介入、查询原始材料与总结三项正式能力。最初将 Zotero 与完整人类文献管理体验降优先级；2026-10-14 按 ADR 0032 澄清：Web 以文献库为中心，阅读体验后续独立深化，不以先前优先级限制其设计，不引入 Zotero 插件兼容路线。

原先“单篇两阶段分析、一个当前最终内容、ParserResult 仅为中间结果、不提供逐段定位”的设计不足以支持上述消费方式。配置和 Browser 可靠性仍是基础，但不再构成全部演进目标。

## 决策

### 1. 双消费者与两类独立结果

科研 Agent 是主要程序消费者，人类是正式使用者。二者消费同一套材料、分析与应用操作；上层 Agent 拥有科研任务编排，SciRetriever 拥有文献与知识产物的完整性和可追溯性。

材料链包括发现、获取、解析与读取，分析链包括单篇不同粒度压缩、问题相关分析和指定集合的综合。材料可用不以分析完成为前提。按 ADR 0028，查询使用与扩充加工为独立入口；查询只消费已有内容并报告缺口，不启动维护任务。每次元数据/PDF 扩充由用户明确开启，独立分析/提取缺材料时也不能自动补库。统一逻辑文献库继续保存事实与产物，但产品目的从维护书目集合明确为科研知识供给。

2026-09-26 Owner 进一步澄清：有效获得真实目标论文 PDF 非常重要，但只是完整系统中的一个模块。其他模块以已有合适材料为输入前提，独立设计并提供功能；获取的重要程度不授予其对分析、总结、提取或查询的业务所有权，也不构成全系统必须先经过下载的流程。

### 2. 新增文档证据与检索责任，扩展 Analysis

- Document/Evidence 拥有可读取文档表示、稳定片段/资源定位和引用的版本绑定；不判断科学结论是否正确。
- Analysis 拥有有证据的解释与压缩，保留条件、局限、分歧、处理范围和输入/生成方法；同一论文可有不同明确用途和粒度的产物。
- Retrieval/Context 拥有基于问题、范围和上下文预算的检索、选择、去重与组装。索引可重建，不拥有文献事实；相关性不代表科学真实性。
- Entry 提供可组合的发现、获取、解析、读取、分析、综合、检索与执行控制；Agent adapter（包括 MCP）和人类入口不得复制这些业务规则。

这些是逻辑职责，不强制独立服务、向量数据库或任意 prompt 平台。共享单次模型层保持无状态；按 ADR 0031，内部另采用 DSH/Cordis 提供受控会话和工具循环，实施已批准，不改变本节业务分工。

### 3. 原始材料、文档表示与派生知识分别管理

2026-10-12 Owner 修订：对已确定输入的解析、总结和集合综合，不设 token、累计调用次数或整篇执行时长的业务预算。分块和整合按输入有限执行，记录实际用量，用户可以取消；连接失败、协议错误与服务端能力限制仍按实际结果报告。此修订不取消 Browser 探索预算、供应商速率和查询上下文预算。

模型负责内容归纳与语义判断。机器接纳检查限于可消费格式、真实来源引用及数据完整性，不以逐字引文、全文数字/公式比对、条件字符串相等、候选逐字保留或分歧组成员数证明科研正确性。科学质量靠来源可回溯及后续使用评价，不要求所有模型判断通过启发式验收才发布。旧总结补全可以补空，不能因模型改写已有书目字段而阻断总结；已接纳事实由 Literature 保留。现有预算请求/配置继续可读取但弃用，新请求无需预算。输入版本/hash、来源保留、取消、不可变发布和凭据/外部访问边界继续适用。

保留稳定文献身份、来源 observation、原始资产和不可变发布。新派生结果必须绑定精确输入版本及其证据；解析或总结的更新不能静默把旧引用重新指向新内容。

不再以“每篇只有一份当前总结”限制新分析用途；不再把无逐段 locator 或旧解析结果无条件可回收作为新知识架构的约束。可以保留当前默认视图，但被有效产物引用的材料表示必须继续可读取，或以明确失效/重新生成政策处理。具体版本保留、索引与回收策略在技术设计中确定，不默认永久保存所有模型尝试。

分析不适用、只读到部分内容或模型失败，不能单独授权删除已接纳原始材料。错误文件/错误文章的拒绝、资产失效与显式删除由相应业务 owner 的独立规则处理。当前 TypeScript 生产 completion 已停止用 `NoUsableContent` 自动撤销材料；旧清理服务仍只作为明确调用的失效机制保留，不由分析结果自动触发。

### 4. 人类协作是正式产品能力

按 ADR 0032，Web 是面向人的独立完整入口，以文献库为首页和操作上下文；CLI/MCP 主要服务 Agent 与自动化。库、阅读标签、全局活动与设置构成整体框架，阅读器细节另行设计，不以任务漏斗组织主界面。人类接口必须支持：

1. 管理项目配置、凭据、适用的显式测试及生效反馈；
2. 从开始到结束观察同一生产 Browser 获取流程，并可自愿针对当前文献给出指导或直接操作页面；无人帮助时自动获取按真实结果结束，不默认进入等待人工的必经流程；
3. 查询并阅读同一文献库的原始材料、可读表示和分析产物，沿证据回到对应来源。

人类接口仅展示与提交意图；Configuration 拥有配置发布，应用运行时拥有控制权与指导生命周期，controller 在安全决策点消费指导，Acquisition 继续裁决 PDF/文章归属。自然语言指导与网页文本输入是不同操作。

直接点击或输入可以作为控制权申请的自然入口，但不能省略服务端授权、文章/会话与页面版本校验。界面不默认突出缺 PDF/需人工待办，用户可稍后在相应文献上主动补充 PDF。自动耗尽与临时失败、取消仍按原合同区分；主动关闭观看界面的目标体验与断线等运行边界，按 ADR 0032 的定稿原型修订及后续控制设计处理。

同一会话同时只有一个动作控制者。暂停/接管必须阻止后续过期动作，已经发送的请求如实处理；交还 AI 后重新观察页面。指导绑定文章/流程，并返回受理、拒绝、过期或消费情况；不能跨目标泄漏。人工得到的文件继续经过统一验收，指导不授予模型任意脚本、凭据或事实写入权。

### 5. 保留不变量与兼容

领域中立、MetaLiterature/Literature 保守身份、来源保留、引用关系支持、统一逻辑存储、单一事实写入 owner、阶段提交、固定配置身份和受控外部访问继续适用。

不因新定位删除已有导入导出能力。既有报告、ID/hash、配置和数据格式需要显式兼容评估；本 ADR 不授权真实数据迁移、历史资料清理或发布。schema/API 的具体破坏性替换必须另有明确策略和授权。

## 未决项

- Web 的库中心结构已由 ADR 0032 确认；阅读器细节、保存视图持久化及直接交互的具体生命周期仍待设计，桌面/嵌入形态不是本轮交付范围。
- 关闭客户端后的运行存续、后台服务与具体恢复保证。
- 实时全过程观看之外的长期截图/录像、事后重放及保留期限。
- 允许的人类页面操作，尤其登录、机构选择、MFA 等独立场景；不能隐式扩大自动 Agent 权限。
- 精确文档/证据/分析 schema、版本保留/回收策略、检索实现和规模指标；不能据此默认迁移。

## 验证与当前边界

必须验证材料无分析也能读取、证据稳定与语义支持、不同粒度压缩的条件/局限保留、预算内检索、跨论文分歧和覆盖；人类须在正式 Browser 路径观看、指导/介入、交还，再与 Agent 读取同一结果。离线、真实 binary+loopback、真实服务和生产切换证据分别记录。

本 ADR 已接受目标架构，未宣称代码完成。当前两目标补全、单篇 Analysis、无证据片段 API、缺正式 MCP 及人类协作生产闭环等差距见 [TS 基线](../typescript-baseline.md)；执行顺序归 [活动计划](../../plans/README.md)。
