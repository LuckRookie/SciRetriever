## 背景与授权依据

Owner 在评审现有 Web 后明确：界面应围绕文献数据库组织，获取、解析、分析、综合、检索和导出都是作用于库的能力。以处理漏斗或固定工作流组织首页，会把产品绑定到一种使用顺序；以后台 service 表单平铺页面，也不能体现人的操作意图。

过去将完整人类文献管理体验降优先级，不等于文献库不能成为界面的中心。Owner 希望继续改善阅读体验，但先确定整体架构，阅读器单独设计；本轮不采用复制 Zotero 或兼容其插件的路线。

Owner 同时要求减少“缺 PDF”“需人工 PDF”等默认提示。Agent 无法处理时应按实际结果结束，人可日后从数据库界面补充 PDF。Browser 是可观看的 Agent 操作界面，人愿意帮助时可以在同一画面直接点击或输入；人工帮助不成为自动获取的前置条件。

2026-10-15，Owner 提供并最终确认[文献库 Web 原型](../web/prototype.html)，明确后续以此为主。[当前 Web 设计说明与定稿原型](../web/README.md)是本 ADR 指定的布局、视觉与交互基准，优先于 10-14 的粗略线框安排和旧蓝白任务工作台设计。下面的导航、按需预览及阅读骨架据此修订；原型中的示例数据和模拟执行不代表生产能力、业务 schema 或持久化合同已经落实。

## 决策

### 1. 文献库是 Web 的主空间

Web 是面向人的独立完整操作入口，CLI/MCP 主要服务 Agent 与自动化。三者复用统一逻辑文献库与应用服务；科研知识供给的产品目的、各业务 owner 和单一事实来源不变。

首页直接进入文献库。用户先查询、选择文献或范围，再按需入库、获取材料、解析、分析、综合或导出；不要求按“元数据 → PDF → 解析 → 分析”的固定页面顺序操作。任务状态服务于操作反馈，不取代文献及其材料、知识事实。

默认存储与首次启动继续遵守 ADR 0018：缺省位于 `~/.sciretriever/`，无需配置向导，已有显式配置优先；不因界面重构搬迁、覆盖或自动升级已有库。

### 2. 以定稿原型组织导航、库与阅读

| 界面区域     | 责任与入口                                                                                                                                             |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 资料导航     | 文献库为默认首页，发现为独立入口；库下组织入库批次，保存视图在库内切换。                                                                               |
| 使用导航     | 洞察、检索、综合、提取有独立入口，复用同一库与明确范围；综合可在导航中展开具体产物。                                                                   |
| 运行导航     | 任务与浏览器有独立页面；任务展示执行情况，浏览器以会话画廊进入同一生产页面的观看与可选介入。                                                           |
| 库列表与预览 | 以参考文献式列表为主，点击文献打开阅读标签，预览按钮才展开右侧面板。选择后浮出操作条，“用这些文献做…”复用当前选择或视图范围；不要求默认常驻三栏。      |
| 阅读标签     | 顶部保留工作区和已打开文献，默认查看已有 PDF；右侧文献信息与 PDF / 全文 / 总结切换共同承载详情和阅读，证据返回原文。精确定位与阅读器实现继续专项设计。 |
| 全局活动     | 顶部入口展开活动抽屉用于快速查看，并链接完整任务页及可观看会话。任务与 Browser 的独立入口不改变库中心结构。                                            |
| 设置         | 固定在侧栏底部，管理存储、来源、Provider/Model、凭据及显式测试；低层提取交付协议、索引重建、原始请求等技术工具归入高级区域。                           |

侧栏按“资料 / 使用 / 运行”分组，不默认设置缺 PDF、未解析、需人工等系统待办分区。批次先展示近期项并提供继续查找入口；保存视图、筛选、排序和批量操作按原型的库内层级组织。导航收纳不意味着新增持久化集合或把所有导入都转换为发现批次，数据边界见第 6 节。

文献面板提供元数据、材料及知识概要和主动上传 PDF 的入口，详细来源、版本、关系与溯源按需展开。不默认铺开加工表单、缺口统计或帮助 Agent 的提醒。

文献筛选留在库页；片段/知识检索采用独立检索页和上下文篮子，结果能回到同一文献和证据。视图、文献、综合与任务应可定位、返回并恢复上下文；具体 URL、标签恢复与布局偏好的持久化不在本 ADR 固定。

### 3. 围绕对象执行操作，读写边界由意图表达

- 入库入口承载主题发现、种子引用扩展、书目导入等显式操作；人工 PDF 接纳须先明确目标文献，复用现有接纳合同。
- 单篇、选中项和当前筛选范围上的获取、解析、分析、综合等操作，先说明实际范围和副作用，再提交对应应用用例。批量执行按既有规则冻结目标；不能把当前页选中项和全部筛选结果混为一谈。
- Library 搜索、正文/知识检索、详情、阅读和证据展开只读取已有事实；查询无结果或材料不足不触发获取或加工。按 ADR 0028，读写入口可以处于同一页面，只要动作与副作用明确。
- 操作反馈可进入统一活动界面，但保留各用例的报告、回执或 durable Job 语义；不要求所有写操作都新建持久任务或保存永久批次历史。控制按钮只对服务端实际支持的操作开放。
- 导出不修改库内文献事实，但要明确输出文件这一副作用。仅展示相关用例已有的范围/预算限制，不重新引入已取消的解析、分析和集合综合总预算。

面向人的提取入口按定稿原型呈现规范、运行、候选、证据与覆盖；低层交付协议操作仍收进高级区。索引维护和既有 CLI/MCP 能力保留，API/JSON 表单不作为普通用户日常操作的必经入口。内置提取执行、洞察统计/地图及外部能力扩展的业务合同和数据支持随后逐项衔接，不能从原型的 `ready` 标记推断已实现。

### 4. 材料状态简洁呈现，失败不强制转入人工流程

列表可以用紧凑状态和可选筛选表达 PDF、文档、知识的可用性；详情再说明具体版本、用途、覆盖和失败。不能将多版本材料与多用途分析压成唯一的线性完成等级，也不能重新解释既有 `LiteratureStatus` / `CONTENT_READY`。

自动获取无需人类在线或响应。无法继续时，按既有结果边界结束该目标并反馈，保留已经取得的事实；不默认创建“等待人工帮助”的必经环节。用户可稍后在相应文献上上传 PDF，或明确请求再次获取。用户主动介入后的暂停和交还按控制协议处理，不与无人介入时的自动执行混淆。

“无法获取”是面向人的摘要，不能把不同事实合并成一个持久失败状态：

- 所有适用自动路线正常耗尽、未取得 PDF 时，可以显示“无法获取”，详情注明“当前自动获取已耗尽”；复用既有耗尽事实和 `needs_manual_pdf` 投影，其含义不包括必须安排人工待办，也不表示永久不可能获取。
- 网络、配置、服务或 Browser 失败、探索限制、取消、未尝试分别按真实结果表达，不能因此写入自动获取耗尽事实。显式重试和人工补充仍由原 owner 决定状态变化。

按 ADR 0029，有效 PDF 通过字节、可读性和任务关联检查后可接纳，文章身份初始未验证，内容身份核验留待解析；不增加普遍的人工候选审核门。人工取得或上传的文件仍经过统一验收与不可变发布，不能绕过来源、hash 和既有主 PDF 保护。

### 5. Browser 默认观看，直接操作自然触发控制权交接

Agent 操作界面展示同一生产 Browser 的真实页面、当前文章、执行状态和必要活动信息。打开或观看画面不暂停 Agent；人工在画面内明确点击、输入时，可以触发控制权申请，不要求先经历独立的接管工作流。取得控制权后，界面明确显示“你正在操作”并提供交还入口；自然语言指导保留为可选能力，不要求占据默认主界面。

交互入口简化不能省略控制协议：

1. 服务端验证当前任务/文章/会话及控制 epoch，成功取得控制权后才派发人工输入；同一会话只能有一个动作控制者。
2. 输入绑定实际看到的页面 revision 与视口。申请期间画面或目标改变时，不把第一次点击无条件重放到新页面；反馈过期并刷新，具体交互由后续设计验证。
3. 接管使尚未派发的旧 Agent 决定失效；已派发的页面动作、下载或发布按实际结果结算。交还后 Agent 重新观察，不继续旧缓存动作。
4. 多窗口依服务端当前控制状态和版本处理竞争，不能保证“最后点击的窗口总能抢到控制权”。未取得控制权的窗口继续观看并显示实际状态。
5. 人工页面操作与自然语言指导保持不同语义；指导仍绑定文章/流程，不扩大模型权限。人工下载继续走同一候选接纳与发布路径。

主动交还、正常离开页面、切换文章和意外断线必须分别定义。10-15 定稿原型将“用户主动关闭观看界面时交还 Agent”作为目标体验；正式实现须确认服务端交还成功并处理失败，不能将关闭回调当作成功依据。该行为不扩展为意外断线时自动恢复；切换文章、断线与恢复策略仍待详细设计和竞态验证。现有生产政策不因原型定稿而直接改变。

### 6. 持久化、阅读与视觉的后续边界

- 保存视图只表示可复用查询条件，不成为第二份文献事实或固化的 Collection。是否保存于浏览器、本机 UI 文件或服务端，以及 owner、作用域、版本、并发和恢复策略，须单独确定；存放在 catalog 之外不等于免除设计审查。
- `DiscoveryRun` 已有持久身份，可以作为发现批次入口；书目导入和其它操作不因此新增 `ImportRun` 或长期报告历史。若要统一长期入库批次，须明确修订 ADR 0013 及相关合同。
- 本轮不新增持久化课题/集合、用户标签、笔记、阅读批注、Zotero 插件宿主或同步协议。原型中的来源/分析标签和领域提取示例须分别映射其业务 owner，不转成固定领域事实。阅读的 PDF / 全文 / 总结骨架按原型落实；真实渲染、证据定位、缺失能力和批注等细节随后设计。
- 视觉以定稿原型的白色内容面、浅灰侧栏、墨蓝主要操作、黄色证据标记、字体层级和轻分隔为基准，保留原型浅色/深色样式。先前蓝白、墨绿、暖白主题切换仍可作为扩展，但沿用同一布局与组件，不重新改变默认设计；偏好存储和字体交付方式另行确定。
- Web、CLI、MCP 共享逻辑数据库，不代表它们已共享同一个活 Browser 或执行进程。跨入口活动可见性、发起方标识、活会话连接与任务存续须按实际运行合同设计，不通过共享库路径推导。

## 对既有决策与实现的影响

本 ADR 修订 ADR 0026 中“最终人类界面形态未定”和将完整人类文献管理体验降优先级的笼统表述：确定 Web 的库中心结构，允许后续独立深化阅读。它不改变 Agent 主要程序消费者定位、模块责任、文献身份、数据所有权或 ADR 0028 的显式扩充边界。

截至本次决策，当前 Web 已有任务工作台、Library 查询、配置、加工入口与生产 Browser 控制基础；它们是复用对象，不代表定稿原型的库首页、标签阅读、分组导航、洞察/提取界面和直接操作交接已经完成。`LibraryQuery` 已有字段筛选、`missing_steps`、`needs_manual_pdf`、`discovery_run_ids`，但不能由此推断所有新材料/知识筛选、汇总计数和保存视图均已实现。

当前 `WorkbenchSession` 对控制者断开采用撤销租约并暂停的政策，接管请求校验 epoch。直接交互仍需验证前端事件、会话绑定及服务端动作的整体链路；不能将本 ADR 解释为只改按钮即可完成。当前实现说明分别见[产品接口技术文档](../technical/01-product-interface.md#4-人类工作台与知识阅读)、[Browser 控制技术文档](../technical/08-browser-control.md#4-观察指导与控制权交接)及 [Web 指南](../../guides/web-workbench.md)。

本次决策不授权数据迁移、删除现有接口或改写持久状态，也不宣称 UI 已交付。旧任务工作台设计记录保留历史身份；后续实现与验收以本 ADR 的整体方向为准。

## 验证方向

- 用实际文献和可控合成数据走通：查询并选范围、发起操作、查看结果、回到同一文献、主动补 PDF；每轮只迭代一个主要使用场景，由操作反馈调整布局，再细化视觉。
- 验证打开库、检索、详情、证据和观看 Agent 都不会隐式发起维护；无人观看/帮助时自动获取仍能给出正常结束、稳定耗尽或明确失败。
- 验证状态摘要不把服务失败写成耗尽，不把已有材料或其它用途知识错误降级，人工补充遵守原接纳合同。
- 验证直接交互、首次点击期间页面变化、在途动作、多窗口竞争、交还、切换文章和断线；旧决定不迟到执行，控制失败不误报成功，恢复后重新观察。
- 阅读器详细验收、精确响应式布局及主题对比度在相应设计中补充；自动化与浏览器操作验证不能只检查按钮是否存在。
