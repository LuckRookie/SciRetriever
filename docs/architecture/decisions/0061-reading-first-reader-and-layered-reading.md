# ADR 0061：阅读优先的阅读页与分层阅读

类型：决策（ADR）
负责：阅读页的版面原则；阅读位置与过渡的规则；分层阅读及其产出类型“分层稿”
状态：Proposed（2026-11-12，方向已由 Owner 确认：“三层都做”；待 Owner 看过效果图后接受）

## 背景

对照审查得到的事实：

- **版面。** 1440 像素宽的窗口里，全站导航占 244 像素，信息栏默认打开占 330 像素，正文只剩约六成。阅读区上方有标题栏和工具栏两行，下方有状态栏；工具栏上有十几个控件。
- **位置。** PDF 和全文各记各的位置，切换视图落不到同一处。图片载入会把正文往下顶，因为版面变化时没有固定阅读位置。
- **切换。** 在 PDF 和全文之间切换，或换一篇文献，阅读区都会清空，重新下载、校验和解析。缩放、调整面板宽度、开合侧栏会把所有 PDF 页清空重画。
- **等待。** 加载过程只有底部一行小字。只有书目、没有 PDF 的文献点开是一片空白，而文献库里点任何一行都固定进入 PDF 视图。
- **过渡。** 结构性的变化几乎都是瞬间完成。

TextFold 在这几处的做法是：任何版面变化都把读者正在读的段落固定在原位；变化都有过渡；只为眼前的内容花计算量。它还有一个核心想法：把每一段折成几个层级，读者在层级之间缩放，每一段都能展开回作者的原文。

这个想法正对应本项目的两个需求：加工结果要以人能直接阅读的方式呈现（用3），Agent 要能从概览逐层展开到原文（用2）。

## 决定

### 1. 阅读页以正文为先

1. 进入阅读页时，全站导航收成一条窄栏，只留图标；需要时可以展开。离开阅读页时恢复原样。
2. 信息、批注列表、翻译和目录都是按需打开的侧栏，默认收起。侧栏打开时正文仍保有可读的宽度；窗口不够宽时，侧栏浮在正文上方，不挤压正文。
3. 阅读页顶部只有一行。上面只放阅读必需的东西：返回文献库、文献题名、视图切换、目录、查找、排版设置、侧栏开关。其余操作收进菜单，例如运行算子、获取或上传 PDF、导出。
4. 不设常驻的底部状态栏。状态在它所指的地方就地出现，用完即走。
5. 正文一行的字数稳定：栏宽随字号变化。
6. 批注、证据标记和出处提示挂在正文旁边的页边；窗口不够宽时，落到所属段落的下方。
7. 提供专注模式：一个键收起所有的栏，指针靠近边缘时各栏再出现。

### 2. 阅读位置不丢

1. 任何会改变版面的变化发生前后，读者正在读的那一段留在屏幕上的同一位置。这些变化包括：改字号或栏宽，开合侧栏，切换视图，切换层级，图片或公式载入，后台刷新。
2. PDF 视图与全文视图的位置互通：切换视图时落在同一段。两边对应不上时如实说明，停在最接近的位置。
3. 跳转之后可以回到原处。每篇文献的阅读位置连同视图和层级，在本机浏览器里记住，再次打开时恢复。
4. 后台的数据刷新不重建阅读器，也不推动正文。

### 3. 变化有过渡，等待有交代

1. 结构性的变化用过渡完成，不瞬间跳变。这包括视图切换、侧栏开合、目录展开和查找栏出现。使用者选择减少动效时，位移和缩放的过渡取消，颜色的变化保留。
2. 切换视图或文献时不清空画面。新内容准备好之前，保留原来的画面或显示骨架。同一次会话里打开过的文献再切回来，不重新下载和校验。
3. PDF 缩放时先把现有画面拉伸到位，再重绘清晰的画面。滚动时，渲染过的页保留低清晰度的画面，不露出空白。
4. 加载有骨架和进度。
5. 从文献库打开一篇文献时，进入它实际具备的材料：有全文文本的进入全文视图，只有 PDF 的进入 PDF 视图，两者都没有的进入信息页并说明缺什么。

### 4. 视觉

1. 保留现有的标识：墨水蓝是唯一的强调色；荧光黄只用于证据和查找命中；正文用衬线体。
2. 阅读面用略偏暖的纸色，与界面的其他部分区分开。阅读区内不用细线分区，用留白分区；阴影只给浮在上面的东西。
3. 字体表明出处：作者的原文用衬线体，机器写的内容用无衬线体。机器写的内容包括要点、一句话、主题和对问题的回答。在任何层级，读者一眼就能分清哪些是作者的话。
4. 标题与正文的层次拉开。中文按中文的习惯排：行高、标点和中西文间距。
5. 阅读页顶部的按钮只用一种形状。
6. 不照搬 TextFold 的配色和标识。

### 5. 分层阅读

1. 一篇文献的全文可以在五个层级之间连续缩放：

   | 层级   | 每一段变成什么                   | 是谁的话         |
   | ------ | -------------------------------- | ---------------- |
   | 原文   | 作者写的段落                     | 作者             |
   | 关键句 | 段落里最关键的一到三句，一字不改 | 作者             |
   | 要点   | 这一段的论点和理由               | 机器，依据关键句 |
   | 一句话 | 这一段在本节脉络中的一句话       | 机器             |
   | 主题   | 几个词；全文变成一张章节地图     | 机器             |

2. 在任何层级，每一段都可以就地展开回原文。机器写的每一句都指向它所依据的原句，证据根是文本位置。
3. 切换层级时，留下来的词留在原处或移到新的位置，其余的淡出。阅读位置按第 2 节固定。
4. 主题层是章节地图，兼作目录。
5. 批注和证据标记随层级保留：一段有批注时，在任何层级都看得出来。
6. 分层由知识加工的一种新产出类型承担，名为“分层稿”。
   - 现有类型不能承载它：报告是对整篇的叙述；记录表的行由调用方定义字段；分层稿是与原文逐段、逐句对齐的结构，它的视图就是阅读器本身。
   - 它是逐篇形态的产出，输入是初稿或校订稿。
   - ADR 0044 与 ADR 0060 的规则全部适用：明确发起，事先估算，结果绑定文本的版本，文本升级后旧结果标为过时。
7. 没有做过分层加工的文献只有“原文”一级。页面说明其余层级需要发起一次加工。
8. Agent 同样可以取用分层稿：按层级读取一篇文献，从主题逐层展开到原文。

### 6. 借鉴的边界

1. 借鉴 TextFold 的设计和做法，不直接使用它的界面。它的文献库不适合万篇规模，它把整篇文档一次载入，这两处沿用本项目现有的做法。
2. 如果复用 TextFold 的代码，保留它的版权声明，并在项目 README 的借鉴表里登记。
3. 把分层稿导出成 TextFold 的开放格式不在本决定之内，需要时另行决定。

## 后果

- 新增一份阅读体验规格，写明第 1–5 节怎样做到；页面规格里阅读页的排布以它为准。
- 知识加工的规格增加“分层稿”类型，计划 16 增加对应的算子与视图。
- 需要一个新的计划，分三步交付：先做第 2、3 节（位置与过渡），再做第 1、4 节（版面与视觉），最后做第 5 节（分层阅读）。
- 每篇文献要先经过一次模型加工才有分层。万篇规模下这是一笔花费，所以分层按需发起，不是打开文献的前提。
- 效果图待 Owner 确认。视觉细节以确认后的效果图和设计内核为准。

## 考虑过但没有采用的方案

| 方案                             | 没有采用的原因                                                                                    |
| -------------------------------- | ------------------------------------------------------------------------------------------------- |
| 只修不顺的地方，不改版面         | 位置和过渡修好以后，正文仍只占六成宽度，被两行栏和两侧面板包围                                    |
| 直接用 TextFold 作阅读器         | 它没有 PDF 原文的完整阅读、批注体系和证据定位，文献库也不适合万篇规模；两套界面会让使用者来回切换 |
| 把分层做成记录表加一个特殊视图   | 记录表的视图是表格；让一种类型有两种性质完全不同的视图，会破坏“类型对应视图”的规则                |
| 打开文献时自动做分层加工         | 违反“花钱的操作由使用者明确发起”                                                                  |
| 照搬 TextFold 的暖色和紫色强调色 | 本项目已有自己的标识；借鉴的是原则，不是外观                                                      |
