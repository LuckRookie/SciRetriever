# ADR 0061：阅读优先的阅读页，按理解的过程读文献

类型：决策（ADR）

## 背景

对照审查得到的事实：

- **版面。** 1440 像素宽的窗口里，全站导航占 244 像素，信息栏默认打开占 330 像素，正文只剩约六成。阅读区上方有标题栏和工具栏两行，下方有状态栏；工具栏上有十几个控件。
- **位置。** PDF 和全文各记各的位置，切换视图落不到同一处。图片载入会把正文往下顶，因为版面变化时没有固定阅读位置。
- **切换。** 在 PDF 和全文之间切换，或换一篇文献，阅读区都会清空，重新下载、校验和解析。缩放、调整面板宽度、开合侧栏会把所有 PDF 页清空重画。
- **等待。** 加载过程只有底部一行小字。只有书目、没有 PDF 的文献点开是一片空白，而文献库里点任何一行都固定进入 PDF 视图。
- **过渡。** 结构性的变化几乎都是瞬间完成。

TextFold 在这几处的做法是：任何版面变化都把读者正在读的段落固定在原位；变化都有过渡；只为眼前的内容花计算量。它还有一个核心想法：把每一段按长度折成五个层级，读者在层级之间缩放，每一段都能展开回作者的原文。

缩放和“展开回原文”正对应本项目的两个需求：加工结果要以人能直接阅读的方式呈现（用3），Agent 要能从概览逐层展开到原文（用2）。但按长度折叠对任何文字都一样，没有用上“读者想弄清什么”。

本项目是通用的知识库，资料不只有研究论文，还有综述、学位论文、手册，以及人自己写的资料。不管读哪一种，读者要弄清的是同样四项内容：

1. 性质与范围：它是哪一类资料，讨论的范围是什么；
2. 要点：最重要的几点内容；
3. 依据：这些要点由什么支撑；
4. 局限与未决事项：没有解决的问题、需要注意的限制和后续工作。

所以本项目按理解的过程来设计，不按长度，也不按资料的类型分别设计。

## 决定

### 1. 阅读页以正文为先

1. 进入阅读页时，全站导航收成一条窄栏，只留图标；需要时可以展开。离开阅读页时恢复原样。
2. 信息、批注列表、翻译和目录都是按需打开的侧栏，默认收起。侧栏打开时正文仍保有可读的宽度；窗口不够宽时，侧栏浮在正文上方，不挤压正文。
3. 阅读页顶部只有一行。上面只放阅读必需的东西：返回文献库、文献题名、视图切换、目录、查找、排版设置、侧栏开关。其余操作收进菜单，例如运行算子、获取或上传 PDF、导出。
4. 不设常驻的底部状态栏。状态在它所指的地方就地出现，用完即走。
5. 正文一行的字数稳定：栏宽随字号变化。
6. 批注、证据标记和出处提示挂在正文旁边的页边；窗口不够宽时，落到所属段落的下方。
7. 提供专注模式：一个键收起所有的栏，指针靠近边缘时各栏再出现。

### 2. 阅读位置不丢

1. 任何会改变版面的变化发生前后，读者正在读的那一段留在屏幕上的同一位置。这些变化包括：改字号或栏宽，开合侧栏，切换视图，切换距离，图片或公式载入，后台刷新。
2. PDF 视图与全文视图的位置互通：切换视图时落在同一段。两边对应不上时如实说明，停在最接近的位置。
3. 跳转之后可以回到原处。每篇文献的阅读位置连同视图和距离，在本机浏览器里记住，再次打开时恢复。
4. 后台的数据刷新不重建阅读器，也不推动正文。

### 3. 变化有过渡，等待有交代

1. 结构性的变化用过渡完成，不瞬间跳变。这包括视图切换、侧栏开合、目录展开和查找栏出现。使用者选择减少动效时，位移和缩放的过渡取消，颜色的变化保留。
2. 切换视图或文献时不清空画面。新内容准备好之前，保留原来的画面或显示骨架。同一次会话里打开过的文献再切回来，不重新下载和校验。
3. PDF 缩放时先把现有画面拉伸到位，再重绘清晰的画面。滚动时，渲染过的页保留低清晰度的画面，不露出空白。
4. 加载有骨架和进度。
5. 从文献库打开一篇文献时，进入它实际具备的材料：有全文文本的进入全文视图，只有 PDF 的进入 PDF 视图，两者都没有的进入信息页并说明缺什么。

### 4. 视觉

1. 保留现有的标识：墨水蓝是唯一的强调色；荧光黄只用于证据和查找命中；正文用衬线体。
2. 阅读面用略偏暖的纸色，与界面的其他部分区分开。阅读区内不用细线分区，用留白分区；阴影只给浮在上面的东西。
3. 字体表明出处：作者的原文用衬线体，机器写的内容用无衬线体。机器写的内容包括概览、脉络里的要点和对问题的回答。在任何距离，读者一眼就能分清哪些是作者的话。
4. 标题与正文的层次拉开。中文按中文的习惯排：行高、标点和中西文间距。
5. 阅读页顶部的按钮只用一种形状。
6. 不照搬 TextFold 的配色和标识。

### 5. 按理解的过程读一份资料

1. 一份资料可以在三个距离上读：

   | 距离     | 看到什么                                                                         | 回答什么           |
   | -------- | -------------------------------------------------------------------------------- | ------------------ |
   | 远：概览 | 一屏：性质与范围、要点、依据、局限与未决事项、精读建议，加上最关键的一两张图或表 | 值不值得读         |
   | 中：脉络 | 要点按原文的章节顺序排开，每个要点下面是它的依据                                 | 它说了什么，凭什么 |
   | 近：原文 | 完整的原文；页边标出每一段支撑的是哪个要点                                       | 细节对不对         |

2. 三个距离之间连续缩放。在任何距离，点一条内容就在原地展开到下一级，直到作者的原句。阅读位置按第 2 节固定。
3. 一种格式通用于各类资料。
   - “概览”固定是上面四项内容，另加精读建议；栏目名不随资料的类型改变。
   - “脉络”的分组直接用作者自己的章节标题：综述的主题、学位论文的章、手册的步骤，都是它们自己的标题。资料没有章节标题时，要点不分组，按原文顺序排。
   - 依据只有固定的几类：原句、图、表、数字、引用的其他文献。
   - 资料没有给出的内容标为“原文未给出”，不硬凑。
4. 提示词分三层，按类型变化的部分不由本项目维护：
   - **固定的核心，只有一份。** 它规定输出的格式、上面四项内容、引用原句必须一字不改、按作者的章节顺序排、原文未给出的内容如实标明。
   - **模型为眼前这份资料写的一两句阅读提示。** 在填写之前，模型先写明这是一份什么资料、阅读时应当关注什么，再照此填写。这一步与填写在同一次调用里完成。阅读提示显示给读者，放在“性质与范围”一栏。
   - **使用者的说明，可选。** 发起加工时可以补一句说明，例如“这是实验记录，重点看条件和结果”。它盖过模型自己的判断；批量加工时一句话管一批。
5. 按类型的提示只作为补丁，并且只在有证据时添加。
   - 起步时不写任何按类型的提示。
   - 用一组不同类型的真实资料作测试集。某一类反复做不好，才给它补几行提示；补完重新测，确认变好才保留。
   - 每条补丁附上改之前哪里不对的例子。
6. 机器写的每一句都指向它所依据的原句、图或表。原句的引用由程序逐字核对，对不上的用现有的警示色标出来，并写明原文是什么。
7. 图和表是主要内容，不是附件。在“脉络”里，每张被引用的图或表都写明它支撑哪一个要点。
8. 长资料按篇幅处理，不按类型：章节多到一屏放不下时，先给每一章做概览和脉络，再给整份资料做一份以章为单位的概览。整份资料的概览写性质与范围、各章要点、局限与未决事项和精读建议；“依据”在各章里看。
9. 两个镜头，叠加在“概览”和“脉络”上。在“原文”上，“按问题阅读”把与问题有关的段落标出来，不隐藏其余内容。
   - **按问题阅读。** 读者提出一个问题，页面只留下与这个问题有关的内容，并给出回答；回答的每一句都能回到原文。
   - **库内关联。** 这份资料与库里其他资料的关系：谁引用了它，它引用了谁，它的要点与哪些资料一致、与哪些矛盾，它出现在哪些主题页里。
10. 想按自己的结构读某一类资料，用已有的两种办法：按问题阅读；提取记录，字段由调用方定义。不另设按类型的模板。
11. 阅读页是关于这份资料的全部知识的汇合处。凡是涉及它的加工结果，包括概览、回答、提取出的记录、跨篇的综合和主题页，都能从阅读页到达，并能回到原句。
12. 批注和证据标记在三个距离上都保留。在“概览”和“脉络”里，它们显示为所属内容旁边的记号；精确的位置在“原文”里看。
13. 在“原文”里可以把关键句的颜色加深。这是排版设置里的一个开关，对做过加工的资料默认打开。加深的仍是作者的原话。
14. 这些内容来自知识加工，不新增产出类型：
    - “概览”来自总结算子；
    - “脉络”是记录表类型下的一份平台内置规范，一个要点是一条记录；
    - “按问题阅读”来自问答算子；
    - “库内关联”来自引用关系、跨篇综合和主题页。
    - ADR 0044 与 ADR 0060 的规则全部适用：明确发起，事先估算，结果绑定文本的版本，文本升级后旧结果标为过时。
15. 没有做过加工的资料只有“原文”这一个距离。页面说明其余内容需要发起一次加工。
16. Agent 按同样的距离取用一份资料：先取概览，再取脉络，需要时取原文。
17. 这一节没有任何一处假定资料是一篇论文。人和 Agent 自己写的资料进入知识库后（ADR 0059 第 5 节），用同一个阅读页阅读。

### 6. 借鉴的边界

1. 从 TextFold 借鉴的是做法：连续缩放，版面变化时固定阅读位置，就地展开回原文，用字体区分作者的话和机器的话，在原文里加深关键句。
2. 不借鉴的有三处：它按长度划分的五个层级；它的文献库，不适合万篇规模；它把整篇文档一次载入。
3. 在项目 README 的借鉴表里登记 TextFold 和借鉴的内容。如果复用它的代码，另外保留它的版权声明。

## 后果

- 新增一份阅读体验规格，写明第 1–5 节怎样做到；页面规格里阅读页的排布以它为准。
- 知识加工的规格增加“脉络”这份内置的记录规范，并写明“概览”必须包含的几项内容；计划 16 增加对应的任务。
- 需要一个新的计划，分三步交付：先做第 2、3 节（位置与过渡），再做第 1、4 节（版面与视觉），最后做第 5 节（三个距离和两个镜头）。
- 每篇文献要先经过模型加工才有“概览”和“脉络”。万篇规模下这是一笔花费，所以它们按需发起，不是打开文献的前提。
- 对使用者的承诺是：任何资料都能如实给出那四项内容，每一句都查得到出处。承诺不包括“任何资料都整理得恰到好处”。阅读提示不贴合时，结果会显得笼统，但不会是错的。
- 两个风险需要用真实资料验证：
  - 一份固定的核心提示对不同学科、不同类型的资料是否都合用（需求“规4”）；
  - 模型能否正确找出要点与依据的对应。找错了比不做更糟，所以程序核对原句这一步不能省。
- 效果图待 Owner 确认。视觉细节以确认后的效果图和设计内核为准。

## 考虑过但没有采用的方案

| 方案                               | 没有采用的原因                                                                                    |
| ---------------------------------- | ------------------------------------------------------------------------------------------------- |
| 只修不顺的地方，不改版面           | 位置和过渡修好以后，正文仍只占六成宽度，被两行栏和两侧面板包围                                    |
| 直接用 TextFold 作阅读器           | 它没有 PDF 原文的完整阅读、批注体系和证据定位，文献库也不适合万篇规模；两套界面会让使用者来回切换 |
| 照搬 TextFold 的五个层级           | 五层只按长度区分，对任何文字都一样；人理解文献靠的是弄清问题、方法、证据和局限                    |
| 为阅读新增一种产出类型             | 概览、回答、记录表已经能承载所需的内容；多一种类型就多一套执行、核对和视图                        |
| 每一类资料各配一份格式和提示词     | 类型列不全，也维护不起；改为固定的核心加模型自拟的阅读提示，按类型的提示只作有证据的补丁          |
| 只用一份提示词，不留任何调整的余地 | 一份提示词不可能适合所有资料；所以保留模型自拟的阅读提示、使用者的说明和补丁三条调整的途径        |
| 打开文献时自动做加工               | 违反“花钱的操作由使用者明确发起”                                                                  |
| 照搬 TextFold 的暖色和紫色强调色   | 本项目已有自己的标识；借鉴的是原则，不是外观                                                      |
