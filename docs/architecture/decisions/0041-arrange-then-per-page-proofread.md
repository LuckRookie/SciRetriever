# ADR 0041：建档先整理、再逐页校订保留内容

类型：决策（ADR）
负责：建档中整理与校订的顺序、各自的权限与校验
状态：Accepted（2026-10-27，Owner 确认）

- Date: 2026-10-27
- 依据：Owner 2026-10-27 决定“建档采用流程 X：先整理，再对保留内容逐页独立校订”；建档不设运行中预算，“只要他不是无意义的消耗预算，我们都是可以接受的”。
- 部分取代：[ADR 0037](0037-literature-archive-and-proofread-text.md) 术语表中“初稿”“矫正”“结构注释”“建档”四行，第 3 节第 1、3、4、5、6 条，第 5 节第一条（章节角色识别），第 6 节中元数据步骤读取的片段范围，第 8 节 `READY` 第 2 条中“正文类章节”的含义。ADR 0037 其余各节不变。
- Related: [计划 17](../../plans/2026-10-27-web-usage-review/README.md) P23、P24；[文档与证据](../technical/04-document-evidence.md) 第 6 节；[文献建档指南](../../guides/literature-archive.md)

## 背景

按 ADR 0037，建档先校订全部初稿，再给章节标角色。Owner 实际使用发现，建档后的全文混入出版社页面杂项：许可声明、“Cite This”“Read Online”“Metrics & More”、装饰图标，摘要前粘着“Supporting Information”。原因是校订只管抄录保真，结构注释只给章节标角色，没有任何一步负责“哪些内容不属于文章”。

2026-10-27 在 sandbox 用同一批 5 篇（ACS 快报 2 篇、Elsevier、Wiley 11 页长文、RSC，共 34 页）做了四轮实验，结果见本机 `sandbox/reports/2026-10-27-archive-arrange*/`：

- **整理不能交给 Agent 改写全文。** 让 Agent 输出整理后的全文，会悄悄改字，例如把跨行的 poten/tial 拼成 potential。只让 Agent 提交操作、由程序渲染，五篇保留内容都做到零文字差异。
- **先校订后整理，校订会浪费在随后被删的内容上。** 合并在一个会话里做时，两篇 ACS 分别有 21/54、22/78 项改字落在页眉、书目行等随后被删的内容上；五篇共 51 项。
- **持续会话的成本随页数累积。** 合并做时，每次调用都带着前面的全部历史，五篇成功路径输入 4017 万 token，单次请求最大 2.4 MB；先整理、再逐页独立短会话校订，输入 850 万 token，单次请求最大 0.6 MB，无失败重跑。
- **两种顺序的实质改字基本相同。** 逐处对齐后，两边同改 209 处；只有一边改的，多为页码连字符改短横、撇号、空格与上标写法，实质性的单边改字两边各有少量。

## 决定

### 1. 建档顺序

建档依次为：**整理、校订、渲染、元数据、参考文献、标签**。ADR 0037 第 1 节的阶段划分、第 4 节的部分、第 7 节的标签不变。

整理与校订都是 DSH 任务，模型绑定沿用现有角色配置。

### 2. 整理

整理决定初稿里每个区块的去向，**不改任何文字**。每篇的每个部分一个整理会话，会话可以读全部区块、查看任意页面图、按文字查找。

1. **Agent 只提交操作**，不输出文字：
   - **归属**：把区块归到骨架中的一个章节；论文自己的小节标题保留原文，作为所在章节下的小标题；
   - **删除**：附一个理由，理由取自封闭列表（页眉、页脚、界面、书目、版权、装饰），列表由技术文档维护；
   - **拆分**：在指定字符位置把一个区块拆成几个叶块，各叶块再分别归属或删除，用于摘要或正文中夹带的版权句等；
   - **合并**：把相邻的正文叶块接成一段。中间夹着已归到别处的脚注、图、表、图注时可以跨过，被跨过的内容渲染在合并后段落之后，不丢失。前块以连字符结尾时分隔为空串、保留连字符，不做去连字符改字；
   - **图注挂接**：把图注挂到对应的图或表下。
2. **骨架**固定为：标题、作者、摘要、关键词、引言、方法、结果与讨论、结论、文末信息、参考文献、附加章节。
   - “作者”只放作者姓名行；单位、通讯作者、致谢、资助、利益声明、作者贡献、注释、支持信息说明归“文末信息”；
   - 期刊卷期页、DOI、收稿与发表日期等书目行删除，理由“书目”；阅读视图的标题区由程序从元数据渲染期刊、年份、DOI。
3. **疑似断段**由程序计算并交给 Agent 逐条决定合并或不合并（不合并附一词理由）。判定规则由技术文档维护，初始规则为：按阅读顺序相邻的两个正文叶块，前块结尾不是句末标点，且后块以小写字母、数字或右括号、右引号开头。
4. **页归属**：ADR 0037 第 2 节“页码与坐标只是定位提示”不变。整理会话可以调整叶块的页归属，每次调整注明依据页码；在 `text-layer` 页上，程序用文字层提示可能归错页的内容。
5. **程序校验**：
   - 每个原始区块都恰好有一个去向，拆分后的每个叶块也是；
   - 每条疑似断段都有决定；
   - 渲染结果与保留叶块的原文零差异，骨架标题、小标题标记与合并分隔属于确定性的结构渲染，单独计数；
   - 校验不通过时把具体错误退回会话修正，不放行。

### 3. 校订

校订只处理**整理后保留的叶块**，目标仍是 ADR 0037 第 3 节所说的抄录保真。

1. **每页一个独立的短会话**，只带本页的保留叶块、页面图（可局部放大）、本页可见文字层和本页疑点；不带其他页，也不带整理阶段的历史。`image-only` 页同样一页一个会话，没有文字层与疑点，对照原图检查。
2. **疑点**在本页重新计算，并排除已被整理删除的文字；ADR 0037 第 3 节第 3 条的前三类疑点保留，第四类“内容出现在别的页”改由整理阶段处理。
3. **改字操作**只有一种：指定叶块、起止字符位置、原文片段、改成什么、依据页码、一词理由。改字不能跨叶块，不能作用于已删除的内容；程序校验原文片段与叶块内容一致。
4. **处置完整性**（程序检查）：
   - 每个有保留叶块的页都有一次提交，可以是“本页无改动”；提交前会话必须读过本页全部保留叶块并查看过整页图；
   - 每条疑点都有处置：已修正、确认初稿无误（附原因）、无法确定（保留初稿，附原因）；
   - 未满足时该页校订尚未完成，可以继续，不进入就绪。
5. 页面原图是最终依据、看不清不猜测、人工决定锁定，均按 ADR 0037 第 3 节第 4、9 条不变。人工也可以改整理结果（恢复删除的区块、改归属），同样锁定。
6. 改字按叶块坐标保存，并确定性映射回原始区块坐标。某一页失败只重跑这一页；整理失败只重跑整理，已接纳的各页校订不受影响。

### 4. 渲染与结构注释

- 校订稿 = 原始区块 + 整理操作 + 已记录的改字；除骨架与小标题的结构渲染外，与原始区块的差异只能来自已记录的改字。
- 已删除的区块不进入阅读视图、检索与算子输入，但保留在原始解析中，可以按理由查看。
- **结构注释**改为由整理的归属结果生成，仍单独保存，不写入文档表示；ADR 0037 第 5 节“先用规则识别、规则没命中的交给模型”不再适用。ADR 0037 第 9 节的内容版本公式不变。
- ADR 0037 第 8 节 `READY` 第 2 条中的“正文类章节”，指骨架中的引言、方法、结果与讨论、结论、附加章节。

### 5. 元数据的读取范围

元数据步骤读取标题、作者、摘要、关键词章节，以及整理时以“书目”理由删除的区块，作为逐字段提议的片段证据。这些书目区块只供元数据步骤读取，不因此回到阅读视图或算子输入。

### 6. 运行预算

- 整理与校订都**不设调用次数或 token 上限**。
- 发起建档前，按页数与历史消耗向用户说明预计的调用次数与 token。
- 运行中只在无意义消耗时停下：同一校验错误反复出现，或连续多次调用既没有读到新区块、新页面，也没有提交新的操作。具体次数由技术文档维护。停下时写明原因，可以重试。
- 会话里只保留最新一张页面图，旧图换成文字占位；单次请求大小不随页数累积增长。

### 7. 已有建档结果

已按 ADR 0037 流程建档的文献保持现状，可以照常阅读与被算子选中。用户重新发起建档时按本 ADR 生成新的文档版本，旧结果按 ADR 0037 第 10 节标记过时；不自动重建。

## 未采用的方案

| 方案                                               | 原因                                                                                                                |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 保持 ADR 0037 的顺序，在结构注释里加“页面杂项”角色 | 校订仍会浪费在杂项上；杂项夹在摘要、正文块里时无法只标出一部分                                                      |
| 让 Agent 输出整理后的全文                          | 实验中会悄悄改字，长文还受输出上限限制；改动范围无法审查                                                            |
| 校订与整理放在同一个持续会话                       | 实验中输入 token 约为分开做的 4.7 倍，单次请求最大 2.4 MB；改字有 51 项落在随后被删除的内容上；实质改字没有因此更好 |
| 逐页校订时允许翻看相邻页                           | 会把会话重新变长；跨页问题（页归属、跨页断段）已经由能看全文的整理阶段处理                                          |
| 为整理和校订设每篇调用上限                         | 长文会中途停下（P24）；Owner 决定只拦截无意义消耗                                                                   |

## 后果

- 建档全文不再含出版社杂项、书目行、版权句和装饰图标，原始区块仍可查。
- 成本：5 篇样本的输入 token 约为合并做的五分之一；整理按篇一个会话，校订的消耗随保留内容的页数线性增长。
- 残余风险如实承认：
  - 整理可能误删正文或把内容归错章节；删除都有理由、可在原始解析中查看，人工可以恢复；
  - 每页校订看不到相邻页，跨页的抄录问题只能靠整理阶段发现；
  - 跨叶块合并处的断行连字符原样保留，不在本 ADR 范围内消除；
  - 页归属调整与“关键词”章节在实验中没有覆盖，需要在实施验收中验证。
- 以下合同有变化，不做兼容：建档任务的步骤与进度事件、结构注释的生成方式与章节角色取值、校订记录的格式。
