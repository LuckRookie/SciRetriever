# ADR 0056：出网代理，按发起方逐项选择

类型：决策（ADR）
负责：出网代理的配置、按发起方选择出口，以及经代理时的连接与失败规则
状态：Accepted（2026-11-05，Owner 确认）

- Date: 2026-11-05
- 依据：Owner 2026-11-05 的意见，原话如下：

  > 如果要加代理，就要改设计，比如说添加一个代理窗口，并控制都谁走？需要分几个大类，浏览器、请求连接、模型调用，这些应该都属于能用代理的地方。

  > 机构IP也可能是一个代理上的，这倒是不影响，是之前的ADR写的有问题，sci-hub也同理。同样都是网络只不过是谁发送这个请求的问题而已。

- 部分取代：
  - [ADR 0016](0016-cloakbrowser-fixed-identity-runtime.md) 第 4 节“使用服务器原始网络出口”：浏览器改为使用 Owner 选择的出口，其余 Network guard 不变。
  - [ADR 0015](0015-publisher-aware-tiered-pdf-acquisition.md)“自动流程首先使用当前机器正常网络出口，因此机构 IP entitlement 仍可直接生效”：自动流程使用 Owner 为各发起方选择的出口。
- 与[产品需求](../requirements.md) Sci-Hub 条目中“不得为该 Source 增加……代理”的修订同时生效：Sci-Hub 与其他来源一样按本 ADR 选择出口，仍不增加该来源专属的代理配置。
- Related：[任务与协作控制](../technical/02-task-coordination.md) 第 7 节；[浏览器控制](../technical/08-browser-control.md)；[配置说明](../../guides/configuration.md)

## 背景

2026-11-05 逐个测试已配置的来源时，Semantic Scholar 失败。原因不是 API key：这台服务器直连它的 CDN 地址超时，只有经本机代理才能连通，而应用没有代理设置。

现在所有出网都经过 Network 模块，没有第二条路径：

- 普通 HTTP 请求在 `connectVerified` 建连。来源检索、出版社 API 下载、DOI 解析、PDF 链接下载、模型调用和远程 MinerU 都走这里。
- 浏览器只连本机的 loopback CONNECT 代理，再由这个代理按已审核的地址建连。

旧决定把“服务器原始出口”写成机构 IP 权限的前提。但机构 IP 只是出口的属性，机构出口本身也可能是一个代理。出口只决定请求由谁发出；有没有权限，仍由出版社的响应确认。

## 决定

### 1. 一个代理，显式配置

- 普通配置增加一个代理地址，只支持 HTTP CONNECT，例如 `http://127.0.0.1:7890`。代理需要认证时，用户名和密码存进 `credentials.toml`，与代理地址绑定。代理地址改变后，旧认证不会发往新地址。
- 代理地址可以是本机或局域网地址。公网地址检查只对目标生效，不对代理这一跳生效。
- 只认这一项配置，不读取环境变量 `HTTP_PROXY`、`HTTPS_PROXY`、`ALL_PROXY`、`NO_PROXY`。
- 只有一个代理。只填代理地址不改变任何流量，各项要分别选择（第 2 节）。

### 2. 按发起方选择，不按目标地址

由哪个组件发起请求，决定这次请求走哪个出口。每一项只有两个值：直连、经代理。默认全部直连。

| 组       | 选择单位                         | 覆盖的请求                                                                                                       |
| -------- | -------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 文献来源 | 每个来源一项，另有“DOI 解析”一项 | 该来源的检索、元数据、API 下载、由它给出的 PDF 链接下载，以及该来源的测试；DOI 解析指获取流程中对 doi.org 的解析 |
| 模型     | 每个 Model Provider 一项         | 该 Provider 的全部模型调用：建档、标签、翻译、浏览器 Agent、分析与模型测试                                       |
| 解析服务 | 远程 MinerU 一项                 | 解析的提交、轮询与取回结果                                                                                       |
| 浏览器   | 一项                             | 浏览器的全部页面请求，包括验证页资源                                                                             |

- 浏览器只设一项，因为所有出版社页面共用一个浏览器进程与 Profile。
- 选择“经代理”而代理地址未配置时，配置校验拒绝保存。
- 目标是本机或局域网服务的项（本机 MinerU、本机模型服务）不提供选择，始终直连。Web 4174 的入站访问不受影响。

### 3. 经代理时的连接

- Network 照常检查 URL、在本机解析 DNS，并拒绝私有地址；本机解析失败照常报错。检查通过后连代理，用 `CONNECT 主机名:端口` 建隧道，由代理解析主机名。
- 隧道内由 SciRetriever 自己完成 TLS，并照常校验证书与主机名。代理不能终止 TLS，系统也不信任额外的 CA。明文 HTTP 目标同样走 CONNECT 隧道，不另设转发方式。
- 浏览器：Chromium 仍只连本机 loopback 代理，Chromium 的启动配置不变；loopback 代理按浏览器这一项决定上游是直连，还是经代理 CONNECT。TLS 仍由 Chromium 端到端完成。
- 限速、额度、超时、字节上限、redirect 检查、`Retry-After` 和凭据只发往原 origin 的规则都不变。代理认证只出现在发给代理的 CONNECT 请求里，不进日志、任务事件或 Web 数据。

### 4. 失败与可见性

- 经代理的请求，如果代理连不上、认证失败或 CONNECT 被拒，报 `proxy-unavailable`，与目标站点自身的失败分开。不回退直连。
- 设置页提供“测试代理”：连上代理，并 CONNECT 到一个固定的公网主机，报告是否连通与耗时。
- 来源测试、获取轨迹和模型测试的结果注明本次出口：直连或经代理。
- 状态与 readiness 显示是否配置了代理、哪些项经代理，不显示代理认证。

### 5. 设置界面

设置页新增“网络”分区：代理地址、可选认证、“测试代理”，下面按第 2 节的四组列出各项开关。各项开关只在这里修改；来源、模型列表的行上只显示“经代理”标记。CLI `config` 提供同样的设置。

### 6. 不做的事

- 不读取环境代理变量，不支持 PAC 或按目标域名配置规则。
- 不提供代理池、轮换，不在失败时自动切换出口或回退直连。
- 自动流程与浏览器 Agent 不能更改出口，出口只由 Owner 在配置中选择。
- 暂不支持 SOCKS5，需要时另议。

## 后果

- Semantic Scholar 这类直连不通的来源可以单独改走代理，其他请求不受影响。
- 浏览器或出版社来源改走代理后，出版社按代理的出口判断权限。是否有权限仍由出版社响应确认，结果照常区分正文、付费墙、challenge 与限流。
- 普通配置与 `credentials.toml` 各增加代理字段，catalog 不变。
- 需要同步修改的文档：
  - 产品需求：Sci-Hub 条目与对应验收行中的“代理”；
  - 技术文档 02 第 7 节：出口选择、CONNECT 隧道与 `proxy-unavailable`；
  - 技术文档 08：loopback 代理的上游与“不改变服务器原始出口”的表述；
  - 原则检查表：浏览器一项改为“没有环境代理，只有显式配置的出口”；
  - 配置说明：新增代理与各项出口字段，删除浏览器一节“不接受代理设置”；
  - 页面规格：设置页“网络”分区与各列表行的“经代理”标记。
