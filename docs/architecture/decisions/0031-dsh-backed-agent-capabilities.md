## 背景与授权依据

Browser 当前使用自有循环，每次重建模型请求并提供近期动作摘要，没有贯穿文章的完整工具调用与结果历史。继续增加上下文、压缩和执行控制时，会扩大自维护 Agent 基础设施。后续数据提取、图片提取等能力也有复用模型—工具协作基础的需求。

Owner 要求把 Agent 能力工具化：工作流通过明确输入、结果与必要执行控制来调用能力，不必逐轮操作其内部对话；同时继续由软件掌握业务事实、Browser 控制和文件发布。

比较 Pi 与 DeepSeek Harness 后，Owner 明确指出 DSH 基于 Cordis，各服务和插件可以按需组合。源码调查确认，循环、会话、工具、模型与压缩可在进程内独立组装，默认 CLI/Web、个人配置和 SDK 子进程均不是必要条件。[选型讨论归档](../../archive/2026-10-13-agent-runtime-options/README.md)保留证据与取舍。

2026-10-13 Owner 决定：“就用 DSH，放弃 pi agents”，并要求先记录决定、编写提案和计划，批准后再实施。本 ADR 接受后端方向与以下边界，不把设计文档编写视为代码实施授权。

## 决策

### 1. 采用 DSH 的最小进程内 Cordis 组合

以 DeepSeek Harness 的公开服务和插件 API 提供受控 Agent 执行基础，按实际需要组装模型、会话、工具、循环与上下文管理。DSH/Cordis 类型和生命周期封装在 `agents` 的私有适配边界；业务模块通过中性 TypeScript 合同使用能力。

不采用 Pi Agent Core 或 Pi Coding Agent 作为另一个 Agent 后端，也不建立 DSH/Pi 双运行时选项。此决定选择 Agent 执行基础，不要求切换模型供应商；Browser 仍使用 SciRetriever 配置中选择的视觉模型和 reasoning/stream 值。

DSH 上游可选模型插件可能依赖 `pi-ai`，这与选择 Pi Agent 后端不同；是否需要该协议库按实际适配评估，不因框架名称自动引入。目标是复用现有受控模型访问，避免复制 wire adapter、凭据和限速。

DSH 默认应用组件按需要选择，不隐式加载其 CLI、Web、shell、用户 home、个人指令、凭据发现、全局代理或后台任务。项目不因此整体迁入 Cordis，也不新增供模型或用户任意安装、执行插件的平台。

### 2. 唯一 DSH 底座，按任务使用单次调用或持续会话

2026-10-16，Owner 明确 DSH 应完整覆盖自建 Agents 并作为全项目唯一执行基础，不维持多个 Agents 后端。单次文本/结构化/图像/工具调用也进入 DSH 的原生模型服务，持续会话使用同一底座的工具循环与上下文管理。2026-10-19 Owner 明确撤销兼容入口：删除 `AgentRuntime` 别名和 `createBrowserDecision()` 单次兼容入口，公开消费者改用 `DshAgentRuntime` 与 Browser capability；不保留独立自研执行路径或隐藏回退。历史产物格式与证据引用继续可读。

同日完成内容对照讨论后，Owner 再次确认停用原内置 Agents 后端，今后默认使用 DSH。此处“默认”表示唯一启用的执行后端，不提供旧后端切换项；DSH 初始化或执行失败时按既有失败合同返回，不绕过底座直接调用模型。保留供应商 wire adapter、Analysis 的业务算法和结果验收不等于保留第二个 Agents 后端；持续阅读、查证与修订策略是否接入某项业务，须由该业务实现与测试明确，不能以底座切换代替。

2026-10-19，Owner 指出默认单篇分析一次提交全部文字并未实现持续阅读，要求将分析实际交由 DSH。单篇/长文的旧分块提取、固定层级归并控制器退役，二者使用同一 DSH 阅读会话。Analysis 只注册固定版本正文分页、片段回读、全文搜索、保存图片读取及结果提交工具；DSH 掌握后续工具选择与上下文。集合综合对原始文档使用同一阅读能力，在综合会话中允许回查候选和原文证据。最终结构、输入版本、证据来源、不可变发布与默认视图 CAS 仍由业务 owner 验收。

执行与数据兼容分开：旧方法的结果可继续读取，但新分析使用新的方法身份，不能把旧结果当成新会话执行结果。公开 `analyze/analyzeLong` 请求作为用途入口汇入同一实现，既有字段不重新启用旧 Agent。身份核验、记录/标签等有明确输入输出的原子模型操作仍通过 DSH 原生模型服务；它们不是第二套 Agent 引擎。实际阅读、图片可用性和科研内容质量分开验收，不以成功工具调用证明科学理解。

迁移必须保留模型选择、reasoning/stream、结构化结果、完整图片、取消、失败和 provenance 等既有能力。Browser 的“只投影最新截图”、动作选择与探索政策由 Browser 明确提供；不能成为通用分析或多图任务的底座默认。消费者可通过统一中性接口创建纯文本、视觉或工具会话。

单次模型 adapter 仍不自动执行工具、不决定业务下一阶段。DSH 执行基础可以编排模型与工具交互；工具的允许范围、操作语义、实际副作用和最终结果接纳继续由相应业务 owner 决定。框架消息、会话树或摘要不成为新的文献事实来源。

有限输入的解析、总结和综合继续遵守 ADR 0026：不因为引入 DSH 而获得 Browser 探索预算，也不强制把所有单次或确定性处理改成自治 Agent。既有公开请求、结果与持久化合同的具体扩展或破坏性变更须按原规则评估。

Owner 要求替换后的能力覆盖和内容质量提升；费用、耗时与调用次数不作为质量优劣依据。底座合同回归与科研内容质量对照分别验收，不从框架能力、会话长度或离线成功推导内容全面优于旧方案。相同材料、任务与模型下评估正确性、完整性、证据支持、综合与修订质量；真实验证沿用单独授权边界。

### 3. 先接入 Browser，保留通用能力方向

本节记载首期接入顺序。2026-10-16 的统一底座决定取代 Browser 专用接入状态：所有现有模型消费者均纳入统一接线，分析算法和新领域能力仍按各业务合同演进。

Browser 是首个替换目标。模型接收当前文章目标、当前稳定观察以及连贯的历史工具调用与结果，不再把最近数条动作摘要作为唯一执行记忆。模型输入投影可以删除过时图像或压缩历史，但不得伪造动作结果、丢失当前任务绑定，或把其它文章的经验变成权限事实。

“能力工具化”表示业务调用方可给出目标、材料和约束，获得进度、暂停/结束结果及产物或失败引用；允许取消和人工介入。它不要求能力是无副作用的纯函数，也不等于把内部所有工具导出为 MCP。

数据提取、图片提取等后续能力可以复用执行基础；本次不接受具体领域 schema、提取算法或新的公共提取 API。ADR 0027 的调用方记录含义、候选交付与领域数据集所有权继续适用。

### 4. Browser 与下载事实继续由现有 owner 掌握

| Owner                        | 继续承担的责任                                                                    |
| ---------------------------- | --------------------------------------------------------------------------------- |
| `agents` 项目适配边界        | 统一模型绑定、协议转换、capability、稳定结果/失败及 Network 接入                   |
| `agents` 唯一 DSH 执行基础   | 原生单次模型派发、多轮上下文、工具循环、压缩与调用/会话生命周期                    |
| Browser/应用控制             | 文章与页面绑定、观察版本、控制权、动作节奏、worker 资格、探索预算、人工指导与接管 |
| Network                      | 真实请求准入、共享供应商/平台政策、取消、凭据作用域与脱敏                         |
| Acquisition/传输管理         | 文件下载、候选归属、PDF 基本验收与交接，不把发布责任转交给 Agent                  |
| Entry 与既有发布 owner       | 沿原调用链完成不可变发布、文献/资产关系提交和真实成功结果，业务写入所有权不变     |
| Analysis/Extraction 等消费者 | 用例目标、工具语义、材料范围、输入版本、结果接纳与 provenance                     |

现有文章会话、worker 和 transfer 的不同寿命继续保留：下载进行时让出决策资源，失败后可以带着真实反馈恢复原文章；文件成功与否以传输、验收和发布为准。DSH 会话与文章会话需要显式绑定，不能用 worker 当前任务或 Web 前台选择隐式决定目标。

每份稳定观察仍至多许可一个页面原子动作。框架可能返回多个工具调用，不授予连续执行旧观察动作的权利。人工接管、取消或页面变化使旧动作资格失效，恢复时重新观察；程序约束不退化为提示词。

### 5. 配置、网络和事实隔离

模型访问继续复用 SciRetriever Configuration/Credential 和 Network。普通推理、摘要压缩及确需的重试均须具有实际派发、归属、取消与 usage 记录；不能只统计外层 Agent turn，也不能另设不可见自动请求路径。具体计量与调度接法在提案及实现中确定。

不把 Browser、Cookie、任意 URL/selector/脚本、数据库写入或文件发布能力交给模型。DSH 只获得该能力明确注册的工具。框架的执行记录和图像保留不改变 Catalog/ArtifactStore 的事实所有权，也不自动授权新增持久化会话、跨进程 Browser 恢复或长期记忆。

## 后果、未采用项与验证

DSH 带来可复用的会话、工具和压缩服务，也引入插件依赖、生命周期、消息转换与升级维护。公开包不等于没有传递依赖，压缩也不等于释放原始事件和截图。首期以 Browser 切片验证接入；统一底座须继续覆盖 Analysis、综合、身份核验、配置 probe、通用文本/多图会话与关闭生命周期，不能以官方测试源码替代本项目验收。

不采用 Pi 后端、默认完整 DSH 应用接管产品、第二套下载调度或并行事实库，也不为本次引入插件市场、热更新、持久工作流引擎或领域提取算法。

实施验收应覆盖真实 DSH 循环与 fake 模型/网络、图像和工具历史、接管与迟到动作、多文章并行与下载恢复、所有模型请求的归属，以及既有 Analysis 和配置兼容；全量门禁与真实站点结果分开记录。首期依赖、离线验收和两轮固定样本结果已记录于实施计划；未验证的缓存收益、普遍性能及站点成功率仍不能由接入完成推导。
