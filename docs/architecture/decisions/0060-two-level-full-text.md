# ADR 0060：全文文本分两级：初稿可读、可加工，校订按需进行；建档规则不预设学科

类型：决策（ADR）
负责：全文文本的等级与标注；初稿的形成、阅读与加工准入；校订的发起方式；建档规则的领域通用

## 背景

现在的规定是：一篇文献必须完成建档，得到校订稿，知识加工才能读它。建档的主要花费在校订，每页调用一次视觉模型。

2026-11-10 的事实：

- 实际文献库有 35,227 篇书目，有全文的 926 篇，完成建档的 3 篇。知识加工平台按现有设计做出来以后，只能在这 3 篇上运行。
- 校订每页一次调用，约 5,500 输入 token、13 秒（ADR 0047、ADR 0054 的实测）。按每篇 12 页推算，一万篇约需 9 亿输入 token。这是推算，没有实测。
- 初稿在 ADR 0037 里已经存在：它是原始解析经规则清理、按页归属后的文本。程序还会在有文字层的页上，把初稿和 PDF 的文字层逐处对比，列出差异（疑点）。这两步都不调用模型。

需求要求万篇规模的文献能读、能加工，同时要求可靠。每篇都先校订，“海量”做不到；完全不校订，“可靠”打折扣。

## 决定

### 1. 两级文本

| 等级   | 怎样形成                                               | 花费                 | 可靠程度                                                             |
| ------ | ------------------------------------------------------ | -------------------- | -------------------------------------------------------------------- |
| 初稿   | 原始解析，加程序规则清理，加与 PDF 文字层的程序对比    | 不调用模型           | 与文字层一致的片段可信；有差异的片段列为疑点，未处理；扫描页无法核对 |
| 校订稿 | 在初稿上做整理和逐页校订（ADR 0041、0047、0048、0054） | 每页一次视觉模型请求 | 现有标准不变：错误可控、可发现、可追溯                               |

1. 初稿成为正式的文本：可以阅读，可以查找，可以加工。
2. 校订稿的标准不因为有了初稿而降低。
3. 只有这两级。ADR 0055 的长文档简化流程不变，它的产物仍是带“长文档”标记的校订稿。

### 2. 初稿怎样形成

1. 一个部分解析完成后，由程序形成初稿。这一步不调用模型，不联网，不需要使用者另外发起。
2. 形成初稿使用的规则是 ADR 0054 的规则预处理：删除页眉页脚，接上明确的断段，以及验证通过后的阅读顺序纠正。
3. 初稿没有章节角色。章节角色由建档里的整理步骤给出。
4. 解析不触发建档。校订仍然只在使用者明确发起时进行。
5. 一篇文献既有初稿又有校订稿时，默认阅读和加工校订稿。

### 3. 标注

1. **片段。** 初稿的每个片段带一个核对依据，取值为三种之一：
   - 与文字层一致；
   - 与文字层有差异（疑点，未处理）；
   - 没有文字层可以核对。
2. **文献。** 文本等级显示在这些位置：文献库的文献行，阅读页的信息栏，全文阅读视图的顶部，以及 HTTP、命令行和 MCP 的文档描述。初稿的说明文字是：“未经校订，文字可能含解析错误；以 PDF 为准”。
3. **查找结果。** 命中的片段带文本等级。
4. **加工结果。**
   - 每份结果记录每篇输入文献读的是初稿还是校订稿。
   - 结果页和机器接口给出两个数：依据初稿的文献数，依据校订稿的文献数。
   - 每条证据显示所引片段的文本等级和核对依据。

### 4. 加工准入

1. 算子可以读取初稿或校订稿。运行发起时可以限定“只用校订稿”。
2. 按章节角色限定读取范围的算子，在初稿上读取整篇正文，并在覆盖说明里注明。
3. 文本等级是内容版本的一部分。一篇文献从初稿升级为校订稿后，依据初稿的旧结果标为过时，不自动重算。
4. 对提取值的文字比对（ADR 0037 第 10 节“用时核对”）在初稿上同样执行。
5. `READY` 的定义不变，仍表示库整理完成。它不是加工的门槛。

### 5. 校订按需进行

1. 校订由使用者明确发起，范围用库内筛选写明（ADR 0052）。系统不自动校订。
2. 为了帮助使用者决定校订哪些文献，下列事实可以用来筛选和排序。它们都不需要调用模型：
   - 初稿的疑点数量；
   - 是否含有扫描页；
   - 是否被加工结果引用；
   - 加工结果里是否有“找不到”的引用指向它。
3. 发起校订前给出估算，按每页一次请求计算（ADR 0047）。

### 6. 建档规则不预设学科

1. ADR 0037 第 7 节的标签规则里，“主要化合物”改为“主要研究对象”：
   - 标签可以描述领域、方法或工作类型，以及主要研究对象。化合物是研究对象的一种。
   - 研究对象的名称必须在题名或摘要中作为研究对象出现。名称用正式名或通用名；代号写入同义词；不得使用文中编号作为名称。
   - 不做标签的内容改为：数值、实验条件、所用的材料与试剂、次要的研究对象，以及出版形式和文章性质。
2. ADR 0047 里针对化学结构图的防护规则保留。它只在页面上出现结构图时起作用，对其他学科的文献没有影响。
3. 整理用的骨架不变。套不上骨架的章节归入附加章节并保留原章名，这一点 ADR 0054 和 ADR 0055 已经规定。
4. 以后新增建档规则时，学科专属的内容只能有两种形式：作为例子；或者作为只在特定内容出现时才触发的防护。它不能成为所有文献都必须满足的条件。
5. 是否做到，用需求“规4”的验收检验：用至少两个差别明显的学科的文献走完收、读、炼、用。

## 后果

- 有全文的文献解析之后就能阅读文本、查找和加工，不必等校订。
- 万篇规模的加工不再以万篇的校订为前提。校订的花费只在使用者选定的范围内发生。
- 代价是：依据初稿得到的知识，可靠程度低于依据校订稿得到的知识。表格、公式和扫描页的风险最高。弥补的办法是第 3 节的标注、第 4 节的文字比对，以及回到 PDF 核对。
- 以下判断没有实测支撑，需要一次经授权的抽样评估来确认：初稿在真实文献上的疑点比例；依据初稿的加工结果与依据校订稿的结果相差多少。
- 需要跟着修改的文档：
  - ADR 0044（接受之前）：第 1 节的输入、第 4 节的证据根、第 5 节的准入。已修改。
  - 技术文档 04（文档与证据）和 05（知识加工）。
  - 计划 16 的第 04 块（按需材料门槛）。
  - 需要一个新的计划，把初稿做成正式的文本。
- 接受后，ADR 0037 与 ADR 0034 的状态行增加“部分被 ADR 0060 取代”。

## 考虑过但没有采用的方案

| 方案                                | 没有采用的原因                                                                                                             |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| 维持现状：每篇都校订之后才能加工    | 一万篇约需 9 亿输入 token（推算）才能开始加工。库里有全文的 926 篇，完成建档的只有 3 篇                                    |
| 第一级包含模型整理（每篇 2 次调用） | 仍然需要模型和授权，一万篇约 1–2 亿输入 token（按 ADR 0054 的每篇 0.9–2.2 万推算）。多数加工不需要章节角色。需要时另行决定 |
| 只校订程序找出疑点的页              | 这是降低校订花费的做法，与分级不冲突，留给建档以后优化                                                                     |
| 让原始解析直接进入加工              | 原始解析带有页眉页脚、断段和可能出错的阅读顺序。初稿经过规则清理，并带有核对依据                                           |
| 初稿由使用者另外发起才形成          | 形成初稿不花钱、不联网、结果确定。多一步操作只增加负担                                                                     |
