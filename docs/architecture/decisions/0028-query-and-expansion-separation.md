# ADR 0028：数据库查询与显式扩充操作分离

- Status: Accepted（操作边界与启动条件；具体接口、权限实现和运行存续仍待设计）

- Related: [产品需求](../requirements.md)、[设计](../design.md)、[统一产品接口：共享合同、结构解析与版本兼容](../technical/01-product-interface.md#6-共享合同结构解析与版本兼容)、[工作流](../knowledge-service-workflows.md)

## 背景与决定依据

Owner 明确要求将查询数据库与扩充数据库分离。不允许因发现库中内容不足而启动外部搜索；每一次新增元数据或 PDF 全文的扩充操作，都需要像当前使用方式一样手动开启。

此前方案虽然规定查询不隐式生成，但“确保目标”“允许前置处理”“准备知识时补齐缺失材料”等描述仍可能让普通知识请求转为收集任务。需要在产品入口和应用调用边界上消除这种歧义，同时完整保留获取、分析、提取和人类协作。

## 决策

### 1. 两类产品入口，共享同一个文献库

- **查询与使用已有内容**：本地文献搜索、详情、原始文件/文档/资源读取、已有总结/候选读取、证据展开、已有内容的上下文组装。
- **扩充与加工数据库**：显式发起元数据发现/补充/导入、PDF 获取/人工接纳；以及显式解析、生成分析/综合或提交提取候选。

两类操作共用稳定 ID、结果和逻辑数据库，但拥有不同副作用合同。查询调用不会转入扩充/加工调度；不要求为了这种分离建立两个数据库、服务进程或通用 CQRS 框架。

### 2. 缺口是查询结果，不是任务触发器

没有命中、缺 PDF、缺解析、缺某用途总结、证据不可用或索引不完整，只返回已知内容、缺口和实际覆盖。可以展示由用户选择的后续操作，但不得自动调用 Metadata/Acquisition、启动 Browser/Parser/Analysis、创建补库任务或自动排队。

本地未命中只表示本次库内查询没有取得对应内容，不证明外部世界没有该文献。知识/提取请求缺少材料时报告缺失，不能由应用协调层代为外部查找或下载。查询预算、分析问题或“完整回答”的目标均不构成扩库授权。

### 3. 每次扩充由用户明确启动，任务内仍可自动批量执行

用户在工作台发起、执行明确 CLI 命令，或明确指示 Agent 代为发起具体扩充任务，均属于主动启动。普通科研问题或 Agent 自行判断需要更多证据不属于主动启动；系统不能据此扩大范围。

一次启动可以覆盖一批文献和明确停止边界。该任务内的来源访问、分层获取和已允许的重试/人工协作仍按既有合同执行，不需要每条元数据或每份 PDF 重复确认。发现和 PDF 获取是不同操作：只启动发现不会随后自动获取 PDF。确需组合维护时，启动请求必须明确列出扩充步骤与范围，不能从一个笼统知识目标推断。

技术实现须保证查询边界只调用读取能力，扩充命令走独立应用用例。具体权限分组、调用来源表达和接口字段在后续契约设计中确定；本决定不预设新的授权令牌或审批系统。

### 4. 已有材料加工与外部扩充保持边界

用户可以对库中已有 PDF 主动启动解析、分析或提取。新知识产物/候选的发布属于显式加工，不是查询。缺少原始材料时返回缺口；对已有材料允许哪些内部准备步骤由加工操作明确说明，不会因此获得外部发现或 PDF 获取权限。

既有分析用例中的元数据提案仍由 Literature 按相应验收合同处理，不把本决定扩张为“每次字段提交都要确认”。但加工不能发起未明确启动的外部元数据补查，也不能静默新增论文或全文。

### 5. 现有行为与兼容

当前手动发起的数据库 completion 是维护操作，已有 `CONTENT_READY` 可包括获取 PDF 的语义须向调用方准确说明；不得将它用作查询或独立分析的内部缺口处理器。现有命令不因本文静默删除或改变受支持行为。新增独立知识操作应使用已有材料前提；如后续改变旧 completion 的公开语义，需单独做兼容评估。

本 ADR 不改变保守身份、不可变资产、事实 owner、来源保留、访问政策、阶段提交及取消语义，也不改变后台存续/长期回放的待定状态。

## 必须验证的边界

1. 空库查询、缺 PDF、缺总结、失效证据、索引不可用均不调用外部发现/获取/生成，不产生扩库 Job 或新增文献事实。
2. 独立分析/提取请求缺材料时报告缺口，不调用旧 completion 自动下载。
3. 用户显式启动有界发现后可以接纳多条元数据，但不会自动获取 PDF；单独启动 PDF 维护后可批量自动获取并验收。
4. 当前明确的组合维护按已声明步骤工作，不把它挂到普通查询后；工作台、CLI、Agent adapter 共享这一边界。
5. 查询和扩充任务并行时，查询读取一致的已提交事实；一次读取不会因发现新缺口继续追赶或发起新任务。

## 后果

科研 Agent 可以稳定消费已有文献库，数据库增长由用户主动控制。缺口能够被观察和处理，但查询不承诺自动取得库外材料或完整回答所有问题。人类工作台与 Agent 工具需要明确区分库内检索和外部发现；“统一接口”表示共用应用语义，不表示把读写副作用合成一个黑箱。

本轮只同步目标合同、ADR 与计划，未修改源码、数据库或现有命令，也未执行真实外部访问。
