# ADR 0038：Web 的定位与设计依据

- Status: Accepted（2026-10-23；Owner 同意设立，正文由负责产品设计的 Claude 起草）
- Date: 2026-10-23
- Supersedes in part: [ADR 0032](0032-library-centered-web-workspace.md) 中以 10-15 HTML 原型为布局与视觉依据的表述（背景第 3 段、第 2 节标题、“对既有决策的影响”中的视觉基准条），以及第 8 节第 1、2、5、7、10 条的页面级细节
- Related: [ADR 0033](0033-machine-interfaces-cover-web-capabilities.md)、[ADR 0036](0036-react-web-frontend.md)、[设计内核](../web/design-core.md)、[页面规格](../web/page-specs.md)

## 背景

1. 2026-10-15 Owner 确认了一份单文件 HTML 原型，ADR 0032 把它定为 Web 的布局与视觉依据。此后生产界面经过多轮修补，与原型逐渐脱节，但原型仍被多份文档称为“现行依据”。2026-10-23 Owner 指出原型早已过时，要求退役。
2. 页面级设计（侧栏分组、页面排布、视觉质感）陆续写进了 ADR 0032 的第 7、8 节，又在 Web 设计说明、design、technical、指南和计划中各复述一遍，版本互相矛盾。
3. 2026-10-23 Owner 明确产品分工：Web 是人管理和使用文献库的平台，CLI 和 MCP 是 Agent 的平台；并要求 Web 在设计上达到“优雅、有美感”的水准。

## 决定

### 1. 定位

Web 为**人**设计：浏览与整理文献、阅读与核对证据、审阅 Agent 和算子的结果、观看与控制运行。CLI 和 MCP 为 **Agent** 设计。两者的业务能力关系仍按 ADR 0033：机器接口覆盖 Web 的业务能力；Web 不必呈现全部维护命令。设计取舍时，Web 优先考虑人读得懂、看得清、少操作，不以“与 CLI 对等”为界面目标。

### 2. 设计依据分三层，全部与生产代码同源

| 层   | 内容                                                     | 位置                                   |
| ---- | -------------------------------------------------------- | -------------------------------------- |
| 规则 | 全站视觉与组织规则                                       | [设计内核](../web/design-core.md)      |
| 规则 | 信息架构与逐页排布                                       | [页面规格](../web/page-specs.md)       |
| 组件 | 每个共享组件的全部变体与状态                             | 应用内组件画廊                         |
| 页面 | 用真实服务端与合成样例库启动正式应用，按固定页面清单截图 | 设计样例库（启动与截图脚本随仓库维护） |

- 不再维护独立的 HTML 原型。需要比较尚不存在的页面或几个方向时，可以做临时静态样稿，只用于当次决定，定下后删除或归档。
- 页面级设计只写在设计内核与页面规格里，ADR 不再记录侧栏分组、页面排布、字号等细节。ADR 0032 第 7、8 节中仍有效的页面细节，以页面规格的现行版本为准。

### 3. 视觉改动以截图审阅

视觉或信息架构的改动，以设计样例库的截图交 Owner 审阅确认后才算定稿。截图中的数据是合成的，只说明界面，不代表真实数据或能力已经实现。

## 后果

- 设计样例库与截图脚本成为前端的一部分，随代码一起维护；其冒烟测试保证它不会悄悄失效。
- ADR 0032 保留库中心、Browser 直接交互、UI 状态与用户数据边界、第 7 节的业务行为（校订稿保存、Agent 原样记录等）和第 8 节第 3、4、6、8、9 条的产品决定；页面形态由页面规格负责。
- design、technical/01、Web 指南、`apps/web` 的说明不再复述页面排布，只链接页面规格。
- 10-15 原型文件已移出仓库现行目录，可从 Git 历史找回。

## 验证方向

- 设计内核、页面规格与组件画廊、样例库截图一致；
- 每次视觉改动都有对应的审阅截图与 Owner 确认记录（记在当次计划中）。
