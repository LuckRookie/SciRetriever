## 背景

解析全文之后，一篇文献是一块一块的文字：标题、段落、图注、列表、脚注，各有编号，并保留着章节结构。阅读页已有对照翻译，它也是一块一块翻的，译文与原文的块一一对应。

但这个翻译只是阅读页上的临时功能：

- 读者翻到哪一页才翻哪一页，要等；
- 译文只放在缓存里，最多留 50 篇，不进文献库；
- 不能导出，命令行和 Agent 用不到，也不能用译文的语言搜索全文。

块与结构都是现成的，缺的是在解析时整篇翻完、存下来、给各处使用。

## 决定

### 1. 译文是解析全文的一步

- 解析全文的步骤依次为：解析、整理、逐页校订、渲染、**翻译**、元数据、参考文献、标签。翻译排在校订之后，翻的是校订好的文字。
- 它不是另一个要使用者发起的操作，也没有开关：解析全文就包含翻译。解析全文的用量估算包含翻译这一步。
- 翻译失败不使解析全文失败：文献得到全文，没有译文，问题记进需处理，可以重试。
- 已经有全文、还没有译文的文献，再执行一次解析全文时只补上缺的这一步，不重做前面的步骤。

### 2. 翻什么，译成什么

- 文献库有一项“译文语言”，默认简体中文。全文已经是这种语言的文献不翻译。
- 逐块翻译，一块对一块，不合并、不拆分；块的编号、顺序与章节结构不变。
- 翻译正文、标题、图注、列表与脚注。公式原样保留；参考文献、作者与机构不翻译。表格的处理在规格里定。

### 3. 存进文献库

- 译文存进文献库，按文献、全文的版本、块与语言记录，并记下所用的模型与提示词版本。
- 译文属于它所依据的那一版全文。全文改动后，只重翻文字变了的块，其余沿用。
- 译文是机器写的，各处都这样标明。它不替代原文：引用、证据定位、批注与加工结果都以原文为准。

### 4. 阅读页：全文的三种读法

- 视图切换的“原文”改称“**全文**”，与“有全文”“解析全文”“全文检索”是同一个词。视图为“全文 · PDF”。
- 全文有三种读法：**原文**（作者写的语言）、**译文**、**对照**。对照是逐块上下排列，上面是原文，下面是译文。
- 读法的选择记在这个浏览器里。没有译文的文献只有“原文”，并说明译文在解析全文时产生。
- “原文”一词此后只表示作者写的那一种语言的文字。
- PDF 视图的对照翻译、划词翻译保留；对照翻译不再现场翻译。

### 5. 译文给各处用

- 导出：全文的 Markdown 可以导出原文、译文或双语三种。
- 检索：全文检索覆盖译文，使用者可以用译文的语言搜到原文是另一种语言的文献；命中回到对应的原文块。
- Agent：读取全文的接口（CLI、MCP）可以取原文、译文或对照。

## 还没有验证的前提

- 逐页分批翻译时，前后页的术语是否一致；不一致到什么程度，要不要按章节给上下文或维护术语表。
- 一篇文献翻译的花费与耗时，以及它使解析全文变慢多少。
- 公式密集的段落、表格与图注的翻译质量。
- 怎样判断“全文已经是译文语言”：按书目的语言字段，还是按文字检测。

## 还没有决定的事

- 分层阅读（概览、脉络等阅读层及其切换）另行设计与决定，见[计划 28 的 09 块](../../plans/2026-11-25-import-and-pdf/09-layered-reading.md)；各层是否也在解析全文时产生，在那里定。
- 一篇文献是否保存多种语言的译文。首版只有“译文语言”一种。

## 后果

- 库结构要加表，正式库执行时须经 Owner 同意。
- 解析全文的花费与耗时增加一步。
- ADR 0051 的全文译文缓存文件不再使用；划词翻译的缓存照旧。
- [阅读体验](../web/reading-experience.md)、[页面规格](../web/page-specs.md)、文档与存储的技术篇、建档指南与代理接口指南随实现更新。

## 考虑过但没有采用的方案

- **做成使用者另外发起的一步，或加一个开关。** Owner 的判断是解析时直接翻好；多一步或多一个开关，多数文献就不会有译文，对照、导出与检索都落空。
- **继续只放缓存。** 缓存会被清掉，译文不能导出、不能检索，Agent 也读不到。
- **翻译校订之前的文字。** 校订改了字，译文就要重翻。
