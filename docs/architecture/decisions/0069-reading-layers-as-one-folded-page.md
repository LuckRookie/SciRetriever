## 背景

ADR 0061 定了一份资料可以在概览、脉络、原文三个距离上读，并把概览与脉络归为知识加工的产出：使用者要另外发起一次加工，结果是一份报告和一张记录表。这一部分一直没有实现。

Owner 现在的判断是这个归类错了。概览与脉络是读一篇文献的方式，和全文、译文是同一类东西；知识加工说的是从文献里炼出别的东西，例如跨篇的综合、主题页、实体与关系。归错了类带来两个后果：多数文献不会有人去另外发起一次加工，于是多数文献没有这两层；概览与脉络成了另外两份文档，与全文之间只能靠链接来回跳。

同时 Owner 要求学习 TextFold 在层与层之间切换的做法。四版样稿试下来的结论是：让留下来的字滑到新位置的做法，半途必然有文字互相压住；把三层看成同一页纸折到三种程度，只让行在竖直方向合拢与展开，任何半途都是干净的，也和阅读页“案头的文稿”的样子一致。

## 决定

### 1. 概览与脉络是阅读层，属于这篇文献的全文

- 概览与脉络是一篇文献的两种读法，与全文、译文同属文献的阅读内容。它们不是知识加工的产出，不经过知识加工的运行、估算与结果页。
- 一篇文献有三层：**概览、脉络、全文**。不设第四层。
- 三层不是三份文档，是同一份全文显示出多少：脉络是折去一部分行的全文，概览是折得更紧的脉络。所以任何一层上的任何一处，在全文里都有确定的位置。
- 跨篇的综合、主题页、实体与关系仍属于知识加工。阅读页上的“库内关联”只显示它们的结果。

### 2. 随解析全文产生

- 解析全文的步骤依次为：解析、整理、逐页校订、渲染、翻译、**分层**、元数据、参考文献、标签。分层排在翻译之后，因为各层的译文读法要用到库里的译文。
- 它不是另一个要使用者发起的操作，也没有开关：解析全文就包含分层。解析全文的用量估算包含这一步。解析全文本身由使用者明确发起、事先估算，所以花钱的操作仍然是使用者明确发起的。
- 分层失败不使解析全文失败：文献得到全文与译文，没有概览与脉络，问题记进需处理，可以重试。
- 已经有全文、还没有分层的文献，再执行一次解析全文时只补上缺的这一步。
- 没有分层的文献只有“全文”与“PDF”。页面说明概览与脉络在解析全文时产生，不提示另外发起加工。
- 发起时不附使用者的说明。提示词只有固定的核心与模型为这份资料自拟的阅读提示两层；按类型的提示仍只作有证据的补丁。
- 用量的估算，没有实测：按正式库的历史用量，一篇十页的文献现有步骤（不含翻译）约 23 万输入、2.4 万输出 token。分层估计每篇两次调用，合计约 2.5 万输入、6 千输出 token，即输入多一成左右、输出多两成半左右。

### 3. 各层写什么，谁的话

| 层   | 机器写的                                                           | 作者的                                             |
| ---- | ------------------------------------------------------------------ | -------------------------------------------------- |
| 概览 | 提要三项：这是一份什么资料、局限与未决事项、精读建议；纲目里的要点 | 题名；纲目里的章节标题                             |
| 脉络 | 要点，每个一句                                                     | 章节标题；每个要点下面的依据，是全文里的原句或图表 |
| 全文 | 没有                                                               | 全部                                               |

- **要点**按全文的顺序排，挂在作者自己的章节标题下。资料没有章节标题时不分组。
- **依据**只有两类：全文里的原句，全文里的图或表。依据不是另抄一遍的引文，而是全文里的那几行本身：在脉络里它们保持全文的排版，同样的行宽、断行与位置。
- **概览的纲目**就是这篇文献的思维导图：左边是章节，右边是这一章的要点，中间一道括线。它是脉络把依据也折进去之后剩下的东西，不另写内容，也不另设一种放射状的图。
- **提要**的“这是一份什么资料”同时是模型自拟的阅读提示。提要的每一项指向它所依据的段落。资料没有给出的内容写“原文未给出”。
- 一种格式通用于各类资料，栏目名不随资料的类型改变。
- **核对。** 每条依据由程序确认它在全文里的位置。确认不了的依据不进入结果；没有依据的要点不进入结果。丢掉了多少记录在案；剩下的要点太少时这一步算失败。读者在页面上看到的每一条依据都是全文里真实存在的原句。
- 字体与颜色沿用 ADR 0061 第 4 节：作者的话用衬线体，机器的话用无衬线体。

### 4. 层与层之间：折

- 换层是把同一页纸折起或展开。不要的行折进去，留下的行原样靠拢。页面上没有文字横向移动。
- 层的位置是一个连续的值，由手势直接决定画面：可以停在半途，可以往回，停手后落到较近的一层。
- 指针所在的那一行在换层前后停在屏幕上的同一高度。
- 可以只展开一处：在脉络里只把一组依据展开成全文，在概览里只展开一个要点的依据；其余保持当前层。
- 折去文字的地方留一道折痕，写明折去了多少行。
- 视图切换为“概览 · 脉络 · 全文”加“PDF”。换层的手势与键位在阅读体验规格里定；调字号的手势不变。
- 使用者选择减少动效时直接换层。
- 书的痕迹只用在结构上：依据左边的界行、折痕、纲目的括线、页眉里层名前的鱼尾记号。不用印章、仿毛笔字、纸纹与朱色。

### 5. 重点词

- 每个要点有至多两个重点词，提要的每一项同样。重点词在要点里、在依据的原句里用同一种颜色标出，这种颜色一直跟到全文。可以关掉。
- 重点词不写在要点的文字里。模型在写要点的同一次调用里，为每个要点另外给出一个词表；每个词必须在要点的句子里逐字出现。
- 程序核对：在要点里找不到的词丢掉，要点本身不受影响。依据里哪些字着色由程序逐字匹配得出，不由模型标。
- 库里只存词表。标在哪几个字上，在显示时计算。

### 6. 各层的译文

- ADR 0068 的三种读法对三层都起作用：原文、译文、对照。
- 机器写的要点与提要有两种语言的版本：文献自己的语言，和文献库的译文语言。两个版本在分层这一步里一起产生。全文已经是译文语言的文献只有一种。
- 依据的译文取自库里已有的全文译文，不另翻一遍。程序确认依据对应译文里的哪一句；确认不了时显示这一段的整段译文。
- 重点词在译文里的对应词，在产生要点的译文时一并给出，在译文的句子里逐字找得到才用。
- 各层的译文同样标明是机器翻译。引用与证据定位一律以原文为准。

### 7. 颜色

- 分层阅读里有四种文字：要点、依据、依据所在行里不属于依据的前后文字、重点词。每一种是一个有名字的颜色角色，每个阅读主题各自取值。
- 这四种文字对背景的对比度都不低于 4.5。不用降低不透明度的办法做出“淡”。
- 重点词的颜色不用笔色（那是读者自己的笔迹），不用警示色。不靠颜色的主题里，重点词用下划线表示。

### 8. 存放与给各处用

- 概览与脉络存进文献库，属于它们所依据的那一版全文，并记下所用的模型与提示词版本。全文改动后旧的分层标为过时，不当作当前的显示，重新解析全文时重新产生。
- 批注与证据标记在三层上都保留（ADR 0061 第 5 节第 12 条）。查找能找到当前层折去的文字，并把那一处展开。
- Agent 按同样的三层取用一份资料：先取概览，再取脉络，需要时取全文。它们经读取全文的接口（CLI、HTTP、MCP）取得，只读已有的内容，不触发任何加工。没有分层时如实返回。
- 概览与脉络可以随全文导出。

## 还没有验证的前提

- 模型能否在不同学科、不同类型的资料上找对要点与依据的对应。找错了比不做更糟。样稿用的那一篇是手工准备的，不是程序产生的。
- 模型挑的重点词好不好，会不会总挑同一个大词。样稿里的词是手工挑的。
- 依据与译文句子的对应，程序能确认的比例有多高。
- 分层这一步的花费与耗时；第 2 节的数字是估算。
- 折的动画在真实的长页面上是否流畅。样稿在手势过程中有个别帧超过 4 毫秒。
- 批注在脉络与概览里怎样显示、查找怎样展开折去的文字，样稿没有做。

## 还没有决定的事

- **长资料。** ADR 0055 的长文档没有逐页校订，篇幅也放不进一次调用。它们怎样分章处理、纲目怎样排，没有设计也没有样稿。首版不给长文档做分层，它们只有全文与 PDF；另行设计后再定。
- **按问题阅读。** 它也是阅读，但依赖问答，体量不小。倾向于在分层阅读之后另立一块，不在本决定里。
- 使用者能否对一篇文献附一句说明、重新产生它的分层。

## 后果

- 库结构要加表，正式库执行时须经 Owner 同意。
- 解析全文的花费与耗时再增加一步。
- 知识加工的规格里“阅读层”一节（内置规范 `key-points`、汇总的两种概览模式、命名组合 `reading-layers`）撤销；[知识加工提案](../../proposals/2026-11-16-knowledge-processing/README.md)里的 `14-reading-layers.md` 与 `reader-13`、`reader-14`、`reader-17` 不再按原样实现，其中仍然适用的内容改写进文档与证据、阅读体验两份规格。
- [文档与证据](../technical/04-document-evidence.md)、[阅读体验](../web/reading-experience.md)、[页面规格](../web/page-specs.md)、[设计内核](../web/design-core.md)、建档指南与代理接口指南随实现更新。
- 对使用者的承诺与 ADR 0061 相同：每一条依据都查得到出处；不承诺任何资料都整理得恰到好处。

## 考虑过但没有采用的方案

| 方案                                     | 没有采用的原因                                                                                 |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------- |
| 仍作为知识加工，由使用者另外发起         | 多数文献不会有人另外发起，于是没有这两层；结果是另外两份文档，与全文之间只能靠链接来回         |
| 留下来的字滑到新位置（第一版样稿）       | 字在页面上横着走，半途必然互相压住                                                             |
| 放射状的思维导图                         | 与书无关；叶子要另写短标签；从导图到脉络没有字可以对应                                         |
| 第四层“只留关键句”                       | 读起来像残缺的全文，与脉络显示的是同一批句子                                                   |
| 让模型在要点的文字里用某种格式标出重点词 | 标记混进文字，复制、检索、翻译、引用都要先清掉；标错一处只能整句重写；改规则要重新产生所有要点 |
| 不用模型，按词频统计挑重点词             | 挑出来的是术语，不是这个要点的关键；对不上译文                                                 |
| 核对不上的依据用警示色显示               | 分层随解析全文自动产生，没有人逐篇过目；依据又必须是全文里的行，对不上的无处可放               |
| 依据的译文另翻一遍                       | 同一句话在库里有两种译法；多花一次翻译                                                         |
| 用降低不透明度的办法显示依据前后的文字   | 第三版样稿这样做，对比度只有 1.6，看不清                                                       |
