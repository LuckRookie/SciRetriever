# ADR 0073：阅读层按段写：每一段一条批语，一节一次调用

  - TextFold 的做法（`textfold/ladder.py`、`links.py`、`translate.py`）：一节一次调用，给每一段写作用、要旨、理由、主题词与依据句，每节另写一句；页面始终是整篇文章，每一段在任何一层都还在原位；写法规则具体（写东西本身、不补事实、单独读得懂、数字带上它数的是什么）；译文语言的各层与译文一起直接用那种语言写；段与段的关系另做一次调用，只看全篇的要旨。

## 背景

阅读层的价值在于让人和 Agent 先读到全文的可靠压缩，再决定读哪里。“挑重点”的写法让压缩本身不完整：没被挑中的段落在脉络里不存在，读者看不出哪里被略过了；一次读完全篇也让长文的后半部分得到的注意更少。逐段写把“压缩”变成全文的一个缩放档：每一段都有它的一句话，作者的结构完整保留，重点由“主干”标出而不是由取舍体现。

## 决定

### 1. 单位是段

- 正文里每一个可读的段各有一条批语：段落、列表项、图注、表题。单位与全文译文的单元相同（[文档与证据 9.2](../technical/04-document-evidence.md#92-单元)），不含标题、作者行、参考文献、首页的文章信息。
- 不是一段文字的单元（只有一个标签或一个词、日期、地址），以及本身已经和一句批语一样短的段，没有批语，在各层原样出现。
- 每一段在脉络里都在，作者的章节结构完整保留。

### 2. 每一段写什么

模型为每一段写下面几样，都用这一版本的语言（第 5 节）：

| 项     | 写法                                                                                                                               | 用在哪里                               |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------- |
| 类别   | 七种之一：背景、问题、方法、结果、分析、结论、局限（与 ADR 0070 相同）                                                             | 页边、导图的“标出”                     |
| 批语   | 一句，写这一段确立的东西本身：结论、做法、数值或发现，结论在前，像标题一样紧。中日韩文不超过 40 字，其他语言不超过 20 个词         | 全文页边、脉络、概览                   |
| 理由   | 一句，接着批语写它的主要理由、机制、条件或后果，不重述批语。只有一句的短段可以没有                                                 | 脉络                                   |
| 题     | 段的主题，一个名词短语，从批语里原样截出；中日韩文不超过 8 字，其他语言不超过 3 个词                                               | 导图、页边的小字                       |
| 依据   | 这一段里最能支撑批语的 1 到 2 句原句的句号（段有 7 句以上时可到 3 句），按顺序；优先陈述结果、定义或决定的句子，不选只作铺垫的句子 | 全文里压朱笔的句子、脉络里批语下的原句 |
| 重点词 | 0 到 2 个，从批语里原样截出，取这一段特有的发现、量、对象或方法                                                                    | 朱色加粗                               |
| 见     | 这一段谈到的这一节里的图表（`fN`），0 到 3 件                                                                                      | 页边与脉络里的图                       |

写法的规则写进提示词：

- 写东西本身，不写活动：不写“本段介绍了……”“作者讨论了……”。用作者自己的术语。
- 不补这一段没有的事实：没有出现的名称、数值、年份一概不写。
- 每一句单独读得懂：不以“该”“此”“其”“上述”或 this、these、it 开头，重说那个东西的名字。
- 这一段依赖的数字都留着，各带上它数的是什么、在什么条件下。
- 理由写机制或后果，不写出处（不写“由 X 支持”“如 Y 所示”），除非出处本身就是发现。
- 公式照原样抄 `$…$`；不写引文号；图表编号只在图注自己里写。
- 依次只读批语，应当能跟上全文的论证。

### 3. 每一节一句，全篇一次

- **节旨**：每一节写一句“这一节在全文里确立了什么”（不是“这一节讲了什么”），和一个题。没有章节标题的文献整篇算一节。
- **全篇的东西**在各节写完之后另做一次调用，模型只看题名、摘要、各节的节旨与各段的批语，不再读全文：
  - 提要：两三句，研究对象、做法、结论。
  - 主干：全篇的主干是哪 3 到 5 段。主干是“标出”，不是“挑选”：其余各段照样有批语。
  - 段与段的关系：承接、依据、解释、总结、引申自，每段至多 3 条，指向别的段。
  - 数据：至多若干个关键数值，各带出处的段或表；数字在出处里逐字找得到。
  - 局限：只写作者自己写出的局限与未决之处，不写模型的推断。
  - 精读建议：哪几节或哪几件图表值得细读，为什么。

### 4. 怎样请求模型

- 一节一次调用。给模型：题名、摘要（作背景）、全文的目录并标出这一节、这一节的各段（每句前写句号）、这一节的图表与图注。节太长时分成几份，每份至多若干段，各份并行；这一节的节旨另用一次调用从它各段的批语写出。
- 各节并行，与其他步骤共用全进程的模型名额，不另加名额。全篇的那一次在各节之后。
- 用量大约是现在的两到三倍（输入是全文一遍加上各节的背景，输出是每段两句）。确认对话框里的用量估算照常按页给出。

### 5. 各语言的版本都直接写

- 文献自己语言的版本，由第 4 节的调用写出。
- 译文语言的版本也逐节直接写，不再从原文语言的版本翻过去：给模型这一节各段在库里的译文（每句前写句号）、原文语言版本里各段选作依据的原句，让它用译文语言写同样的几样，依据写成译文里对应那几句的句号。全篇的那一次同样各写一份。
- 两个版本的段一一对应、类别相同；依据在两个版本里指的是同一处原文。
- 全文已经是译文语言的文献只有一个版本。

### 6. 视图里显示什么

- **全文**：每一段的页边是它的批语：开头是类别，下面是批语，再下面一行淡墨小字写关系（“承接 ¶41”“见 图 3”）。主干段的批语前有一个实心的朱圈。被批的依据句旁照旧压朱笔。批语的编号就是段号：段号在左页边，句末不再另标带圈的批号。
- **脉络**：每节先排节旨（楷体墨字），再排这一节每一段：批语（楷体墨字大字）与理由（同一段接着写，淡墨），下面低两格是它的依据句（宋体），段号在左页边；它谈到的图在页边（3.3）。主干段的段号用实心圈。没有批语的段原样排出。点依据句或批语，原地展开成整段（阅读体验 3.3.5）。
- **概览**：提要；各节的节旨作纲，每节下面是这一节的主干段批语，各带所据的一句；数据；局限；精读建议。
- **导图**：题名，各节（节旨的题），各段（段的题），主干突出；按类别标出、收起一节、指针停在一段上右栏显示它的批语与依据，与现在相同。
- 凡例相应改写：去掉“批语的编号”一条，改为“实心圈是全篇主干”。

### 7. 核对，不改写

程序核对模型的回答，不改写它写的文字：段号与句号存在、依据连续；题与重点词在批语里逐字找得到；长度在限度内；数据的数字在出处里逐字找得到；关系指向存在的段。不过的那一项丢掉、记入 `dropped`，其余照存。一节的回答整个不合格时，这一节再请求一次；仍不合格的，这一节的段没有批语，步骤记为部分完成。

### 8. 存放与版本

- 阅读层文件的版本升为 3，提示词版本为 `reading-layers-v3` 与 `reading-layers-translation-v3`。版本 2 的文件按[文档与证据 10.6](../technical/04-document-evidence.md#106-全文改动之后) 算过时，阅读页按“没有当前的阅读层”处理。
- 已有的文献要重做阅读层这一步才有新的内容；这要调用模型，按建档的授权进行。

## 还没有验证的前提

- 全文页边每段一条批语会不会太密。宽屏上页边与段落对齐、逐段排下，窄屏上落到段落下面；需要在真实文献上看。
- 逐段写出的批语会不会千篇一律、只是把段落缩短。TextFold 的经验是写法规则越具体越好，需要在几篇真实文献上比较。
- 每节分开写时，跨节的论证是否还连得起来。全篇的那一次只看批语来找关系与主干，需要验证够不够。
- 用量的“两到三倍”是估计，需要按真实文献的页数与段数实测。

## 还没有决定的事

- 长文档（结构里有 `long_document`）现在不做阅读层；逐段写以后是否可以做，做的话分多少份。
- 全文页边的批语是否可以只显示主干、其余收起，由读者选择。

## 后果

- 阅读层的生成、核对、存放与读取按新的单位重写：服务端的 `layers` 一步与它的提示词、合同包里阅读层的结构、阅读页的四个视图与凡例。
- 技术篇“文档与证据”第 10 节与阅读体验第 3 节按本决定改写；ADR 0069、0070 的原文不改，由本决定修订。
- 已有的阅读层在重做之前不再显示。

## 考虑过但没有采用的方案

| 方案                                               | 不采用的原因                                                                                                         |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 结构不动，只把 TextFold 的写法规则补进现在的提示词 | “挑重点”带来的空白只能缓解，去不掉；没被挑中的段在脉络里仍然不存在                                                   |
| 全文翻译与阅读层合成一次调用（TextFold 的做法）    | 我们已有独立的翻译一步与它的缓存、沿用与重试；合并要重做翻译一步。译文语言的阅读层改为看着库里的译文直接写，效果相同 |
| 只写译文语言一个版本                               | 原文读法需要文献自己语言的批语；Agent 读取时也要两种都有                                                             |
