# ADR 0027：通用提取能力与调用方定义的记录

- Status: Accepted（提取模块及责任边界；具体接口与执行方式仍待设计）
- Date: 2026-09-26
- Amends: [ADR 0001](0001-sciretriever-scope-and-boundary.md)、[ADR 0026](0026-agent-knowledge-and-human-collaboration.md)
- Related: [产品需求 R13](../requirements.md#r13-通用提取能力与调用方定义的记录)、[知识加工：调用方规范与提取交付](../technical/05-knowledge-processing.md#4-调用方规范与提取交付)、[统一产品接口：共享合同、结构解析与版本兼容](../technical/01-product-interface.md#6-共享合同结构解析与版本兼容)

## 需求与决定依据

Owner 同意支持文献中的批量结构化数据提取，并明确：一条记录的业务含义由定义提取内容的调用方决定；领域与算法无法由项目穷尽，项目应提供功能接口，让外部 Agent 或程序实施各自的提取。最终研究数据集、领域判断和机器学习仍归下游。

本决定确认 Extraction 的逻辑责任，不接受某个字段清单、统一实验实体、插件执行机制或模型提取算法。先前从需求重新推导的部署、任务存续和身份模型备选方案，也不因本决定自动成为 Accepted 实现合同。

## 2026-10-18 修订

按 [ADR 0034](0034-unified-processors-and-results.md)，平台提供可替换的默认记录提取处理器与独立长期结果托管；外部策略继续可用。以下关于内部提取器和持久形式尚未确定的表述由 ADR 0034 的精简范围收口，科学含义、领域规范、原始材料与事实所有权等不变量保留。实施状态由源码和验收说明。

## 决策

### 1. 通用能力与提取策略分别拥有

SciRetriever 提供材料准备、结构化与有界读取、局部检索、资源访问、证据定位，以及提取结果的中性交换、通用校验和交付能力。Extraction 与通用 Analysis 分别表达结构化候选记录和解释/压缩知识，共享材料与证据基础；提取不依赖总结完成。

调用方定义记录含义、输出结构、字段解释、适用范围和领域规则，并选择如何读取与提取。外部 Agent、规则程序、领域模型等可以通过同一能力接口工作；项目不内建覆盖所有领域的算法，也不将某种内部模型策略作为唯一入口。

接口背后必须有实际材料读取、证据校验和结果交付能力。不能只留空接口，让每个下游重复实现 PDF/解析协议、文件路径、版本与证据基础。

### 2. 统一交付边界，不统一领域记录

通用合同需要表达规范版本、材料输入、候选记录、字段或记录关系的证据、覆盖与失败，以及生产者和方法来源。具体记录字段、嵌套结构、跨文献组合和业务唯一键由调用方的规范决定。

记录交付 ID 只用于引用、版本与重复提交控制，不代替领域实体身份；平台不推断一篇论文只能对应一条记录，也不据论文 ID 自动合并业务记录。

结构合法、证据可解析、执行完成和领域接纳是不同结论。平台承担通用完整性验证；科学含义、物理合理性、记录去重和最终数据集接纳属于调用方。未处理材料不能被描述为原文未报告，零记录不能掩盖提取失败。

### 3. 结果归属与文献事实分离

领域 schema 由调用方定义和维护。依规范交付的 payload 属于明确提取任务的候选产物，不成为 Literature 固定字段、来源 observation 或权威科学事实。结果可交给下游管理；若由本系统托管，须使用独立的产物合同、版本、依赖和保留规则，具体持久化形式待设计。

这项修订允许领域中立的平台承载调用方定义的提取交换，不把领域数据集建设、特征工程、模型训练或通用领域数据库纳入文献主库责任。不能以任意 JSON 字段绕过对象与写入所有权设计。

### 4. 可替换执行方式

优先设计外部提取器能够组合的能力接口。受 schema 约束的内部 LLM 提取器可以作为后续默认策略建议，但其必要性、接口及运行位置尚未确定。不得将任意上传脚本、自动安装插件或通用 prompt 执行平台作为本决定的默认实现。

外部生产者声明的方法和 usage 与本系统实际观测到的执行信息分别记录，不能把未观测执行冒充已验证 provenance。通用能力不会自动授予外部提取器数据库写入、凭据或任意浏览器控制权限。

## 契约设计与验证

完整协作场景见[工作流](../knowledge-service-workflows.md)，与当前代码的差异见[演进对照](../evolution-map.md)。具体字段、schema 方言、传输、批量提交和失败协议见提取技术文档中的建议范围；跨模块输入/输出、所有权、错误、副作用及版本问题集中在模块契约草案。草案没有自动冻结为已接受 API。

后续需要用不同形状的合成记录验证：换领域只改变调用方规范与策略；直接材料读取不要求内部模型；记录可引用多个材料；过期引用、结构错误、重复提交、部分覆盖与取消有明确结果；领域接纳不会被格式验证替代。生产源码、用户数据与真实外部服务未因本 ADR 改变。
