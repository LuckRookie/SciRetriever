# ADR 0058：文献库的导入系统，以及 Agent 怎样接入文献库

类型：决策（ADR）
负责：文献库的对外地址与设备连接；与来源无关的导入模型、导入会话和来源适配器；给 Agent 用的 skill 与 HTTP 版 MCP
状态：Proposed（2026-11-10，待 Owner 接受）

- Date: 2026-11-10

  > 我觉得就是给出一个zotero的信息+PDF位置，然后通过URL批量导入坐不到吗？

  > zotero一直都是外部的文献库，我们要做我们自己的文献库，肯定不可能和他依赖过深，适配zotero只是因为他比较的泛用，用的人多，还有其他软件呢，比如说endnote，其实我们也可以适配，所以这不是一个小模块，而是一整个的导入系统的设计。

  > 可以去除64MB的上限，除非去除有一定的风险

## 背景

ADR 0057 把导入设计成一个 Zotero 模块：服务端去读 Zotero 的本地 API 或网络 API，设置页有 Zotero 分区，catalog 里保存 Zotero 编号。Owner 审视后指出三点：

- **文献库常常不在用户的电脑上。** Owner 的文献库跑在集群服务器上，通过端口映射在本机浏览器里打开 `http://localhost:4174`。Zotero 和它的 PDF 在 Owner 自己的电脑上（下称“桌面”），服务器读不到。
- **Zotero 只是外部来源之一。** 文献库是自己的产品，不应依赖某个外部工具；以后还要适配 EndNote 等。要设计的是一套导入系统，Zotero 是第一个适配的来源。
- **搬运的活交给 Agent。** 桌面上的 Agent 能读本机的 Zotero 和文件，也能发 HTTP 请求。导入不应要求在桌面安装额外的运行环境。

现状：

- 导入书目只支持 BibTeX/BibLaTeX、RIS、CSL JSON 文件，没有预览，带不进 PDF 和分组。
- 上传 PDF 一次一篇，文件整个读进内存，所以网页、CLI、MCP 三个入口都限 16 MB。
- MCP 只有 stdio 一种方式，要在装有本仓库的机器上启动；桌面上的 Agent 用不上。
- 仓库里还没有 skill。ADR 0019 已经定了它的边界：skill 只讲怎样使用和工作流程，不是权威接口。

## 决定

### 1. 文献库只有一个地址

- 文献库对外只有一个地址，就是用户在浏览器里打开 Web 工作台用的地址。浏览器扩展、桌面上的 Agent 和脚本都只连这个地址。文献库在本机还是在远程，对它们没有区别。
- 远程时，由用户自己让这个地址在桌面上可达，例如端口映射（`ssh -L 4174:localhost:4174 <服务器>`）、局域网或 VPN。本系统不建隧道，也不自动发现服务。
- 客户端里设置的是完整地址（协议、主机、端口），默认 `http://localhost:4174`。地址规则与服务现有规则相同：`localhost` 或 IPv4 地址，加明确端口。域名与 HTTPS 另议。
- 连不上时，提示里写明所连的地址，并提醒用户检查端口映射是否开着。
- 与 ADR 0035 一样，HTTP 不加密，只在可信网络或隧道内使用。

### 2. 设备连接：连接码与令牌

本节取代 ADR 0057 第 6 节。

- 用户在 Web 设置页“设备连接”分区点“连接浏览器扩展”或“连接 Agent”。页面取自己的地址，生成一串**连接码**，包含：
  - 文献库地址；
  - 一次性配对码：随机生成，10 分钟内有效，只能用一次。
- 客户端用连接码向其中的地址换取长期**令牌**，并记住这个地址。换令牌的接口有次数限制。
- 每个设备连接有名称、用途、创建时间和最近使用时间。服务端只保存令牌的派生值。设置页列出全部连接，可以随时撤销。
- 用途决定令牌能做什么，生成连接码时勾选：

  | 用途 | 能做什么                                                             | 默认给谁   |
  | ---- | -------------------------------------------------------------------- | ---------- |
  | 收藏 | ADR 0057 第 5 节的收藏：查询文献状态、列出文件夹、保存书目、上传 PDF | 浏览器扩展 |
  | 导入 | 第 4 节的导入会话：只新增，不删除、不替换已有内容                    | Agent      |
  | 读取 | 第 8 节 HTTP 版 MCP 的只读工具                                       | Agent      |
  | 操作 | 第 8 节 HTTP 版 MCP 的操作工具                                       | 不默认勾选 |

- 令牌只放在请求头里，不放进地址或查询串。凭令牌访问的接口不校验 Origin；其他接口照 ADR 0035 不变。
- 令牌不能登录 Web 工作台，不能读写配置和凭据，也不能管理设备连接。
- 桌面上不保存 Web 登录密码。令牌保存在只有本人可读的文件里，或扩展自己的存储里。
- 映射端口变了时，在客户端改地址即可，令牌不变；令牌被撤销后，要重新生成连接码。

### 3. 导入模型与来源适配器

- 文献库有自己的**导入模型**。一条导入记录包含：
  - 书目与标识；
  - 外部编号：来源系统、来源库、记录在来源里的编号；
  - 所属分组：有层级，带外部编号；
  - 作者关键词与用户标签；
  - 文件：在来源里的引用名（附件编号或相对路径）、文件名，以及来源给出的大小与哈希；
  - 批注。
- 导入模型按文献库能保存什么来定，不按外部工具有什么来定。存不下的内容只计数，写进预览和报告，不导入。
- 每种外部格式有一个**适配器**，放在服务端，把这种格式的原始数据转成导入记录。适配器不联网，不读文件，不写库。
- 首批适配器：
  - Zotero 接口 JSON（第 6 节）；
  - 现有的 BibTeX/BibLaTeX、RIS、CSL JSON，并入同一套导入会话。
- 以后适配 EndNote、Zotero RDF 等，只增加适配器，不改会话、界面和令牌。
- catalog 里不保存任何来源专用的表。外部编号对应是通用的：来源系统、来源库、对象种类（记录、分组、文件、批注）、外部编号，对应到文献库里的对象。

### 4. 导入会话

所有导入都经过导入会话，不论是 Agent 推送、脚本调用，还是在网页上传。对外是一组 HTTP 接口，用 `curl` 就能完成一次导入。

1. **建会话**：写明数据格式、来源库和范围说明。范围由客户端解释，例如整库、某个分组、指定的几条、某天之后添加的；服务端只记录。
2. **交数据**：把来源的原始数据发过来，可以分多次。每次带序号，重发同一序号就是替换。
3. **预览**：服务端解析并给出下列内容，不写库：
   - 新增多少篇、已在库多少篇、与已在库文献冲突多少篇；
   - 有多少个文件要上传；
   - 多少条批注能导入、多少条不能导入及原因；
   - 不导入的内容及数量。
4. **确认**：写库，形成入库批次（ADR 0052），书目先入库。确认时重新判定，结果以报告为准，预览只是估计。
5. **交文件**：服务端列出需要的文件，客户端逐个处理。
   - 文献还没有主 PDF：上传文件内容。
   - 文献已有主 PDF：只报文件的 sha256。相同就记为已有，不同就记为冲突，都不上传。
   - 服务端随时能列出还缺哪些文件。中断后，客户端照这份清单继续；重复上传不会重复入库。
6. **结束**：客户端声明结束，或文件全部到齐。报告按预览的分类写明实际结果，没交来的文件在报告里列出。

- 会话的状态：收集中、待确认、导入中、完成、已取消。
- 同一个来源库同时只能有一个进行中的会话。
- 没确认的会话 7 天后自动取消；“导入中”的会话 7 天没有新文件就自动结束。
- 暂存的原始数据在会话结束或取消时删除。
- 会话持久保存，服务重启或连接中断后能继续。Web 入库页实时显示进行中的会话，不论是谁发起的。
- 一次请求的大小和一个会话的记录条数有上限，具体数值归技术文档。
- **确认可以由 Agent 做**，令牌有“导入”用途即可。理由：
  - 预览不写库；
  - 导入只新增，已有主 PDF 不被替换；
  - 冲突只记录，不自动处理。

  用户想把关时，在网页上看同一个会话再确认；用户要求 Agent 等人确认时，Agent 就等。

- **没有单独的“同步”。** 对同一个来源库再导入一次就是同步：
  - 按外部编号对应，内容没变的记录跳过；
  - 内容有变化的形成新的来源记录；
  - 新增的记录补进来；
  - 在来源里删除的不同步删除。

  判断有没有变化用记录内容的哈希，不依赖来源的版本号。

### 5. 落库规则

- **书目与身份**：同 ADR 0057 第 3 节。作为用户来源记录保存，先按标识匹配已有文献；没有标识的按现有身份规则处理。
- **来源库的身份**：
  - 来源能给出全局唯一的库编号时，用它；
  - 给不出时，用设备连接的编号加来源里的本地编号。
- **分组**：
  - 导成文件夹，放在以来源库命名的根文件夹下，保持层级；一条记录在多个分组里，就进多个文件夹。
  - 文件夹按分组的外部编号对应，只建一次。再次导入只补成员，不跟着来源改名，也不动用户在文献库里的整理。
  - 同级重名时在名称后加序号；名称超过 128 个字符时截断。
- **文件**：
  - 取来源指定的首选文件作为主 PDF；其他文件首版不导入，只计数。
  - 验收按 ADR 0029：文件有效即可，标为“文章身份未验证”。
  - **不设大小上限。** 上传时边收边写盘，不整个读进内存。只保留两条技术保护：
    - 磁盘剩余空间不足时拒收；
    - 解析环节保留自己的大小限制，超限的文件能入库和阅读，解析时如实报告。
- **批注**：同 ADR 0057 第 3 节，只在主 PDF 与来源附件逐字节相同时导入。
- **只单向导入**，不写回来源（ADR 0057 第 4 节不变）。

### 6. Zotero 适配

- 输入格式是 Zotero 接口返回的 JSON。Zotero 本地 API 与网络 API 的格式相同，适配器不区分。
- 数据由客户端取得再交给会话，服务端不连 Zotero：
  - 通常由桌面上的 Agent 读本机的 Zotero 本地 API（`localhost:23119/api/`），PDF 按本地 API 给出的路径读取后上传；
  - 库只在 Zotero 网站上时，Agent 在桌面上用用户的只读 key 读网络 API，交来的数据格式相同。key 留在桌面，不交给文献库。
- 文件的引用名是 Zotero 的附件编号。
- 书目字段优先用 Zotero 转换出的 CSL JSON，经现有的 CSL JSON 规则落库。本地 API 是否提供 CSL JSON，以计划 20 的探测为准；没有时由适配器按 Zotero 字段映射。
- 标签、批注、不导入的内容，按 ADR 0057 第 3 节的规则。
- 不做：服务端读 Zotero、设置页的 Zotero 分区、保存 Zotero key。

### 7. Skill

- 按 ADR 0019，skill 只讲怎样使用，不是权威接口。接口的细节只有一份，由文献库在自己的地址上提供；skill 指向它，不重复抄写。
- skill 由文献库提供下载，内容与服务版本一致。它是一组 Markdown 文件，任何 Agent 都能读。
- 内容：
  - **连接**：用连接码换令牌、令牌存在哪、连不上怎么办。令牌不进对话，也不打印。
  - **导入**：会话的步骤；哪一步要先问用户；只导入用户指定的范围。
  - **各来源的取数办法**：怎样把数据从某个外部工具里拿出来。首版写 Zotero，以后加 EndNote 等。
  - **使用文献库**：怎样配置第 8 节的 MCP，以及常用的工作流程。
  - **失败与恢复**：重新读取当前状态再继续，不凭旧结果行动。
- 分工：skill 讲“怎样把数据从外部工具里取出来”，适配器管“怎样解读这种格式”。
- Web 设置页“连接 Agent”给出一段可以直接复制给 Agent 的话，包含连接码、skill 的下载地址和 MCP 地址。

### 8. HTTP 版 MCP

- 文献库在同一个地址上提供 MCP（Streamable HTTP），凭设备连接令牌访问。桌面上不需要安装任何东西。
- 它运行在服务进程内，与 stdio 版 MCP 用同一套工具和语义（ADR 0033），不形成第二套产品（ADR 0019）。
- 工具按令牌的用途给出：
  - **读取**：stdio 版只读模式的工具，例如查询文献库、读文献和全文、读任务与结果，另加读导入会话的状态与报告；
  - **操作**：stdio 版 `--maintenance` 模式的业务工具，例如发现、获取 PDF、提交加工、控制任务、整理文件夹。
- 首版不经 HTTP 版 MCP 提供：
  - 配置与凭据；
  - 设备连接管理；
  - 浏览器观看与控制。

  这些仍用 Web 登录，或服务器上的 CLI 与 stdio 版 MCP。

- 导入的数据和文件不经 MCP 传，走第 4 节的 HTTP 接口：文件经 MCP 要编码后经过模型的上下文，又慢又费。
- stdio 版 MCP 和 `--workbench-url` 的连接方式不变。

### 9. 界面

- 设置页的“设备连接”分区（取代 ADR 0057 的“浏览器扩展”分区）：
  - 连接浏览器扩展、连接 Agent，勾选用途；
  - 下载扩展安装包与 skill；
  - 已连接设备列表与撤销。
- 入库页的“导入”（现有“导入书目”并入）：
  - 上传导出文件，可以连同 PDF 文件夹；
  - 列出进行中和最近的会话，包括 Agent 发起的；
  - 会话页显示预览、进度、冲突与报告，并有确认和取消按钮。
- 网页不与 Zotero 通讯，设置页不设 Zotero 分区。

## 后果

- 交付顺序：
  1. 设备连接、导入会话及其 HTTP 接口、Zotero 适配器、现有书目格式并入、入库页“导入”、skill：书目、分组、PDF；
  2. HTTP 版 MCP；
  3. 浏览器扩展收藏；
  4. 批注导入；
  5. 其他来源的适配器，按需要做。
- catalog 升级要保存外部编号对应、导入会话和设备连接，取代 ADR 0057 设想的 Zotero 编号表与扩展配对令牌表。
- 现有的书目导入入口（Web、CLI、MCP）保留，内部改走导入会话。
- 设备连接令牌是第二种认证方式。“操作”用途的令牌能发起会联网、会花费的任务，所以不默认勾选。
- 大批量上传由客户端自己循环。Agent 逐个上传几千个文件会比较慢；需要时再提供可选的辅助脚本，它不是前提。
- 计划 20 按本决定重排。它的 01 探测仍然要做：Zotero 适配器要按本地 API 的真实格式来写。
- 规格写进[文献与材料技术文档](../technical/03-literature-materials.md)、[页面规格](../web/page-specs.md)的入库与设置部分、[Agent 接口指南](../../guides/agent-interface.md)。
- 不在本决定内：域名与 HTTPS 地址；一个客户端连多个文献库；定时同步；写回外部工具；Firefox 版扩展。
