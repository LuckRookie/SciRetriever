# ADR 0036：Web 前端采用 React 重建

类型：决策（ADR）
负责：Web 前端技术栈
状态：**Accepted**（2026-10-19）。

Owner 在讨论动效库与前端框架后明确表示：不考虑重写成本，推荐使用 React，并据此重写 Web 体验计划。本 ADR 记录这一技术选择及其约束。依赖版本、CSP 验证与体积数据由[前端依赖说明](../../notes/web-frontend-dependencies.md)维护；Owner 随后明确要求完成整份计划，并在可交互 React 版本中确认了控件 / Motion 手感及阅读方向；本技术选择据此生效。2026-10-19，Owner 又确认当前版本定稿（GB），授权检查通过后切换默认和删除旧前端；确认不替代完整功能对等与最终Full。随后 Owner 明确要求取消全部旧前端兼容处理、以新版为准；本 ADR 的第七、九条据此修订。

## 背景

[ADR 0032](0032-library-centered-web-workspace.md) 确定了以文献库为中心的 Web 与定稿原型。决策前的正式实现是原生 TypeScript 直接操作 DOM（`apps/web/src/workspace/`，约 7,000 行），由 esbuild 打包，没有使用前端框架。

2026-10-19 的两轮反馈与实测暴露了三类问题：

1. **状态与视图不一致**：迟到的响应覆盖了当前视图、选项高亮与内容不一致、快速切换后显示旧数据。这些缺陷反复出现，每次都要逐处手写取消和比对逻辑来修复。
2. **交互质量受限**：进出场动画、布局让位、可打断的动画、焦点归还、弹层定位都要自己实现；整段重建 HTML 的写法还会丢失焦点、滚动位置和动画。Owner 反馈“交互硬邦邦”、点击效果与成熟产品差距大。
3. **控件一致性缺乏载体**：同类控件在多处手写，样式和状态各不相同，例如 14 种圆角、3 套焦点样式、没有按下态。

这些问题都有成熟的通用解法，但大多以 React 生态为首要目标。项目代码主要由 AI 执行者编写，统一的声明式结构也更利于生成与审查。

## 决策

**一、框架**：Web 前端采用 **React 19 + TypeScript**。界面由状态声明式推导，业务状态在每个页面只保留一份。

**二、组件行为**：采用 **React Aria Components**（无样式）。它负责：
- 键盘交互、焦点管理与读屏语义；
- 按下状态（包括触摸与键盘）；
- 弹层定位与焦点圈定。

样式完全由 SciRetriever 自有的设计变量与 CSS 提供，六态通过组件暴露的数据属性表达。不引入 Floating UI 或其他定位库。

**三、动画**：采用 **Motion**。分工如下：
- CSS 负责：颜色、背景、按下缩放、焦点；
- Motion 负责：进出场、布局让位（FLIP）、选中指示滑动、可打断的弹簧动画。

约束：
- 业务状态先改变，动画只是装饰；
- 尊重“减少动效”设置；
- 不对宽、高、位置等布局属性做逐帧动画；
- 不引入其他动画库。

**四、数据与列表**：
- 服务端数据由 **TanStack Query** 统一负责请求取消、去重、缓存与按推送失效；
- 长列表使用 **TanStack Virtual**；
- 结果表使用 **TanStack Table**（无样式）。

页面代码不直接调用 `fetch`。

**五、样式与安全**：
- 使用自有 CSS 加设计变量（设计语言 v2，见 [Web 设计基准](../web/README.md)）；
- 不使用 Tailwind、CSS-in-JS 或带样式的组件库；
- **不放宽现有 CSP**：仍为 `script-src 'self'`、`style-src 'self'`，不允许运行时注入 `<style>` 或内联脚本。不满足这一点的依赖或用法不得采用。

**六、构建**：
- 开发与生产构建使用 **Vite**；
- 生产产物离线可用，由构建脚本放入服务端静态资源目录，不依赖 CDN 或外部字体；
- 所有依赖使用发布满两周的稳定版本，并由 lockfile 锁定。

**七、正式入口与界面状态**：
- 不引入路由库，正式入口使用 `/` 与当前 `view`、`query`、`sort`、`literature`、`reader` 参数；独立维护服务保留所需 `/query`；
- 删除 `/next` 路由、旧 `workspace` URL 别名以及旧偏好键的读取回退和一次迁移，静态资源使用 `/assets/`；
- 本机偏好只读写当前 React 命名空间。旧前端书签和旧主题、栏宽、筛选设置不再承诺延续；当前 React 界面的偏好继续有效；
- 服务端 API、读取与证据合同、认证（[ADR 0035](0035-authenticated-remote-web-access.md)）、CLI/MCP 能力关系（[ADR 0033](0033-machine-interfaces-cover-web-capabilities.md)）都不因本决定改变。

**八、阅读引擎**：PDF.js 渲染、Markdown 与 KaTeX 排版、续读传输保持为框架无关的模块，由 React 组件通过 ref 包装。React 不接管已渲染正文的 DOM。既有的阅读性能与资源释放口径不得退化。

**九、单一前端**：
- 迁移期曾并行开发，现已结束；Owner 已试用并确认 React 为唯一正式界面；
- 删除旧前端源码、样式、临时入口和界面偏好兼容层，不保留切换旧界面的模式；
- 业务能力逐项迁移验收；仅删除 Owner 明确撤销的前端兼容断言，不删除或弱化文献、证据、认证、持久化等业务合同断言。

## 未采用的方案

| 方案 | 不采用的原因 |
| --- | --- |
| 继续原生 DOM，自写控件、动画与请求取消模块 | 可以实现，但需要自行维护上述全部能力；状态一致性依赖人工纪律，既往缺陷说明代价较高 |
| Vue / Svelte | 都是可行的框架，Svelte 还内置过渡与 FLIP。但无样式可访问组件与 TanStack 系列在 React 上最成熟，AI 执行者对 React 也最熟悉 |
| Preact | 体积小、写法与 React 相同，但兼容性存在边界问题，生态库以 React 为准 |
| 基于 Web Components 的组件库（Shoelace / Web Awesome 等） | 自带视觉风格，与已确认的设计冲突；主题定制和 Shadow DOM 样式控制成本高 |
| GSAP | 功能强，但采用自有许可证而非 OSI 开源许可证，存在使用限制 |
| Tailwind / shadcn/ui | 风格已经确定，自有设计变量足以表达；引入后会产生第二套样式体系 |
| 路由库（React Router、TanStack Router） | 应用是单一工作区，状态参数已在 URL 中，少量自写 hook 即可，不值得为此引入依赖 |

## 影响与兼容性

**新增依赖**（具体版本见实施计划 02 的评估表）：
- 运行时：`react`、`react-dom`、`react-aria-components`（Apache-2.0）、`motion`、`@tanstack/react-query`、`@tanstack/react-virtual`、`@tanstack/react-table`（MIT）；
- 开发：`vite`、`@vitejs/plugin-react`、React 类型定义、`eslint-plugin-react-hooks`。

首屏 JS 体积会增加，预算由计划设定并在构建时检查；PDF.js、KaTeX 等按需加载。

**构建链变化**：
- `apps/web` 增加 JSX 与 Vite 配置；
- Quick 的格式、lint、类型检查覆盖 `.tsx`；
- 便携安装包体积变化，在实施记录中说明。

**迁移处置**：
- 并行开发阶段已经结束；当前仅维护 React 前端；
- 切换后删除旧前端源码、样式和只针对旧界面的测试；
- 引用旧静态资源名的服务端测试同步更新。

**不变的部分**：
- [ADR 0032](0032-library-centered-web-workspace.md) 的产品与布局决定不变，本 ADR 只决定其实现技术；
- 定稿原型 `prototype.html` 的字节不变；
- 查询、维护和样本预览入口保留并迁到同一React工程；各自继续使用既有传输、能力与认证边界，共享界面不会授予新权限。

**回退**：在删除旧前端之前，可以把默认入口切回旧界面。删除之后再回退，需要另立决定。

## 实施注记（2026-10-19）

React Aria的固定交互CSS已随包静态提供，所需上游补丁、Motion禁用的样式注入路径及许可证在依赖说明中记录，未放宽CSP。阅读保留框架无关引擎，原型字节不变；四主题、字体、组件与动效由G4/G5及本次整体定稿确认。

功能对等按54项旧测试及69条能力逐一映射；样本5项保留迁移，旧断言不因换框架删除。GB确认后，默认 `/` 已切换React；随后按 Owner 最新要求移除迁移期入口、旧 URL 别名与旧偏好兼容。旧渲染器与对应旧UI测试已按清单删除，共享引擎和原型保留。最终Full与离线安装结果见[归档验收记录](../../archive/2026-10-19-web-experience/README.md)，不能由Accepted状态推断已验收。
