# Web 页面规格

类型：规格（前端页面）
负责：信息架构、侧栏、页面模板与逐页排布
状态：现行

视觉规则见[设计内核](design-core.md)；当前已实现的操作见 [Web 指南](../../guides/web-workbench.md)。

## 整体信息架构

产品围绕一条主线组织：**找到文献 → 阅读与核对 → 在一批文献上运行算子 → 查看结果**，另有一组页面观看后台运行。

```
SciRetriever
搜索 ⌘K
资料
  文献库            35,177
    最近阅读             6
    需处理              12
    文件夹…
  快照
  词表
加工
  算子
  全文检索
  洞察
运行
  任务          2 进行中
  浏览器
────────
设置
```

| 侧栏分组 | 页面     | 在主线中的位置                                      |
| -------- | -------- | --------------------------------------------------- |
| 资料     | 文献库   | 找到文献、选择一批；下挂最近阅读、需处理与文件夹    |
|          | 快照     | 把一批文献及其版本固定下来，作为范围                |
|          | 词表     | 管理标签                                            |
| 加工     | 算子     | 运行算子、回看运行记录与结果                        |
|          | 全文检索 | 在已建档全文中找片段                                |
|          | 洞察     | 看分布与引用关系                                    |
| 运行     | 任务     | 后台任务的进度与失败；切换到“Agent 会话”看 DSH 会话 |
|          | 浏览器   | 观看与接管下载                                      |
| 底部     | 设置     |                                                     |

- “需处理”是需要人处理的建档问题，在文献库框架内显示；计数为 0 时显示为灰色。
- Agent 会话都由任务发起，因此并入任务页；任务项旁显示进行中的数量，没有进行中时不显示。
- 旧地址照常可用：`view=agent` 打开任务页的“Agent 会话”，`view=archive` 打开文献库的“需处理”。
- 阅读页不在侧栏：从任何文献标题打开，以顶部标签页的形式存在。
- 结果有两个入口：算子页按运行记录看，阅读页侧栏“信息”标签页里的“加工结果”按单篇看。
- 运行算子只有一种入口形式：四步对话框（范围 → 算子 → 规范 → 确认），可从文献库、阅读页、快照页、算子页打开；已有范围时跳过“范围”一步。
- 入库不在侧栏：文献库页头的“入库”按钮进入入库页。

## 页面模板

```
页标题  上下文数字                                   [主操作]
工具条（一行；必要时第二行放快速筛选）
内容
```

- 页头不放说明系统行为的句子；对用户有用的信息改为界面状态、按钮文案、字段旁的提示，或页面底部的页注。
- 上下文数字示例：文献库“35,177 篇”、快照“3 个”、任务“2 个进行中”、需处理“12 项”。
- 空状态：一句话加至多一个动作，例如快照为空时“还没有快照。在文献库筛选后，可以把结果生成快照。”
- 没有数据时隐藏分页与批量操作。

每页按“用户来做什么 → 要呈现的信息（按优先级）→ 排布”说明。

## 文献库

**用户来做什么**：找到文献，看清它的材料状态，选一批去做事。

**信息优先级**：

1. 文献行：标题、书目（作者 · _期刊_ · 年份）、标签、状态；
2. 当前检索与筛选：检索词、状态、已应用的筛选条件；
3. 结果数量：已显示 / 共几篇；
4. 批量操作。

**排布**：

```
文献库  35,177 篇                                              [＋ 入库]
┌ 工具条（吸顶）────────────────────────────────────────────────────┐
│ [搜索：标题、作者、期刊                ] [筛选·2▾] [最近入库▾] [用当前结果▾] │
│ 全部 · 已就绪 · 有 PDF · 建档中 · 建档失败 · 无法获取 · 仅元数据 · 更多状态▾ │
│ （有筛选条件时）年份 2020– ✕  期刊 ACS Catalysis ✕                      │
│ 全文已取得 9,812 / 总数 33,906，未取得 24,094（其中自动途径已试完 1,204） │
├ 表头（吸顶）：□ 全选已加载                     已显示 50 / 共 35,177 篇 ┤
│ 文献行 …                                                            │
└────────────────────────────────────────────────────────────────────┘
（勾选后浮出）已选 3 篇  [运行算子…] [建档] [加入文件夹…] [更多▾]      取消选择
```

- 整页一个滚动容器；标题随内容滚走，工具条与表头吸顶。
- 输入框、下拉框不带上方标签（保留无障碍名称）。“入库”是次按钮，勾选后浮出的“运行算子”是这页唯一的主按钮。
- “筛选”是一个菜单：展开或收起筛选条件、应用已保存的筛选、保存当前筛选、删除当前筛选。
  - 目标（尚未实现，[用户整理 9.1、9.6](../technical/09-user-organization.md#9-尚未实现)）：保存的筛选存在文献库里，菜单另有“用当前条件更新这项筛选”“导出筛选”；这个浏览器里还有未导入的旧筛选时，菜单末尾显示“导入这个浏览器里保存的筛选（n 项）”，导入后用一个对话框列出导入、改名、跳过与未导入的项及原因。条件里的文件夹已被删除的项，在菜单里以次级文字注明“文件夹已删除”。
- 快速筛选显示当前检索下的数量，计数为 0 的项不显示（当前选中的除外）；“已排除”收在“更多状态”里；默认显示全部状态，按最近入库排序。窄屏时快速筛选横向滑动。
- 全文取得情况（目标，尚未实现，[查询技术篇 2.1.8](../technical/06-retrieval-context.md#218-文献库计数与全文取得情况)）：表头上方一行次级文字，写当前范围的“全文已取得 n / 总数 m，未取得 k（其中自动途径已试完 j）”。数字按论文计，同一论文的几个版本只算一次，所以总数可以少于表头的篇数。范围与快速筛选的计数相同：随检索、筛选条件、文件夹、入库批次变化，不随当前选中的快速筛选变化。每个数字是链接，点了在当前范围上应用对应的筛选：已取得 → 有 PDF，未取得 → 仅元数据，已试完 → 无法获取，总数 → 全部。j 为 0 时括号整段不显示。范围为空时这一行不显示。
- 快速筛选的含义（目标，尚未实现）：“有 PDF”是有主 PDF 的文献，不论之后处于等待解析、建档中、建档失败、已就绪还是已排除；“仅元数据”是没有主 PDF 的文献，与“有 PDF”互补；“无法获取”仍是没有主 PDF 且自动途径已试完的文献。“已就绪”“建档中”“建档失败”照旧按状态，与“有 PDF”可以重叠。当前实现中“有 PDF”只是“有 PDF、尚未建档”这一种状态，“仅元数据”只是还没有 PDF 的状态。
- 文本等级与初稿（[查询技术篇 2.1.7](../technical/06-retrieval-context.md#217-目标接口尚未实现文本等级与选择校订范围的事实)，只看主 PDF）：“筛选”条件里有“文本等级”（全部 / 初稿 / 校订稿）、“初稿与文字层有差异”（不限 / 有 / 没有）、“含扫描页”（不限 / 有 / 没有），筛选条件标签写同样的名称与取值；排序菜单增加“初稿差异：多到少”“扫描页：多到少”。“被结果引用”“找不到的引用”两项筛选与排序在加工能读取初稿之前恒为 0，不出现。筛选结果可以经“用当前结果 → 建档”交给建档，对话框照常写明范围与篇数。
- 书目待补（目标，尚未实现，[文献与材料 8.4](../technical/03-literature-materials.md#84-书目待补目标尚未实现)）：“筛选”条件里有“书目待补”一项；带这个标记的文献行，在书目一行末尾用次要色标注“书目待补”。
- 文献行：第一行衬线标题，最多两行；第二行书目，作者超过 3 位显示“等”，中文期刊名不用斜体；第三行（有才显示）标签最多 3 个，多出显示 +N，没有标签时改用浅色字列出最多 3 个作者关键词，再没有就列主题词；右侧为非默认状态的徽标，已建档的长文档在状态下方以小字注明“长文档”，主 PDF 的默认文本是初稿时在同一位置注明“初稿”；排序为“初稿差异”或“扫描页”时，这行小字后接对应计数，例如“初稿 · 差异 12 段”“初稿 · 扫描 3 页”；悬停或聚焦时出现“预览”与“文献操作”菜单（运行算子、加入文件夹、获取 PDF、建档）；最小行高 56，上下内边距 12。
- 入库批次：侧栏“文献库”下有“最近入库”分区，列出最近 5 个入库批次和各自篇数，最后一行“全部入库记录”进入入库页。点批次即把文献库限定到这一批，页头标题为批次名；筛选条件里批次显示名称，不显示内部 ID。
- 范围内的词：有筛选条件时，筛选条件下方一块浅底区域按标签、作者关键词、主题词的顺序分行列出当前结果里最常见的词，各取前 8 个，带篇数，末尾“更多”展开到 30 个。每行名称后用浅色字写覆盖篇数，如“1,200 / 17,010 篇”。点一个词即加为筛选条件（标签取“任一”，作者关键词与主题词各自取“同时具有”），已选的词用荧光黄底。有标签的篇数达到结果的一半时，主题词一行只显示名称和“展开”。作者关键词对应某个标签时，词后带一个小标签记号；已选的作者关键词有对应标签而该标签未选时，这块末尾提示“‘词’对应标签‘名称’”，旁边按钮“改用标签筛选”，按下即去掉该关键词、加上该标签。三层都没有词时不显示这块。
- 获取 PDF 的范围：选择栏的“获取 PDF”和批次的“获取 PDF”都先打开对话框，对话框第一块写明范围：来历（勾选的 n 篇，或批次名与筛选条件）、处理多少篇、跳过多少篇及原因（已有 PDF、已标记无法获取、超出本次上限）。下面是“本次最多 N 篇”，超出时按文献库当前排序取前 N 篇，并写出排序名称。主按钮写“获取 n 篇”。选择了“全部 N 篇符合条件的文献”时按筛选条件整体提交，不受已加载行数限制，篇数来自服务端预览。
- 文件夹：侧栏“文献库”下展开为目录树（最近阅读、最近入库、需处理、文件夹），点文件夹即在本页按文件夹筛选；文件夹视图有“只看本层”开关与“移出文件夹”；文献行可拖到文件夹，文件夹可拖进别的文件夹。文件夹、最近阅读、需处理共用页头模板，标题即视图名。目标（尚未实现，[用户整理 9.6](../technical/09-user-organization.md#96-分组与筛选的导出)）：目录树“文件夹”一组的标题行有一个菜单，含“导出分组”，下载整棵文件夹树与成员的 JSON 文件。

### 连续选择与选择栏

**用户来做什么**：一次选中一批文献，给它们获取 PDF 或运行算子；选中的文献状态不一，系统替用户分好哪些能做什么。

**连续选择**

- 在勾选框一列按住拖动，经过的行连续选中；从已选的行开始拖动则连续取消。拖到列表上下边缘时自动滚动。
- Shift + 点击勾选框，选中上次点击的行到当前行之间的整段。
- 在未选中的行上按下并移动超过 4 px，拉出选框，经过的行被选中；按住 Shift、⌘ 或 Ctrl 时追加。已选中的行按下即拖起，可放到侧栏文件夹（计划 17 · P29、P30）。
- Esc 取消全部选择。“全选已加载”选满后，列表上方出现一行“选择全部 N 篇符合条件的文献”，可切换到服务端范围（批量获取 PDF 常用）。

**选择栏**

```
已选 8 篇   (无 PDF 3) (待建档 2) (已就绪 3)   [获取 PDF 3]  运行算子 3  建档 2  加入文件夹…  更多▾  取消选择
```

- 左侧写选中篇数，紧跟按状态的组成（无 PDF、待建档、已就绪、其他），每类一个小标签；点标签把选择缩小到这一类。
- 按钮写“对几篇生效”，数字就是实际会被处理的篇数，系统只处理满足前提的那部分：获取 PDF → 无 PDF 的；建档 → 有 PDF 未建档或建档失败的（建档先补解析）；运行算子 → 已就绪的。数字为 0 时按钮停用，悬停说明原因（例如“所选文献都已有 PDF”“所选文献没有待建档的；建档需要先有 PDF”）。
- “获取 PDF”是主按钮；运行算子、建档、加入文件夹为次按钮；核验文章身份、生成快照、导出书目收进“更多”。行菜单同样有获取 PDF、建档，不满足前提的一项停用并写明缺什么。
- 选择“全部 N 篇”时组成与数字来自服务端计数。
- 运行算子只对已就绪的文献运行，对话框写明篇数；其余文献不自动补齐材料。

## 阅读页

**用户来做什么**：读一份资料。先看概览，判断值不值得读；再看脉络，知道它说了什么、凭什么；需要时回到原文和 PDF 核对。在页边做批注，向这份资料提问，看它与库里其他资料的关联。

**区域**：

```
[导航] [标签页 …]           [概览 | 脉络 | 原文 | PDF] [向这份资料提问] [查找][Aa][侧栏][⋯]
────────────────────────────────────────────────────────────────────────────────────────
案头
     ┌ 纸页 ───────────────────────────────────────────┐ ▌    ┌ 右侧面板（默认收起）┐
     │ 页眉：出处                       视图 · 依据的文本 │ ▌    │ 信息 批注 关联 翻译  │
     │ 左页边 │ 正文栏                       │ 右页边   │ ▌书脊 │                      │
     └─────────────────────────────────────────────────┘ ▌    └──────────────────────┘
```

- **顶栏**：一行；导航按钮、按资料打开的标签页、四个视图、提问框、查找、排版、侧栏、更多。阅读页不显示侧栏导航。
- **案头与纸页**：阅读区是案头，中间一张白色纸页，分左页边、正文栏、右页边；纸页顶部是页眉。
- **书脊**：挂在纸页右边缘外的细条，是整份资料的缩略。
- **右侧面板**：信息、批注、关联、翻译四个标签页，默认收起。
- “更多”菜单的内容见[阅读体验 1.3](reading-experience.md#13-顶栏)。目标，尚未实现（计划 20 的 14 块）：“上传 PDF”改用入库的补 PDF 接口（[产品接口 2.4.2](../technical/01-product-interface.md#242-入库-http目标尚未实现)），没有大小上限，上传的文件归入当天的“补充文件”批次；入库页不再有“上传 PDF”标签页。
- 文本等级写在页眉右侧；初稿与长文档的说明文字在页眉下方。

各区域的尺寸、排版与标记、四个视图的内容、阅读位置、过渡与加载、验证，见[阅读体验](reading-experience.md)。

## 命令面板

- `⌘K` / `Ctrl+K` 或侧栏“搜索”打开；靠上居中的浮层，宽 640。
- 一个大输入框，无标签无按钮；实时显示前 8 条文献（标题、书目、状态）；空输入显示最近阅读的 8 篇。
- ↑↓ 选择，回车打开阅读，`⌘回车` 在文献库中查看全部；底部一行“在文献库中查看全部 N 条”。
- 复用文献库检索接口；输入停顿 150 ms 后请求，新请求中止仍未返回的上一个请求。

## 算子

**用户来做什么**：在一批文献上运行算子；回看运行记录，打开结果。

**排布**：

```
算子                                                         [运行算子]
[运行记录 | 算子与规范]
运行记录：
  [全部算子▾] [来源文献，或选择快照                ] ○ 只看过时
  全文总结 · 规范名  ● 已过时                          查看结果  运行过程
  快照或首篇来源 · 等 N 个输入 · 10/22 14:02 · 网页登录
  有结果 120  结果为空 6  读取不完整 2  未形成结果 1
算子与规范：
  内置算子（全文总结、记录提取、问答标注、多篇综合）各一块：做什么、读取范围、输出；
  已保存的规范列表；外部交付作为次级入口。
```

- 只有一级标签；运行记录的筛选为一行无标签工具条。来源只有一个输入框：输入文字按来源文献筛选，聚焦或输入时下拉列出匹配的快照，选中后按该快照筛选。
- 运行记录是一个列表，不用卡片：第一行为算子名与规范名，过时用徽标，当前版本不加标签；第二行为来源、时间、发起方；第三行为按篇计数，数字加重，未形成结果用失败色。“查看结果”“运行过程”为文字按钮。

**结果详情**：顶部“← 全部结果”、标题与一行说明；结果集合列表、字段表、分页与跨页选择、字段证据侧栏、确认后继续综合、按明确范围完整导出。字段取值在悬停或键盘聚焦约半秒后预览第一段原文（最多 6 行，注明 PDF 页码与原文处数），只读不可交互；点击仍打开证据侧栏核对全部来源。筛选工具条无标签；只有应用筛选后才显示筛选状态。六种核对状态在单元格内用同色小徽标；部分结果与未知值保留原义。

**四步对话框**：步骤条（范围 → 算子 → 规范 → 确认）；底部“上一步 / 下一步”，最后一步为“开始运行”。每一步高度相同，步骤条与底部按钮位置固定。确认页用定义表列出范围、算子、规范、输入与缺口，下面是复用与 token 预估。已有范围时步骤条只显示三步。提交以当次范围和规范为准，重复点击不重复建任务，失败保留草稿。

- 两张表：PDF 来源按获取顺序排列，来源名后用次要色写所在阶段；元数据来源按检索覆盖从高到低。
- PDF：尝试 = 进入该来源并实际发出请求的篇数（未启用、冷却中不计）；拿到 = 由该来源拿到 PDF 的篇数；比例条统一用强调色，不因比例低改成失败色——低比例可能是来源本身覆盖面窄。没拿到不等于错误：没有全文、未收录是正常结果。错误 = 请求本身失败的比例。

- 数字全部取自各任务的逐来源记录，与任务详情一致，不另算一套；历史任务没有逐来源记录的不计入，表头下注明统计起点一次。
- 窄屏：每个来源两行，第一行名称与阶段，第二行比例条（附“拿到 / 尝试”）与主要原因。

## 需处理

处理型清单。没有问题时只显示一句空状态；有问题时按可读原因分组，每行显示文献、步骤与是否影响就绪，操作放在行内，编辑在该行下方展开；勾选后才出现“确认已处理”。

## 设置

对象为配置，形态为“左侧分区导航 + 定义表”。

- 桌面：页内左侧为竖排分区导航（文献库位置、文献来源、模型、解析与 Browser、网络、设备连接、建档、凭据、运行状态、外观、高级），宽 180；窄屏改为页头下方的下拉菜单。
- 每个分区由若干节组成，每节为节标题、可选的一句说明和一张定义表：左列为名称加一句说明，右列为控件，能给出当前生效值时写在控件下方。
- 路径用等宽字体单行省略，旁边一个复制图标按钮。
- 保存按钮放在节标题右侧，只在这一节有未保存的改动时出现；数字框输入一个范围内的新值即算作改动，不必先离开输入框。切换分区保留草稿；离开设置页时提示是否放弃。
- Provider 与 Model 在“模型服务”节内逐条列出，下方有“添加”；角色绑定为单独一节。
- “文献来源”分区的排布见下面的“文献来源”一节。

### 错误的呈现

真实网络中的错误无法穷举，界面不对错误分类：凡请求失败一律显示为“错误”。只有三种用户能直接处理的情况单独写出名称：**未配置**、**凭据无效**（API Key / Token 被拒）、**无全文权限**（出版社认证通过但无订阅）。没拿到结果（无全文、未收录、0 条）是正常结果，不算错误。具体原因码只出现在“技术详情”里，供排查。

- 页面不写说明句。两个选源方式并排放在最上面；PDF 获取顺序按五级分栏，只列名称。
- “来源”是一张表，每个来源一行，每格只放一个符号或短语：
  - 用途四列：元数据分为主题检索、补全书目、引用关系三列（表头上方一个“元数据”分组标），加一列 PDF。● 在用，○ 能用但未启用（缺配置或自定义关掉），— 不提供；PDF 列的“线索”表示只提供 PDF 链接、交给直链阶段下载。自定义模式下，对应列的标记变成开关（元数据与 PDF 各自独立）。
  - 配置：缺什么（黄色，“缺联系邮箱”）、已配置了什么（“API Key 已配置”）、可选增强（灰色，“可加 API Key”）或“无需配置”；可展开的配置后带 ›。

- 测试做真实但最小的请求，只判断“能不能用”，不写入文献库：元数据来源对固定样本做一次查询；PDF 来源对固定样本请求一次 PDF 并只校验响应（不保存、不发布），出版社 API 区分“无全文权限”；Browser Agent 只检查运行时能否启动。测试结果保留到下一次测试或配置变更。CLI 的 `config test` 是另一组更保守的探测，PDF 来源不发请求，见[配置手册](../../guides/configuration.md)。

- 点一行展开它的配置：凭据只显示“已配置”与替换、清除，不回显值；参数如联系邮箱、Web of Science 产品与数据库、Sci-Hub 镜像；“保存”在展开区内，只保存这一个来源，保存后自动测试一次。无需配置的来源不可展开。来源凭据从“凭据”分区移到这里，“凭据”分区只留模型服务。
- **自动**：配置齐全的来源全部启用，包括无需配置的公开来源与 Sci-Hub 内置镜像。**自定义**：用途列变成开关；顺序仍按阶段，不提供拖动排序。
- 窄屏：表头保留名称与四个用途列；每行两行，第一行名称与用途标记，第二行配置与测试；获取顺序改为每级一行。
- 保存后由页头的“应用配置”生效，不需要在终端重启服务。

- 两节：“代理”与“走代理”，各自按上面的定义表规则保存。保存后由页头的“应用配置”生效。
- 代理地址只接受 `http://主机:端口`。认证展开后填用户名与密码；已配置时只显示“已配置”与替换、清除，不回显值。
- “测试代理”用已保存的地址，只检查代理能否连通，不弹确认框；结果写在按钮旁：“已连通 · 耗时”或“错误”，原因码放在技术详情里。
- “走代理”按文献来源、模型、解析服务、浏览器四行列出开关，默认全部不勾。文献来源一行列出全部来源，外加“DOI 解析”；模型一行列出已添加的 Provider。本机或局域网上的服务（本机 MinerU、本机模型服务）不列出，它们始终直连。
- 没有已保存的代理地址时，这一节只写一句“先填写并保存代理地址”；测试代理与认证同样要等地址保存后才可用。
- 其他分区只显示、不修改：“文献来源”表与“模型服务”节中，走代理的项在名称旁加灰色小字“经代理”；走代理的来源测试成功时写“可用 · 经代理”。代理连不上时，这些测试显示“错误”。

### 设备连接

**用户来做什么**：让浏览器扩展或自己电脑上的 Agent 连上文献库，看清连了哪些设备，不用了就撤销。决定见 [ADR 0058](../decisions/0058-import-system-and-agent-access.md)。

```
设备连接                                   [连接浏览器扩展]  [连接 Agent]
  名称              用途          连接于        最近使用       状态
  办公室笔记本 Agent  入库 · 读取    11-10 14:02   11-10 15:30   已连接   [改名] [撤销]
  Chrome 扩展        入库          11-10 14:10   —             待配对   [改名] [撤销]
  旧电脑             入库          11-02 09:12   11-03 18:40   已撤销
```

- 点“连接浏览器扩展”或“连接 Agent”打开对话框：名称（预填“浏览器扩展”或“Agent”）与用途。目标，尚未实现（计划 20 的 18 块）：用途三个勾选框：入库、读取、操作，各带一句说明（入库：收藏网页、从 Zotero 或文件入库，只能看到本设备发起的批次；读取：经 MCP 查询与阅读文献库；操作：经 MCP 发起获取、加工等任务）。扩展默认勾入库，Agent 默认勾入库与读取；“操作”从不默认勾选，说明里写明它能发起会联网、会花费的任务。至少勾一项才能生成。
- 生成后对话框换成交付页：
  - 连接码等宽显示，旁边“复制”；下面一行写剩余有效时间（“9 分 40 秒内有效，只能用一次”），每秒更新，到期后写“已过期，请重新生成”。
  - 连接 Agent 时另有一段“复制给 Agent 的话”：说明连接码的用法、令牌只存本人可读的文件、请求头带令牌，并指向文献库自带的使用说明；“复制”按钮在段落右上。
  - 关闭对话框后连接码不再显示，也不保存在页面以外的任何地方；丢了就重新生成。列表里这一行显示“待配对”，过期未用的同样显示“待配对”，可以撤销。
- 列表显示全部连接，包括已撤销的（灰色、无操作），按状态（已连接、待配对、已撤销）再按连接时间倒序。名称可改；撤销前确认一次，确认框写明“该设备的请求会立即被拒绝，要再连接需重新生成连接码”。
- 表下两行“下载扩展安装包”与“下载 skill”，分别对应 `/api/v1/intake/extension` 与 `/api/v1/intake/skill`（[产品接口 2.4.1](../technical/01-product-interface.md#241-设备连接与按用途准入)）。还没构建时按钮旁写“扩展安装包尚未构建”或“skill 包尚未构建”。
- 地址取页面自己的地址；用户经端口映射打开页面时，连接码里就是映射后的地址。

## 浏览器扩展弹窗

**用户来做什么**：在出版社或预印本页面上点扩展按钮，看这篇在不在库，不在就连同 PDF 收进来；或者从 Zotero 导入。决定见 [ADR 0057](../decisions/0057-zotero-import-and-browser-capture.md) 第 5 节、[ADR 0058](../decisions/0058-import-system-and-agent-access.md) 第 1、2 节与 [ADR 0063](../decisions/0063-unified-intake.md) 第 6、10 节。

目标，尚未实现（计划 20 的 19 块）：弹窗下方的“从 Zotero 导入”一行与扩展的整页；页面标签改由服务端解读；没有 DOI 或 arXiv 号时有标题即可收藏。本节其余内容已实现。

弹窗宽 360，与工作台同一套颜色与字体。从上到下是状态区、正文、“从 Zotero 导入”一行、底部一行“已连接 http://localhost:4174 · 设置”。

```
未连接                         已在库                          不在库
┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ 连接文献库            │   │ ● 已在库 · 已有 PDF   │   │ Argyrodite electro…  │
│ 粘贴设置页生成的连接码 │   │ Argyrodite electro…  │   │ Smith, Lee 等 · 2021  │
│ [sr-connect1:…     ] │   │                      │   │ DOI 10.5555/abc      │
│            [连接]    │   │                      │   │ 文件夹 [不放进文件夹▾]│
└──────────────────────┘   │──────────────────────│   │ ☑ 连同 PDF           │
                           │ 从 Zotero 导入      › │   │            [收藏]    │
                           └──────────────────────┘   │──────────────────────│
                                                       │ 从 Zotero 导入      › │
                                                       └──────────────────────┘
```

**收藏这一页**（弹窗的主体）：

- **未连接**：
  - 一个输入框粘贴连接码，“连接”。
  - 浏览器先询问是否允许访问文献库地址；拒绝时写“没有访问 <地址> 的权限，扩展无法连接”。
  - 连接码过期、已用时照服务端原因写出，并提示到设置页重新生成。
  - 未连接时不显示“从 Zotero 导入”一行。
- **连不上**：写“连不上 <地址>”，下一行“文献库在服务器上时，请检查端口映射是否开着”，以及“重试”和“修改地址”。
- **读页面**：
  - 只在打开弹窗时读当前页一次，把页面标签原样交给文献库预览（[产品接口 2.4.2](../technical/01-product-interface.md#242-入库-http目标尚未实现)）。
  - 读出的书目与 PDF 地址以服务端的预览结果为准。
  - 读不到标识、但有标题时照常可以收藏。
  - 标识与标题都没有时写“这一页没有读到书目，无法收藏”，并提供一个输入框“DOI 或 arXiv 号”：填写后再预览一次。
- **已在库**：
  - 状态徽标写“已在库 · 已有 PDF”或“已在库 · 还没有 PDF”，下面是库里的标题。
  - 还没有 PDF 且预览给出了 PDF 地址时，显示“补上 PDF”。
- **不在库**：
  - 标题、作者（最多三位，其余写“等”）与年份、标识；没有标识时写“没有读到 DOI 或 arXiv 号”。
  - “文件夹”下拉，默认不放进文件夹，按层级缩进。
  - “连同 PDF”勾选框，预览没有给出 PDF 地址时不显示。
  - 主按钮“收藏”。
- **可能重复**：预览给出可能重复的候选时（只在没有标识的页面上出现），“不在库”的正文下方加一块：
  - 标题“库里可能已有这篇”，下面列出候选，最多 3 个，每个一行：标题 · 第一作者 · 年份。
  - 两个选择：每个候选行尾的“并入这一篇”，以及底部的“作为新文献收藏”。
  - 主按钮“收藏”在使用者选定之前不可用；选定后按钮写“并入并收藏”或“作为新文献收藏”。
  - 使用者不选、直接关闭弹窗时，不收藏，不入库。
  - 并入时，结果一行写“已并入库里的《标题》”。
- **收藏中**：
  - 按钮写“正在收藏…”；有 PDF 时依次写“正在下载 PDF”“正在上传 PDF”。
  - PDF 所在网站第一次用到时，浏览器会询问是否允许访问该网站；拒绝时书目照常保存，写明 PDF 没有收进来。
- **收藏结果**：
  - 写“已收进‘网页收藏 2026-11-14’”。
  - 下面一行写 PDF 的结果：已上传、库里已有相同文件、与库里的 PDF 不同（不替换）、没能下载（原因）。
  - 补全元数据部分或全部失败时，加一句“文献信息来源暂时没能补全，书目已保存”。
- **设置**：显示地址，可以修改（令牌不变）；“断开连接”删除本机保存的令牌，并提示到设置页撤销这个设备。

**从 Zotero 导入**（弹窗下方一行）：点击后打开扩展自己的整页，弹窗关闭。整页的各状态：

- **找不到 Zotero**：写“没有连上本机的 Zotero”，并说明三件事：Zotero 需要保持打开；需要在 Zotero 的设置中开启本地接口；需要允许扩展访问 `http://localhost:23119`。下方有“重试”。
- **选择**：
  - 左侧列出个人库与群组库；右侧是所选库的分组树，可以勾选多个分组，或勾选“整个库”。
  - 下方写所选范围的条目数与附件数；主按钮“开始导入”。
  - 这一步不交任何数据。
- **交清单**：写“正在读取 Zotero 并交给文献库 n / 总数”，可以“停止”。交完后自动在新标签页打开文献库里这个批次的页面，整页写“已交给文献库，请在文献库的批次页上预览和确认”。
- **需要数据文件夹**：扩展读不到 Zotero 的文件时，写“请选择 Zotero 的数据文件夹，以便上传 PDF”，并说明默认位置（Windows 为 `C:\Users\<用户名>\Zotero`，macOS 为 `~/Zotero`）；主按钮“选择文件夹”。只需要选一次。
- **后台上传**：
  - 确认之后，扩展在后台上传文件。
  - 整页与弹窗下方一行写“正在上传 n / 总数”；进度以文献库的缺失清单为准。
  - 浏览器关闭后再打开，扩展从缺失清单继续。
  - 上传完成后写“文件已交齐”。
  - 预览、进度细节和报告都只在文献库的批次页上，扩展不显示。
- **连不上文献库**、**令牌已撤销**：写法同上面的“连不上”与“未连接”；后台上传暂停，恢复连接后继续。

## 浏览器

**用户来做什么**：看 Agent 获取 PDF 的过程，监督它干活；想点就直接在它的画面上点。Agent 是一套固定能力的获取流程，不是万能助手；流程失败就由 Owner 自己获取 PDF，页面不暗示“人帮一把就能成功”，也不出现“人工接管”“需要你帮忙”一类说法。

**排布**：

```
浏览器                                                         [刷新会话]
进行中
  本次获取 · 10 篇 · 14:02 开始 · 3 进行中 · 2 等待 · 5 已结束
    [卡] 衬线标题                      ● 推理中            观看 Agent
    [卡] 衬线标题                      ● 等待执行          观看 Agent
已结束
  › 本次获取 · 14:02 · 已入库 4 · 未获取 1        （展开为紧凑行）
  › 10/25 21:30 · 10 篇 · 已入库 7 · 未获取 3
      标题 · ✓ 已入库
      标题 · ● 未获取 · Agent 停止原因一句
```

- 每篇会话（卡片与已结束的行）显示一行小字“已尝试：Elsevier API 未命中 · 公开网站未命中 → 交给 Agent”，说明为什么轮到 Agent；没有记录时不显示。
- 会话按获取任务归组，组标题写开始时间、篇数与各状态计数；进行中的组在上，用浮起白卡；已结束的组在下，默认折叠，展开后每篇一行。
- 只列当前服务持有的会话（服务重启后清空）；更早的记录看任务页。
- 阶段颜色：推理、下载、验收等进行中为绿色；等待执行为灰色；已入库为中性灰带勾；未获取为红色，并原样显示 Agent 的停止原因。
- 没有会话时只显示一句空状态。

**观看**：

- 画面占主要宽度。Agent 的鼠标指针叠在画面上，随每次动作移到目标位置；点击时出现一圈波纹，指针旁写一句动作，例如“点击 View PDF”。指针位置来自 Agent 实际动作的坐标或元素位置，不推测。
- 右栏是动作记录：按时间往下列 Agent 实际做过的动作（点击的元素或位置、滚动、输入、新页签、进入的页面标题）和平台事件（开始下载、验收通过或失败）；流程停止时把停止原因放在末尾。不预设步骤，不替 Agent 编写理由。
- 画面可以直接点击、滚动、输入：第一次操作时 Agent 暂停，顶部写“你在操作 · Agent 已暂停 · 停手 10 秒后继续”，旁边一个“现在继续”；停手满 10 秒自动交还。不显示页面元素按钮墙。
- 剩余模型调用与时间以一行小字显示。“更多操作”折叠在动作记录下方：“暂停 Agent”、暂停或继续会话、页面上的链接与按钮列表（画面是图片，键盘用户靠它操作页面）、页面文字、给 Agent 的可选指导、取消会话。

## 入库

**用户来做什么**：把文献放进文献库：从检索来源发现、放入手头的文件、从 Zotero 导入，或在网页上收藏；之后在入库记录里看每一批的结果，决定接着做什么。决定见 [ADR 0052](../decisions/0052-intake-batches-and-explicit-scope.md) 与 [ADR 0063](../decisions/0063-unified-intake.md)。

目标，尚未实现（计划 20 的 18 块）。本节按 ADR 0063 第 10 节规定入库页与批次页；接口见[产品接口 2.4.2](../technical/01-product-interface.md#242-入库-http目标尚未实现)，过程与状态见[文献与材料 6.4.2](../technical/03-literature-materials.md#642-过程与状态)。

```
入库
  检索 · 文件 · Zotero · 网页
  ┌──────────────────────────────────────────────────────────┐
  │ 把 PDF、文件夹或导出文件拖到这里，或 [选择文件] [选择文件夹] │
  │ 支持 PDF；BibTeX、BibLaTeX、RIS、CSL JSON 导出文件           │
  └──────────────────────────────────────────────────────────┘
入库记录
  我的文库 (Zotero) · 扩展 · 11-14 15:20   待确认      新增 120 · 已在库 30 · 可能重复 3    ›
  网页收藏 2026-11-14 · Chrome 扩展        入库中      新增 4 · 已在库 1                    ›
  library.bib · 网页 · 11-14 14:02         部分完成    新增 118 · 冲突 2 · 未交文件 12      ›
```

**顶部标签页**：检索、文件、Zotero、网页四个，取代原来的“主题发现、引用扩展、导入、上传 PDF”。

- **检索**：主题发现与引用扩展两张表单，内容与原来相同。
  - 表单为定义表；数字框按内容取宽，年份起止合成一行；主按钮为“开始发现”。发现在提交前确认范围与所用服务。
  - 确认后对话框立即关闭，主按钮变为“正在发现…”并暂不可用，下方写明“进度见入库记录”。
- **文件**：一个放置区，接受 PDF、文件夹与导出文件，可以拖入，也可以用“选择文件”“选择文件夹”。
  - 自动识别的规则：
    - 扩展名为 `.pdf`，或者内容以 `%PDF-` 开头的，是 PDF；
    - 扩展名为 `.bib`、`.ris`、`.json`，或者内容符合 BibTeX、RIS、CSL JSON 格式的，是导出文件，格式写在放置区下方的一行里，可以改。
    - 文件夹逐层展开，按同样的规则识别其中的文件。
  - 一次放入的内容形成一个批次：
    - 只有 PDF 时，每个 PDF 是一条只有文件的条目；
    - 有导出文件时，导出文件与同一次放入的 PDF 按导出里写的路径配对（[文献与材料 6.4.3](../technical/03-literature-materials.md#643-只有文件的条目与配对)）。
    - 一次只接受一个导出文件。
  - 识别不了的文件不交给服务端，在放置区下方逐个列出：“没有识别出这个文件的格式：<文件名>”，并说明支持哪些格式。导出文件的格式识别不了时，格式一栏为空，必须选一个才能继续。
  - 放入之后立即建批次、交数据与文件，并打开这个批次的页面；这一步不写文献库。
  - 导出文件不超过 7 MiB。
- **Zotero**：
  - 上方一行写扩展的连接状态：“已连接扩展 · <连接名>”或“没有连接扩展”。
  - 已连接时，下面一句说明：“在扩展里选择要导入的库和分组。导入开始后，这里的入库记录会出现这一批。”
  - 没有连接扩展时，写明三步：在“设置 · 设备连接”下载扩展安装包；在浏览器的扩展页面以开发者模式加载；在设置页生成连接码，粘贴到扩展里。三步各带一个链接或按钮。
- **网页**：
  - 一句说明：“在出版社或预印本的文献页面上，点浏览器工具栏里的扩展按钮即可收藏。”
  - 下面一行写扩展的连接状态，写法同 Zotero 标签页。

**入库记录**：标签页下方是全部入库批次，只有一种行，不论由检索、文件、扩展、Agent、CLI 还是 MCP 发起，也包括合成的“早期入库”。原来单独的导入列表并入其中。

- 按建立时间倒序，分页加载。
- 每一行的左侧：
  - 名称（可改名）；
  - 第二行：时间 · 发起者（网页、CLI、MCP，或“扩展 · 连接名”“Agent · 连接名”）· 范围（年份、来源或文件名）。
- 每一行的中间：状态徽标。已结束的批次显示结果（完成、部分完成、失败、中断）；其余显示状态（收集中、待确认、入库中、已取消、已撤回）。
- 每一行的右侧：
  - 计数“新增 · 已在库 · 恢复 · 冲突 · 可能重复 · 未接纳”，0 不显示；有来源未完整返回时写出几个；
  - PDF 进度细条（已有、无法获取、待获取）与数字；
  - “在文献库查看”。
- 点一行打开批次页。
- 有处于收集中、待确认或入库中的批次时，记录每 3 秒刷新。刚建立的批次出现在最上方。

### 批次页

批次在入库页内打开，地址里带批次编号；“返回”回到入库页。各部分自上而下：

```
library.bib                                              待确认
  网页 · 11-14 14:02 · 来源 library.bib（导出文件）
  新增 118 · 已在库 30 · 冲突 2 · 可能重复 3 · 未接纳 1 · 文件 要上传 118 · 只核对 30
需要决定（6）
  可能重复   Solid electrolytes: a review · Doe 2020   [并入 ▾] [新增]
  可能是这一篇  scan_0041.pdf → Argyrodite electrolyte one (2021)  [采用 ▾] [都不是]
  未配对的文件  supplement.pdf   [作为单独的文献入库] [不入库]
                                                    [取消]  [确认入库]
```

1. **页眉**：
   - 名称，可改；
   - 第二行：来源（库名、文件名或网页）、发起者、建立时间；
   - 右侧是状态徽标，已结束的批次显示结果。
2. **计数概况**：
   - 预览阶段写“预览（估计，确认时按当时的文献库重新判定）”，之后写实际数；
   - 分类为新增、已在库、恢复（重新入库了以前撤回的文献）、冲突、可能重复、书目待补、未接纳；
   - 文件写要上传与只核对的个数；
   - 批注写可导入、不能导入的条数；
   - 不导入的内容写各种类的数量。
3. **需要决定的事项**：可能重复、可能是这一篇、未配对的文件三类，每类一个小标题与条数。每条一行：
   - 可能重复：库里的候选（最多 3 个，标题 · 第一作者 · 年份），“并入”下拉选一篇，或“新增”。
   - 可能是这一篇：候选（最多 3 项），“采用”下拉选一项，或“都不是”。
   - 未配对的文件：“作为单独的文献入库”或“不入库”。
   - 已作出的决定写在行尾，可以改，直到确认；批次结束后只剩待决定的条目可以处理。
   - 没有需要决定的事项时，整块不显示。
4. **进度**：
   - 认篇时写“正在识别文件 n / 总数”，旁边有“停止识别”；
   - 入库中写当前阶段（书目入库、等待文件、收尾）、“已处理 n / 总数”，以及文件进度细条（已上传、已有、冲突、待交）。
   - 还有待上传的文件时，显示“选择文件夹”按需续传，匹配不到的文件逐个列出，并有“结束入库”：它把余下的文件记为未交，确认前再问一次。
5. **报告**：
   - 按计数概况的分类写实际结果；冲突、未接纳与待决定的条目逐条列出原因；
   - 文件的冲突与未交逐个列出；
   - 一行全文取得情况：“全文已取得 n / 总数 m，未取得 k（其中自动途径已试完 j）”。
6. **接着做什么**：
   - 两个按钮，“获取全文 n 篇”与“解析并形成初稿 n 篇”，n 为预估数，为 0 时按钮不可用；
   - 旁边写明“会联网，可能花费”；点按钮先打开与文献库相同的范围对话框；
   - 入库本身不自动做这两件事。
7. **更多**：页眉右侧的“更多”菜单里有“在文献库查看”与“撤回这一批”。撤回只在已结束、已取消的批次上可用；入库中的批次菜单项不可用，并说明“入库结束后才能撤回”。规则见[文献与材料 6.4.11](../technical/03-literature-materials.md#6411-撤回)。
   - 点“撤回这一批”打开对话框：
     - 先取预估。对话框写明将移除的文献、文件、文件夹、批注各多少，将保留的文献多少篇，并按原因分行（入库前已在库、之后被别的批次命中、加入过别的文件夹、有批注、打开过、加工过、改过书目、与别的文献合并）；
     - 保留的文献可展开逐篇列出；
     - 下面一句“撤回只是从文献库中移除，可以恢复；文件不会被删除”；
     - 按钮“撤回”与“取消”。
   - 有任务正在处理这一批的文献时，对话框写“这一批有文献正在被任务处理，请等任务结束或取消后再撤回”，不显示“撤回”按钮。
   - 撤回之后，页眉状态为“已撤回”；页面顶部一行写“这一批已于 <时间> 撤回”，以及“恢复这一批”按钮；下面是撤回报告，分移除与保留两部分，保留的逐篇写原因。
   - 点“恢复这一批”先确认一次，写明将恢复的数量（已经被后来的入库恢复的不计）；恢复之后，批次回到撤回之前的状态，并显示恢复报告。

各状态下显示的部分：

| 状态   | 页眉 | 计数概况             | 需要决定         | 进度       | 报告             | 接着做什么 | 主操作           |
| ------ | ---- | -------------------- | ---------------- | ---------- | ---------------- | ---------- | ---------------- |
| 收集中 | 有   | “还没有交来条目”     | —                | —          | —                | —          | “取消”           |
| 待确认 | 有   | 预览估计             | 有就显示         | 认篇时显示 | —                | —          | “确认入库”“取消” |
| 入库中 | 有   | 实际，随进度更新     | 只有待决定时显示 | 有         | 到当时为止的累计 | 有         | “结束入库”“取消” |
| 已结束 | 结果 | 实际                 | 只有待决定时显示 | —          | 有               | 有         | —                |
| 已取消 | 有   | 实际（已入库的部分） | —                | —          | 有               | 有         | —                |
| 已撤回 | 有   | 实际                 | —                | —          | 撤回报告         | —          | “恢复这一批”     |

- 认篇还没结束时，“确认入库”不可用，旁边写“正在识别文件，完成后才能确认”。
- “确认入库”之前再确认一次，写明“只新增，不删除、不替换已有 PDF；需要决定而没有决定的条目不入库”。
- 网页上传中断后（刷新、关闭）再打开批次页，按服务端的缺失清单继续，已上传的不再传。
- 收集中、待确认与入库中的批次每 3 秒刷新。
- 逐条确认的开放批次（网页收藏、补充文件）显示为入库中，报告给出到当时为止的累计。
