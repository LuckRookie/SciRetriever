# Web 页面规格

类型：规格（前端页面）
负责：信息架构、侧栏、页面模板与逐页排布
状态：现行

视觉规则见[设计内核](design-core.md)；当前已实现的操作见 [Web 指南](../../guides/web-workbench.md)。

## 整体信息架构

产品的主线是：**找到文献 → 拿到全文 → 阅读**。全站一条顶栏、一个侧栏（Owner 2026-11-24）：顶栏管“打开着什么”，侧栏管“去哪里”，文件夹是侧栏的主体。

```
顶栏（每一页都有）
[S] [开合侧栏] [文献库]  | 文献标题… ✕ | 文献标题… ✕ |            （阅读页：阅读工具）

侧栏
文献库              147
最近读过
文件夹               ＋ ⋯
  …（文件夹树）
────────（以下固定在侧栏底部）
找文献
全文检索
任务      2 进行中 · 12 需处理
加工
设置
```

| 位置     | 项       | 用来做什么                                                                       |
| -------- | -------- | -------------------------------------------------------------------------------- |
| 顶栏     | 开合侧栏 | 任何页面上收起或展开侧栏                                                         |
|          | 工作区签 | 阅读页之外的那一页；名字是当前页面（文献库、找文献、全文检索、任务、加工、设置） |
|          | 文献签   | 打开着的文献，一篇一张                                                           |
| 侧栏上半 | 文献库   | 文献库里的文献（界面用词）；数字是文献库的篇数，不是全库篇数                     |
|          | 最近读过 | 最近 30 天打开过的文献                                                           |
|          | 文件夹   | 目录树；点文件夹即在文献库页按文件夹筛选                                         |
| 侧栏底部 | 找文献   | 找新文献、导入文件；批次记录与各批次在这一页里                                   |
|          | 全文检索 | 在全文中找片段                                                                   |
|          | 任务     | 后台任务的进度与失败；标签页：任务、需处理、浏览器、Agent 会话、来源统计         |
|          | 加工     | 标签页：算子、快照、标签词表、洞察                                               |
|          | 设置     |                                                                                  |

**顶栏**

- 每一页都有，一行；外观与阅读页内的规则见[阅读体验 1.3](reading-experience.md#13-顶栏)。从左到右：标志、开合侧栏的按钮、工作区签、文献签；阅读页右端是阅读工具，其他页面右端留空。
- 工作区签代表阅读页之外的那一页，名字跟着当前页面变。在阅读页点它，回到离开时的那一页：同一个范围、同一组条件，文献库回到离开时的位置和那一行。不在阅读页时它是当前项。
- 文献签一篇一张，从任何文献标题打开；点签切到那一篇。关闭、中键、右键与标签页过多时的收起见[阅读体验 1.3、1.8.3](reading-experience.md#183-标签页)。侧栏不再列出打开着的文献。
- 页面自己的标题仍在页面里（设计内核“页头”）；顶栏不重复页面的工具。

**侧栏**

- 上半是文献库、最近读过和文件夹树，自己滚动；文件夹多了只占这一区。下半五项固定在底部，高度不变，不随文件夹增多而被挤走。
- “文件夹”标题行右端是“新建文件夹”与这一组的菜单（导出分组）；不另占一行。还没有文件夹时，标题行下面一句“还没有文件夹。新建一个，再把文献拖进来。”
- 侧栏不列批次：最近的批次与全部批次记录在“找文献”页。侧栏的数字只有文献库的篇数与任务的状态，都来自写入时维护的计数或进行中的任务，不发随库变大的请求。
- “需处理”是解析全文过程中需要人处理的问题，是任务页的一个标签页。侧栏“任务”旁写“n 进行中 · m 需处理”，哪个为 0 就不写哪个，都为 0 时不显示数字。
- “加工”是一个入口，进去是算子；算子、快照、标签词表、洞察是这一页的标签页，做法与任务页相同，每个标签页有自己的地址。页头写“加工”，右端是当前标签页自己的主操作（运行算子、生成快照）。从结果详情、快照详情里点侧栏的“加工”或点一个标签页，都回到那个标签页的最上一层。只读入口只有算子与洞察两个标签页。

**开合**

- 全站同一个侧栏、同一个按钮（顶栏左端，标志右边）。
- 阅读页之外：侧栏默认展开，停靠在左边，宽度可拖；收起后页面用满宽度。开合记在浏览器里。
- 阅读页：侧栏默认收起。按开合按钮，侧栏以抽屉的形式从左侧滑出，盖在案头上，不挤动纸页；点一处去处、点抽屉外或按 Esc 即收起。每次进入阅读页都是收起的。
- 窗口宽度不超过 720 px 时，所有页面都按阅读页的做法：侧栏是抽屉。

**其他**

- “浏览器”（观看与接管下载）与“Agent 会话”都由任务发起，是任务页的标签页。
- 任务页的标签页用下划线式（设计内核“组件外观”）；任务列表的快速筛选为“全部 · 进行中 · 有问题 · 已结束”，“有问题”是已暂停、已中断与失败的任务，不与“需处理”同名。
- 旧地址照常可用：`view=agent` 打开任务页的“Agent 会话”，`view=archive` 打开任务页的“需处理”，`view=web` 打开任务页的“浏览器”；设置的旧分区地址转到新分区（来源 → 获取 PDF，解析与建档 → 解析全文，凭据 → 模型服务）。
- 结果有两个入口：算子页按运行记录看，阅读页“更多 → 加工结果”按单篇看。
- 地址无效时，全站给同一页“找不到这个页面”，一句“地址可能写错了，或者这项内容已经不在了。”，加“回到文献库”；浏览器打开这样的地址也得到这个页面，不看到原始 JSON（[产品接口](../technical/01-product-interface.md)）。
- 运行算子只有一种入口形式：四步对话框（范围 → 算子 → 规范 → 确认），可从文献库、阅读页、快照页、算子页打开；已有范围时跳过“范围”一步。在文献库与阅读页，它和“生成快照”都排在菜单的最后一组“加工”里，不在选择栏和菜单的前列。
- 文献库页头没有“入库”按钮；找新文献从侧栏“找文献”进。

## 页面模板

```
页标题  上下文数字                                   [主操作]
工具条（一行；必要时第二行放快速筛选）
内容
```

- 页头不放说明系统行为的句子；对用户有用的信息改为界面状态、按钮文案、字段旁的提示，或页面底部的页注。
- 上下文数字示例：文献库“35,177 篇”、任务“2 个进行中”；需处理是任务页的标签页，数字写在它的工具条上（“共 12 项”）。
- 空状态：一句话加至多一个动作，例如快照为空时“还没有快照。在文献库应用筛选后，从“批量操作”生成快照。”
- 没有数据时隐藏分页与批量操作。
- 所有页面从同一条左边界开始（页边 32），左对齐，不居中；文献库用满宽度，其余页面最宽 1400。换页面、换标签页时页头不移动。
- 一页里有两层切换时，上层用下划线式标签页（各有自己的地址），下层用分段控件；不叠两排同样的标签页。

每页按“用户来做什么 → 要呈现的信息（按优先级）→ 排布”说明。

## 界面用词

界面上按“这篇文献手里有什么”来说，不用内部状态名（Owner 2026-11-19）。命令行、MCP 与技术文档里的英文名和内部名不变。

| 内部含义                       | 界面上的词                    |
| ------------------------------ | ----------------------------- |
| 没有主 PDF（仅元数据）         | 只有书目（文献行上不挂徽标）  |
| 有主 PDF、还没有全文           | 有 PDF                        |
| 全文可读可搜（已就绪）         | 有全文                        |
| 建档（解析、整理、校订到发布） | 解析全文                      |
| 建档中 / 建档失败              | 正在解析全文 / 全文解析失败   |
| 自动途径已试完（无法获取）     | 没找到 PDF                    |
| 书目待补                       | 书目不全                      |
| 初稿 / 校订稿                  | 全文 · 未校对 / 全文 · 已校对 |
| PDF 文字层                     | PDF 自带的文字                |
| 对当前筛选结果做批量操作       | 批量操作（原“用当前结果”）    |
| 任务 queued，没点过启动        | 未启动                        |
| 任务 queued，点过启动          | 排队中                        |
| running                        | 进行中                        |
| paused（等人处理）             | 等你处理                      |
| interrupted / failed           | 已中断 / 失败                 |
| completed / cancelled          | 已完成 / 已取消               |
| collected（选用过）            | 文献库（文献库里的文献）      |
| 库里有、但不在文献库里         | 候选                          |
| 让候选进入文献库               | 加入文献库 / 已加入           |
| 让文献库里的一篇回到候选       | 移出文献库                    |
| 文献库与候选合在一起           | 全部文献                      |
| 发现、导入的页面（原“入库”）   | 找文献                        |
| 一次发现或一次导入             | 批次；全部批次是“批次记录”    |
| 最近 30 天打开过               | 最近读过                      |
| 计数截断（`count_truncated`）  | 1 万篇以上                    |
| Catalog 路径、资产目录         | 文献库文件、文件存放位置      |
| Provider、Model                | 模型服务、模型                |

- 文本等级按场合写：书目块与检索命中写“全文 · 未校对 / 已校对”，阅读页页眉写“全文 · 未校对 / 已校对”，文献行与信息栏只写“未校对”；长文档注明“未逐页校对”。没有可核对文字的段落标“无自带文字”。
- 快速筛选是互不重叠的几类，数量加起来等于总数：全部、有全文、有 PDF、只有书目；正在解析全文、全文解析失败、没找到 PDF、已排除收在“更多状态”里。洞察页的“材料状态”用同一组分类与同一组数。
- “加工”组里的词（算子、规范、缺口、快照）不在这次范围，随知识加工提案另定。

## 文献库

**用户来做什么**：找到文献，看清手里有什么材料，选一批去做事。

打开就是**文献库**的列表（Owner 2026-11-22 选定样稿甲）。文献库是使用者要的文献，其余是**候选**；两者的关系、一篇文献怎样进出文献库，见 [ADR 0067](../decisions/0067-library-and-candidates.md)。候选通过搜索、“找文献”页的批次、引用关系、最近读过与候选的列表找到。

**信息优先级**：

1. 文献行：标题、书目（作者 · _期刊_ · 年份）、材料；
2. 当前这一篇（右栏）：书目、摘要、材料与可做的事、文件夹、标签；
3. 当前检索与筛选：检索词、材料分类、已应用的条件；
4. 结果数量：共几篇 / 符合几篇；
5. 批量操作。

**排布**（Owner 2026-11-24：三栏，用满宽度）：

```
侧栏 │ [搜索文献                                             ] │ 右栏：当前这一篇
     │ 文献库  共 4,812 篇        [筛选] [排序▾] [列表|表格] [批量操作▾] [▯] │ 标题
     │ 全部 · 有全文 · 有 PDF · 只有书目 · 更多状态▾                │ 作者、期刊、年份
     │ （有条件时）起始年份：2020 ✕  期刊：ACS Catalysis ✕  清除    │ [打开阅读] [获取 PDF]
     │ （有条件时）范围内的词                                      │ 摘要
     │ ─────────────────────────────────────────────── │ 关键词、材料
     │ 文献行 …                                                    │ 标签
     │ 文献行 …                                                    │ 技术详情
（勾选后浮出）已选 8 篇 (只有书目 3)(有 PDF 2)(有全文 3) [获取 PDF 3] [解析全文 2] [移动…] [更多▾] 取消选择
```

- 页面用满侧栏以外的宽度，不限宽、不居中。中间一栏是一个滚动容器，右栏固定在窗口右侧，自己滚动。
- 滚动时留在顶部的只有标题行（页名、总数与工具），下面一条细线；搜索框、材料分类、条件与范围内的词随文献行滚走，表格显示的表头接在标题行下面（Owner 2026-11-25：顶部不能占住列表）。工具最右是图钉按钮“滚动时固定搜索与筛选”：按下后搜索框、标题行、材料分类与条件整块留在顶部，按钮变成“取消固定”并用笔色；这个选择记在这个浏览器里。没有固定并且已经滚下去时点“筛选”，页面回到顶部再展开筛选面板。
- 回到顶部：页面滚过约一屏后，列表右下角浮出一个圆形按钮“回到顶部”，按下直接回到最上面；有选择栏时它在选择栏上方。
- 标题行左边是页名与总数，右边是工具：筛选、排序、显示、批量操作。右栏的开合是页面右上角的一个图标按钮。页面上没有全库带，也没有“活动”面板；后台情况看侧栏“任务”旁的数字和任务页。
- 输入框、下拉框不带上方标签（保留无障碍名称）。勾选后浮出的选择栏里至多一个主按钮（见“连续选择与选择栏”）。
- 总数只在标题旁写一次：没有条件时写“共 n 篇”，有时写“符合 n 篇 / 共 m 篇”；m 是当前范围（文献库、文件夹、批次）的总数，“最近读过”里前面加“最近 30 天 · ”。超过一万篇的写法见“超过一万篇”。
- 没有结果时，列表区域居中一句“没有符合条件的文献”，有条件时下面是“清除条件”。文献库里还没有文献时写“文献库里还没有文献”，下面是“去找文献”；已经有候选时，另写一句“在上方搜索，也会列出候选”。

**搜索框**

- 每个视图最上面都有。文献库视图里写“搜索文献”，回车在全部文献里搜索（进入搜索结果）；文件夹、批次、最近读过等视图里写“在「视图名」里搜索”，在这个范围里搜索。搜索词不算作筛选条件，不另出一个条件标签。
- 文献库视图里，标题旁的总数之后写“候选 n 篇”，n 是全库候选的篇数，来自写入时维护的计数；它是次要色的文字按钮，点它在本页列出全部候选（Owner 2026-11-25）。没有候选时不出现；文件夹、批次、最近读过与搜索结果里不出现。
- 候选的列表：页名“候选”，总数是候选的篇数；侧栏不选中任何一项，点侧栏“文献库”回到文献库。默认并且超过一万篇时只能按“最近新增”排序，计数与范围内的词照“超过一万篇”的写法；排序菜单里没有“最近加入”。搜索框写“在「候选」里搜索”，在候选里搜索。每一行的来历只写“· 来自引用扩展”或“· 来自主题搜索”，不再重复“候选”；行内操作与选择栏同“搜索结果”里的候选。

**搜索结果**（Owner 2026-11-24：先列文献库里的，再列候选，不设范围开关）

```
搜索“cross-coupling”  1 万篇以上符合  [算出准确数]
                                              按相关度显示前 1,000 条
文献库里  812 篇  [只看文献库里的]
文献行 …（最相关的 5 篇）
候选  1 万篇以上  发现任务找到、还没有加入文献库的文献
文献行 … · 候选：来自引用扩展              [加入文献库]
```

- 搜索框的搜索进入这一页；页头写“搜索“词””，旁边写符合篇数（超过一万篇的写法见下）。
- 在全部文献里搜索时，结果是一张列表分两段，各有一行段头：
  - **文献库里**：文献库里符合的文献，按当前排序取前 5 篇，段头写篇数；多于 5 篇时段头有“只看文献库里的”，按下后只列文献库里的全部命中，搜索框下出现一个可移除的条件“只看文献库里的”，移除它回到两段。文献库里没有命中时没有这一段。
  - **候选**：发现任务找到、还没有加入文献库的文献，段头写篇数与这一句说明；全站只在这里解释一次。在这一页上加入文献库的候选留在原位，行上写“已加入”。
  - 两段是同一张列表：勾选、连选、当前行、↑ ↓ 与右栏都连着用。表格显示时段头横跨整行。
- 在文件夹、批次、最近读过等视图里搜索时不分段，默认查“「视图名」里”；搜索框下是一组单选“「视图名」里 / 全部文献”，切到全部文献即成为上面的两段，切换保留检索词与条件。
- 默认按相关度排序，排序名旁写“按相关度显示前 1,000 条”（[查询技术篇](../technical/06-retrieval-context.md)的 `relevance_limit`）；翻到第 1,000 条后，列表末尾写“相关度排序只显示前 1,000 条；加条件或换个检索词可以看到其余的”。
- 搜索一次只查一批，批的大小见[查询技术篇 2.4](../technical/06-retrieval-context.md#24-规模与目标耗时)与 [ADR 0065](../decisions/0065-scale-rules.md) 第 6 节第 4 条：在全部文献里搜索时，查最近写入索引的一批命中（例如 75,000 条）；在超过一万篇的文件夹、批次、任务的产出、最近读过和“只看文献库里的”里搜索时，查这个范围按自身顺序最近的一批成员（例如 8,000 篇；文件夹、批次、任务的产出按入库时间，收进来的按加入时间，最近读过按打开时间）。下面的说法只换被查的对象，句式相同；“这个文件夹”“入库”按范围换词，收进来的写“最近加入的 8,000 篇”，最近读过写“最近打开的 8,000 篇”。这一批之外还有更早的部分时：
  - 标题旁写“至少 n 篇符合”，同时超过一万篇时只写“1 万篇以上符合”；快速筛选与范围内的词的数字后加“+”；为 0 时不写数字。
  - 排序名旁写“在最近写入索引的 75,000 条命中里按相关度显示前 1,000 条”或“在这个文件夹最近新增的 8,000 篇里查找”，后接“在更早的命中里继续找”或“在更早新增的文献里继续找”；列表末尾也有这个按钮。
  - 这一批里没有结果时，标题旁不写数字，排序名旁不再重复说明；列表区域写“最近写入索引的 75,000 条命中里没有，更早的还没查”或“这个文件夹最近新增的 8,000 篇里没有，更早的还没查”，下面是继续找的按钮，不写“没有符合条件的文献”。在全部文献里搜索、文献库里有命中而这一批里没有候选时，文献库里的命中照常列出，下面在候选该开始的地方写“候选　最近写入索引的 75,000 条命中里没有，更早的还没查”，再是继续找的按钮。
  - 排序：查命中时只能按相关度；查成员时还可以按这个范围自身的时间排序（最近新增、最近加入、最近打开）。其他排序在菜单里停用，写法同“超过一万篇”；地址里带着别的排序时，列表区域给“改按相关度”。
  - 要先列出全部结果的操作（选择全部 N 篇，批量操作里的解析全文、移动、导出、运行算子）停用，说明“这次搜索只查了最近写入索引的命中，更早的还没查；请先加条件缩小范围。”，查成员时说明“这次搜索只查了这个范围里最近的一部分文献，更早的还没查；请先加条件缩小范围。”
- 按下继续找的按钮，列表、计数与范围内的词一起换到更早的下一批：排序名旁改写“在更早的第 k 批 75,000 条命中里……”或“在这个文件夹更早新增的第 k 批 8,000 篇里……”，标题旁写“这一批 n 篇符合”，快速筛选写这一批的数字，旁边有“回到最近的命中”或“回到最近新增的文献”。批次只记在页面里，换了检索词、条件、范围或排序即回到最近的一批；服务端不再认得这一批时，也回到最近的一批，不显示错误。
- 在文件夹、批次、任务的产出、最近读过和“只看文献库里的”里搜索时，不超过一万篇的范围不分批，符合的文献、计数与范围内的词都准确。相关度排不完全部（或这一批）时（[ADR 0065](../decisions/0065-scale-rules.md) 第 6 节第 4 条），只对按范围自身顺序取的前 n 篇打分：这些按相关度排在前面，其余按范围自身顺序排在后面。
  - 排序名旁写“按相关度排了最近加入的 847 篇，其余 9,153 篇按加入时间排在后面；先加条件，或缩小范围，可全部按相关度排”，“加入”按范围换成“新增”“打开”；计数截断或分批时不写其余的篇数；一篇也没排到时写“没有按相关度排序，按加入时间从近到远排列；先加条件，或缩小范围，可全部按相关度排”。查成员的一批里也只排了一部分时，两句合成一句：“在这个文件夹最近新增的 8,000 篇里，按相关度排了最近新增的 847 篇，其余按入库时间排在后面；……”。
  - 列表里两部分交界处，第一篇未排的文献上方有一行小字“以下未按相关度排序”，只在交界落在已读到的行里时出现。
  - 其他排序照常可用。
- 候选的来历写在书目行末尾，次要色：在“候选”段里只写“· 来自引用扩展”或“· 来自主题搜索”，段头已经说过它们是候选；在不分段的列表里（批次、文件夹里查全部文献）写“· 候选：来自引用扩展”，没有来历的只写“· 候选”。来历是链接，点它在文献库里打开那个任务的发现批次；平时不带下划线，悬停这一行时用笔色，悬停它本身时加下划线。“加入文献库”是行内操作（Owner 2026-11-23 选定样稿甲）：带加号的笔色文字按钮，与预览、文献操作排在行右侧同一处，只在悬停、聚焦或选择状态时出现，触屏常驻；材料标记与行内操作排成一行，不上下叠放。按下后这个位置换成小字“已加入”，这一行去掉“候选”，侧栏“文献库”旁的数字随之更新。勾选多篇时，选择栏最前面是主按钮“加入文献库 n”，n 是所选里候选的篇数，为 0 时不出现。
- 其余（快速筛选、条件、文献行、预览、选择栏）与列表相同。

**超过一万篇**

工作集或搜索结果超过一万篇时，计数与部分排序按 [ADR 0065](../decisions/0065-scale-rules.md) 第 6 节第 2、3 条截断，界面写明（字段见[查询技术篇](../technical/06-retrieval-context.md)的 `LibraryCounts`）。

- 总数：`count_truncated` 时标题旁写“1 万篇以上”或“符合 1 万篇以上 / 共 m 篇”，后接次按钮“算出准确数”。按下后按钮换成“正在计算…”，在后台算出准确数后替换“1 万篇以上”，并在数字后用次要色写“（截至 时:分）”；计算失败时按钮恢复，旁边写一句原因。换了条件后，算出的数作废，回到“1 万篇以上”。
- 快速筛选与范围内的词：快速筛选在 `count_truncated` 时、范围内的词在 `facets_truncated` 时，各项的数字写“1 万+”，不写不准确的数。
- 状态正在更新（`status_updating`，例如改了标签上限或建档方式之后在后台重算）：快速筛选一行末尾用次要色写“状态正在更新，数字可能不准”，更新完后去掉。
- 排序：超过一万篇时排序菜单只有可用的几项——文献库“最近加入”，文件夹与批次“最近新增”，最近读过“最近打开”，搜索结果“相关度”；其他排序在菜单里停用，悬停写“超过 1 万篇时只能按这几种排序；先加条件，或缩小范围”。表格的表头排序同样停用。服务端返回 `library-sort-scope-limit` 时（例如地址里带着旧的排序），列表区域写同一句话，旁边按钮“改按（可用的默认排序）”，不自动换排序。
- 批量操作不受影响：“批量操作”与“选择全部 N 篇”照旧按全部命中处理。

**工具条**

- 在标题行右边，一行：筛选、排序、显示、批量操作。窄屏时这些收进“更多操作”。
- 右栏的开合是一个图标按钮，只在宽屏出现，固定在页面右上角、与搜索框同一行：右栏收起时它在搜索框右边，展开时它在右栏的右上角，位置不变。
- 右栏的宽度可以调：拖它的左边缘，或聚焦这条边后按 ← →（每次 16 px），在 320 px 与窗口宽度的六成（最多 800 px）之间；双击这条边回到默认宽度。宽度记在这个浏览器里。
- “筛选”是开合条件面板的按钮；有条件时写“筛选 · n”，应用了保存的筛选时写“筛选：名称”。
- 条件面板第一行是作者、期刊、年份、标签，其余在“更多条件”里，展开后列表仍在屏幕内；面板底部是“更多条件”。改一项即生效，没有“应用”按钮：选择类的条件选定就生效，文字类的条件按回车或离开输入框时生效；面板开着不收起，再按“筛选”才收起。已应用的条件写成“名称：值 ✕”排在快速筛选下面，末尾唯一一个“清除”。
- 保存的筛选：面板右上角的菜单“保存的筛选”，依次是各条保存的筛选、保存当前筛选…、用当前条件更新这项筛选、删除当前筛选、导出筛选。
  - 保存的筛选存在文献库里（[用户整理](../technical/09-user-organization.md)）；这个浏览器里还有未导入的旧筛选时，菜单末尾显示“导入这个浏览器里保存的筛选（n 项）”，导入后用一个对话框列出导入、改名、跳过与未导入的项及原因。条件里的文件夹已被删除的项，在菜单里以次级文字注明“文件夹已删除”。
- 显示方式两种，记在浏览器里：列表（两行一篇，见“文献行”）；表格（一行一篇，列为标题、作者、期刊、年份、材料，行高 32；作者只写第一作者加“等”；点“标题”“年份”的表头排序）。
- “批量操作”菜单只列这批用得上的操作，顺序为获取 PDF、解析全文、移动…、导出…，最后一组是加工（运行算子、生成快照）；结果为 0 时不出现。

**快速筛选**

- 四类互不重叠，数量加起来等于总数（[界面用词](#界面用词)）：有全文；有 PDF（有主 PDF、还没有全文）；只有书目（没有主 PDF、自动途径还没试完）；“更多状态”里是正在解析全文、全文解析失败、没找到 PDF（没有主 PDF、自动途径已试完）、已排除。
- 显示当前检索下的数量，计数为 0 的项不显示（当前选中的除外）；默认“全部”。文献库默认按最近加入排序，其他视图按最近新增。窄屏时横向滑动。

**条件**

- 文本等级（[查询技术篇 2.1.7](../technical/06-retrieval-context.md#217-文本等级与选择校订范围的事实)，只看主 PDF），在“更多条件”里：“文本等级”（全部 / 未校对 / 已校对）、“全文和 PDF 自带的文字不一样”（不限 / 有 / 没有）、“含扫描页”（不限 / 有 / 没有），条件标签写同样的名称与取值；排序菜单有“与 PDF 自带文字的差异：多到少”“扫描页：多到少”。“被结果引用”“找不到的引用”两项筛选与排序在加工能读取全文之前恒为 0，不出现。筛选结果可以经“批量操作 → 解析全文…”交给解析全文，对话框照常写明范围与篇数。
- 书目不全（[文献与材料 8.4](../technical/03-literature-materials.md#84-书目待补)）：“更多条件”里的勾选框“书目不全”，条件标签写“书目不全：是”。
- 批次：批次记录在“找文献”页，每条记录有“在文献库查看”。打开后文献库限定到这一批，页头标题为批次名，条件标签写“批次：名称”，不显示内部 ID。
- 范围内的词：有条件标签时（搜索词与快速筛选不算），条件下方一块浅底区域按标签、作者关键词、主题词的顺序分行列出当前结果里最常见的词，各取前 8 个，带篇数，末尾“更多”展开到 30 个。每行名称后用浅色字写覆盖篇数，如“1,200 / 17,010 篇”。点一个词即加为条件（标签取“任一”，作者关键词与主题词各自取“同时具有”），已选的词用荧光黄底。有标签的篇数达到结果的一半时，主题词一行只显示名称和“展开”。作者关键词对应某个标签时，词后带一个小标签记号；已选的作者关键词有对应标签而该标签未选时，这块末尾提示“‘词’对应标签‘名称’”，旁边按钮“改用标签筛选”，按下即去掉该关键词、加上该标签。三层都没有词时不显示这块。这块与条件在一起：随文献行滚走，固定顶部时一起留下。

**文献行**（列表显示）

- 第一行衬线标题，最多两行；第二行书目，作者超过 3 位显示“等”，中文期刊名不用斜体，书目不全的末尾用次要色写“· 书目不全”。标签与关键词不在行里，在右栏。最小行高 56，上下内边距 12。
- 右侧是非默认材料的状态徽标（只有书目不挂徽标）：圆点加文字加淡色底，每种状态一种颜色（[设计内核规则 5](design-core.md#规则)；[ADR 0070](../decisions/0070-book-style-annotated-copy.md) 第 5 节恢复 2026-10-23 的写法）。行里与右栏只放这一篇是什么、材料到了哪一步、能做的事；不显示批语的条数、读者批注的数目，快速筛选里不设“有批语”。下方小字：有全文的长文档注明“未逐页校对”；主 PDF 的全文未校对时注明“未校对”，排序为差异或扫描页时后接计数，如“未校对 · 差异 12 段”“未校对 · 扫描 3 页”；正在解析全文的写停在哪一步；已排除的写文章性质。全文解析失败的行，徽标旁有“查看问题”，打开需处理。
- **当前行**（Owner 2026-11-24：单击选中，双击打开，任何情况下都一样）：单击一行（标题也一样）使它成为当前行；↑ ↓ 换到上一篇、下一篇。双击这一行、按回车或点右栏的“打开阅读”打开阅读页。当前行在行首有一条笔色竖线并带浅底色。右栏在的时候它显示当前行；右栏收起或窄屏时，单击同样只是选中，不打开。
- **勾选框**在行首左侧的页边里，不占正文的位置；悬停、聚焦或已有选中时出现，触屏常驻。表格显示时它是第一列，常驻。“全选已加载”一行只在已有选中时出现在列表上方（表格显示时在表头）。
- 悬停或聚焦时出现“文献操作”菜单；右键或 Shift+F10 打开同一个菜单。菜单分两组，中间一条细线：线上是对任何一篇都做的事，依次为打开阅读、（候选）加入文献库、（文献库里的）移动…、（在文件夹里时）移出「文件夹名」、导出…、（文献库里的）移出文献库…、删除；线下是取得或使用材料的事，依次为识别书目…、获取 PDF、解析全文、扩展引用…、运行算子…，只列这篇用得上的：识别书目只在书目不全的文献上出现（还没有 PDF 时停用，说明“需要先有 PDF”），获取 PDF 只在只有书目的文献上出现，有全文或已排除的不出现解析全文。“识别书目…”先弹出确认，写明范围与会查的来源，确认后建一个任务（[文献与材料 8.4](../technical/03-literature-materials.md#84-书目待补)）。“移动…”打开“移动到文件夹”对话框：在文献库里是把文献放进所选文件夹；在某个文件夹里是移到另一个文件夹，对话框里可以勾“同时保留在「文件夹名」里”。“移出文献库…”先弹出确认，写明这篇文献回到候选、离开所有文件夹、书目与文件和批注都保留、以后再加入时文件夹不恢复；确认后提示“已把《题名》移出文献库”，没有撤销。“删除”把文献移到“最近删除”：一篇直接删除，提示里有“撤销”；焦点在行上时按 Delete 相同，这一行在多选里时删除整个选择，先确认。在多选中的一行上点右键，打开的是这个选择的菜单，每一项都作用于全部已选文献：打开阅读 n 篇（每篇一个标签页，显示点右键的那一篇；一次最多 20 篇）、加入文献库 n（n 是其中候选的篇数，为 0 时不出现）、移动…（所选里有候选时停用，说明同选择栏）、移出、导出…、移出文献库 n…（n 是其中文献库里的篇数，为 0 时不出现）、删除 n 篇…，线下是获取 PDF n、解析全文 n、扩展引用…、运行算子 n，数字与停用原因同选择栏。在未选中的行上点右键仍是那一行自己的菜单。右栏收起或窄屏时，行上另有“预览”。
- 把 PDF 文件拖到一行上，打开这一篇的“补充 PDF”对话框。

**右栏**（当前这一篇）

- 宽屏（窗口宽于 1100 px）时固定在右侧，宽 432，左侧一条细线，不带阴影与遮罩；列表让出这块位置。它总是显示当前行：进页面时是第一篇，从阅读页回来是离开时的那一篇，换了条件后当前行不在结果里时回到第一篇。
- 自上而下：类型与年份、标题、作者、出处；材料一行与“打开阅读”“获取 PDF”（都是普通按钮：这一页的主按钮留给选择栏和对话框，一页只有一个）；摘要；关键词；标签；“技术详情”。材料和能做的事排在摘要之前，因为看右栏是为了决定要不要打开这一篇。书目部分与阅读页的书目页是同一个组件。
- 标签一行只列标签名，主标签加重。标签是谁标的、依据是什么，要服务端在文献条目里给出每个标签的来源才写得出来，现在不写。
- 右上角的按钮把它收起，列表用满宽度；工具条最后的按钮把它展开。开合记在浏览器里。
- 右栏收起时，行上的“预览”把当前这一篇作为浮层打开，盖在列表右侧；↑ ↓ 换篇，Esc 或关闭按钮回到原来那一行。窄于 1100 px 时没有常驻的右栏，行上的工具也收起，靠双击打开阅读页。

**获取 PDF 的范围**：选择栏、批量操作与批次的“获取 PDF”都先打开对话框（设计内核规则 9）。

- 第一块写明范围：来历（勾选的 n 篇，或批次名与筛选条件）、处理多少篇、跳过多少篇及原因（已有 PDF、已标记没找到 PDF、超出本次上限）。
- 按筛选整体提交时有“本次最多 N 篇”，超出时按文献库当前排序取前 N 篇，并写出排序名称；篇数来自服务端预览，不受已加载行数限制。
- “高级选项”默认折叠：受阻时（自动处理 / 通知并继续 / 暂停等待人工）、尝试上限、重试上限、保存后立即执行。
- 主按钮写“获取 n 篇”。

**文件夹**：侧栏上半是目录树（最近读过、文件夹），点文件夹即在本页按文件夹筛选；文件夹视图有“只看本层”开关与“移出文件夹”；文献库里的文献行可拖到文件夹（候选不能：拖一篇候选时提示“候选要先加入文献库，才能放进文件夹”，拖多篇时只带走其中文献库里的），文件夹可拖进别的文件夹。文件夹一组的最后是“最近删除”，只在里面有文献时出现，写着篇数；点开是一个列表，每篇写题名、年份和删除时间，可以“恢复”，恢复后回到原来的文件夹。每个文件夹有菜单：新建子文件夹…、重命名…、上移、下移、移到顶层、删除文件夹…；菜单从行末的“⋯”按钮打开（悬停、聚焦或它是当前文件夹时显示），在行上点右键也打开同一个菜单；“文件夹”一组的标题行另有一个菜单，含“导出分组”，下载整棵文件夹树与成员的 JSON 文件，组下有“新建文件夹”。文件夹、最近读过共用页头模板，标题即视图名。

### 连续选择与选择栏

**用户来做什么**：一次选中一批文献，给它们获取 PDF 或解析全文；选中的文献材料不一，系统替用户分好哪些能做什么。

**连续选择**

- 在勾选框一列按住拖动，经过的行连续选中；从已选的行开始拖动则连续取消。拖到列表上下边缘时自动滚动。
- Shift + 点击勾选框，选中上次点击的行到当前行之间的整段。
- 在未选中的行上按下并移动超过 4 px，拉出选框，经过的行被选中；按住 Shift、⌘ 或 Ctrl 时追加。已选中的行按下即拖起，可放到侧栏文件夹（计划 17 · P29、P30）。
- Esc 取消全部选择。“全选已加载”选满后，列表上方出现一行“选择全部 N 篇符合条件的文献”：它把这 N 篇读到页面上，最多 1,000 篇；超过时这个按钮停用，提示改用“批量操作 → 获取 PDF”。

**选择栏**

```
已选 8 篇   (只有书目 3) (有 PDF 2) (有全文 3)   [获取 PDF 3]  解析全文 2  移动…  更多▾  取消选择
```

- 左侧写选中篇数，紧跟按材料的组成（只有书目、有 PDF、有全文、其他），每类一个小标签；点标签把选择缩小到这一类。“只有书目”包含所有没有 PDF 的文献，没找到 PDF 的也在内。
- 按钮写“对几篇生效”，数字就是实际会被处理的篇数，系统只处理满足前提的那部分：获取 PDF → 只有书目的；解析全文 → 有 PDF 还没有全文、或全文解析失败的（先补解析）；运行算子 → 有全文的。数字为 0 时按钮停用，悬停说明原因（“所选文献都已有 PDF”“所选文献没有要解析全文的；解析全文需要先有 PDF”“所选文献都还没有全文”）；超过 1,000 篇时写“最多处理 1,000 篇，请减少选择。”
- 选择栏从左到右是：获取 PDF、解析全文、移动、更多。在页面空白处点一下（不在文献行、按钮、选择栏和右栏上）取消选择，与“取消选择”相同。所选里有候选时，这几个按钮之前是主按钮“加入文献库 n”，其余按钮都不作主按钮，“移动…”停用，说明“所选里有 n 篇候选，先加入文献库再移动。”：文件夹里只放文献库里的文献（[ADR 0067](../decisions/0067-library-and-candidates.md) 第 5 节）。没有候选时，主按钮是“获取 PDF”与“解析全文”里第一个数字不为 0 的；两个都为 0 时选择栏没有主按钮，停用的按钮不作主按钮。“更多”里依次是（在文件夹里时）移出「文件夹名」、导出…、移出文献库 n…、删除 n 篇…，细线之后是扩展引用…、核验文章身份，然后是“加工”一组：运行算子、生成快照。“删除 n 篇…”先弹出确认，写明文献会移到“最近删除”、书目与文件都保留。选择里有书目不全的文献时，细线之后第一项是“识别书目 n…”，n 是其中有 PDF 的篇数；多选的右键菜单同样。
- 组成与数字按已读到页面上的文献计算（选“全部 N 篇”时即读到的这 N 篇）。
- 运行算子只对有全文的文献运行，对话框写明篇数；其余文献不自动补齐材料。

## 阅读页

**用户来做什么**：读一份资料，需要时回到 PDF 核对；在页边做批注，看它与库里其他资料的关联。还没有全文时，先拿到 PDF 或解析全文。

**区域**：

```
[导航] [标签页 …]        [全文 | PDF] [原文·译文·对照] [目录][查找][高亮▾][Aa][专注][右侧面板][⋯]
──────────────────────────────────────────────────────────────────────────────
案头
     ┌ 纸页 ───────────────────────────────────────────┐ ▏    ┌ 右侧面板（默认收起）┐
     │ 页眉：出处                       视图 · 文本等级 │ ▏    │ 信息 批注 关联 翻译  │
     │ 左页边 │ 正文栏                       │ 右页边   │ ▏书脊 │                      │
     └─────────────────────────────────────────────────┘ ▏    └──────────────────────┘
```

- **顶栏**：一行；导航按钮、按资料打开的标签页、“导图”按钮（有阅读层的资料）、阅读工具、更多。阅读页不显示侧栏导航。[ADR 0071](../decisions/0071-pdf-first-reader-two-floating-balls.md)、[阅读体验 1.9](reading-experience.md#19-小球与程度条)：打开就是 PDF 原件；案头右下角“读”“译”两个悬浮小球，单击是换、双击是并；读本（概览、脉络、全文）在场时它的下方有程度条。
- **案头与纸页**：阅读区是案头，中间一张纸页，分左页边、正文栏、右页边；纸页顶部是页眉，右侧写视图与文本等级。目标（ADR 0070）：纸页顶部是书眉（刊名、当前章节、页码，下面一粗一细的线）；正文栏与右页边之间一条栏线，机器的批语在右页边。
- **书脊**：纸页右边缘外的一条细线，是整份资料的缩略。
- **右侧面板**：信息、批注、关联、翻译四个标签页，默认收起。
- **按材料打开**：有全文时打开全文；有 PDF 没有全文时打开 PDF，页眉下一行提供“解析全文”；没有 PDF 时纸页上排出书目页，提供获取 PDF 与上传 PDF。上传 PDF 用入库的补 PDF 接口（[产品接口 2.4.2](../technical/01-product-interface.md#242-入库-http)），没有大小上限，上传的文件归入当天的“补充文件”批次。

各区域的尺寸、排版与标记、视图的内容、阅读位置、过渡与加载、验证，见[阅读体验](reading-experience.md)。

## 命令面板

- `⌘K` / `Ctrl+K` 或侧栏“搜索”打开；靠上居中的浮层，宽 640。
- 一个大输入框，无标签无按钮；实时显示前 8 条文献（标题、书目、状态）；空输入显示最近读过的 8 篇。
- ↑↓ 选择，回车打开阅读，`⌘回车` 在文献库中查看全部；底部一行“在文献库中查看全部 N 条”，旁边是键盘提示。
- 复用文献库检索接口；输入停顿 150 ms 后请求，新请求中止仍未返回的上一个请求。

## 算子

**用户来做什么**：在一批文献上运行算子；回看运行记录，打开结果。

**排布**：

```
算子                                                         [运行算子]
[运行记录 | 算子与规范]
运行记录：
  [全部算子▾] [来源文献，或选择快照                ] ○ 只看过时
  全文总结 · 规范名  ● 已过时                          查看结果  运行过程
  快照或首篇来源 · 等 N 个输入 · 10/22 14:02 · 网页登录
  有结果 120  结果为空 6  读取不完整 2  未形成结果 1
算子与规范：
  内置算子（全文总结、记录提取、问答标注、多篇综合）各一块：做什么、读取范围、输出；
  已保存的规范列表；外部交付作为次级入口。
```

- 只有一级标签；运行记录的筛选为一行无标签工具条。来源只有一个输入框：输入文字按来源文献筛选，聚焦或输入时下拉列出匹配的快照，选中后按该快照筛选。
- 运行记录是一个列表，不用卡片：第一行为算子名与规范名，过时用徽标，当前版本不加标签；第二行为来源、时间、发起方；第三行为按篇计数，数字加重，未形成结果用失败色。“查看结果”“运行过程”为文字按钮。

**结果详情**：顶部“← 全部结果”、标题与一行说明；结果集合列表、字段表、分页与跨页选择、字段证据侧栏、确认后继续综合、按明确范围完整导出。字段取值在悬停或键盘聚焦约半秒后预览第一段原文（最多 6 行，注明 PDF 页码与原文处数），只读不可交互；点击仍打开证据侧栏核对全部来源。筛选工具条无标签；只有应用筛选后才显示筛选状态。六种核对状态在单元格内用同色小徽标；部分结果与未知值保留原义。

**四步对话框**：步骤条（范围 → 算子 → 规范 → 确认）；底部“上一步 / 下一步”，最后一步为“开始运行”。每一步高度相同，步骤条与底部按钮位置固定。确认页用定义表列出范围、算子、规范、输入与缺口，下面是复用与 token 预估。已有范围时步骤条只显示三步。提交以当次范围和规范为准，重复点击不重复建任务，失败保留草稿。

## 快照

**用户来做什么**：把一批文献及其版本固定下来，命名、比较，并在上面运行算子。

**排布**：列表页加详情页（对象页）。

- 列表页为表格：名称、篇数、创建时排除、创建时间，数字右对齐，点行进入详情；窄屏隐藏“创建时排除”。页头右上“从当前筛选生成快照”。没有快照时只显示一句说明。
- 详情页：顶部“返回快照列表”，标题为快照名称（可改名、可恢复默认名称）；内容按节往下排：成员与版本（生成条件、成员）、与另一快照对比、运行算子（打开四步对话框并跳过范围）、基于此快照的运行记录。打开的快照记在 URL 中，可后退。

## 全文检索

**用户来做什么**：在全文与算子结果中找片段，挑出来交给 Agent。

```
全文检索
[全文 | 算子结果]
[ 输入要查找的问题或关键词                              ] [检索]
（索引不是最新时）索引状态一行
▸ 高级检索选项
10 条结果
文献标题（衬线）
书目
  2 结果与讨论 · 第 4 页 · 全文 · 未校对
  │ 命中处前后的原文，检索词用证据黄标出……
  │ 在全文中查看 · 记下出处 · 加入上下文
  展开另外 3 条
```

- 全文：大搜索框，下面一行提示检索按词匹配、不扩展同义词；解析全文时存下的译文也在索引里，用译文语言可以搜到另一种语言的资料，这样的命中在位置后面标“译文”，摘录显示译文（无衬线、`--fg2`），原文的摘录用衬线；“在全文中查看”打开原文那一段。加入上下文后复制为 Markdown 时，译文命中的正文前写明“译文（机器翻译，语言）；引用请以出处的原文为准”。内容范围的三种模式叫“全文与知识”“仅全文”“仅知识”。索引按旧规则建成时，状态行写“检索规则已更新，需要重建索引”（译文语言改了时写“译文语言已更改，需要重建索引”），书目检索按旧规则时另有一行并提供“重写书目检索”；两个操作都只在点击并确认后执行。命中按文献分组，组标题是文献标题与书目；每条命中先写它在文中的位置（章节名，取不到时写“正文”，书目命中写“书目与摘要”；PDF 页码能取到时写页码）与文本等级（“全文 · 未校对 / 已校对”），次要色；片段是命中处前后的原文，最多四行，不重复标题，去掉 Markdown 标题符号。同一篇超过 3 条时先显示 3 条，其余“展开另外 n 条”。
- 命中下方的“在全文中查看”“记下出处”“加入上下文”（已加入时为“移出上下文”）是操作，用笔色（设计内核规则 10）。
- “上下文”栏在选了第一个片段后才出现，在右侧，可复制为 Markdown 或导出 JSON。
- 没有结果时只有一句话和一个建议。
- 算子结果：一行无标签工具条（检索范围、只看过时结果、关键词），列表行为集合或结果名、算子、过时徽标与“打开”。地址为 `view=ask&results=all`。
- 索引状态：搜索框下方一行，只在索引不是最新时出现，与结果状态行分开。状态取自索引状态读取，索引在变化时每 2 秒刷新一次，平时 30 秒一次，离开本页即停止。

  | 状态     | 显示                                                                                                    | 操作                                                         |
  | -------- | ------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
  | 最新     | 不显示                                                                                                  | —                                                            |
  | 更新中   | “全文索引正在更新，还有 N 篇的最新内容暂时搜不到。”（拿不到篇数时写“最近变化的文献暂时搜不到最新内容”） | 无；完成后若当前结果来自旧索引，显示“索引已更新”和“重新检索” |

  | 尚未建立 | “还没有全文索引，原文和元数据都搜不到。”，并写明约需几分钟、可以离开本页                                | “建立索引”                                                   |

## 任务与 Agent 会话

**用户来做什么**：看后台在跑什么、跑到哪一步、哪里失败；必要时查看任务发起的 Agent 会话原样记录。

**排布**：

```
任务  2 个进行中
[任务 | 需处理 | 浏览器 | Agent 会话 | 来源统计]
[全部 · 进行中 · 有问题 · 已结束]  [搜索任务]       已显示 20 个任务，符合筛选 20 个
任务                     发起方      进度            状态        开始
获取 PDF · 12 篇         网页登录    ███████░░ 8/12  ◌ 进行中    14:28
解析全文 · 文献标题      CLI                         ● 已完成    09:46
```

- 状态用词按[界面用词](#界面用词)。“未启动”与“排队中”的区分来自任务的活动记录里有没有“请求启动”一条（[任务协调](../technical/02-task-coordination.md)）；服务重启后，请求过启动而仍在排队的任务自动接着排，已中断的任务仍要手动继续。
- 每种状态只给用得上的按钮：未启动的有“启动”“取消任务”，排队中与进行中的有“暂停”“取消任务”，等你处理与已中断的有“继续”“取消任务”，失败的有“重试”。取消要先确认。
- 任务名写出对象：只有一篇时写“解析全文 · 文献标题”，多篇时写“获取 PDF · 10 篇”；只有一项的任务不画进度条，其余在有总数时画进度条，否则写已处理数。
- “发起方”一列在所列任务全是同一来源时不显示；时间按设计内核规则 6。
- 点行从右侧打开详情面板：总结（见“获取任务详情”）、运行过程、逐篇结果与失败原因、该任务发起的 Agent 会话。获取 PDF 任务的逐篇结果带一行获取经过，按实际尝试顺序列出来源与结果，例如“Elsevier API 未命中 · 公开网站未命中 → Browser Agent · 已入库”；没有发起网络请求的来源写“未启用”或“冷却中”，不写成未命中。面板不遮挡列表，可以直接点另一行切换；Esc 或关闭按钮收起，焦点回到原行；地址记录打开的任务，可后退。面板打开时表格隐藏发起方与开始两列。
- 任务在等人处理时，详情里有一块“任务等你处理”，按钮是“继续任务”“跳过此项”“取消任务”。
- 按范围提交的获取 PDF 任务，详情顶部写出范围：来历与条件，以及创建时的处理与跳过篇数。
- 长文档的解析全文任务，详情的步骤列表中校对一步写“长文档，未逐页校对（n 页）”。
- 窄屏：表格改为卡片式列表，详情面板占满全屏。
- **Agent 会话**（主从容器）：左为会话列表（算子或校订、文献标题、状态、已用时间、token），列表上方的状态筛选为“正在运行 / 最近会话 / 失败”；右为原样的 DSH 会话记录。列表包括没有对应任务的直接调用。

### 获取任务详情

**用户来做什么**：先看这次任务怎么样、用了多久，再看每篇的经过。

所有任务的详情都以同一段总结开头：

- 状态与用时（进行中为已用时，逐秒更新），后跟起止时间；未启动的写“未启动 · 某时创建”，不计用时；
- 一块浅灰底块，写一句结果：完成、失败、未处理各几项；进行中时附进度条。

- 一句结果：拿到几篇、没拿到几篇；

### 来源统计

**用户来做什么**：看出哪些来源好用、哪些不好用，好找问题；统计只供人判断，系统不据此调整获取顺序。

“来源统计”标签页右侧是时间范围 [近 30 天 | 全部]。

```

  来源                     尝试   拿到   拿到比例             错误
  Elsevier API 出版社 API   140    128   ██████████░ 91%     1%
  Wiley API    出版社 API    61      9   ██░░░░░░░░░ 15%     5% [无全文权限]
  Sci-Hub      公开网站     168     59   ████░░░░░░░ 35%     未收录 98

  来源               检索覆盖     补全命中     引用命中     错误
  OpenAlex            74%          91%          88%         <1%          —
                    38 次检索    1,204 篇      96 篇     1,338 次请求
  CORE                 5%          27%          12%          9%      [API Key 无效]
```

- 两张表：PDF 来源按获取顺序排列，来源名后用次要色写所在阶段；元数据来源按检索覆盖从高到低。
- PDF：尝试 = 进入该来源并实际发出请求的篇数（未启用、冷却中不计）；拿到 = 由该来源拿到 PDF 的篇数；比例条统一用强调色，不因比例低改成失败色——低比例可能是来源本身覆盖面窄。没拿到不等于错误：没有全文、未收录是正常结果。错误 = 请求本身失败的比例。
- 元数据只用比例，不用累计条数：累计条数和“新入库”都随文献库变大而变化（库越全，新入库越少），不能说明来源好坏。按三种用途各一个比例，分母写在比例下方：
  - 检索覆盖：每次主题检索合并去重后的结果中，有多少是这个来源找到的，取各次检索的平均。说明它“找得全不全”，与库里已有多少无关。
  - 补全命中：请它补全的文献中，它查到匹配记录的比例。
  - 引用命中：请它查引用的文献中，它给出引用列表的比例。
  - 错误：失败请求占全部请求的比例。
  - 不提供该用途的格子写“—”；缺配置的来源整行“—”。
- 错误比例不小于 5% 时用失败色。错误不分类，只在出现下面三种时于行尾加一个失败色小标签；行不可展开。
- 数字全部取自各任务的逐来源记录，与任务详情一致，不另算一套；历史任务没有逐来源记录的不计入，表头下注明统计起点一次。
- 窄屏：每个来源两行，第一行名称与阶段，第二行比例条（附“拿到 / 尝试”）与主要原因。

任务页的一个标签页（见“整体信息架构”）。

处理型清单。没有问题时只显示一句空状态。工具条上是“问题原因”下拉框（各项带条数）与“共 n 项”。有问题时按问题分组，分组标题写问题本身（“解析服务连不上”“书目缺少必填项”），不写整句报错；每行显示文献、步骤与是否影响阅读，一个主要动作放在行内，编辑在该行下方展开；勾选后才出现“确认已处理（n）”。

## 设置

对象为配置，形态为“左侧分区导航 + 定义表”。设置按“要做的事”分区。

- 桌面：页内左侧为竖排分区导航，宽 180，顺序为外观、模型服务、获取 PDF、解析全文、设备连接、网络、文献库文件、运行状态、高级；窄屏改为页头下方的下拉菜单。“退出登录”在页面最下方，不属于任何分区。
- 每个分区由若干块组成，每块为标题、可选的一句说明和一张定义表：左列为名称加一句说明，右列为控件，能给出当前生效值时写在控件下方。参数的说明写它是什么、调大调小的后果。
- 路径用等宽字体单行省略，旁边一个复制图标按钮。
- 保存按钮在每块底部的右下角，一直在：没有改动时停用，悬停说明“还没有改动”；有改动时是主按钮，旁边写“有未保存的改动”。数字框输入一个范围内的新值即算作改动，不必先离开输入框。切换分区保留草稿；离开设置页时提示是否放弃。
- 密钥与令牌只显示“已保存”或“未填”与替换、清除，不回显值。没有单独的“凭据”分区：模型服务的密钥在该服务的块里，文献来源的密钥在该来源的行里。

各分区：

- **外观**：主题卡片（[设计内核 · 主题](design-core.md)的七套，加“跟随系统”；选跟随系统时另有“白天”“夜里”两项）、默认阅读字号（16–32 px）、阅读行宽（窄 / 适中 / 宽，与阅读页排版面板是同一项）、动效（跟随系统 / 减少动效 / 完整动效）。
- **模型服务**：每个服务一块，块内是名称、协议、地址、密钥、模型（远程名称、推理强度、支持图像、流式输出）与测试，以及添加、移除模型；下方有“添加”。后面是“角色绑定”一块：分析模型、校订矫正模型、文献打标模型、词表整理模型、标签回溯模型、浏览器模型。
- **获取 PDF**：“文献来源”（见下面的“文献来源”一节）、“主题检索”（元数据结果上限）、“受控浏览器”（启用浏览器、浏览器个人资料、浏览器模型、连接测试）。
- **解析全文**：“解析服务”（地址、连接方式、模型、访问令牌、连接测试，以及只读的解析方式）与“参数”（每篇标签上限、候选检索数量、回溯批量）。
- **设备连接**、**网络**：见下面两节。
- **文献库文件**：文献库文件与文件存放位置，改动前提示要重启。
- **运行状态**：只读，逐项列出各部分是否就绪与下一步该做什么，右上“刷新状态”。
- **高级**：第一块是“配置 → 重新读取配置”；下面是维护工具本身，分“材料与分析 / 规范与交付 / 索引与请求”三项。文件选择用本站的按钮样式与中文；要求填机器编号的地方改为从文献库选择。

### 错误的呈现

真实网络中的错误无法穷举，界面不对错误分类：凡请求失败一律显示为“错误”。只有三种用户能直接处理的情况单独写出名称：**未配置**、**凭据无效**（API Key / Token 被拒）、**无全文权限**（出版社认证通过但无订阅）。没拿到结果（无全文、未收录、0 条）是正常结果，不算错误。具体原因码只出现在“技术详情”里，供排查。

- “来源”是一张表，每个来源一行，每格只放一个符号或短语：
  - 用途四列：元数据分为主题检索、补全书目、引用关系三列（表头上方一个“元数据”分组标），加一列 PDF。格里写“在用”“未启用”（能用但缺配置或自定义关掉）或“—”（不提供）；PDF 列的“线索”表示只提供 PDF 链接、交给直链阶段下载。直链一级里的来源写“直接链接”。自定义模式下，对应列的标记变成开关（元数据与 PDF 各自独立）。
  - 配置：缺什么（失败色字，“缺联系邮箱”，整行不着色）、已配置了什么（“API Key 已配置”）、可选增强（灰色，“可加 API Key”）或“无需配置”；可展开的配置后带 ›。

- 测试做真实但最小的请求，只判断“能不能用”，不写入文献库：元数据来源对固定样本做一次查询；PDF 来源对固定样本请求一次 PDF 并只校验响应（不保存、不发布），出版社 API 区分“无全文权限”；Browser Agent 只检查运行时能否启动。测试结果保留到下一次测试或配置变更。CLI 的 `config test` 是另一组更保守的探测，PDF 来源不发请求，见[配置手册](../../guides/configuration.md)。
- 缺配置的行置顶；其余按“出版社 API、通用 API、元数据、公开与内置”大致分组排列。
- 点一行展开它的配置：凭据只显示“已配置”与替换、清除，不回显值；参数如联系邮箱、Web of Science 产品与数据库、Sci-Hub 镜像；“保存”在展开区内，只保存这一个来源，保存后自动测试一次。无需配置的来源不可展开。
- 表下另有一行“Browser Agent 运行时”与“测试”，只检查运行时能否启动。
- **自动**：配置齐全的来源全部启用，包括无需配置的公开来源与 Sci-Hub 内置镜像。**自定义**：用途格变成开关；顺序仍按阶段，不提供拖动排序。
- 窄屏：表头保留名称与四个用途列；每行两行，第一行名称与用途标记，第二行配置与测试；获取顺序改为每级一行。
- 保存后由页头的“应用配置”生效，不需要在终端重启服务。

**用户来做什么**：让直连不通的服务改走代理，看清哪些服务走代理。决定见 [ADR 0056](../decisions/0056-outbound-proxy-by-requester.md)。

- 代理地址只接受 `http://主机:端口`。认证展开后填用户名与密码；已配置时只显示“已配置”与替换、清除，不回显值。

- 其他分区只显示、不修改：“文献来源”表与“模型服务”节中，走代理的项在名称旁加灰色小字“经代理”；走代理的来源测试成功时写“可用 · 经代理”。代理连不上时，这些测试显示“错误”。

### 设备连接

**用户来做什么**：让浏览器扩展或自己电脑上的 Agent 连上文献库，看清连了哪些设备，不用了就撤销。决定见 [ADR 0058](../decisions/0058-import-system-and-agent-access.md)。

```
设备连接                                   [连接浏览器扩展]  [连接 Agent]
  名称              用途          连接于           最近使用         状态     操作
  办公室笔记本 Agent  入库 · 读取    11月10日 14:02   11月10日 15:30   已连接   [改名] [撤销]
  Chrome 扩展        入库          11月10日 14:10   —                待配对   [改名] [撤销]
  旧电脑             入库          11月2日 09:12    11月3日 18:40    已撤销
```

- 点“连接浏览器扩展”或“连接 Agent”打开对话框：名称（预填“浏览器扩展”或“Agent”）与用途。用途三个勾选框：入库、读取、操作，各带一句说明（入库：收藏网页、从 Zotero 或文件入库，只能看到本设备发起的批次；读取：经 MCP 查询与阅读文献库；操作：经 MCP 发起获取、加工等任务）。扩展默认勾入库，Agent 默认勾入库与读取；“操作”从不默认勾选，说明里写明它能发起会联网、会花费的任务。至少勾一项才能生成。
- 生成后对话框换成交付页：
  - 连接码等宽显示，旁边“复制”；下面一行写剩余有效时间（“9 分 40 秒内有效，只能用一次”），每秒更新，到期后写“已过期，请重新生成”。
  - 连接 Agent 时另有一段“复制给 Agent 的话”：说明连接码的用法、令牌只存本人可读的文件、请求头带令牌，并指向文献库自带的使用说明；“复制”按钮在段落右上。
  - 关闭对话框后连接码不再显示，也不保存在页面以外的任何地方；丢了就重新生成。列表里这一行显示“待配对”，过期未用的同样显示“待配对”，可以撤销。
- 列表显示全部连接，包括已撤销的（灰色、无操作），按状态（已连接、待配对、已撤销）再按连接时间倒序。名称可改；撤销前确认一次，确认框写明“该设备的请求会立即被拒绝，要再连接需重新生成连接码”。
- 表下两行“下载扩展安装包”与“下载 skill”，分别对应 `/api/v1/intake/extension` 与 `/api/v1/intake/skill`（[产品接口 2.4.1](../technical/01-product-interface.md#241-设备连接与按用途准入)）。还没构建时按钮旁写“扩展安装包尚未构建”或“skill 包尚未构建”。
- 地址取页面自己的地址；用户经端口映射打开页面时，连接码里就是映射后的地址。

## 浏览器扩展弹窗

**用户来做什么**：在出版社或预印本页面上点扩展按钮，看这篇在不在库，不在就连同 PDF 收进来；或者从 Zotero 导入。决定见 [ADR 0057](../decisions/0057-zotero-import-and-browser-capture.md) 第 5 节、[ADR 0058](../decisions/0058-import-system-and-agent-access.md) 第 1、2 节与 [ADR 0063](../decisions/0063-unified-intake.md) 第 6、10 节。

弹窗宽 360，与工作台同一套颜色与字体。从上到下是状态区、正文、“从 Zotero 导入”一行、底部一行“已连接 http://localhost:4174 · 设置”。

```
未连接                         已在库                          不在库
┌──────────────────────┐   ┌──────────────────────┐   ┌──────────────────────┐
│ 连接文献库            │   │ ● 已在库 · 已有 PDF   │   │ Argyrodite electro…  │
│ 粘贴设置页生成的连接码 │   │ Argyrodite electro…  │   │ Smith, Lee 等 · 2021  │
│ [sr-connect1:…     ] │   │                      │   │ DOI 10.5555/abc      │
│            [连接]    │   │                      │   │ 文件夹 [不放进文件夹▾]│
└──────────────────────┘   │──────────────────────│   │ ☑ 连同 PDF           │
                           │ 从 Zotero 导入      › │   │            [收藏]    │
                           └──────────────────────┘   │──────────────────────│
                                                       │ 从 Zotero 导入      › │
                                                       └──────────────────────┘
```

**收藏这一页**（弹窗的主体）：

- **未连接**：
  - 一个输入框粘贴连接码，“连接”。
  - 浏览器先询问是否允许访问文献库地址；拒绝时写“没有访问 <地址> 的权限，扩展无法连接”。
  - 连接码过期、已用时照服务端原因写出，并提示到设置页重新生成。
  - 未连接时不显示“从 Zotero 导入”一行。
- **连不上**：写“连不上 <地址>”，下一行“文献库在服务器上时，请检查端口映射是否开着”，以及“重试”和“修改地址”。
- **读页面**：
  - 只在打开弹窗时读当前页一次，把页面标签原样交给文献库预览（[产品接口 2.4.2](../technical/01-product-interface.md#242-入库-http)）。
  - 读出的书目与 PDF 地址以服务端的预览结果为准。
  - 读不到标识、但有标题时照常可以收藏。
  - 标识与标题都没有时写“这一页没有读到书目，无法收藏”，并提供一个输入框“DOI 或 arXiv 号”：填写后再预览一次。
- **已在库**：
  - 状态徽标写“已在库 · 已有 PDF”或“已在库 · 还没有 PDF”，下面是库里的标题。
  - 还没有 PDF 且预览给出了 PDF 地址时，显示“补上 PDF”。
- **不在库**：
  - 标题、作者（最多三位，其余写“等”）与年份、标识；没有标识时写“没有读到 DOI 或 arXiv 号”。
  - “文件夹”下拉，默认不放进文件夹，按层级缩进。
  - “连同 PDF”勾选框，预览没有给出 PDF 地址时不显示。
  - 主按钮“收藏”。
- **可能重复**：预览给出可能重复的候选时（只在没有标识的页面上出现），“不在库”的正文下方加一块：
  - 标题“库里可能已有这篇”，下面列出候选，最多 3 个，每个一行：标题 · 第一作者 · 年份。
  - 两个选择：每个候选行尾的“并入这一篇”，以及底部的“作为新文献收藏”。
  - 主按钮“收藏”在使用者选定之前不可用；选定后按钮写“并入并收藏”或“作为新文献收藏”。
  - 使用者不选、直接关闭弹窗时，不收藏，不入库。
  - 并入时，结果一行写“已并入库里的《标题》”。
- **收藏中**：
  - 按钮写“正在收藏…”；有 PDF 时依次写“正在下载 PDF”“正在上传 PDF”。
  - PDF 所在网站第一次用到时，浏览器会询问是否允许访问该网站；拒绝时书目照常保存，写明 PDF 没有收进来。
- **收藏结果**：
  - 写“已收进‘网页收藏 2026-11-14’”。
  - 下面一行写 PDF 的结果：已上传、库里已有相同文件、与库里的 PDF 不同（不替换）、没能下载（原因）。
  - 补全元数据部分或全部失败时，加一句“文献信息来源暂时没能补全，书目已保存”。
- **设置**：显示地址，可以修改（令牌不变）；“断开连接”删除本机保存的令牌，并提示到设置页撤销这个设备。

**从 Zotero 导入**（弹窗下方一行）：点击后打开扩展自己的整页，弹窗关闭。整页的各状态：

- **找不到 Zotero**：写“没有连上本机的 Zotero”，并说明三件事：Zotero 需要保持打开；需要在 Zotero 的设置中开启本地接口；需要允许扩展访问 `http://localhost:23119`。下方有“重试”。
- **选择**：
  - 左侧列出个人库与群组库；右侧是所选库的分组树，可以勾选多个分组，或勾选“整个库”。
  - 下方写所选范围的条目数与附件数；主按钮“开始导入”。
  - 这一步不交任何数据。
- **交清单**：写“正在读取 Zotero 并交给文献库 n / 总数”，可以“停止”。交完后自动在新标签页打开文献库里这个批次的页面，整页写“已交给文献库，请在文献库的批次页上预览和确认”。
- **需要数据文件夹**：扩展读不到 Zotero 的文件时，写“请选择 Zotero 的数据文件夹，以便上传 PDF”，并说明默认位置（Windows 为 `C:\Users\<用户名>\Zotero`，macOS 为 `~/Zotero`）；主按钮“选择文件夹”。只需要选一次。
- **后台上传**：
  - 确认之后，扩展在后台上传文件。
  - 整页与弹窗下方一行写“正在上传 n / 总数”；进度以文献库的缺失清单为准。
  - 浏览器关闭后再打开，扩展从缺失清单继续。
  - 上传完成后写“文件已交齐”。
  - 预览、进度细节和报告都只在文献库的批次页上，扩展不显示。
- **连不上文献库**、**令牌已撤销**：写法同上面的“连不上”与“未连接”；后台上传暂停，恢复连接后继续。

任务页的一个标签页（见“整体信息架构”）；下面的内容不变。

**用户来做什么**：看 Agent 获取 PDF 的过程，监督它干活；想点就直接在它的画面上点。Agent 是一套固定能力的获取流程，不是万能助手；流程失败就由 Owner 自己获取 PDF，页面不暗示“人帮一把就能成功”，也不出现“人工接管”“需要你帮忙”一类说法。

**排布**：

```

  本次获取 · 10 篇 · 14:02 开始 · 3 进行中 · 2 等待 · 5 已结束
    [卡] 衬线标题                      ● 推理中            观看 Agent
    [卡] 衬线标题                      ● 等待执行          观看 Agent

      标题 · ✓ 已入库

```

- 每篇会话（卡片与已结束的行）显示一行小字“已尝试：Elsevier API 未命中 · 公开网站未命中 → 交给 Agent”，说明为什么轮到 Agent；没有记录时不显示。
- 会话按获取任务归组，组标题写开始时间、篇数与各状态计数；进行中的组在上，每篇一块底块；已结束的组在下，默认折叠，展开后每篇一行。

- 阶段颜色：推理、下载、验收等进行中为绿色；等待执行为灰色；已入库为中性灰带勾；未获取为红色，并原样显示 Agent 的停止原因。

**观看**：

- 画面占主要宽度。Agent 的鼠标指针叠在画面上，随每次动作移到目标位置；点击时出现一圈波纹，指针旁写一句动作，例如“点击 View PDF”。指针位置来自 Agent 实际动作的坐标或元素位置，不推测。
- 右栏是动作记录：按时间往下列 Agent 实际做过的动作（点击的元素或位置、滚动、输入、新页签、进入的页面标题）和平台事件（开始下载、验收通过或失败）；流程停止时把停止原因放在末尾。不预设步骤，不替 Agent 编写理由。
- 画面可以直接点击、滚动、输入：第一次操作时 Agent 暂停，顶部写“你在操作 · Agent 已暂停 · 停手 10 秒后继续”，旁边一个“现在继续”；停手满 10 秒自动交还。不显示页面元素按钮墙。
- 剩余模型调用与时间以一行小字显示。“更多操作”折叠在动作记录下方：“暂停 Agent”、暂停或继续会话、页面上的链接与按钮列表（画面是图片，键盘用户靠它操作页面）、页面文字、给 Agent 的可选指导、取消会话。

## 找文献

**用户来做什么**：把文献放进文献库：从检索来源发现、点名要某几篇、放入手头的文件、从 Zotero 导入，或在网页上收藏；之后在批次记录里看每一批的结果，决定接着做什么。决定见 [ADR 0052](../decisions/0052-intake-batches-and-explicit-scope.md) 与 [ADR 0063](../decisions/0063-unified-intake.md)。

本节按 ADR 0063 第 10 节规定“找文献”页与批次页；接口见[产品接口 2.4.2](../technical/01-product-interface.md#242-入库-http)，过程与状态见[文献与材料 6.4.2](../technical/03-literature-materials.md#642-过程与状态)。

```
入库
  检索 · 指定文献 · 文件 · Zotero · 网页
  ┌──────────────────────────────────────────────────────────┐
  │ 把 PDF、文件夹或导出文件拖到这里，或 [选择文件] [选择文件夹] │
  │ 支持 PDF；BibTeX、BibLaTeX、RIS、CSL JSON 导出文件           │
  └──────────────────────────────────────────────────────────┘
批次记录
  我的文库 (Zotero) 改名                 待确认      新增 120 · 已在库 30 · 可能重复 3
  11月14日 15:20 · 扩展 · Chrome          ▓▓▓░░ 有 PDF 30 · 没找到 PDF 2 · 待获取 118   [在文献库查看]
  library.bib 改名                        部分完成    新增 118 · 冲突 2 · 未交文件 12
  11月14日 14:02 · 网页 · library.bib     ▓▓▓▓▓ 全部有 PDF                              [在文献库查看]
```

**顶部标签页**：检索、指定文献、文件、Zotero、网页五个。单篇补 PDF 不在“找文献”页，从文献行或阅读页上传。

- **检索**：一个分段控件切换“主题发现”与“引用扩展”两张表单。表单为定义表；数字框按内容取宽。
  - 主题发现：主题或检索式、逐来源扫描上限（默认 200）、出版年份（起止合成一行）。
  - 引用扩展（[ADR 0064](../decisions/0064-citation-expansion-bounded-by-depth.md)）：种子文献、方向（参考文献或被引文献）、层数（0–32，默认 1）、结果上限与扫描上限（都可以不填，不填即不限）。
    - 种子文献从文献库里选，不填编号（设计内核规则 8）：一个搜索框按标题或作者找，下拉列出前 8 篇（标题 · 第一作者 · 年份），选中即加入；粘贴的文献编号也能找到这一篇。可以选多篇，最多 1,000 篇，同一篇只算一次。
    - 已选的种子在搜索框下逐篇列出（标题 · 第一作者 · 年份），每篇有“移除”；超过 5 篇时先列 5 篇，其余“另外 n 篇”展开；列表上方写“已选 n 篇”，有两篇以上时旁边“全部移除”。没有种子时“开始扩展”不可用，旁边写“先选种子文献”。
    - 从文献库带入：选择栏的“更多”与文献行菜单里的“扩展引用…”，打开“找文献”页“检索 → 引用扩展”，所选文献已作为种子（选择栏最多 1,000 篇）；种子只留在页面里，不写进地址。
  - 提交前打开“确认发现文献”对话框：范围一行（引用扩展如“6 篇种子 · 1 层 · 不限条数”，主题发现如“每来源最多 N 条”）；服务一行列出本次会查的来源名称，没有在用的来源时写“没有在用的来源，可在“设置 · 获取 PDF”里补上配置”；主按钮写“开始发现”或“开始扩展”。
  - 确认后对话框立即关闭，主按钮变为“正在发现…”并暂不可用，下方写明“正在查找，进度见下方批次记录；完成前请不要关闭本页。”
- **指定文献**（目标，尚未实现；规则见[文献与材料 6.4.12](../technical/03-literature-materials.md#6412-指定文献逐行给出标识或标题)）：知道要哪几篇时用。
  - 一个多行输入框，上方一句说明：“每行一篇：DOI、文献的网址，或完整的标题。”占位文字给三行例子（一个 DOI、一个 arXiv 地址、一个标题）。
  - 输入框下方左边写“n 行”，超过 200 行时改用警示色写“一次最多 200 行，请分批”，按钮停用；右边是主按钮“查找这些文献”，没有内容时停用。
  - 按下后建批次、交数据，并打开这个批次的页面；这一步不写文献库。批次名默认“指定文献 · n 篇”。
  - 批次页照现有的预览：认出的、已在库的、需要决定的各自成段。需要决定的有两种：“可能是这一篇”（采用一项，或都不是）；“没认出”（每行写出原文与原因，可以选“仍然入库”，默认不入库）。无法处理的行（不支持的网址、太短）列在“没有导入的内容”里，写出行号与原文。
  - 确认入库后，这些文献在文献库里；批次页照常提供“获取全文”。
- **文件**：一个放置区，接受 PDF、文件夹与导出文件，可以拖入，也可以用“选择文件”“选择文件夹”。
  - 自动识别的规则：
    - 扩展名为 `.pdf`，或者内容以 `%PDF-` 开头的，是 PDF；
    - 扩展名为 `.bib`、`.ris`、`.json`，或者内容符合 BibTeX、RIS、CSL JSON 格式的，是导出文件，格式写在放置区下方的一行里，可以改。
    - 文件夹逐层展开，按同样的规则识别其中的文件。
  - 一次放入的内容形成一个批次：
    - 只有 PDF 时，每个 PDF 是一条只有文件的条目；
    - 有导出文件时，导出文件与同一次放入的 PDF 按导出里写的路径配对（[文献与材料 6.4.3](../technical/03-literature-materials.md#643-只有文件的条目与配对)）。
    - 一次只接受一个导出文件。
  - 识别不了的文件不交给服务端，在放置区下方逐个列出：“没有识别出这个文件的格式：<文件名>”，并说明支持哪些格式。导出文件的格式识别不了时，格式一栏为空，必须选一个才能继续。
  - 放入之后立即建批次、交数据与文件，并打开这个批次的页面；这一步不写文献库。放入的是导出文件时，先确认格式，再点“继续”。
  - 导出文件不超过 7 MiB。
- **Zotero**：
  - 上方一行写扩展的连接状态：“已连接扩展 · <连接名>”或“没有连接扩展”。“已连接”指 `kind` 为 extension、已配对、未撤销、带“入库”用途的连接；`kind` 为 null 的旧连接不算扩展。
  - 下面一句说明：“从 Zotero 直接导入还没有开放。现在可以在 Zotero 里导出 BibTeX 或 RIS，再从‘文件’导入。”开放之后（[计划 28](../../plans/2026-11-25-import-and-pdf/README.md) 的 07、16）改回：“在扩展里选择要导入的库和分组。导入开始后，这里的批次记录会出现这一批。”
  - 没有连接扩展时，写明三步：在“设置 · 设备连接”下载扩展安装包；在浏览器的扩展页面以开发者模式加载；在设置页生成连接码，粘贴到扩展里。三步各带一个按钮：下载扩展安装包、复制扩展页面地址、前往设备连接。
- **网页**：
  - 一句说明：“在出版社或预印本的文献页面上，点浏览器工具栏里的扩展按钮即可收藏。”
  - 下面一行写扩展的连接状态，写法同 Zotero 标签页。

**批次记录**：标签页下方是全部批次，只有一种行，不论由检索、文件、扩展、Agent、CLI 还是 MCP 发起，也包括合成的“早期入库”。原来单独的导入列表并入其中。

- 按建立时间倒序，分页加载。
- 每一行的左侧：
  - 名称，点名称打开批次页，旁边“改名”；
  - 第二行：时间 · 发起者（网页、CLI、MCP，或“扩展 · 连接名”“Agent · 连接名”，连接的 `kind` 为 null 时写“设备 · 连接名”）· 范围（年份、来源或文件名）。
- 每一行的中间：状态徽标。已结束的批次显示结果（完成、部分完成、失败、中断）；其余显示状态（收集中、待确认、进行中、已取消、已撤回）。
- 每一行的右侧：
  - 计数“新增 · 已在库 · 恢复 · 冲突 · 可能重复 · 未接纳”，0 不显示；有来源未完整返回时写出几个；
  - PDF 进度细条，加一行“有 PDF n · 没找到 PDF n · 待获取 n”（全有时写“全部有 PDF”）；
  - “在文献库查看”。
- 合成的“早期入库”一行写“迁移前已有，没有逐次记录”。
- 有处于收集中、待确认或进行中的批次时，记录每 3 秒刷新。刚建立的批次出现在最上方。

### 批次页

批次在“找文献”页内打开，地址里带批次编号；“返回”回到“找文献”页。各部分自上而下：

```
library.bib                                              待确认
  网页 · 11-14 14:02 · 来源 library.bib（导出文件）
  新增 118 · 已在库 30 · 冲突 2 · 可能重复 3 · 未接纳 1 · 文件 要上传 118 · 只核对 30
需要决定（6）
  可能重复   Solid electrolytes: a review · Doe 2020   [并入 ▾] [新增]
  可能是这一篇  scan_0041.pdf → Argyrodite electrolyte one (2021)  [采用 ▾] [都不是]
  未配对的文件  supplement.pdf   [作为单独的文献入库] [不入库]
                                                    [取消]  [确认入库]
```

1. **页眉**：
   - 名称，可改；
   - 第二行：来源（库名、文件名或网页）、发起者、建立时间；
   - 右侧是状态徽标，已结束的批次显示结果。
2. **计数概况**：
   - 预览阶段写“预览（估计，确认时按当时的文献库重新判定）”，之后写实际数；
   - 分类为新增、已在库、恢复（重新入库了以前撤回的文献）、冲突、可能重复、书目不全、未接纳；
   - 文件写要上传与只核对的个数；
   - 批注写可导入、不能导入的条数；
   - 有 PDF 的内容没读出来时，另写一行“没读出内容的 PDF”，按原因列篇数（扫描件、加密、不是有效的 PDF、读取超时、读取失败、服务器读不了 PDF），并说明它们按文件名入库、入库后可以“识别书目”；
   - 不导入的内容写各种类的数量。
3. **需要决定的事项**：可能重复、可能是这一篇、未配对的文件三类，每类一个小标题与条数。每条一行：
   - 可能重复：库里的候选（最多 3 个，标题 · 第一作者 · 年份），“并入”下拉选一篇，或“新增”。
   - 可能是这一篇：候选（最多 3 项），“采用”下拉选一项，或“都不是”。
   - 未配对的文件：“作为单独的文献入库”或“不入库”。
   - 已作出的决定写在行尾，可以改，直到确认；批次结束后只剩待决定的条目可以处理。
   - 没有需要决定的事项时，整块不显示。
4. **进度**：
   - 认篇时写“正在识别文件 n / 总数”，旁边有“停止识别”；
   - 进行中写当前阶段（书目入库、等待文件、收尾）、“已处理 n / 总数”，以及文件进度细条（已上传、已有、冲突、待交）。
   - 还有待上传的文件时，显示“选择文件夹”按需续传，匹配不到的文件逐个列出，并有“结束入库”：它把余下的文件记为未交，确认前再问一次。
5. **报告**：
   - 按计数概况的分类写实际结果；冲突、未接纳与待决定的条目逐条列出原因；
   - 文件的冲突与未交逐个列出；
   - 一行全文取得情况：“全文已取得 n / 总数 m，未取得 k（其中自动途径已试完 j）”。
6. **接着做什么**：
   - 两个按钮，“获取全文 n 篇”与“解析并形成未校对的全文 n 篇”，n 为预估数，为 0 时按钮不可用；
   - 旁边写明“会联网，可能花费”；“获取全文”先打开与文献库相同的获取 PDF 范围对话框；“解析并形成未校对的全文”打开同名对话框：第一块写范围（批次名与预估要解析的篇数，取批次的 `estimates.parse`），第二块写“会把 PDF 交给 MinerU 解析，可能花费；解析完成后自动形成未校对的全文，不调用模型”，主按钮“解析 n 篇”提交 `parse-documents` 任务（范围为 `{intake_batch_ids:[本批]}`），提交后与获取 PDF 一样直接开始运行，页面显示任务链接；
   - 入库本身不自动做这两件事。
7. **更多**：页眉右侧的“更多”菜单里有“在文献库查看”与“撤回这一批”。撤回只在已结束、已取消的批次上可用；进行中的批次菜单项不可用，并说明“入库结束后才能撤回”。规则见[文献与材料 6.4.11](../technical/03-literature-materials.md#6411-撤回)。
   - 点“撤回这一批”打开对话框：
     - 先取预估。对话框写明将移除的文献、文件、文件夹成员、批注各多少，将保留的文献多少篇，并按原因分行（入库前已在库、之后被别的批次命中、加入过别的文件夹、有批注、打开过、加工过、改过书目、与别的文献合并）；
     - 保留的文献可展开逐篇列出；
     - 下面一句“撤回只是从文献库中移除，可以恢复；文件不会被删除”；
     - 批次在登记之前形成时，加一句“本批在登记之前形成，文件夹与批注不在撤回范围内。”；
     - 按钮“撤回”与“取消”。
   - 有任务正在处理这一批的文献时，对话框写“这一批有文献正在被任务处理，请等任务结束或取消后再撤回”，不显示“撤回”按钮。
   - 撤回之后，页眉状态为“已撤回”；页面顶部一行写“这一批已于 <时间> 撤回”，以及“恢复这一批”按钮；下面是撤回报告，分移除与保留两部分，保留的逐篇写原因。
   - 点“恢复这一批”先确认一次，写明将恢复的数量（已经被后来的入库恢复的不计）；恢复之后，批次回到撤回之前的状态，并显示恢复报告。

各状态下显示的部分：

| 状态   | 页眉 | 计数概况             | 需要决定         | 进度       | 报告             | 接着做什么 | 主操作           |
| ------ | ---- | -------------------- | ---------------- | ---------- | ---------------- | ---------- | ---------------- |
| 收集中 | 有   | “还没有交来条目”     | —                | —          | —                | —          | “取消”           |
| 待确认 | 有   | 预览估计             | 有就显示         | 认篇时显示 | —                | —          | “确认入库”“取消” |
| 进行中 | 有   | 实际，随进度更新     | 只有待决定时显示 | 有         | 到当时为止的累计 | 有         | “结束入库”“取消” |
| 已结束 | 结果 | 实际                 | 只有待决定时显示 | —          | 有               | 有         | —                |
| 已取消 | 有   | 实际（已入库的部分） | —                | —          | 有               | 有         | —                |
| 已撤回 | 有   | 实际                 | —                | —          | 撤回报告         | —          | “恢复这一批”     |

- 认篇还没结束时，“确认入库”不可用，旁边写“正在识别文件，完成后才能确认”。
- “确认入库”之前再确认一次，写明“只新增，不删除、不替换已有 PDF；需要决定而没有决定的条目不入库”。
- 网页上传中断后（刷新、关闭）再打开批次页，按服务端的缺失清单继续，已上传的不再传。
- 收集中、待确认与进行中的批次每 3 秒刷新。
- 逐条确认的开放批次（网页收藏、补充文件）显示为进行中，报告给出到当时为止的累计。
