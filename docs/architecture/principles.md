# SciRetriever 架构原则

本文把[产品需求](requirements.md)和[架构决策](decisions/README.md)转换为实现与审查时长期遵守的原则。它不替代[系统设计](system-design.md)，也不提前决定尚待讨论的 schema、算法、进程模型或用户界面。

## 1. 需求先于实现

SciRetriever 的目标是根据用户指定的领域条件或种子文献，大批量完成多来源文献元数据搜索、资产获取、轻结构化文本解析和通用结构化文献分析，最终形成可查询并可交换书目信息的文献数据库。

`Work`、状态、parser、CLI、数据库引擎和其它技术机制只能用于满足该目标，不能反向定义产品需求。当前代码已经存在的能力也不会自动成为长期产品合同。

## 2. 领域边界

SciRetriever 只拥有通用文献信息：

- 文献身份和通用元数据；
- 文献资产及其来源、hash 和关系；
- 领域中立的轻结构化文本；
- 产品规定含义的通用结构化文献分析结果；
- 产生上述结果所需的 provenance、处理证据和失败信息。

通用结构化文献分析结果必须能够追溯到轻结构化文本，且不能替代完整文本。反应、分子、路线、产率、材料性质等特定领域数据属于下游消费者，不进入 SciRetriever 文献数据库。下游消费者自行决定领域 schema、导出格式和存储方式。

## 3. 来源事实不能丢失

多家供应商返回的内容先作为来源事实保存，再形成统一文献视图。一个来源不能无声覆盖另一个来源；合并规则变化时应能够从保留的事实重新计算。

供应商专有响应在 adapter 边界转换为中性结构，不能穿透到核心数据合同。

## 4. 身份收敛必须保守

`Work` 和 `WorkVersion` 是当前接受的内部身份机制，用于处理跨来源重复和真实书目版本。

- 明确相同才自动合并；
- 明确冲突时保持分离；
- 证据不足时不得使用不可复现的猜测静默合并；
- 具体标识符优先级、标题规则和版本关系算法由系统设计决定并由测试证明。

## 5. 原始资产是证据

已接受的原始资产不可原地修改。文件字节由资产存储拥有，文献数据库保存相对引用、hash、角色、来源和关系，不保存大型关系型 BLOB。

解析错误通过重新处理原始资产修复，不通过手工修改原文件或伪造来源关系修复。

## 6. 轻结构化文本保持通用和可追溯

解析结果保留文献主要内容、通用结构和回到原始资产的 source locator。摘要、标签等有损信息只是辅助视图，不能成为内容的唯一副本。

具体 parser 可以替换，但必须转换到 parser-neutral 合同。外部 parser 的 URL、归档、JSON、文本、图片和坐标均作为不可信输入验证。

## 7. 阶段结果独立提交

元数据、资产和解析结果分别形成可持久化事实。局部失败不撤销其它文献或已经成功的前面阶段；后续运行根据现有事实补充缺失内容。

批次、尝试和失败记录可以用于调度、诊断和审计，但不能成为文献身份或结果可用程度的第二真相源。

## 8. 单机不等于预设进程模型

产品运行边界是单机，不要求跨机器协调或分布式任务所有权。单进程、多进程、同机互斥、中断恢复和调度方式属于后续系统设计，不由本原则提前固定。

## 9. 一个事实只有一个写入所有者

系统设计必须为文献身份、元数据统一视图、资产字节、资产关系、解析结果和诊断事实分别指定唯一写入所有者。其它模块通过明确合同读取或请求修改，不复制第二份权威状态。

## 10. 当前导出实现不是产品边界

当前实现可以发布版本化 `DocumentPackage`。它是现有导出合同，不是产品目标、内部文献身份或唯一允许的未来导出设计。

任何下游集成都必须使用文档化的稳定标识符、hash、provenance 和领域中立表示，不得直接依赖内部数据库表。

## 审查清单

- [ ] 变化是否能追溯到一项产品需求或已接受 ADR？
- [ ] 是否把技术选择误写成了用户需求？
- [ ] 是否保持元数据、资产、轻结构化文本和通用结构化文献分析结果的领域中立边界？
- [ ] 是否避免把领域字段写入 SciRetriever 文献数据库？
- [ ] 是否保留来源 observation、资产 hash、解析输入和 provenance？
- [ ] 是否以保守、确定、可审计的方式处理跨来源身份？
- [ ] 是否避免原地修改已接受资产或覆盖冲突证据？
- [ ] 外部 provider 和 parser 输出是否在边界验证并转换为中性合同？
- [ ] 局部失败是否保留其它已提交结果并允许后续补全？
- [ ] 是否为每项持久化事实指定唯一写入所有者？
- [ ] 是否把单机边界错误扩大成未经讨论的进程或调度方案？
- [ ] 当前 `DocumentPackage` 变化是否明确处理公开合同和版本影响，而没有把它当成产品边界？
