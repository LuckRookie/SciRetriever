日期：2026-10-19。状态：**Proposal，待讨论**。本轮用户授权明确缺陷修复、调研、提案与计划；总结内容组织需先解释机制再讨论。本文不替换 Accepted ADR，也不替换或归档 定稿原型（已于 2026-10-23 退役）。

依据：[Web 设计基准及 G1–G3](README.md)、[ADR 0032](../../architecture/decisions/0032-library-centered-web-workspace.md)、[ADR 0033](../../architecture/decisions/0033-machine-interfaces-cover-web-capabilities.md)、[ADR 0034](../../architecture/decisions/0034-unified-processors-and-results.md)。实施历史见 [Web 体验归档记录](../2026-10-19-web-experience/README.md)。

## 问题判断与已核实原因

当前界面沿用原型外框，但新增功能没有保持原型的信息主次和空间关系。字号调大以后，固定栏宽、技术信息和同级操作越来越拥挤；状态变化多为直接替换内容。改善“塑料感”的重点是可读层级、稳定布局和连贯反馈，动效负责解释变化。

| 用户反馈                            | 已核实原因                                                                                                           | 本轮处置与边界                                                                   |
| ----------------------------------- | -------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 正文出现 Supporting Information     | 指定论文的原 PDF 是正文论文；首页有小型附件入口，被解析 Markdown 提升为一级标题。Web 原样渲染，不能据此认定下载了 SI | 保留原始资产；解析质量专项制定定位与修复策略，不用某个标题的前端过滤掩盖来源错误 |

## 总结究竟如何生成

这次截图中的 `overview / single-document-knowledge v2` 是旧知识产物路线。它不是打开阅读器后临时拼出的总结，也不是原始元数据 abstract。

1. 固定输入文献、PDF hash 和文档版本。验证 Markdown 与结构，并逐片段计算证据 hash。
2. 将全部片段的编号和文字，以及 purpose/question 放入 JSON 输入。提示要求保留条件、否定、数量、单位、局限和分歧，区分作者报告与模型推断，只能引用给定片段编号。
3. 单文档服务调用一次 `agents.execute`，请求结构化 JSON。当前此接口走唯一 DSH 底座的 `foundation.call`；**使用 DSH 不意味着该业务自动变成多轮自主阅读**。长文服务和通用处理器另有各自执行流程，不能把它们都称为这一条单文档路线。
4. 校验 `outcome/title/statements` 和片段编号。statement 包含 finding/method/result/limitation/disagreement、reported/inference、正文、conditions、可选 quantity 和证据。
5. 服务端将片段编号绑定为固定文档证据，补齐版本、范围/定位和 hash；按不可变结果发布并保存 provenance/coverage。hash 证明引用对象和字节一致，**不证明断言科学正确**；complete 表示这条路线覆盖了全部输入片段，不表示已正确理解所有图表。
6. Web 读取保存的产物，复用 `renderKnowledgeArtifact()` 输出技术字段；阅读器再按每条证据追加核对按钮。因此多段证据会变成多条重复按钮，UUID/hash 成为阅读障碍。

本次反馈涉及的历史产物早于 DSH 底座迁移；其诊断记录在本机 sandbox，不作为共享测试数据。manifest 记录的能力缺口含表格结构、独立图注、页码和 bbox。历史 provenance 没有明确 executor backend，不能仅凭今天的组装认定旧结果由 DSH 生成。图像资源没有在这条单文档文字 prompt 中作为视觉输入送入模型，不能把文字覆盖当成看过全部图片。

`overview` 提示目前没有专门规定中文表达、先总后分的阅读结构或面向人的摘要长度。得到英文结构化条目有原因，但把它直接当最终阅读页是展示设计的问题。

## 推荐方向：稳定的库界面，安静的阅读面

保留原型导航、标签、蓝白/深色/墨绿/暖白主题及 18px 界面、20px 阅读、40px 常规控件。标题、正文、辅助说明和诊断资料形成清楚的四级关系。白纸内容面、弱分隔与已有证据高亮足够，不叠加玻璃、渐变或满屏阴影。

阅读正文与下载/导航是日常动作；解析、分析、核验、综合、提取属于显式加工，建议收敛为次级操作组。信息栏先让人知道文献身份和摘要，再按需打开来源和处理能力。这一分组需和代表性阅读页面一起审看，不能只凭首页截图确定。

加载中保留已经呈现的内容，异步结果落在发起它的位置；失败让人知道保留了什么、可以如何恢复。空态说明当前范围和数据事实，避免大幅空画布、孤立点或巨大占位卡片。

## 设计语言 v2 （2026-10-19，G4 已确认）

Owner 对实际 React 控件和 Motion 的反馈为「目前就挺好的，加了motion之后手感好多了」。本节保留第二轮反馈及设计依据；当前定稿变量、参数和边界以 [Web 设计基准](README.md#设计语言-v2g4与阅读方向g52026-10-19) 为准。此确认不代替最终 Full、GB 或未具备环境的 macOS 验收。

### 为什么需要 v2

Owner 第二轮反馈：控件圆角不统一，很多框接近直角；风格大体统一了，局部设计没跟上，阅读、总结、全文查看都不够好；整体交互“硬邦邦”，设计破缺太多。实测（真实库只读浏览与 `workspace.css` 核对，明细见 [计划 03 的破缺清单](../2026-10-19-web-experience/03-design-audit-and-language.md#已知破缺首轮实测)）证实这是**体系缺失**，不是个别控件的问题：

- 设计变量只有字号和控件高度，没有圆角、间距、表面、阴影、焦点和动效；全文件出现 14 种圆角值。
- 同一种控件分别手写：输入类控件至少 8 处独立定义；任务页筛选框仍是浏览器默认外观，深色主题下为浅灰底。
- `workspace/dom.ts` 的 `button()` 固定输出 36px 小按钮，静态 HTML 按钮为 40px，同一行内两种高度。
- 状态不完整：没有按下态和提交中态，禁用透明度三种，焦点样式三套；免费操作与可能产生费用的加工操作外观相同。
- 设计说明写明 Source Serif 4 / Source Sans 3，但页面从未加载这两种字体，实际显示的是系统回退字体。
- 除原型遗留的两处布局属性动画外，面板、筛选、菜单、标签切换都是瞬间替换。

v2 不推翻原型。**保留**：导航结构与页面布局、四个主题与主色（白纸、墨蓝、荧光黄）、18/20/17 px 字号与 40 px 常规控件、证据荧光笔。**新增或改变**：设计变量、控件族与使用规则、表面层级、状态体系、字体落地、信息分层和动效。

**实现技术**：Owner 于 2026-10-19 讨论后决定，前端改用 React 重建。行为组件使用 React Aria Components（无样式，样式由本设计提供），动画使用 Motion，数据请求使用 TanStack。详见 [Web 体验计划](../2026-10-19-web-experience/README.md)的 D1–D10，以及已 Accepted 的 [ADR 0036](../../architecture/decisions/0036-react-web-frontend.md)。

### 设计原则

1. **一种用途只有一种控件**，同一行控件同高，圆角只取变量。
2. **嵌套圆角**：内层圆角 = 外层圆角 − 内边距（例如分段控件轨道 8 px、内边距 2 px，滑块 6 px）。
3. **层级靠表面而不是边框堆叠**：平面内容不加框；浮起的对象（菜单、对话框、提示）用圆角加阴影。
4. **每个可交互对象都有六态**：默认、悬停、按下、焦点、禁用（附原因）、提交中。
5. **技术身份退后**：UUID、hash、字节数、方法 ID、配置版本默认收进“技术详情”，一级界面只说人话。
6. **动效只解释变化**：状态先同步改变，动画只是装饰；可取消，减少动效时立即完成。

| 场景                     | 做法                                                                                                                                        | 时长                    |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------- |
| 悬停、按下、选中颜色     | 背景与颜色过渡。按钮和筛选标签在指针按下时轻微缩放，松开后弹簧回弹，比例由 G4 实验台决定，候选为 1.00 / 0.98 / 0.97；列表行和文字链接不缩放 | `--dur-1`；回弹用弹簧   |
| 分段滑块、页内标签指示条 | `transform` 平移；内容区直接替换，不做横向滑动                                                                                              | `--dur-2`               |
| 菜单、下拉、提示         | 透明度加 4 px 位移、0.98→1 缩放，从触发点方向出现                                                                                           | 进 `--dur-2`，出 120 ms |
| 对话框                   | 遮罩淡入；面板透明度加 0.98→1 缩放                                                                                                          | `--dur-3`               |
| 信息栏、目录、活动抽屉   | **布局一步到位**，只让面板内容做透明度加 8 px 位移；PDF 在动画结束后只重渲染一次；拖动栏宽不加动画                                          | `--dur-3`               |
| 筛选面板展开             | `grid-template-rows: 0fr → 1fr` 或改为浮层；不推挤列表                                                                                      | `--dur-2`               |
| 证据定位                 | 1.5 屏以内平滑滚动，更远直接跳转；`--mark` 底色 900 ms 渐隐为淡标记，保留到下一次操作                                                       | 900 ms                  |
| 提示条                   | 自底部上移 8 px 并淡入；4 s 后淡出                                                                                                          | `--dur-2`               |
| 结果到达                 | 新内容淡入，不依次错开                                                                                                                      | `--dur-1`               |

**不做动效**：列表行、续读插入、页内内容替换、数字变化、页面路由、PDF 页、栏宽拖动。

**实现约束**：

- 只对 `opacity`、`transform`、颜色、边框色、阴影做过渡，禁止对 `width`、`height`、`top`、`left` 做动画（原型遗留的 `.ptr` 与 `.pbar` 一并改掉）。
- 颜色、背景、按下、焦点用 CSS。进出场、布局让位（Motion `layout`，即 FLIP）、选中指示滑动、可打断的动画用 Motion。不引入其他动画库，不使用会运行时注入 `<style>` 的模式（CSP 为 `style-src 'self'`）。
- 当前参数：按下缩放 0.98；指示条弹簧 stiffness 520 / damping 38 / mass 0.7；短 120 ms、标准 180 ms、面板 240 ms、证据 900 ms。CSS 负责普通控件颜色/按下，Motion 负责指示条与内容过渡；实验台的临时参数只有显式导出后才成为评审材料，不会自行修改生产配置。
- `prefers-reduced-motion` 下立即完成。状态改变不能依赖 `transitionend` / `animationend`，因为全局减少动效规则会让这两个事件不再触发。
- 必须验证连续两次开关、异步结果迟到、焦点归还和组件卸载。

## 待讨论的总结与解析设计

建议先做**展示分层**：现有 statement 正文为主体，类型改为人类栏目；短证据编号展开原文，技术详情默认折叠；不得仅隐藏证据而失去核验入口。是否需要另写一篇中文叙述总结，是独立的内容生成选择，涉及 prompt、语言和质量评测，不能伪装成 CSS 改动。

下一次讨论聚焦三点：

- 总结优先展示研究问题/主要发现/方法条件/局限四组要点，还是先有一段连贯说明再进入结构化证据？推荐先验证前者，避免立即增加新生成步骤。
- 是否要求新生成的总结默认中文、保留关键英文术语？旧英文产物不能无提示地自动重写或追加费用。
- 解析质量先检测和提示哪些问题：标题层级、跨栏顺序、图表/图注归属、公式？修复若改变正文，必须发布新版本并保留旧证据，不覆盖已接纳字节。

引用网络的后续工作也应单列：当前前 40 篇的取样很容易得到零边，需要选择围绕选中文献展开邻居，或有界查询更能代表范围的关系集合。查询与覆盖语义先明确，再做图形布局；不能用随机线或放大节点数量制造“有网络”的效果。

## 验收与边界

这份提案完成不代表视觉方案已确认或实现。下一阶段在原应用上用合成数据呈现库、全文/总结、提取结果、浏览器、洞察的代表状态，集中看一轮桌面/中宽/窄屏和多主题，再修一轮。键盘、200% 缩放、reduced motion、长标题/多来源、续读失败、快速切换与资源释放必须有对应验证。

当前不增加批注、插件体系、账户权限、向量库，不调用外部 MinerU/模型，不修改用户原资产与 catalog。PRODUCT.md 的旧 localhost 描述已发现漂移；当前运行方式以 ADR 0035 和用户指南为准，该设计提案不另外定义认证模式。
