# 阅读批注：高亮、笔记与框选

类型：历史提案
负责：阅读批注的评审方案与对位实测记录
状态：已接受（2026-10-29），决定见 [ADR 0046](../../architecture/decisions/0046-reading-marks.md)；本文只作历史

Owner 希望在文献阅读中加入高亮、笔记、标签和框选等辅助阅读功能，具体做法交给 Claude。本提案给出体验设计、性能做法、数据边界和分阶段范围。可交互原型见 `sandbox/cases/2026-10-29-reading-annotations/prototype.html`（已发布为私有 Artifact）。原型里的文献和数据都是虚构的，批注只存在页面内存里。

## 已有约束

- [需求](../../architecture/requirements.md)“阅读”一节：批注、笔记属于用户数据，要有来源、稳定保存、导出，并在同等授权下可由机器访问；具体范围另行设计。
- [ADR 0032](../../architecture/decisions/0032-library-centered-web-workspace.md)：当时没有引入批注和笔记；以后引入时须明确业务 owner、来源绑定、持久化、保留与导出。
- [ADR 0033](../../architecture/decisions/0033-machine-interfaces-cover-web-capabilities.md)：Web 的业务能力须被 CLI 和 MCP 覆盖，阅读器的视觉交互本身不必复制。
- 证据规则不变：不伪造页码、坐标或高亮。批注无法定位时如实显示“未能定位”。

所以实施前需要一个新 ADR（暂编 0046）定下批注的数据 owner 与机器接口。体验部分属于前端，由 Claude 决定。

## 体验设计

**选区工具栏**：选中文字后，选区上方出现一条深色小工具栏，有五个颜色、“笔记”“引用”“检索”。
- 鼠标停在某个颜色上时，选区先按这个颜色预览，点下去才保存。
- 高亮落下时，颜色从左往右刷开，像荧光笔划过。这是整套交互里唯一的“表演”，其余动效都克制。
- 选区靠近顶部时，工具栏改到选区下方；滚动时跟着选区走。

**颜色有含义**：五色默认是“重点、方法、结论、疑问、待查”，名称可以在设置里改。面板可以按颜色筛选，导出时也写出颜色名。不提供任意取色：颜色少，含义才稳定。

**高亮笔**（快捷键 H）：开启后选中即高亮，不再弹工具栏，适合连续通读。光标变成当前颜色的笔。工具按钮上的色点打开颜色菜单。

**笔记与标签**：笔记挂在一条高亮或一块框选上。
- 有笔记的批注在页边显示一个带序号的小标记，点击直接打开笔记。
- 笔记里写 `#标签` 即可归类，面板和搜索都认这些标签。
- 这些标签是用户自己的，与 [ADR 0034](../../architecture/decisions/0034-unified-processors-and-results.md) 的派生标签结果分开，不互相写入。

**框选区域**（R，或按住 Alt 拖动）：拖出矩形框住图、表、公式或一段排版。
- 拖动时实时显示“第 n 页 · 宽 × 高 pt”。
- 框住图时自动标成“框选 · 图 1”。
- 面板里的缩略图直接截取页面本身来显示，不另存图片。

**点击已有批注**：弹出同样的工具栏，可以改颜色、写笔记、复制引用、删除。删除和改动都能撤销（⌘Z，或提示条里的“撤销”）。

**批注面板**：右栏“信息 | 批注 N”两个标签页。
- 批注按页分组，可按类型和颜色筛选，也能搜索引文、笔记和标签。
- 鼠标在卡片和页面高亮之间双向联动：指向一边，另一边同时加深。
- 点击卡片会滚到原文，原文闪一下定位环。

**滚动条刻度**：PDF 视图右边缘用彩色短刻度标出每条批注的位置，点击直接跳过去。

**全文同步**：PDF 上做的高亮在“全文”（校订稿）里同步显示，反过来也一样。

原型里两边用的是同一份文字，所以匹配必然成功。真实情况下，校订稿和 PDF 文字层并不相同：
- 连字和破折号写法不同；
- 行末断词在 PDF 里被拆开；
- 上下标的写法不同；
- 校订会改错字，整理会删掉杂项。

所以实际做法是两步：
1. **先按位置缩小范围**：校订稿的每个区块都保留了页码和区域（见 [04 文档证据](../../architecture/technical/04-document-evidence.md)），先找出与高亮所在页、所在区域重叠的区块。
2. **再在这些区块里比对文字**：先把两边的文字统一写法（Unicode 规范化，统一破折号、引号、连字，去掉行末断词和标记），再按编辑距离对齐。

结果分三档：
- 对齐可靠：按精确位置显示。
- 只能大致对上：显示成虚线下划线，并标“近似位置”；高亮范围内有校订改过的字时，卡片上注明“与 PDF 原文不同”。
- 对不上：标“仅 PDF”或“仅全文”，不伪造位置。

另外：
- 按 [ADR 0037](../../architecture/decisions/0037-literature-archive-and-proofread-text.md)，区块的页码和区域只是定位提示，所以最终仍以文字比对为准。
- 没有文字层的扫描件只能框选。
- 框选只属于 PDF。

**实测**（2026-10-29，只读）：用计划 17 真实样本库副本中按现行流程建档的 5 篇，共 34 页。脚本见 `sandbox/cases/2026-10-29-reading-annotations/map-test.mjs`，结果见 `sandbox/runs/2026-10-29-reading-annotations/map-1.json`。

PDF → 校订稿：在 PDF 文字层上模拟 816 次选取，每次 6–35 个词。

| 情况 | 次数 | 结果 |
| --- | --- | --- |
| 选中的文字在校订稿里存在（全文相似度 ≥ 0.85） | 709 | 全部对上。完全一致 540 次（76%），近似 169 次（24%，相似度中位 0.97）。近似的差别来自 PDF 字体编码坏掉的连字（“eect”对“effect”）、LaTeX 写法和断词。抽查的近似结果都是正确位置 |
| 只靠页码和区域缩小范围就找到 | 607 | 其余靠退到整页（56 次）或相邻页（46 次）才找到，说明区块的页码和区域不能单独依赖 |
| 与全文搜索结果不一致 | 3 | 同一段文字在文中出现不止一次，对位结果和全文搜索给出的位置不同 |
| 选中的文字在校订稿里不存在 | 77 | 全部如实标为对不上，没有一次被放到错误位置。这些是整理时删掉的内容：版权行、“Cite This”、页眉、DOI 行、单独存放的参考文献 |
| 部分存在 | 30 | 选区跨了正文与图注或表格，只能大致对上，属于“近似位置”或“仅 PDF” |

校订稿 → PDF：在校订稿上模拟 588 次选取，每次 20–140 个字符。
- 完全一致 475 次（81%），近似 101 次（17%），对不上 12 次（2%）。
- 对不上的都是图、反应式里的文字：它们是从图像识别出来的，PDF 文字层里本来没有。这种情况可以改为在 PDF 上框出该区块的区域。

据此定的规则：
- 相似度 ≥ 0.85 按位置显示，其中 1.0 为精确位置；
- 0.7–0.85 显示“近似位置”；
- 低于 0.7 标“仅 PDF”或“仅全文”。

对位在创建批注时算一次，结果和两个锚点一起保存，不在渲染时重算。

这次的局限：只有 5 篇，选取是脚本模拟的，没有真人选取；扫描件没有覆盖。

**复制引用与导出**：
- “引用”复制的格式是 `“原文”（作者，年份，第 n 页，doi:…）`。
- “导出 Markdown”按页列出全部批注，带颜色名和笔记。

**快捷键**：

| 按键 | 作用 |
| --- | --- |
| `1`–`5` | 按颜色高亮 |
| `N` | 写笔记 |
| `C` | 复制为引用 |
| `[` / `]` | 上一条 / 下一条批注 |
| `⌫` | 删除当前批注 |
| `/` | 搜索批注 |
| `?` | 快捷键表 |

**交互规则**（同时作为 P31 交互规范的第一批条目）：
- 悬停效果即时出现，离开时 120–140 ms 淡出。
- 按下时轻微缩小。
- 弹出物 150 ms 进场、90 ms 退场。
- 提示气泡第一次出现等 450 ms，之后半秒内移到别的按钮立即出现。
- 系统开启“减少动态效果”时，全部改为即时切换。

## 性能做法

- **只画看得见的页**：批注层只建在已渲染的页面上。现有 PDF 引擎本来就只渲染可见页和相邻页，所以每页只处理自己的批注。
- **坐标存在 PDF 页面单位里**：位置在创建时从文字层测一次，按行合并。之后任何缩放都只做乘法，不再测量文字层，也不改文字层的 DOM。
- **高亮画在文字下方**：每行一个块，用乘色混合，像墨水印在纸上；动效只用裁剪、透明度和位移。
- **悬停只靠一个监听**：整页只有一个指针监听，每帧最多处理一次，用点和矩形比较命中，不给每条高亮单独挂事件。这与 P32 的悬停卡顿是同一类问题。
- **全文视图用 CSS Custom Highlight API**：浏览器直接画 `Range`，不往正文里插 `<mark>`，不打断正文的分段续读，也不让已渲染的段落重建。
- **面板按需渲染**：超过约 200 条时改为虚拟列表；筛选和搜索在内存中完成。
- **保存不阻塞界面**：先在界面显示，再合并写入。写入失败的卡片标“未保存”并可重试，不丢输入。

## 数据与边界（新 ADR 要定的部分）

**归属**：批注是用户数据，由新的 `annotations` 业务 owner 负责。建议存进 catalog，跟着现有备份和导出走。

**锚点**：每条批注同时记三样东西。
- 材料身份：PDF 的 sha256，或解析全文的固定版本。
- 精确位置：PDF 记页码和 PDF 坐标矩形；全文记 UTF-8 范围。
- 引文本身：原文，加前后各一小段上下文。

材料换了版本时，先用引文重新定位；定位不到的进“未能定位”，保留内容，不删除。

**字段**：颜色、笔记（Markdown）、标签、创建与修改时间、操作者。删除先软删除，可以撤销。

**机器访问**：
- CLI 提供 `annotations list / show / export / add / remove`。
- MCP 提供只读的 `annotations_query` 和可写的 `annotations_manage`。
- 导出支持 Markdown 和 JSON。

**不做**：Zotero 等外部工具的笔记同步、多人共享批注、手写笔迹。

## 分阶段

1. **第一阶段**（核心）：
   - 选区工具栏、五色高亮、高亮笔、笔记与 `#标签`、框选区域；
   - 批注面板、滚动条刻度、复制引用、撤销、快捷键、Markdown 导出；
   - PDF 与全文两个视图都支持；
   - 存储、ADR、CLI 与 MCP。
2. **第二阶段**：
   - 跨文献的“批注”页，按颜色、标签、文献检索全部批注；
   - 每篇一份整篇笔记，可以把高亮拖进去当引文；
   - 文内引用悬停预览，显示该文献是否已入库。
3. **第三阶段**（需要调用模型，费用另议）：选段翻译、术语解释、对选段提问。

## 请 Owner 决定

1. 批注存进 catalog（推荐，随备份走），还是单独一个用户数据文件。
2. 五种颜色及其默认含义是否合适。
3. 第一阶段范围是否就是上面这些。第三阶段要不要做，什么时候做。

Owner 2026-10-29 的决定：批注存进 catalog；五种颜色及其默认含义可以；第一阶段排在 P26–P32 之后实施。
