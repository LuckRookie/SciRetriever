# 文献自动下载产品方案

## 1. 产品目标

用户准备一份统一的 `config.toml`，配置自己拥有的 API key、下载来源、代理、保存位置和访问方式，然后提交一篇或一批文献。SciRetriever 自动寻找全文、慢速下载、验证文件、保存结果，并持续记录成功或失败原因。

理想体验是：

> 配置一次，提交任务，系统保守地自动下载；成功文件直接保存，失败项目给出明确原因和下一步建议。

## 2. 用户看到的完整流程

```text
准备一份 TOML 配置
        ↓
运行配置自检
        ↓
提交 DOI、标题、文献清单或检索结果
        ↓
系统生成下载任务并去重
        ↓
按保守速度从多个来源依次寻找和下载
        ↓
必要时使用网页解析、Sci-Hub、代理、浏览器或机构登录
        ↓
核对文件是否完整且属于目标文献
        ↓
保存成功文件，记录所有失败原因
        ↓
输出进度、总结和可执行的处理建议
```

内部仍可保留 discovery 和 acquisition 两阶段，但普通用户应获得一个统一的自动下载入口，不需要理解内部工作流。

## 3. 需要提供的大功能

### 3.1 统一配置

用户只维护一份 TOML 文件，至少可以配置：

- 文件和数据库保存位置。
- 各文献来源是否启用以及尝试顺序。
- Unpaywall、Semantic Scholar、OpenAlex、出版社等 API key 或联系邮箱。
- Sci-Hub 的显式镜像地址。
- HTTP/HTTPS/SOCKS 代理。
- 下载速度、批次大小和每日上限。
- 是否允许网页解析、无头浏览器和机构登录会话。
- 默认下载主文、补充材料或其它格式。

配置文件允许直接保存 API key，继续要求只对当前用户可读；同时保留环境变量覆盖方式，方便不愿在文件中保存 key 的用户。任何命令和报告都不得显示完整 key、Cookie 或签名 URL。

### 3.2 配置自检

开始大批量下载前，用户可以运行一次自检。自检应告诉用户：

- TOML 格式是否正确，文件权限是否合适。
- 哪些来源已经可用，哪些缺少 API key。
- key 是否能完成最小健康检查，但不显示 key 本身。
- 代理是否可连接，浏览器是否可启动。
- 保存目录和磁盘空间是否满足当前任务。
- 当前启用的下载来源、速度限制和预计行为。

自检只做最小请求，不批量下载正文，不因为检查本身消耗大量配额。

### 3.3 保守自动下载

默认采用“宁可慢，不要被封”的安全模式：

- 默认只处理一个下载任务。
- 默认每 30 秒最多开始下载一篇新文献。
- 同一网站的实际请求间隔不得快于该网站公开规则或本地更严格设置。
- 收到限流信号后自动等待，不连续重试。
- 同一来源连续失败时自动暂停该来源，继续其它来源或等待用户处理。
- 用户可以暂停、继续和安全停止；重新启动后从未完成项目继续。

元数据查询和正文下载分别限速。元数据 API 可以遵守各自的官方预算，正文获取仍默认按一篇 30 秒的节奏推进，避免因为一个任务产生多个来源请求而形成突发流量。

高级用户可以调整速度，但快于默认 30 秒必须使用显式高级覆盖，并由配置自检明确显示实际并发和间隔；程序不得因为缺省值、旧配置或其它入口而静默提速，也不得绕过 provider 限制或 `Retry-After`。

### 3.4 多来源全文获取

系统依次尝试：

1. 公开全文和开放文献库。
2. 用户配置的出版社 API 和机构访问路径。
3. 文献网页中的 PDF 下载入口，采用类似 Zotero 的网页识别方式。
4. 用户显式启用的 Sci-Hub 来源。
5. 必要时使用代理、无头浏览器或人工登录会话。

一个地址失败后自动尝试其它地址，不让首个失效链接直接导致整篇失败。系统需要避免重复请求同一地址，也不能把登录页、验证码页或错误文章当成成功文件。

### 3.5 浏览器、代理与机构会话

- 普通网络请求优先，只有需要 JavaScript、Cookie 或页面交互时才启动浏览器。
- 无头浏览器用于自动页面处理；需要登录或验证码时允许用户临时打开有界面浏览器接管。
- 登录成功后可以在用户明确配置的会话中复用，过期后提示重新登录。
- 普通下载器和浏览器使用同一套代理配置。
- 浏览器或代理失败不能影响已经成功保存的文献，也不能泄露会话信息。

### 3.6 下载进度与任务控制

用户应能随时查看：

- 总任务数、成功数、失败数、等待数和正在处理的文献。
- 当前使用的来源以及下一次允许请求的时间。
- 预计剩余时间；估算不确定时明确表示未知。
- 当前被限流、暂停或等待登录的来源。

用户应能执行：暂停、继续、安全停止、只重试失败项、只重试某一类失败，以及跳过明确不再处理的项目。

### 3.7 失败原因跟踪

每篇失败文献需要保存一条可回看的处理历史，而不是只显示“下载失败”。用户至少应看到：

| 用户看到的原因 | 含义 | 建议动作 |
|---|---|---|
| 未找到全文 | 已启用来源都没有给出候选 | 增加来源，稍后重试或人工提供地址 |
| 缺少配置 | 所需 API key、邮箱、镜像或代理未配置 | 根据提示补充 TOML |
| API key 无效 | key 过期、撤销或格式错误 | 更新 key 后只重试受影响项目 |
| 没有访问权限 | key 有效，但当前账户或机构无权获取 | 检查订阅、机构网络或其它来源 |
| 请求过快 | provider 返回限流或本地预算已用完 | 系统自动等待，通常无需用户操作 |
| 网络不可达 | DNS、代理、连接或超时失败 | 检查网络和代理配置 |
| 需要登录或人工处理 | 页面要求登录、验证码或交互 | 打开浏览器会话完成操作 |
| 下载地址失效 | 地址返回 404、过期或重定向失败 | 重新解析来源并尝试其它候选 |
| 文件不是有效文献 | 返回网页、损坏文件、空白或预览 PDF | 自动拒绝并尝试其它来源 |
| 文献身份不匹配 | 下载文件不是目标文章 | 禁止保存，记录来源并尝试其它候选 |
| 存储失败 | 磁盘空间、权限或写入失败 | 修复存储后恢复任务 |
| 程序内部错误 | 本地实现问题，不能归因于 provider | 保留诊断编号，供开发者排查 |

每条失败记录还应说明：失败发生在哪个来源、是否会自动重试、何时可以重试、系统已经尝试了什么、用户下一步应该做什么。默认界面显示简明原因；需要排查时可以导出完整但已脱敏的诊断报告。

系统可以提出配置优化建议，但不得在未告知用户时自动修改 TOML、替换 key、启用新来源或提高下载速度。

### 3.8 文件检查与整理

- 确认下载内容是目标文章的完整文件，而不是网页、验证码、错误文章或损坏 PDF。
- 同一篇文献和同一文件不重复保存。
- 保留 DOI、来源、下载时间、文件 hash 和最终保存关系。
- 批量开始前检查磁盘空间，空间不足时提前暂停。
- 已成功文件不因后续任务失败、重试或配置变化而被覆盖。

### 3.9 结果报告

任务结束或暂停后，系统生成用户可读报告：

- 成功、失败、等待和跳过数量。
- 成功文件的保存位置。
- 按失败原因和来源分组的数量。
- 可以自动重试的项目及预计重试时间。
- 需要补充 key、代理、登录或人工地址的项目。
- 本次实际下载速度、限流等待和来源健康情况。

报告支持终端摘要和 JSON/JSONL 导出，便于后续筛选和再次提交。

## 4. 建议补充的产品功能

除用户已经提出的统一配置、慢速下载和失败跟踪外，建议同时加入以下功能：

1. **一键配置自检**：批量任务前发现 key、代理、权限和磁盘问题。
2. **暂停、继续和安全停止**：长时间慢速任务必须可以被用户控制。
3. **分类重试**：例如只重试“网络失败”或“刚补好 API key”的文献。
4. **下载前去重**：避免同一 DOI 在多个清单中重复下载。
5. **容量预检**：避免运行数小时后因为磁盘不足整体失败。
6. **人工处理清单**：把需要登录、验证码或人工地址的项目单独列出，不阻塞其它任务。
7. **配置档案**：允许用户准备“只用公开来源”“机构网络”“浏览器+代理”等不同配置文件，但每次运行仍只选择一份 TOML。
8. **可导出诊断报告**：用户可以把脱敏报告交给维护者排查，而不暴露 API key 和个人会话。

第一版不需要 Web UI、后台服务或复杂任务平台。命令行加统一 TOML、清晰状态和持久化报告足以形成完整产品。

## 5. 功能优先级

### P0：先让产品可放心运行

- 统一 TOML 和配置自检。
- 默认单任务、每 30 秒一篇的保守下载模式。
- 状态、失败历史、处理建议和脱敏报告。
- 暂停、继续、安全停止和失败项重试。

### P1：提高全文命中率

- 同一来源多个地址自动回退。
- 更多公开来源和出版社来源。
- 从文章网页寻找 PDF。
- Sci-Hub 显式 provider。

### P2：处理复杂访问环境

- HTTP/HTTPS/SOCKS 代理。
- 无头浏览器。
- 人工登录、Cookie 和机构会话复用。
- 人工处理清单。

### P3：提高长期效率

- 根据历史成功率优化来源顺序。
- 更准确的预计完成时间。
- 来源健康趋势和配置优化建议。

## 6. 产品完成标准

当以下场景成立时，文献自动下载可以视为形成完整产品：

1. 新用户只需准备一份 TOML，通过自检后即可提交批量任务。
2. 默认设置下，系统不会以高并发或无间隔方式请求正文来源。
3. 中断、退出和重启不会丢失成功文件或未完成任务。
4. 每个失败项目都有稳定原因、处理历史、重试状态和建议动作。
5. 用户可以只重试受某个配置问题影响的项目。
6. 浏览器、代理和 Sci-Hub 未启用时，不影响普通来源的下载。
7. 下载成功必须同时满足文件有效、文章身份匹配和安全保存。
8. 所有用户报告均不泄露 API key、Cookie、签名 URL 或个人身份。
