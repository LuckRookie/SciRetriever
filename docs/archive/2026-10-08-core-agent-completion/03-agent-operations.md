# 03 · 正式 Agent 协议与统一任务生命周期

## Outcome 与责任

外部 Agent 可通过正式 MCP 调用库内读取和显式产品操作，长操作有稳定任务引用、结果及取消/重试语义。
独立解析、分析和综合复用当前 Application 与执行存储，不实现第二套业务流水线。
进入条件：R11/ADR 0019/0025/0028；冻结输入与副作用，确定进程关闭/重启合同。

## Tasks

- [x] 3.1 定义类型化操作映射、能力声明、幂等输入、结果持久化及错误分类；保留既有 completion 合同。
- [x] 3.2 将独立解析、分析、长文分析及综合纳入既有执行控制，使用固定材料和 manifest，提交不等于成功。
- [x] 3.3 实现 MCP stdio 正式入口、初始化/工具发现/调用/取消与安全错误，复用 Application 生命周期。
- [x] 3.4 公开 TS/CLI 接入任务状态和产物读取；关闭时结算在途工作，重启显式恢复，不声称离线进程会继续运行。
- [x] 3.5 协议客户端经生产组装的合成闭环：提交、查询、结果、重复冲突、取消、部分失败、重开与恢复。

## 集成与验证

依赖仅在协议实现必要时新增，说明锁文件影响。查询面不组装/触发维护，无任意 SQL、路径、脚本或模型提示入口。
任务保留成功产物；不承诺远端模型恰好执行一次，不重复执行已持久完成目标。
运行 MCP/执行/解析/分析直接测试、安装入口回归及 `pnpm full`。
退出要求：可从文档命令启动 MCP 并走完整操作生命周期，不以仅有工具列表或 fake Application 声称完成。
失败恢复点在既有已提交业务事实和 durable attempts；临时日志进入 `/tmp/sciretriever-*`，证据回填本块。

## 实施与证据（2026-10-08）

官方 MCP SDK 1.27.1 提供 stdio 协议；读取惰性组装 QueryApplication，维护需 `--maintenance`。
封闭加工请求使用既有 durable queue/owner，结果回执保存稳定 ID/hash；没有新工作流引擎或业务副本。
新增依赖仅 MCP SDK 及其传递依赖，未主动升级其它依赖。

`processing-tasks.test.ts` 4 项通过：幂等与冲突、部分失败仅重试未完成项、回执落盘后的崩溃重放、
暂停/恢复、同 catalog 多 Application 所有权、跨进程控制与异步锁释放竞争。
`mcp.test.ts` 经官方协议客户端和生产 Application 完成解析、身份核验、单篇/长文分析、集合综合与产物读取；
只读模式验证未启动维护，错误输出不泄露原异常。`mcp-stdio.test.ts` 使用编译 CLI 的真实 stdio 子进程验证初始化、发现和调用。
既有 `cli-main.test.ts` 回归通过，旧 jobs run 返回形状保持。最终 Full 见根 README。

进程停止不继续工作；重启须显式恢复。执行冲突留下 `processing-runtime-owned` 回执而不改写活任务，
同进程并发使用原 execution 配置；不保证崩溃时远端模型恰好执行一次。
所有 Provider/模型边界使用合成响应，未访问真实服务或个人配置。

Full 发现并补充修复：便携包原来强制把传递依赖按名字压成唯一版本，MCP SDK 与 body-parser
需要不同 `content-type`，导致三项安装验收失败。打包器和离线安装 fixture 改为按实际依赖边
固定 tarball，保留多版本和本地 peer resolution；增加安装后版本断言。长构建改异步子进程，
避免 Vitest 控制通道被同步打包阻塞；包入口测试预算按实际完整依赖打包量从 60 s 调整至 150 s。
初始化/升级安装旅程改验 v9，旧版本输入与备份读取仍保留。复验日志 `/tmp/sciretriever-core-installation-repair.log`。
