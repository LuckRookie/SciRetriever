# 11 · 真实文献抽样评估

类型：计划（结果块）
负责：经授权的真实文献评估：初稿的疑点有多少，依据初稿与依据校订稿的文本和加工结果差多少
状态：Superseded（2026-11-16：11.1–11.3、11.5 移入计划 25 的 23.7–23.9；11.4 E3 移入知识加工提案）

## Outcome

一份交 Owner 的评估报告，回答 ADR 0060 后果中没有实测的两个问题：

1. 初稿在真实文献上的疑点比例是多少，疑点信号是否有用；
2. 依据初稿的结果与依据校订稿的结果相差多少。

评估**不设通过线**，不卡交付。现在没有依据给出阈值：没有基线，也不知道多大的差距会影响使用。报告给出数字与典型例子，由 Owner 决定（G5）：

- 是否维持“初稿可加工”的默认（改变要写新 ADR）；
- 是否调整对比规则（升初稿方法版本）；
- 是否另立“只校订疑点页”的工作（ADR 0060 留给以后的方案）。

## 进入条件

- 05 完成（能在副本上批量形成初稿）。
- G2：Owner 授权在本机复制正式库与资产，作为只读副本使用。
- E2：G3（为样本建档要调用模型）。
- E3：G3，且计划 16 的算子已能读取初稿（使用 07 的 7.7）。

## 授权要写清的内容

请 Owner 授权时，一次说明：

| 项   | 内容                                                                                              |
| ---- | ------------------------------------------------------------------------------------------------- |
| 数据 | 复制正式 catalog 与所选文献的 PDF 到 `sandbox/runs/`，只在副本上运行；不写正式库；报告不含全文    |
| E1   | 不调用模型、不联网；只运行初稿形成与人工抽查                                                      |
| E2   | 为样本建档：整理与逐页校订每页一次视觉模型请求。发起前用 `usage-estimate` 给出调用数与 token 估算 |
| E3   | 在样本上各运行一次所选算子，依据初稿与依据校订稿各一次；发起前给出估算                            |
| 模型 | 用部署配置中已有的 `proofreading` 与算子角色；不读取、不打印配置与凭据                            |
| 上限 | 每项的篇数与预计花费上限，超出即停                                                                |

## 责任边界

- 负责：总设计师确定样本口径和测量项目，并写报告；运行与人工抽查由 Owner 安排的执行者完成；Owner 授权并决定。
- 不改：任何代码与规格。发现缺陷时记录，交回对应块修复。

## Tasks

- [ ] **11.1 样本**（2026-11-16 移入计划 25 的 23.7）：从副本里有文字层的文献中分层抽样，并写明抽样规则：
  - 至少两个差别明显的学科（规4）；
  - 出版社、年代不同；
  - 含表格多的、公式多的、有扫描页的、超过 50 页的长文档各有一些。
  - 建议 E1 约 30 篇，E2 约 10 篇（含现有已建档的 3 篇），E3 约 10 篇。篇数由 Owner 在授权时确定。
- [ ] **11.2 E1：初稿的疑点**（2026-11-16 移入计划 25 的 23.7）（G2，无模型）
  - 在副本上形成样本的初稿（可复用 05 的 5.6）。
  - 测量：
    - 形成成功率与失败原因；
    - 每页耗时；
    - 每篇疑点片段占有文字层片段的比例，每页差异处数（中位数、P90）；
    - `no-text-layer` 片段的比例、扫描页比例；
    - 按区块类型（正文、表格、公式、图注）分别统计。表格单列，用来确认 02 的去标记有效。
  - 人工抽查：
    - 随机取疑点片段，对照 PDF 原图，分为真错误与写法噪声，得到疑点信号的准确率；
    - 随机取“与文字层一致”的片段，对照原图，看是否漏掉错误。
    - 每类抽查篇数写进报告。
- [ ] **11.3 E2：初稿与校订稿的文本**（2026-11-16 移入计划 25 的 23.8）（G3）
  - 对 E2 样本建档，得到校订稿。
  - 测量：
    - 两级文本逐片段的词级差异率；
    - 校订改字落在 `text-layer-differs`、`text-layer-match`、`no-text-layer` 片段中各多少，即疑点信号覆盖了多少真实改动；
    - 校订花费与 `usage-estimate` 的估算对比。
- [ ] **11.4 E3：两种加工结果**（2026-11-16 移入知识加工提案）（G3，需计划 16）
  - 在同样的文献上，同一算子、规范、模型各依据初稿与校订稿运行一次。
  - 测量：
    - 逐值核对状态的分布（可找到、找不到等）；
    - 提取值的一致率；
    - 不一致处的原因分类：初稿错字、表格、公式、扫描页、阅读顺序、章节角色缺失；
    - 花费与耗时。
- [ ] **11.5 报告**（2026-11-16 移入计划 25 的 23.9）：数字、方法、样本清单（只写文献 ID 与书目，不含全文）、典型例子、未覆盖的范围。放 `sandbox/reports/`，结论摘要写进本块与计划 README 的进度。交 Owner。

## 验证

- 每个数字能从副本与运行材料复算；运行脚本放 `sandbox/cases/`。
- 抽查标准写在报告里，同一标准用于所有样本。
- 只读副本：结束后核对正式库的修改时间与大小没有变化。

## 证据

授权记录（日期、范围、上限、Owner 原话）；样本清单；运行材料与报告位置；实际花费。

## 退出条件

## 恢复与交接

- 超出花费上限、出现非预期的写入或模型调用时立即停止，记录已完成的部分。
- E3 等计划 16 时，E1、E2 的报告先交，E3 单独补交。
