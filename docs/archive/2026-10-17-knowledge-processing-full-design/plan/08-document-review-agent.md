# 08 · 文档复查与修复 Agent

状态：Pending。

## Outcome 与进入条件

02、03 已完成。用户明确启动材料任务后，复查 Agent 对照原 PDF 页面检查解析结果，产出有原文依据的补丁。补丁经校验后发布为新的 DocumentVersion，并附质量与覆盖说明。这条配方属于材料区，复用 03 的执行、依赖和发布机制。

## 责任与 Tasks

- [ ] 8.1 复查范围策略：只查疑点（来自 02 的问题清单）、指定区域或全文。实际复查范围必须如实记录；只查了疑点，不能标为全文复查。还要从源页面出发检查初稿中完全缺失的内容。
- [ ] 8.2 受控工具：读取页面图像与区域、读取 Unit 与上下文、提交补丁、报告无法解决的问题。通过 DSH 的受控 Agent 会话提供，不开放任意代码、网络或存储访问。
- [ ] 8.3 补丁合同：每个补丁绑定基线版本与哈希、目标 Unit 或区域、修改前内容、建议值、理由和原 PDF 证据。操作类型包括替换、补入、拆分、合并。没有原文依据时不猜值；论文本身可能写错的内容保留原样并标注。
- [ ] 8.4 应用与复验：应用前确认基线仍然匹配；结构、Markdown 投影和位置映射同步更新；复验失败时不发布半套结果。Unit 的跨版本对应关系写入规格要求的映射，无法匹配时明确标出冲突。
- [ ] 8.5 发布：材料 owner 发布新版本并保留旧版本与原始解析；默认版本按规格规则选择。下游加工不会因为新版本发布而自动启动，只通过 05 的显式更新使用新版本。

## 验证与退出条件

- 合成 fixture 中预置已知错误：漏段、数值符号错误、上下标错误、表格错位、多栏顺序错误。fake Agent 产出补丁后，检查能否被发现、修复、复验和发布。
- 基线已变化或证据缺失时，补丁被拒绝。
- 与 05 联动：修复一张表后，只有读过它的结果被标为需要更新。
- 定向测试与 Quick 通过。真实修复质量不在离线验收中声称，留给 09 的真实评估。
