# 文献知识加工平台首版

状态：参考副本（未执行；2026-10-18 已由精简计划取代）。日期：2026-10-17。Primary owner：当前执行者。

依据：[文献知识加工平台提案](../proposal.md)、[产品需求](../../../architecture/requirements.md)、[HARNESS](../../../../HARNESS.md)、[AGENTS](../../../../AGENTS.md)。本计划把提案收敛为可执行结果块；提案中仍为开放项的内容，以本页“决定”为准，并在 [01](01-decisions-and-contracts.md) 中同步回提案、ADR 与需求。

## 目标

从已接纳 PDF 的可核对文档出发，人和 Agent 只需描述**文献范围、问题或记录规范**，平台即可用默认方法完成逐篇提问、筛选、记录提取、分组统计和整集综合；产物带证据、版本和依赖，可以查询、修订、复用，并在新输入上按依赖更新。

首版闭环：同一批文献完成“问题分析 + 报告”与“记录提取 + 分组统计”；扩大范围只处理新增与受影响部分；补 SI、修复文档、人工改值后能识别并更新受影响结果；在已有结果上新增“实验条件比较”时不重写读取、证据与执行代码。

## 决定（Owner 确认后生效）

| 编号 | 决定 |
| --- | --- |
| D1 | 定位：科研 Agent 与人共用的文献知识加工服务。主要消费者是经 MCP/CLI 调用的 Agent；Web 用于查看、核对、修正和发起任务。 |
| D2 | 两区与只读快照：材料区只由明确的探索/材料任务写入；结果区只由加工任务写入。加工任务读取冻结快照，不下载、不加文献、不解析、不修复原文，不把模型记忆当作证据；两类任务之间只由用户衔接。 |
| D3 | 三层抽象：**算子形状**（封闭）+ **处理方法**（开放）+ **配方**（有序步骤）。首版形状为逐项变换、逐项筛选、逐项展开、按组处理、整集合成；成对处理推迟到第二版。运行时只向方法提供其形状允许看到的输入，依赖由运行时记录。 |
| D4 | 首版任务：逐篇提问/打标签、筛选判断、记录提取、分组统计、整集综合；单位换算与数值解析为程序方法。矛盾核查、全局实体归并不在首版。 |
| D5 | 首版入口：结构化规范 + 模板表单；模型可以起草规范供用户确认。不做模型自动组合配方或生成可执行代码。 |
| D6 | 技术路线：在现有 TypeScript 底座上薄实现。DocETL、LOTUS、Palimpzest、CocoIndex 只作设计参考，首版不接入。 |
| D7 | 文档：保留 MinerU 原始输出（修订 ADR 0010 第 5 节）；首版 Unit 与位置映射来自保留输出。历史解析缺少结构输出时报告能力缺口，是否重解析由明确材料任务决定。文档复查修复 Agent 为独立结果块，不阻塞应用闭环。 |
| D8 | 更新：逐项操作按实际依赖复用；按组操作只重算成员或定义变化的组；整集合成在输入变化后标记待更新，用户显式更新时重新生成，首版不做折叠式增量。 |
| D9 | 值类型封闭集合：文本、枚举、开放枚举、带单位数值（含误差与比较符）、区间、布尔、列表、文献引用。曲线与序列后续增加。 |
| D10 | 验收：合成 fixture 与 fake 模型证明机制；真实 30–50 篇人工标注的质量评估是单独的 Owner 授权步骤，不由离线通过推导。 |
| D11 | 兼容：既有 KnowledgeArtifact、提取交付、综合产物和证据引用保持可读；新路径并行引入。旧产物是否迁移另行决定。 |

## 范围与边界

- 授权（待 Owner 确认）：代码、文档、合成测试、Quick 与 Full。不访问真实 Provider、MinerU 服务、用户 catalog、语料、配置或凭据；不执行 Git 提交、推送、发布或真实数据迁移。
- 发现、引用扩展、PDF 获取、Browser 协作的实现不在本计划内修改，只调整它们与新材料区合同的衔接。
- 首版不做：可视化 DAG 编辑器、自动模型或计划优化器、分布式执行、自研向量库、成对算子、全局实体图谱、自然语言自动编排。
- 新增第三方依赖须按 AGENTS 的依赖规则评估并记录；优先使用已有依赖。
