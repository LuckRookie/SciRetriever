# 03 · 内容资产与运行时

状态：Pending。

## Outcome 与进入条件

01 的合同已就绪。平台能保存 Item、Collection、Asset 版本、Run、Attempt、Dependency 与 Revision；能按算子形状把配方步骤展开为工作项，判断复用，执行缺失部分，不可变地发布结果，并在取消、失败或进程中断后恢复。方法可以是程序、经 DSH 的模型调用或受控 Agent。

## 责任与 Tasks

- [ ] 3.1 存储：新增 schema 版本与仓储。表至少覆盖条目与版本、集合成员（引用精确版本）、资产逻辑身份与版本、运行与尝试、依赖、修订；内容体积大的条目放入不可变文件存储。入口为 `apps/server/src/storage/`。
- [ ] 3.2 形状化执行器：五种形状各自的工作项展开规则。方法只拿到形状允许的输入；读取通过运行时提供的上下文完成，例如 `ctx.readUnits`、`ctx.readItem`、`ctx.search`，所有读取自动记录为依赖。方法不能直接访问存储、凭据、网络或 Browser。
- [ ] 3.3 方法注册：方法声明适用形状、输入输出类型、版本、影响结果的参数与模型绑定；签名由这些部分确定。模型调用统一经 `apps/server/src/agents/` 的 DSH 入口，沿用现有配置、网络与 provenance。
- [ ] 3.4 复用判断：按 01 的适用性规则，结合输入身份与内容、方法签名、实际依赖与材料范围，查找已发布结果。失败或覆盖不足的历史结果不能当作成功复用。模型请求缓存（如果实现）与正式产物复用分开。
- [ ] 3.5 运行生命周期：与 `apps/server/src/application/jobs/` 现有任务系统集成，支持排队、并发与限速（沿用现有 Provider 调度）、重试、取消、部分成功、成本记录与恢复。恢复依据持久执行状态和输出完整性检查，不只凭缓存存在。
- [ ] 3.6 发布：结果先完整校验再发布为不可变版本；半成品不可见；同一逻辑资产可以有多个版本，默认版本选择按规格规则。清理缓存不影响已发布产物。
- [ ] 3.7 写入边界：加工任务只写结果区，材料任务只写材料区；入口声明允许的写入范围，配方字段不能提升权限。

## 验证与退出条件

- 用 fake 方法覆盖：五种形状的展开与可见范围（方法越权读取会被拒绝）、依赖记录、复用命中与不命中、失败隔离、重试、取消、进程中断后恢复、并发发布冲突、缓存清理后产物仍可读。
- 定向测试与 Quick 通过。现有任务、分析、综合、提取交付的回归测试保持通过。
