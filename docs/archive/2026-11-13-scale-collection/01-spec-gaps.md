## Tasks

每项写清：要回答的问题，写进哪一节。规则写在规格里，不写在本计划里。

- [x] **1.1 补规格：“全文取得情况”三个数的定义**（06 §2.1，新的小节或 `LibraryCounts` 的说明）
  - 收2 写“多少已经取得，多少还没有，其中多少已经试完了自动途径”。现有计数按六种状态给出，三个数要由调用方拼。要写明：
    - “已取得全文”包含哪些状态：`ASSET_READY`、`ARCHIVING`、`ARCHIVE_FAILED`、`READY` 都有主 PDF；`EXCLUDED`（观点、评论、勘误、社论）有 PDF 时算不算、要不要单列；
    - “还没有”是否就是 `UNREVIEWED`；
    - “已试完”是否就是现有的 `unavailable_pdf`（没有主 PDF 且有自动获取耗尽事实）；
    - 计数的单位：按具体版本（`Literature`，现有计数的单位，见 06 §2.2.1），还是按 MetaLiterature（收4“同一篇文献有多个版本时，默认只需要其中一个达到目标”）。若两种都要，各叫什么，Web 与机器入口默认给哪一种；
    - 三个数之间的关系（例如“已取得 + 还没有 + 单列项 = 总数”）。
  - 已回答：[查询技术篇 2.1.8](../../architecture/technical/06-retrieval-context.md#218-文献库计数与全文取得情况)“全文取得情况”：按论文计；有主 PDF 的都算已取得（含 `EXCLUDED`）；已试完是未取得的一部分；`total = obtained + missing`。
- [x] **1.2 补规格：计数合同**（06 §2.1）
  - `LibraryCounts`（`total`、`statuses`、`unavailable_pdf`、`recently_opened`）现在只在 `packages/contracts/src/library-counts.ts` 里，规格没有它。要写明：
    - 三个数在合同里的字段名，是扩展 `LibraryCounts` 还是新的读取；
    - 计数忽略哪些条件（现在计数忽略快速筛选的状态与 `needs_manual_pdf`）；
    - 三个入口的名称沿用 `literature counts`、`library_counts` 与 `library-counts`，还是另起；
    - 只读与一致性：同一次读取的三个数来自同一个只读快照。
  - 已回答：06 §2.1.8：`LibraryCounts` 写进规格，增加 `full_text` 与按版本的 `with_primary_pdf`，没有新操作；`LibraryQuery` 增加 `has_primary_pdf`（2.1.1 标注目标）。
- [x] **1.3 补规格：Web 上的位置**（页面规格“文献库”）
  - 要写明：当前范围的三个数显示在哪里（工具条、页头，或入库批次与文件夹的页头）；与快速筛选“有 PDF”“无法获取”“仅元数据”的关系（现在“有 PDF”只等于 `ASSET_READY`，已建档的文献不在其中）；点击三个数是否等于应用相应的筛选。
  - 已回答：[页面规格“文献库”](../../architecture/web/page-specs.md#文献库)的“全文取得情况”与“快速筛选的含义”两条，以及排布图中的一行。
- [x] **1.4 补规格：万篇机制验收的口径**（02 §5 或 03 §4 的验收小节；按 ADR 0059 第 3 节第 4 条，做法的验收写在规定这项做法的技术文档里）
  - 收4 验收行写“至少一万篇文献及其材料的持续接纳、重复收敛、缺失补全、中断后继续、局部失败隔离和库内查询都成立；记录所用数据、时长、吞吐、内存、磁盘和外部调用花费”。按 [tests/README](../../../tests/README.md)“明确的性能验收”的要求，要写明：
    - 合成数据的组成：总篇数；完全重复、同一文献不同来源、同一 MetaLiterature 的不同版本各占多少；有 DOI 与没有 DOI 的比例；
    - 假来源的结果组成：拿到、正常未命中、临时错误、限流、永久错误各占多少；PDF 的大小分布；
    - 入库途径：导入会话、假的元数据来源发现，或两者都用；
    - 中断的方式：取消任务、关闭进程后重新打开；中断点；
    - 测量的起止点与环境：只测指定操作，不把生成数据和启动服务计入；内存取哪个量（例如进程 RSS 峰值），磁盘取 catalog 与资产目录的大小；
    - 硬性条件只有计划 README 的不变量；数字本身不设通过线，只记录。
  - 已回答：[任务协调 9.4](../../architecture/technical/02-task-coordination.md#94-万篇机制检查)。
