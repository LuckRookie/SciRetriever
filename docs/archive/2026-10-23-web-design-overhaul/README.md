# 计划 14：Web 设计改版

类型：计划
负责：Web 设计改版的执行、审阅点与交接
状态：Completed（2026-10-24）；6.3 未获 G-real 授权，未执行

## 目标

Web 是**人**管理和使用文献库的平台；CLI 和 MCP 是 **Agent** 的平台。本计划让 Web 在设计上配得上这个定位：

- 看上去统一、安静、有书卷气，中文和英文同样好看；
- 页面按人要做的事组织，而不是按系统概念平铺；
- 每一种状态都有像样的样子，包括空、失败和加载；
- 以后改设计有一套可持续的办法，不再靠零碎补丁。

同时收掉上一计划移交过来的三项后端遗留问题。

## 背景与诊断

2026-10-23 用正式库只读副本截取了 11 个页面，Owner 的评价是“感觉不到优雅和美感”。具体原因：

1. **中文没有配字体。** 只内置了 Source Sans 3 / Source Serif 4 的拉丁字符，中文落到各系统的回退字体，中英混排粗细与字面大小不一；为避开系统宋体，10-22 把标题改成了无衬线粗体，显得笨重。
2. **借了 Notion 的配色，没有借到它的规则。** 墨蓝同时用于主按钮、当前标签、图表、链接和选中，没有一处是重点；间距没有统一节奏。
3. **层级是平的。** 文献库工具栏三行和列表一样醒目，快速筛选一半是 0；算子页同一屏出现三次“运行记录”；设置页小标题 28 px，内容是一片原始路径。
4. **组件不统一。** 按钮有白底描边、实心、纯文字三种混用；同一行里下拉框白底有边、搜索框灰底无边；阅读页工具栏挤着四种控件。
5. **页面套模板，空白没有被设计。** 每页都是“大标题 + 一句解释系统行为的话 + 右上按钮”；监视页右栏是一大块空框。
6. **过程原因。** 设计依据（10-15 的 HTML 原型）与生产代码是两套实现，生产界面一路修补后与它脱节，却仍被当作依据；每轮只修反馈点，没有整体判断；功能先行，视觉最后。

## 范围与非目标

范围：`apps/web/` 的视觉、信息架构与页面；字体资产；设计样例库与截图工具；把确认后的草案并入规格、同步 Web 指南；06 列出的三项后端问题。

非目标：

- 不改业务合同、数据库结构或算子语义（06 若发现必须改，先交 Owner）；
- 不新增前端框架或 UI 库，沿用 React、React Aria、Motion、TanStack 与自有 CSS；
- 不做 Markdown 渲染的其余问题（继续暂缓）；
- 不新增 Web 功能，页面规格草案列出的重组与命令面板除外。

## 不变量

- 所有界面变化都在设计样例库里有截图；截图里的数据是合成的，不冒充真实数据或能力。
- 测试只因选择器或文案变化而改写，断言的目的不变；删测试或放宽断言须在交接记录说明理由。
- 键盘可完成全部操作；焦点可见；“减少动效”生效；390 px 宽度可用；正文文本对比度不低于 4.5:1。
- 离线可用：不加载任何外部字体或资源，CSP 不放宽。
- 正式库只读；不调用真实 Provider、模型或 MinerU，G-real 除外。
