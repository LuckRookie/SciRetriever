## 目标与完成条件

同一授权、配置和运行条件下，CLI、MCP **分别**覆盖 Web 的业务能力。Web 面向人的常规操作，机器入口支持完整、非交互、结构化调用，以及更深入的诊断和维护。三端共享 Application/Entry 与配置 owner，不复制业务逻辑。

本计划覆盖当前正式 Web 已有的业务能力；主题、面板、标签布局等纯呈现状态不做机器接口。尚未实现的自动提取执行器、长期导入历史、笔记批注不借本计划新增。不给 Agent 原始 SQL、任意脚本、Cookie 或凭据读取能力，不改变用户数据或数据库 schema，不执行真实服务验收或 Git 提交。

完成条件：能力矩阵各项都有可执行的 CLI/MCP 对应入口、明确副作用与有界结果；现有 Web 和机器客户端保持兼容；直接测试覆盖正常路径、失败、只读拒写、取消与资源释放；必要指南、对象图与 Full 验收同步。

## 实施顺序

1. **设计与清单**：新增三端能力覆盖 ADR，协调 R11/R12、ADR 0019/0032；核对 [能力矩阵](capability-matrix.md)。
2. **共享应用操作与只读能力**：补齐文献筛选/关系、文档证据、知识/综合列表与默认值、上下文和提取准备；CLI 与 MCP 使用同一分派和既有领域 parser。
3. **入库、任务与交付**：导入/引用发现、PDF 接纳、获取策略、任务列表/详情/控制、索引维护及提取交付。大型字节不默认进模型上下文；明确传输范围、资源寿命和校验。
4. **配置与运行协作**：非交互配置读/预览/发布、凭据安全输入和状态、显式 probe；Browser 观察/指导/控制采用现有会话与 epoch 合同。需要操作活会话时显式连接持有该会话的 runtime，不因共享数据库推断可接管其它进程。
5. **集成验收与文档**：通过实际 CLI 和 MCP 客户端对同一合成库操作，并由 Web 查询结果；验证错误与权限边界，运行 Quick/Full，更新指南和矩阵。

按能力切片实施，每片完成生产组装、测试和必要文档。发现旧适配器中的业务编排时移入共享应用边界，保持旧入口形状；不增加绕过类型合同的通用任意方法调用器。
