# 计划 20：入库

类型：计划
负责：ADR 0063（统一的入库）、ADR 0058 与 ADR 0057 仍然有效部分的落地
状态：Superseded（2026-11-16 归档。M1 已部署：02、03、05、07、08、12、13、14 完成，15、16 除真实核对外完成，06 的通用部分与 19.1、19.2、18.1 完成。未完成的块与任务移入[计划 25](../../plans/2026-11-16-before-processing/README.md)：18 → 12，17 → 13，01 → 14，04 → 15，19 → 16，10 → 17；15.9、16.6、6.12、11.3–11.6 → 23；11.7 → 24）

## 目标

按 [ADR 0063](../../architecture/decisions/0063-unified-intake.md)，把“把文献放进文献库”收成一套：一种条目、一个过程、三种载体。

- **一个过程**：所有入库都形成一个入库批次，依次是交清单、预览、确认（在后台进行）、补全文、报告。单篇收藏采用逐条确认；批次可以撤回。
- **一种条目**：至少有标识、标题、文件三者之一。只有一个 PDF 也可以入库：由文献库认出它是哪一篇，认不出时标为“书目待补”。没有标识的条目可能与已在库的文献重复时，由使用者决定。
- **三种载体**：
  - 扩展：收藏当前网页，从 Zotero 导入；
  - 网页：入库页的放置区；
  - 接口：给 Agent 和脚本；HTTP 版 MCP 随入库一起上线。
- **先修缺陷**：2026-11-13 实现审查发现的、与重新设计无关的缺陷先修，首先是上传被 5 秒请求超时掐断（H1）。

已有实现的去留，见 ADR 0063“后果”：导入会话的状态机与暂存、设备连接、文件通道、外部编号对应、书目格式适配器，以及扩展的外壳与连接，都保留下来，在原代码上改。

## 不变量

- 预览不写文献库。只有文件的条目在预览阶段认篇时，可以向文献信息来源查询，但不写文献、来源记录与状态投影。
- 入库只新增：不删除文献，不替换已有主 PDF，不改动用户在文献库里的整理。唯一的例外是撤回：只能由网页登录的使用者发起，只移除这一批新增、之后没有被动过的内容（ADR 0063 第 9 节）。
- 服务端不连 Zotero 或其他外部文献管理工具。适配器不联网、不写库；文件适配器只读交来的文件。
- catalog 里没有来源专用的表。
- 再次入库同一个来源，不重复入库、不重复建来源记录。没有标识的可能重复条目，不自动合并，也不自动新增。
- 入库的 PDF 按 ADR 0029 标为“文章身份未验证”。上传边收边写盘，不设大小上限，也不设时长上限。
- 认篇只用程序和文献信息来源，不调用模型。入库本身不触发获取全文、解析等会联网或花费的后续操作（需求规2）。
- 设备连接令牌：
  - 服务端只存派生值，令牌只放在请求头里；
  - 不进日志、事件、报告或 Web 数据；
  - 不能登录 Web，不能读写配置与凭据，不能管理设备连接，不能撤回批次；
  - 只能看到和操作本设备发起的批次。
- HTTP 版 MCP 与 stdio 版用同一套工具实现；“操作”用途不默认勾选。
- 用户浏览器里的 Cookie 与登录信息不发往服务端。
- 不使用 Zotero 翻译器，不实现 Zotero Connector 协议。
- 界面上不出现“导入会话”一词；对外只有“入库批次”。
- 测试只用合成数据和假的外部服务，不连真实 Zotero。

- **15、16、17 分开**：三者各自能用合成数据单独验收，各有一项要回到 ADR 的前提验证。
- **18、19 归前端**：网页与扩展各自独立交付，依赖后端的合同。

## 计划级验证与完成标准

- 01–19 的退出条件都满足。开发中只跑定向测试；M1 部署前与收尾各跑一次全量（HARNESS 5.4、6）。
- 用合成数据与假的外部服务覆盖：
  - 预览不写库，确认后以实际结果为准，确认立即返回；
  - 中断后继续，再次入库幂等；
  - 已有主 PDF 不被替换，经过 HTTP 的慢速大文件上传成功；
  - 令牌按用途限权，只能看到本设备的批次，撤销立即生效（包括正在进行的上传），令牌不外泄；
  - HTTP 版 MCP 的工具随用途变化；
  - 只有文件的条目入库，四步认篇，“书目待补”；
  - 可能重复无人决定时不入库；
  - 撤回只移除未动过的内容。
- ADR 0063 的五项前提各有验证结论（见“仍需验证的前提”）。
- G-trial、G-zotero 的真实试用通过。
- 需求、规格、页面规格与指南按实现更新；界面与对外文档中没有“导入会话”。

不能由局部证据推出的结论：

- 合成 PDF 上认篇成功，不说明真实文献也能认出。真实情形要看 15.9。
- 假服务端上后台续传稳定，不说明真实浏览器里也稳定。真实情形要看 19.8。
