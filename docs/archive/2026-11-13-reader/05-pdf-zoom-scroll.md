# 05 · PDF 的缩放与滚动

类型：计划（结果块）
负责：缩放先拉伸后变清晰；滚动保留低清晰度画面；画布与 worker 的上限不变
状态：Completed（2026-11-15）

## Outcome

- 缩放、适合宽度、改变窗口大小、开合信息栏时，PDF 页面在同一帧拉伸到新尺寸，随后换成清晰画面，中间没有一帧空白。
- 快速滚动时，离开渲染范围的页保留低清晰度的位图，没有位图的页显示占位和页码，不露出白色空白。
- 只有可见页及前后各一页持有画布与文字层；位图有总量上限。

规格：[5.3 PDF 的缩放与滚动](../../architecture/web/reading-experience.md#53-pdf-的缩放与滚动)。

## 进入条件

- 03 退出。
- 5.3 需要 04 的 4.2（缩放时与锚点一起完成）。

## 责任边界

- 负责：前端实施者。
- 触达：`apps/web/src/reading/pdf.ts`（现在的 `reflow()` 先对所有已渲染页调用 `clearPage`，再按新比例重排；渲染窗口是可见页 ±1）。
- 不改：画布与文字层的上限；PDF worker 的来源与加载方式；页面渲染失败时的提示。

## Tasks

- [x] **5.1 先拉伸，后变清晰**
  - `reflow()` 不再先清空：已渲染的画布按新比例用 CSS 变换拉伸到位；停止变化 120 ms 后，重新渲染可见页及前后各一页，渲染完一页替换一页。
  - 替换时新旧画布同时存在的时间只到新画布绘制完成，上限按“可见页 ±1 各至多两张”计算，并写进 `next-reader-boundaries.test.ts`。
- [x] **5.2 滚动时的低清晰度位图**
  - 页离开渲染范围时，把画面转成比例不超过 0.5 的位图保存；每份资料最多 40 页、48 MB，按离当前页的远近淘汰。
  - 没有位图的页显示 `--reader-skeleton` 色的占位与页码（令牌在第一次交付时按设计内核“阅读页”一节先加入 `tokens.css`；该节写明目标值）。
  - 隐藏的引擎（03 的 3.2）不保留位图，或计入同一上限。
- [x] **5.3 与锚点一起完成**
  - 缩放与拉伸在同一帧里恢复锚点（04 的 4.2），清晰画面替换时不移动锚点。

## 集成与影响

用户可见：缩放与滚动不再闪白。内存：位图上限由规格给出，测量工具记录峰值。

## 验证

- 扩展 `apps/web/test/next-reader-boundaries.test.ts`：缩放过程中画布数不超过上限；位图总量不超过规格上限；关闭后为零。
- 扩展 `next-reader.test.ts`：缩放后第一帧可见页都有画面；清晰画面替换后像素尺寸与新比例一致。
- 测量工具：“PDF 缩放”“不出现空白画面”（缩放部分）两行。
- 失败注入：恢复旧的 `clearPage` 路径时，测量工具报出空白帧。
