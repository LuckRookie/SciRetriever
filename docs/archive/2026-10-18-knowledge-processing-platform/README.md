# 文献知识加工平台首版（精简）

状态：Completed（01–03 已完成离线机制验收并归档）。完成日期：2026-10-18。

依据：[文献知识加工平台提案](proposal.md)、[产品需求](../../architecture/requirements.md)、[HARNESS](../../../HARNESS.md)、[AGENTS](../../../AGENTS.md)。Owner 于 2026-10-18 授权执行修订后的三块计划，完成后归档；[完整版设计](../../proposals/2026-10-17-knowledge-processing-full-design/README.md)保留为参考，不在本计划内实施。原提案和 ADR 的同步属于 01。

## 目标

定义统一的**处理器接口**和**结果格式**，提供基于现有任务底座的**批量执行能力**：对冻结的文献输入逐篇处理，只复用输入、方法和执行配置一致且覆盖合格的结果。之后新增一种分析或提取，主要增加处理器、注册与直接测试，无需修改批量执行、存储或公共入口。结果长期保存，人和 Agent 都能通过 CLI/MCP 查找内容、展开证据，并显式作为后续处理的输入。

首版闭环：现有单篇分析、长文分析和综合通过处理器适配，外部提取交付通过持久结果接纳适配，旧入口及历史产物保持兼容；新增打标签与记录提取，跑通“筛选 → 提取 → 查询 → 综合”。100 篇扩大到包含原集合的 120 篇时复用 100、处理 20；若新 120 篇仅重叠 80 篇，则复用 80、处理 40，新集合不夹带旧集合独有的 20 篇。

## 已确认决定

| D1   | 定位：科研 Agent 与人共用的文献知识加工服务，主要通过 MCP/CLI 调用。                                                                                                                                                                            |
| D2   | 处理器只读取已有材料，不下载、不加文献、不解析、不修复原文，不把模型记忆当作证据。探索与加工之间只由用户衔接。                                                                                                                                  |

| D4   | 处理输出区分 `ok`、`empty`、`failed`，另记覆盖范围与缺口。已发布结果有稳定 ID、内容类型/schema、内容 hash、输入清单、方法与规范身份、证据、实际来源和时间；失败尝试留在现有任务记录。`empty` 只表示已完成声明范围的处理且无记录。               |

| D6   | 保持旧入口、旧产物和旧证据的公开行为，允许为适配调整内部结构。旧产物沿用原 owner，新结果由明确的知识加工 owner 发布；大内容使用不可变文件，SQL 保存目录、依赖及可重建查询投影。长期结果的证据保护独立于外部交付回执期限。                       |
| D7   | 同时支持结果集合发现与结果内容检索；FTS5 覆盖集合说明、结果正文和可检索记录字段，命中返回结果/记录引用。字段查询在服务端筛选、排序、分页；索引可重建，查询不触发加工。                                                                          |

| D9   | 不在首版：形状、配方、Unit 级依赖、版本对比、修订传播、“待更新”标记、新旧记录匹配、文档 Unit 与坐标、复查修复 Agent、语义向量检索、Web 新页面。触发条件见参考设计。                                                                             |

## 必须闭合的最小合同

1. **输入与执行配置固定。** 文献 ID 或查询只是选取方式；入队前解析成精确文档版本及 hash、上游结果 ID 及 hash，并保存缺失项和规范。模型绑定、提示词/输出 schema、读取与合并策略等影响结果的配置进入指纹，不保存凭据。恢复不重新选当前文档或当前模型；绑定不可重建时报告缺口。
2. **覆盖与执行状态分别表达。** 每项结果说明预期处理范围、实际读取范围、未处理部分及原因。检索零命中、上下文截断和不支持的表格/图片不能变成全文未报告。部分结果允许保存和明确使用，但不按完整成功跳过；首版重新处理整篇，不做局部续算。
3. **结果、集合与运行分别保存。** 内容只发布一次，结果集合保存精确结果引用，不复制正文。每次新提交创建运行；同一幂等请求返回同一运行。运行进度可变，已发布结果及集合清单不可变；重试/更新产生新的产物或集合清单，旧引用继续有效。同输入集合满足覆盖等条件时可复用旧产物，首版不额外提供对完整成功结果的同身份强制重算机制；partial 可以另起尝试，不能因旧局部产物占用复用键而无法补全。
4. **跨处理器可组合。** 规范与内容类型必须可校验，记录身份限于所属结果。综合适配器能读取标签、记录和既有知识，保留字段证据与真实文献来源；不能把任意 JSON 冒充旧知识产物，也不能把同一论文的多份结果当成多个独立来源。
5. **持久内容与查询投影分离。** 旧知识产物由原服务拥有，新通用结果由知识加工服务验收发布，Storage 只保存决定。记录行与全文索引从不可变内容重建。发布有效结果时登记精确输入依赖，外部回执过期不解除长期结果的引用保护。

这些合同不引入通用 DAG、Unit 级失效或自动修订传播；它们使首版的批量复用、组合和长期读取成立。精确 TypeScript 接口、schema 与发布事务由 01/02 落实。
