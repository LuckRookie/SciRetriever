## 责任边界

- `packages/contracts` 拥有可序列化的中性输入、结果、证据与校验；可执行函数不通过 CLI/MCP 序列化。
- `analysis/` 拥有处理器接口、注册与结果验收；`extraction/` 继续拥有外部候选校验，新增默认提取方法不改变调用方对领域含义的所有权。
- 文档读取复用 `document/`，定位检索复用 `retrieval/`，模型调用复用 `agents/`；输入冻结与生命周期由 `application/` 负责，生产依赖由 `bootstrap/` 组装。不新建平行任务或模型运行时。

- [x] 1.5 定义中性请求/结果 parser、服务内 `Processor`/`ProcessorContext` 及发布/读取端口，并做直接合同测试：
  - 处理器描述包含 id@版本、`document/collection` 范围、接受的输入类型、规范和输出 schema。跨文献综合接受显式结果引用，不从文献 ID 猜测选用哪个历史结果。
  - 冻结清单绑定每个目标的文档版本/表示 hash、材料引用、上游结果 ID/内容 hash，以及记录子集选择；记录缺失输入、规范 hash 和有效执行配置。不接受运行中隐式扩展读取范围。
  - `ctx` 提供冻结范围内的文档读取/定位检索、结果读取、DSH 模型调用与 `AbortSignal`。文档级处理限于本目标及显式输入；集合级限于固定成员。读取、模型和 usage 通过共享边界记录，不授予 SQL、凭据或任意网络能力。
  - 发布结果有 schema 版本、稳定 ID、内容类型与内容引用/hash、处理器/规范/执行配置身份、输入清单、证据、覆盖、时间及生产者。记录型内容有字段 schema，记录 ID 只在结果内唯一，字段以明确路径关联证据；不建立跨运行样品身份。已有知识结构通过适配保留，不强行改成 Markdown。
  - 输出状态为 `ok/empty/failed`，覆盖另记 `complete/partial/none`、预期/已读范围及缺口原因。`empty` 必须 complete 且确实无记录；零命中、截断、能力不支持不能满足它。有效局部内容可以作为 partial 结果发布；结果 ID 与复用键分开，同一输入的多个局部尝试及后续完整结果均有独立引用。失败尝试进入既有 Jobs，不用错误信息覆盖旧产物。
  - 方法指纹包含 prompt/输出 schema、读取/合并策略、有效模型绑定及影响输出的配置；无模型方法如实记录。外部生产者声明与平台观测分开，不能把外部方法 id 当作完整、已验证的执行指纹。
- [x] 1.6 适配现有处理，保留旧公开请求、错误语义、默认指针、历史产物与证据；允许必要内部重构：
  - `analysis/knowledge.ts` 包装为 `knowledge-overview`、`knowledge-detailed`、`knowledge-question` 三个文献级处理器；
  - 长文处理经 `analysis/knowledge.ts` 的服务入口适配，复用 `knowledge-long.ts` 的分块算法与已有方法身份，保留原发布责任；
  - `analysis/synthesis.ts` 增加版本化的通用结果输入适配，旧文档/知识输入继续可用。通过公开结果读取端口把标签、记录、文本或既有知识转换为可引用候选；保留记录/字段引用及原文证据，不把它们伪造成旧 `KnowledgeArtifact`。按实际引用的 Literature 去重来源；
  - 外部交付作为接纳适配器，复用 `extraction/delivery.ts` 的 schema/证据检查，随后显式请求长期保存。旧 submit/receipt 的有效期和回显行为不变，不声称旧回执能恢复候选正文；新持久接口接收完整候选与规范/输入绑定，生产者标为外部；
  - 旧服务发布的内容仅以稳定引用映射到统一结果；新通用结果由 Analysis 验收并经同一 Storage 发布机制保存。新路径的覆盖与复用策略必须贯穿服务适配，不能在外层拒绝 partial 复用后又由内层缓存返回同一旧局部产物。旧入口维持原合同，不在本块批量迁移历史结果。
- [x] 1.7 处理器注册表按 `id@version` 查找，允许多版本并存，并公开规范/输入/输出描述以供 CLI/MCP 发现。已有产物读取不要求对应处理器仍注册；未知处理器或不兼容输入在执行前失败。
