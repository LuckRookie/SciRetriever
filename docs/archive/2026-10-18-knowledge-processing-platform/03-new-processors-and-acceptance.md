## 责任与 Tasks

- [x] 3.1 打标签处理器（文献级）：输入问题、答案类型（枚举、布尔或文本）及读取范围，输出答案、证据与覆盖。例如“是否做了空气暴露实验：是、否、不确定”。判断不确定与执行失败分别表达；缺失值不能变成 `false`，局部检索未命中不能得出“全文未报告”。通过统一结果合同输出可筛选记录。
- [x] 3.2 记录提取处理器（文献级）：
  - 规范：一句话说明“一行代表什么”，字段至少有名称和说明，类型与单位可选。未声明类型的字段采用固定的可空文本默认值；执行前形成并冻结字段 schema，不逐篇猜测字段类型。声明纳入条件、处理范围与缺失值表达。
  - 执行：通过 `ctx` 在冻结文档中定位相关内容，联合抽取同一记录的所有字段。局部检索可以辅助定位；若规范要求全文覆盖，则按片段分批完成读取，否则只报告实际覆盖，不以一次模型调用塞入全文作为前提。
  - 首版只消费当前可读文本与 Markdown 中的表格文本；可靠的单元格、页坐标、图片数值和 SI 能力必须由输入实际提供，缺失时报告限制，不隐式获取、解析或修复。表头/脚注支持一个值时保留相应文本证据，不伪造单元格坐标。
  - 结果：实际报告值附字段证据，未找到/未处理/不可读有独立原因，不给缺失值编造证据。数值在保留原串的前提下做明确格式校验；单位保留原文，不能识别则标明限制，不静默换算或按无量纲处理。数值出现于引文只是检查项，不代表归属、条件与科学解释正确。
  - 完成声明的材料范围且无记录才返回 `empty`；读到有效记录但还有未处理部分，保存 partial 与缺口，后续整篇重跑。记录 ID 限于本次结果，保留原文报告粒度，不合并重复测量或匹配新旧样品。
- [x] 3.3 经 01 已验证、02 已接线的公开结果接口，将标签和记录引用交给综合处理器，跑通“提取 → 综合 → 字段证据 → 原文”。综合明确继承输入的覆盖缺口，同一篇论文的标签与多条记录不能重复计算独立来源；新材料改变时另运行综合，旧报告仍可读取。
- [x] 3.4 端到端合成场景：
  - 从已准备的合成文档打标签，保留“不确定”，显式选择符合规则的文献；
  - 对筛出的固定输入提取记录，通过有类型的公共查询条件筛选、排序和分页，不向调用方暴露 SQL；
  - 明确选中结果或记录子集生成综合，重启后仍能从报告展开到字段和原文；
  - 覆盖 02 的 100→120 包含关系、部分重叠、5 篇变化、模型/规范变化及恢复期间默认版本变化；检查实际输入、结果成员、证据和模型调用，不只检查计数；
  - 用只出现在结果正文/记录值中的词经 MCP/CLI 找到内容；索引重建后仍能查到，所有读取不触发模型；
  - 注入零命中、字段缺失、局部不可读、坏证据、模型失败、取消和外部回执过期，验证覆盖、长期引用与重试边界；
  - 经真实应用组装与合成存储调用 CLI/MCP，并使用 fake 模型；新增方法的接入差异应限于处理器、注册、必要资源/测试和文档。验收驱动脚本不等于完成真实 Agent 的自主操作评测。
- [x] 3.5 运行 `pnpm full`。若出现既有的冷启动超时，可按既有做法调整 `VITEST_MAX_FORKS` 与 `VITEST_MIN_FORKS` 重跑，但不修改用例、断言、超时或测试范围。
- [x] 3.6 文档同步：项目 README、技术文档、CLI/MCP 指南、模块 README、计划与提案索引；检查链接并运行 `git diff --check`。
- [x] 3.7 在 `sandbox/cases/` 编写真实质量评估方案、标注模板及待授权步骤：计划选 30–50 篇，评价提取准确性、漏抽、字段归属、条件/单位、证据支持与覆盖。使用占位样本说明，不读取或标注真实语料，不运行真实模型；后续经 Owner 授权才选择样本、标注和执行，不能把方案当成已建好的评测集。
