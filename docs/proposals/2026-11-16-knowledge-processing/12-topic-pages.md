# 12 · 主题页面：从主题读到原文

类型：计划（结果块）
负责：`groups`（`topic` 变体）与 `pages` 产出类型、主题分组、按组汇总、论文页与主题页、页面集的发布与条件切换
状态：Pending

## Outcome

1. 人在 Web 上，或 Agent 经 CLI、MCP，对一批论文发起“主题页面”（命名组合 `topic-wiki` 的最小形式），分四段运行，每段单独经过检查点：
   1. 逐篇按论文页的内置规范采集（`qa`，`text` 答案，带引用）；
   2. 主题分组：模型提出组定义，确认后逐篇归属，可以多归属，组定义冻结；
   3. 按组汇总：每组一份带引用的报告；
   4. 派生页面集：主题索引、主题页、论文页与页间链接。
2. 人只用 Web，从主题索引进入主题页，读到其中一篇论文的论文页，再从陈述打开证据、跳到原文的位置，并原路返回到原来的主题页与位置（需求用3）。
3. 页面集是版本化清单：一次显式更新生成新清单，条件切换入口；旧页面与旧链接仍可读。未变的单元经复用键复用，不重新付费。
4. 页面区分“当前文献集中未找到”与已有证据的陈述；不把局部说成整个领域，结果写明实际覆盖的文献。

本块只有论文页与主题页两种页面类型。方法、论断、研究空白页与受影响范围的增量更新在 [08](08-topic-wiki.md)，页面中的实体与关系链接在 [10](10-relation-graph.md)。

`groups`（`topic`）与 `pages` 两种类型的三样交付（规格 8.12）：

| 交付           | 内容                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------- |
| 人读的页面     | 主题索引；主题页（名称、定义、成员论文与归属理由、按组汇总的陈述带短证据编号）；论文页；证据抽屉跳到原文 |
| Agent 按层读取 | 页面清单分页 → 按页读取所引结果 → 组列表分页、按组分页读取成员 → 证据 → 原文                             |
| 带出处的导出   | Markdown 文件夹（每页一个文件，页间链接写成相对链接），引用带出处，附被引文献的书目；组的 CSV            |

规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.2、8.3、8.7–8.9、8.12。

## Tasks

- [ ] **12.1 类型**〔worker〕
  - 落实规格 8.2 的 `groups`（本块只实现 `topic` 变体）与 `pages`；在类型注册表登记校验器、判断取值与视图标识。
- [ ] **12.2 论文页的采集规范**〔总设计师设计，worker 实现〕
  - 内置一份 `qa` 规范，`text` 答案：概述本文研究的问题、所用的方法或论据、主要结论，以及结论成立的条件与局限，逐条带引用。规范不预设学科，不要求文献有“方法”“结果”章节（需求规4）。
  - 按规格 8.9，页面由自己的规范驱动采集，不以通用总结代替。
  - 论文页另外引用这篇论文已有的、同一文本版本上的概览与脉络（14，规格 8.16），只引用，不新建运行；没有时只显示本 Task 的回答，并给出发起 `reading-layers` 的入口。人打开一篇论文先读的是概览，不是 `summary@3`。
  - 论文页链到这篇论文的阅读页。阅读页本身由另立的阅读页计划实现，不在本计划内。
  - 按规格 8.9：资料已有脉络与概览时，论文页取自它们，不再另行逐篇采集；没有时才用本 Task 的 `qa` 采集。
- [ ] **12.3 主题分组**〔worker〕
  - 落实规格 8.8 的主题分组：模型基于冻结的上游条目（12.2 的回答）提出组定义（容量预检，超限分批提议再合并），经确认后逐篇归属，每项归属带理由与引用；“归入现有组”与“重新分组”两种模式，结果标明模式。
  - 提议是辅助付费步骤，开始前给出规格 8.6 表中“分组提议”一行的已知内容。
- [ ] **12.4 按组汇总**〔worker〕
  - 汇总增加 `per-group` 模式：对每组成员分别汇总（`question-report`，以组定义为问题的背景），结果引用组 ID 与组定义 hash。
- [ ] **12.5 页面集组装与发布**〔worker〕
  - 在 07 的派生执行中增加页面清单组装：主题索引页、主题页、论文页，以及主题页与论文页之间的双向链接；一页可以引用多份结果。
  - 落实规格 8.9 的版本化清单与条件切换：基于的入口版本不再是当前版本时发布失败并保留结果；旧页面与链接仍解析到原版本；失败时保留旧入口。
  - 更新是一次显式的新运行：按冻结输入重新展开组合，未变单元经复用键复用；受影响范围的预先计算在 08。
- [ ] **12.6 命名组合 `topic-wiki`（最小形式）**〔worker〕

- [ ] **12.7 机器读取与导出**〔worker〕

  - 导出接上 02 的 2.11：Markdown 文件夹，页间链接写成相对链接，附书目；组导出 CSV。
- [ ] **12.8 Web**〔前端〕

## 验证

命令按根 README 的验证路线；新增 `processor-grouping.test.ts`、`wiki-pages.test.ts`，以及 Web 的端到端测试 `topic-pages-journey`（合成样例服务）。

- 用3 路径：在合成样例上从主题索引 → 主题页 → 论文页 → 证据抽屉 → 阅读页的原文位置 → 返回，回到同一页面与位置；每一步的内容与所引结果一致；
- 多归属；组定义冻结；“重新分组”生成新结果，不改旧组；
- 页面陈述的证据链在合成样例上可回到证据根（只证明信息传递，不证明真实质量）；
- 条件切换：两个并发更新基于同一入口版本时只有一个切换成功；发布失败不换入口；旧页面与旧链接持续可读；
- 更新时未变的单元复用，fake 模型对它们的调用次数为 0；
- 未经确认不产生调用；Agent 发起的分组提议在 06 之前生成待确认请求；阅读页面不触发任何运行；
- 同一页面集经 Web 与 CLI、MCP 读到的页面、所引结果与链接一致；导出的 Markdown 文件夹里相对链接都能解析，引用键与书目一致；
- 两种学科形态的合成论文（有实验章节的、没有“方法”“结果”章节的）都能得到论文页，不报缺材料。

未覆盖：真实文献集上的分组与页面质量（11 的成套效果评估）。
