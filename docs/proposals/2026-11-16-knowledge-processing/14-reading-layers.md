# 14 · 阅读层：概览与脉络

类型：计划（结果块）
负责：内置规范 `key-points@1`（脉络）、汇总的 `overview` 与 `overview-by-chapter` 模式（概览）、补丁表、命名组合 `reading-layers`，以及它们的机器读取、导出与结果视图
状态：Pending

## Outcome

一份资料（论文、综述、学位论文、手册等）的脉络与概览可以生成、可以被 Agent 按层读取、可以带出处导出：

1. 人在 Web 上，或 Agent 经 CLI、MCP，对一份或一批资料发起 `reading-layers`。它是两段独立的运行，每段各自估算与确认：先逐篇读一遍原文得到脉络，再以脉络为输入汇总出概览。原文只读这一遍。
2. 脉络是 `records@3` 下的内置规范 `key-points@1`：一个要点一条记录，按作者的顺序编号，挂在作者自己的标题下，每条要点带依据（原句、图、表、数字、引用）。原句与数字逐字核对。
3. 概览是一份 `report`，各节固定（性质与范围、要点、依据、局限与未决事项、精读建议、关键图表）。它只从脉络取材，不读未被引用的原文；资料里没有的内容写成“原文未给出”。
4. 长资料按章处理：每章一个执行单元，得到每章的脉络与概览，再汇总出按章的整份概览。
5. 每份结果的外框记下三层提示词（核心、阅读提示、使用者说明）与实际用到的补丁；补丁表是数据，起步为空，只在有失败案例与复核结论时加入。
6. 按资料取用时，Agent 先取概览，再取脉络，需要时再进原文；每一层都只读已有内容，不触发加工。

本块不新增产出类型，三样交付沿用 `report` 与 `records` 两族（规格 8.12）：

| 交付           | 内容                                                                                                                                                                        |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 人读的页面     | 02 的结果页外框里的概览视图与脉络视图，证据抽屉跳到原文；阅读页本身不在本计划，由另立的阅读页计划实现（[阅读体验](../../architecture/web/reading-experience.md)第 3、7 节） |
| Agent 按层读取 | 概览（外框与各节，引用随带被引要点的编号与短文本）→ 脉络（按要点分页）→ 证据 → 原文                                                                                         |
| 带出处的导出   | 概览导出为 Markdown，脉络导出为 CSV 与 JSON，都附被引文献的书目                                                                                                             |

规格见[知识加工规格](../../architecture/technical/05-knowledge-processing.md) 8.16，以及它改动的 8.2（`report` 的 `refs[]`、`not_given[]`、`origin`，章节与图表块的受控引用，逐字核对的匹配位置）、8.7（两种汇总模式与 `reading-layers`）、8.12（按资料取用的顺序）、8.13。决策依据：[ADR 0061](../../architecture/decisions/0061-reading-first-reader-and-layered-reading.md) 第 5 节。

## 责任边界

## Tasks

- [ ] **14.1 内置规范 `key-points@1` 与校验**〔worker；核心提示词由总设计师写〕
  - 按规格 8.16“脉络”登记内置规范：字段 `number`、`statement`、`heading`、`evidence`，依据类别是封闭集合 `quote`、`figure`、`table`、`number`、`reference`，各类别的字段与引用目标按规格。
  - `requires: main-text`；读取范围是正文整篇（长资料是一章），不按章节角色限定，所以在初稿上照常读取，不出现 8.4 的整篇说明。
  - 平台校验，任一项不过就退回同一会话修正：
    - `number` 从 1 起连续、唯一；按 `number` 排序时 `heading` 所指章节在大纲里的顺序不倒退；
    - `heading` 指向所读版本大纲里存在的章节；大纲没有标题时必须为 `null`；
    - `statement`、`reference.note` 不超过 120 个字符，各至少一个引用；
    - `evidence` 为 1–8 项，或缺失原因为 `not-given` 的 `null` 并附一句缺什么；为 `null` 时 `statement` 仍有自己的引用；
    - `figure`、`table` 的块存在、类别与结构一致，结构分不出图与表时只核对存在；`reference.work` 指向资料参考文献表里的条目；
    - 核对方式逐字段声明：`quote.text` 与 `number.value` 逐字核对；`statement`、`quantity`、`note` 只核对引用存在。
  - 规范与核心只用于内置的脉络与概览；声明式算子不能按章读取或使用补丁（05 的 5.1 保存时拒绝）。
- [ ] **14.2 逐篇一段：阅读提示与使用者说明**〔worker〕
  - 会话先接受阅读提示、再接受记录：阅读提示一两句，每句至少一个引用（文本位置或冻结元数据）；提交阅读提示之前提交的记录被拒。
  - 使用者说明是运行参数 `instruction`：纯文本，不超过 300 个字符；一次运行一句，管这次运行的全部成员；作为规范进入复用键，不计入方法 hash。
  - 完整读取声明的范围，规则同 `qa`：读取未完成时提交退回同一会话。
  - 外框 `reading` 写入：`core`（`{id, version, sha256}`）、`note`、`instruction`、`patches[]`（只列这个成员实际用到的）。
- [ ] **14.3 逐字核对与匹配位置**〔worker；部分〔计划 21〕〕
  - `quote.text` 与 `number.value` 按规格 8.2 逐字核对；结果为 `found` 时同时给出匹配位置：所引片段内的 UTF-8 字节范围。
  - 不符时保留原值与核对状态，所引片段的原文可以读到；不改写数值，不猜测。
  - 〔计划 21〕在初稿上同样执行，核对结果旁带片段的文本等级与核对依据。
- [ ] **14.4 汇总的 `overview` 模式**〔worker〕
  - 在 02 的 2.2 中注册 `records → overview`。输入是一份资料的脉络结果的集合清单；脉络不完整时请求无效。复用键含输入清单的 hash；脉络过时，以它为输入的概览同样标为过时。
  - 各节按规格 8.16“概览”的表：`section_id` 与 `heading` 固定；各节上限按表，超出的提交退回同一会话；机器写的陈述每句不超过 200 个字符、带引用，引用脉络的条目（综合值）。
  - 性质与范围由平台从输入脉络的外框照录：使用者说明（`origin: user`，有说明时才有），再是阅读提示（`origin: model`）；模型不另写。
  - 每节的 `refs[]` 只能引用规定类别的脉络条目，平台核对类别。
  - 同一条要点只出现在一栏：列入“局限与未决事项”的要点不再列入“要点”。
  - “原文未给出”（`not_given[]`）只在“依据”与“局限与未决事项”两节可用，含义是输入的脉络里没有这类内容；输入完整才能提交。
  - 读取范围限定为输入的脉络记录，以及这些记录所引的片段；会话工具对未被引用的片段一律拒绝。
  - 批量时每份资料一次汇总，这一段的全部汇总一并估算与确认。
- [ ] **14.5 长资料：按章执行与 `overview-by-chapter`**〔worker〕
  - 判定：所读版本正文的 UTF-8 字节数超过阈值，且大纲最高一级章节至少 2 个，就按章处理。阈值是方法参数，默认 512 KiB（规格 8.16），计入方法 hash；它是校准值：11 的 11.10 用测试集中的长资料核对它，改动阈值按补丁同样的规则升级 `key-points` 的版本。
  - 判定结果与各章的片段范围随快照冻结（在 04 的 4.4 的冻结中增加这一项），在估算前显示。
  - 一章是最高一级的一个章节连同下级章节；第一个最高级标题之前的内容并入第一章。每章是一个执行单元，要点编号在章内从 1 起；章数不设上限。
  - 在 02 的 2.2 中注册 `report → overview-by-chapter`：输入是各章概览的集合清单，清单里每份长资料各产出一份整份概览。各节为性质与范围（这次汇总写的阅读提示，加使用者说明）、各章要点 `chapters`（每章一条陈述，引用该章概览的要点条目；章号、作者章标题与可靠的页码范围由平台按冻结的大纲填入）、局限与未决事项、精读建议；没有“依据”与“关键图表”。只读各章的结果，可回读被引用的片段，不补读原文。
- [ ] **14.6 补丁表**〔worker 实现加载与校验；总设计师提议条目〕
  - 补丁表是随内置方法发布的规范 JSON，起步为空。每条 `{patch_id, key, text, failing_example, check}`。
  - 加载与构建时校验：`key` 的字段只能是 `publication_form` 或 `article_kind`，取值属于元数据合同的封闭取值；缺 `failing_example` 或 `check` 的条目拒绝；`failing_example` 只含案例 ID、结果 ID 与一两句说明，不含资料原文。
  - 选用：按成员的冻结元数据选用，不按阅读提示；没有该字段的成员不用补丁；命中多条时按表中顺序附在核心之后；两种汇总用同样的规则。用于选用的元数据字段进入复用键；整张表的 hash 进入脉络与两种汇总的方法 hash。
  - 表的任何改动都升级 `key-points` 的版本；旧结果按规格 8.13 处理，不自动重算；新方法没有同口径历史时估算显示“未知”。
  - 条目由谁提议、谁判定，见 11 的 11.10。
- [ ] **14.7 命名组合 `reading-layers`、估算与确认**〔worker〕
  - 按规格 8.7 展开：普通资料为逐篇脉络 → `overview` 两段；长资料为每章脉络 → 每章 `overview` → `overview-by-chapter` 三段。展开写入运行记录；每段在上一段冻结后由人或 Agent 发起，界面与机器接口预填，不自动连跑。
  - 每段各自按规格 8.6 估算与确认（02 的 2.5、2.9）；Agent 没有任务授权时生成待确认请求。按章判定在估算前显示。
  - 复用：同一资料、同一文本版本、同一规范、说明与方法已有完整结果时直接复用。
- [ ] **14.8 由脉络推出的内容**〔worker〕
  - 读取时按规格 8.16 计算，不另存，不调用模型：图表支撑的要点；段落与要点的对应；关键句（`quote` 逐字核对为 `found` 的匹配位置）；出处角标（段号与句号，分句规则见[文档与证据 3.5](../../architecture/technical/04-document-evidence.md#35-分句与出处角标目标尚未实现)）。
  - 库内关联中的 `reference` 依据：按引用关系里绑定这份文档与参考条目的支持解析到库内文献；初稿没有参考条目，不解析，也不显示为“不在库内”。
  - 按问题阅读的“有关的要点”：同一文档版本的脉络里，引用片段与回答某句的引用片段相同的要点；文档版本不同时不给出。
- [ ] **14.9 机器读取**〔worker〕
  - CLI、MCP（HTTP 共用应用边界）按资料取用：先取概览（外框与各节；每个 `refs[]` 引用随带被引条目的编号与短文本，从脉络读出），再取脉络（按要点分页，可按 `heading` 筛选），再按 02 的 2.10 进证据与原文；14.8 的内容同样可读。
  - 长资料：章的列表（编号、作者章标题、可靠的页码范围、一行要点）与各章的概览、脉络。
  - 资料没有概览或脉络时，返回缺口与可发起的组合，不触发加工（需求规1）；过时与文本等级如实给出。
  - 按规格 8.12“按资料的阅读读取”交付九个只读操作，Web、CLI、MCP 三端共用；按规格 8.13 在状态读取里报告加工能力是否可用。阅读页（[计划 24](../../archive/2026-11-13-reader/README.md)）依赖这两项；其中回答、关联、主题页三类读取在对应的块交付之前返回空结果或“能力不可用”，不报错。
- [ ] **14.10 导出**〔worker〕
  - 概览按 02 的 2.11 导出为 Markdown：各节固定标题，引用写成脚注，“原文未给出”照录缺什么，使用者说明标明来源；脉络按 03 的 3.1a 导出 CSV 与 JSON；都附书目。长资料导出整份概览与各章文件。导出只读已有结果，不调用模型。
- [ ] **14.11 结果页里的视图**〔前端〕
  - 先在页面规格写草案节，再在 02 的结果页外框内登记两种视图：概览视图（`report` 族：固定各节、被引要点的编号与短文本、“原文未给出”、关键图表）与脉络视图（`records` 族：按作者标题分组的要点、五类依据、逐字核对状态）；外框显示 `reading` 的核心版本、阅读提示、使用者说明与用到的补丁，以及三个数。
  - 视图只用来查看与核对结果；阅读页的版面、排版与阅读位置属于另立的阅读页计划。结果页给出到这份资料阅读页的链接。
- [ ] **14.12 验证与审阅点 C 审阅包**
  - 运行下节测试；审阅包含一份普通资料与一份长资料的概览、脉络、导出文件与机器读取的输出，以及同一组合由 Web 与 CLI 发起的结果对照。

## 集成与影响

- 调用方：02 的结果页与汇总执行；12 的论文页引用概览与脉络；10 的 `library-relations` 以脉络要点为端点；另立的阅读页计划读取本块的全部结果与推出内容。
- 存储：结果沿用现有外壳；快照增加按章判定；补丁表是随方法发布的数据，不进 catalog。需要表结构变化时并入 G-schema 的 M1 窗口。
- 用户可见变化：每份资料可以先得到概览与脉络；Agent 可以先读概览再决定是否深入。

## 验证

命令按根 README 的验证路线。新增 `processor-key-points.test.ts`、`processor-overview.test.ts`、`processor-reading-layers.test.ts`、`processor-patch-table.test.ts`。合成测试集放在 `tests/fixtures/`，覆盖规格 8.16 测试集的各种资料：研究论文、综述、学位论文、手册、笔记形态的资料，来自两个差别明显的学科，至少一份按章处理的长资料，至少一份没有章节标题的资料；〔计划 21〕另加以初稿为默认文本的样例。合成测试集只证明机制。

- 脉络：每项校验规则各有负例并被退回；没有标题的资料 `heading` 全为 `null`；同一图表出现在多条要点的依据里；依据为 `not-given` 时 `statement` 仍有引用；提交阅读提示之前的记录被拒；读取未完成的提交被退回；
- 使用者说明：超过 300 个字符被拒；说明不同则复用键不同、方法 hash 相同；
- 逐字核对：原句与数字在原文中时为 `found` 且匹配位置正确；改错一个字或一位数字时为不符，原值不被改写；机器写的字段不产生逐字核对记录；
- 概览：
  - fake 模型的会话日志证明：概览只读取了输入的脉络记录与它们所引的片段；请求未被引用的片段被拒；
  - 同一条要点只出现在一栏：把一条要点同时放进“要点”与“局限与未决事项”的提交被退回；
  - 脉络里没有局限时“局限与未决事项”为 `not_given[]`；脉络不完整时请求无效；`refs[]` 引用不允许的类别被拒；超出各节上限被退回；
  - 性质与范围与输入脉络外框的说明、阅读提示逐字相同；
  - 脉络过时后概览同样标为过时；
- 长资料：刚好低于与高于阈值、只有一个最高级章节的三份样例分别判定正确；第一个最高级标题之前的内容并入第一章；章内编号从 1 起；整份概览的章号、标题与页码由大纲填入；阈值改动后方法 hash 不同；
- 补丁表：空表时没有补丁；缺 `failing_example` 或 `check` 的条目加载失败；`key` 用其它字段被拒；按冻结元数据选用，与阅读提示无关；没有该字段的成员不用补丁；多条命中按表序；表改动后版本升级、估算为“未知”、旧结果不被重算；
- 组合与估算：两段分别估算与确认，第一段不自动带出第二段的运行；未确认时调用次数为 0；Agent 无授权时生成待确认请求；批量时第二段一并估算与确认；
- 推出内容：图表支撑的要点、段落与要点的对应、关键句与合成数据的已知值相等；初稿不解析参考条目；
- 机器读取：概览第一层就带被引要点的编号与短文本；按资料的读取顺序在 CLI 与 MCP 上一致；没有结果时返回缺口且不创建任务；
- 导出：Markdown 与 CSV、JSON 的引用键与书目一致；导出不调用模型。

未覆盖：真实资料上的阅读质量（11 的 11.10，须授权）；阅读页的显示（阅读页计划）。
