本轮根据用户已确认的产品重点重新组织页面，并采用蓝白工具风格。用户随后明确授权以此版 Web 为主接入全部已有功能。原型仍使用合成数据，正式实现和验收状态见[工作台实施计划](../../plans/2026-10-13-web-workbench/README.md)，实际使用见[Web 指南](../../guides/web-workbench.md)。

## 已确认的设计依据

Web 的主线是**发起、观察和干预文献处理任务，以及检查任务结果**。文献阅读承担检查和使用结果的配套责任，应完整、好用，但不决定整个工作台的首页排版。

- 工作台优先回答“现在在做什么”“有什么需要我处理”“已经得到什么”。
- 保留工作台、任务、文献库、设置四个一级入口。
- 采用蓝白工具风格；通过空间分配、信息层级和操作反馈改善视觉，不仅替换原型的强调色。
- 人类和 Agent 查看同一套文献与任务事实；Web 不另建业务库或任务状态体系。

## 本轮布局方案

外框采用约 216px 的轻量左导航、顶部上下文与主操作、右侧主要工作区域。导航和背景退到次要层级，任务名称、状态和下一步操作形成稳定的阅读顺序。主要页面共享对齐、按钮、表格和状态表达，内部空间按任务执行或阅读需要分配。

| 页面     | 重点与空间分配                                                                                                                             |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| 工作台   | 新建任务入口明确；活动任务为主体，需要介入的事项就近提供处理入口；最近完成结果能够直接打开。统计信息压缩为辅助内容，不占据大面积展示卡片。 |
| 任务     | 用可扫描列表组织队列和历史；选中任务进入详情，保留目标、范围、状态及返回路径。                                                             |
| 任务详情 | 以“执行 / 结果 / 活动记录”分开当前工作、产物检查和过程追溯。任务目标和主要控制保持可见，结果同时呈现已完成部分与缺口。                     |
| 文献库   | 通过搜索、筛选和列表查找已有材料；从任务结果进入阅读时保留返回任务的上下文。                                                               |
| 设置     | 按运行条件组织入口，让用户识别当前库、来源、模型和解析服务的状态；原型中的状态与值均为合成示例。                                           |

Browser 隶属任务详情中的执行场景，不增加第五个一级导航。当任务需要观看或接管时，画面获得足够空间，并持续显示所属任务、文章和控制者；其他阶段使用相应的执行信息。接管、交还与指导采用独立操作，不把任务取消、页面动作和文件传输混成一个控制按钮。

新建任务使用结构化表单，表达目标、范围及要执行的操作。具体字段用于验证操作流程，不冻结公开接口、配置或任务 schema。提交、接管、交还等反馈在原型中仅改变页面内存中的合成状态。

## 从任务到结果的闭环

本轮可点击稿围绕以下路径组织：

1. 从工作台新建任务，理解本次工作的目标与范围。
2. 打开任务详情，在“执行”页查看当前阶段和需要介入的事项。
3. 从具体任务进入 Browser 场景，尝试接管、交还或指导的示例反馈。
4. 切换“结果”，区分已有材料、已完成知识结果和未完成部分。
5. 打开文献阅读与证据，再返回原任务；也能从文献库独立查找同类内容。

阅读区给正文主要宽度，知识、来源和证据按需展开。打开材料只表达读取；缺少解析或知识结果时，后续加工需要独立、明确的任务操作。任务失败或取消也不意味着抹去已经完成的有效材料。

## 视觉约定

| 角色     | 设计值    | 用途                             |
| -------- | --------- | -------------------------------- |
| 内容表面 | `#FFFFFF` | 列表、主要工作区、阅读正文       |
| 页面底色 | `#F4F7FC` | 区分外框与内容区域               |
| 主要文字 | `#18243A` | 标题、任务目标、重要数值         |
| 次级文字 | `#64748B` | 辅助说明、时间和元信息           |
| 分隔线   | `#E2E8F2` | 行、面板和区域边界               |
| 主蓝色   | `#2563EB` | 主要操作、当前选择与进行中的工作 |

工具正文以 14px 为基准，阅读正文以 16px 为基准；通过字重、对齐和留白建立层级，长文献标题允许合理换行。控件与面板使用 6–10px 圆角，阴影仅用于浮层。大面积背景保持中性，不用蓝色填满侧栏和每个模块。

成功、等待处理和失败使用独立语义色，同时保留文字或图标，避免仅凭颜色识别状态。焦点应可见；窄屏收敛导航并按优先级纵向排列内容，保留新建、任务查看和结果阅读入口。

这些数值是当前设计稿的视觉基线，最终密度、响应式断点和细部对比度仍以实际原型检查及用户反馈调整。

## 示例与实现边界

- 设计稿为单文件离线 HTML，文章、数字、任务、Browser 画面和配置值均为合成示例。
- 示例只保存在页面内存中，刷新后重置；不连接真实数据库、Provider、模型、解析服务或用户凭据。
- 页面中的数据库或服务状态只是设计展示，不证明本机已有正式绑定，也不读取个人配置。
- 本轮不修改 `apps/web` 生产代码，不新增依赖、公开 API、schema、持久化事实或实施计划。
- 生产任务类型、控制支持、生效时机、数据库绑定与断连恢复需要在后续实现时对照已有合同核实；原型点击成功不能作为生产能力完成证明。

10 月 8 日的两版原型继续保留用于历史对比。本轮新增蓝白设计稿，不覆盖原有暖白/墨绿探索，也不把旧原型中的功能状态说明当作当前生产事实。
